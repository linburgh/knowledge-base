# 前端后端服务地址独立配置方案

## 1. 改造目标

将前端浏览器访问的 API 公共地址与 Nginx 实际转发的后端服务地址分离配置，避免前端代码和 Nginx 配置绑定固定的后端容器名称。

目标配置：

```env
# 前端构建时使用，浏览器请求的公共 API 地址
VITE_API_BASE_URL=/knowledgebase/api/v1

# Nginx 运行时使用，实际后端服务地址
BACKEND_URL=http://knowledge-base-backend:28003
```

## 2. 当前问题

当前前端 API 地址在 `src/api/client.ts` 中按生产环境硬编码为：

```text
/knowledgebase/api/v1
```

Nginx 中又将后端地址硬编码为：

```nginx
proxy_pass http://knowledge-base-backend:28003/;
```

修改后端容器名、主机地址或端口时，需要修改镜像源码或重新构建配置，环境独立性不足。

## 3. 调整方案

### 3.1 前端 API 公共地址

修改 `src/api/client.ts`，统一从 Vite 环境变量读取：

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || "/api/v1";
```

开发环境：

```env
VITE_API_BASE_URL=/api/v1
```

生产环境：

```env
VITE_API_BASE_URL=/knowledgebase/api/v1
```

该变量属于构建时变量，会被编译进前端静态资源。

### 3.2 Nginx 后端地址

将固定 Nginx 配置改为模板：

```nginx
location /knowledgebase/ {
    proxy_pass ${BACKEND_URL}/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Request-ID $request_id;
}
```

容器启动时，根据 `BACKEND_URL` 生成实际 Nginx 配置。该变量属于运行时变量，修改后不需要重新构建前端镜像。

可配置为容器服务名：

```env
BACKEND_URL=http://knowledge-base-backend:28003
```

也可配置为其他容器、主机或服务地址：

```env
BACKEND_URL=http://backend-service:28003
BACKEND_URL=http://192.168.1.100:28003
```

## 4. 文件调整范围

前端项目需要调整：

- `src/api/client.ts`
- `nginx.conf`，改为 Nginx 模板
- `Dockerfile`，增加模板配置和启动时生成配置逻辑
- `scripts/run-image.sh`，通过 `--env-file .env` 注入运行时变量
- `.env.example`，增加 `VITE_API_BASE_URL` 和 `BACKEND_URL`
- 新增 Nginx 配置生成脚本

## 5. 配置生命周期

```text
VITE_API_BASE_URL
    ↓ 构建时注入
前端静态资源
    ↓ 浏览器请求
/knowledgebase/api/v1
    ↓ Nginx 运行时读取 BACKEND_URL
实际后端服务
```

## 6. Docker 网络要求

如果 `BACKEND_URL` 使用容器名称，前端和后端容器必须加入同一个 Docker 网络：

```text
knowledge-base-net
```

如果使用宿主机地址或独立服务地址，则不要求前后端使用同一 Docker 网络，但必须保证网络可达。

## 7. 当前 `knowledge-base-backend` 的来源

当前 Nginx 配置文件为：

```text
knowledge-base-web/nginx.conf
```

其中存在固定配置：

```nginx
proxy_pass http://knowledge-base-backend:28003/;
```

`knowledge-base-backend` 对应后端容器名称，默认来源是后端运行脚本：

```text
knowledge-base/scripts/run-image.sh
```

其中配置为：

```bash
CONTAINER_NAME="${CONTAINER_NAME:-knowledge-base-backend}"
```

前端运行脚本默认使用同一个 Docker 网络：

```text
knowledge-base-web/scripts/run-image.sh
```

因此当前 Nginx 通过 Docker 网络 DNS，将 `knowledge-base-backend` 解析为后端容器。

当前配置关系是：

```text
后端 run-image.sh
    ↓ 默认容器名
knowledge-base-backend
    ↓ Docker 网络 DNS
前端 nginx.conf 的 proxy_pass
```

## 8. 实施验证

- 前端开发环境可以通过 `VITE_API_BASE_URL` 切换 API 地址。
- 生产环境 API 前缀不再写死在 `client.ts`。
- 修改 `BACKEND_URL` 后，前端镜像无需重新构建即可切换后端地址。
- 前后端使用容器名通信时，两个容器处于同一 Docker 网络。
- Nginx 启动后通过 `nginx -t` 验证生成的配置有效。
