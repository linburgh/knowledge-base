# 开发者开放 API 在线文档原型设计

可直接查看统一交互原型：[知识库工作区原型.html](前端原型设计/知识库工作区原型.html)。登录后进入“平台管理”，点击“开发者中心” Tab 查看开放 API 文档。

## 1. 设计目标

建设面向企业开发者的在线 API 文档入口，帮助开发者完成以下集成：

- 查询当前用户可访问的知识库。
- 调用知识库检索和问答能力。
- 查询、创建和管理会话。
- 上传文档并查看文档处理状态。
- 在授权范围内获取知识库、文档和问答引用信息。

平台用户、租户、组织和权限管理仍属于管理后台能力，不直接作为普通开发者 API 开放。

## 2. 当前接口开放评估

### 2.1 推荐作为第一批开发能力开放

| 能力域 | 当前接口 | 开放建议 | 说明 |
| --- | --- | --- | --- |
| 登录与上下文 | `/api/v1/auth/login`、`/api/v1/auth/refresh`、`/api/v1/auth/me`、`/api/v1/auth/tenant` | 复用现有能力 | 当前前端文档使用平台用户 Bearer Token，不新增应用凭证体系 |
| 知识库 | `/api/v1/knowledge-bases`、`/api/v1/knowledge-bases/page`、`/api/v1/knowledge-bases/{id}` | 有范围开放 | 仅返回当前用户已授权的知识库，不开放跨租户查询 |
| 检索 | `GET/POST /api/v1/search` | 通过开放 Facade 暴露 | 开放路径为 `/api/v1/open/search`，由后端统一校验知识库访问范围 |
| 问答 | `POST /api/v1/chat`、`POST /api/v1/guest/chat` | 优先开放 | 适合作为同步问答 API；需要限制可访问知识库、`top_k`、问题长度和模型消耗 |
| 会话 | `/api/v1/conversations` 及消息、引用接口 | 有范围开放 | 适合需要保存上下文的应用；资源必须归属于调用应用或用户 |
| 文档读取 | `/api/v1/documents`、`/api/v1/documents/{id}`、`/api/v1/documents/{id}/chunks` | 有范围开放 | 仅允许读取当前用户授权知识库中的文档；分片内容需配置是否允许返回 |
| 文档上传 | `POST /api/v1/documents/upload` | 审核后开放 | 需要文件大小、格式、病毒检查、存储配额和异步任务状态 |
| 文档索引 | `POST /api/v1/documents/{id}/index` | 不建议直接开放 | 当前接口是同步触发任务，建议改造成异步任务提交接口并返回 task_id |

### 2.2 仅限平台或租户管理后台

以下接口涉及组织结构、成员关系、租户配置或平台级权限，不应直接加入普通开发者 API：

- `/api/v1/users/*`
- `/api/v1/tenants/*`
- `/api/v1/organizations/*`
- `/api/v1/platform/*`
- `/api/v1/knowledge-bases/{id}/organizations/*`
- `/api/v1/knowledge-bases/{id}/users/*`

知识库用户授权和组织授权应由租户管理员在管理后台完成；开发者应用只继承已经授予应用的知识库范围，不自行修改平台成员权限。

### 2.3 当前不宜直接开放的原因

当前路由虽然可以被 FastAPI 自动生成 OpenAPI 文档，但还不等于具备安全的开发者开放能力：

1. 认证主要围绕当前用户登录态，缺少应用级身份、密钥轮换和独立撤销能力。
2. 部分请求仍由调用方传入 `user_id` 或 `created_by`，开放后不能信任客户端提交的身份字段。
3. 缺少统一的应用数据范围模型，不能仅依赖前端或调用方传入 `kb_id` 做隔离。
4. 检索、问答、上传和索引缺少统一的限流、配额、超时和费用统计接口。
5. 文档索引当前更适合后台任务，开放接口需要明确异步状态和重试语义。
6. 错误响应、请求 ID、分页、幂等键和版本策略需要统一。

- 平台管理标题和 Tab，当前选中“开发者中心”。

### 3.3 左侧 API 导航

每个接口显示 HTTP 方法、路径和开放状态标签：`可用`、`需申请`、`规划中`。

## 4. 接口详情原型

接口详情统一包含以下结构：

1. 接口标题和一句话用途说明。
2. 方法、路径、版本和所需权限范围。
3. 认证方式和请求头。
4. 请求参数表：位置、名称、类型、必填、默认值、说明、示例。
5. 请求示例：JSON、cURL、JavaScript、Python。
6. 响应字段表和成功响应示例。
7. 错误码和处理建议。
8. 限制说明：频率、大小、超时、配额和幂等要求。
9. 代码示例：至少提供 cURL、Python、JavaScript 三种语言。

当前原型只展示接口文档、请求参数、响应示例、错误处理和代码示例。

## 5. 首批接口文档内容

### 5.1 获取可访问知识库

```text
GET /api/v1/open/knowledge-bases
权限：knowledge_base:read
用途：查询当前用户被授权访问的知识库列表。
```

### 5.2 知识库检索

```text
POST /api/v1/open/search
权限：knowledge_base:search
用途：在指定知识库中执行关键词、向量或混合检索。
```

请求示例：

```json
{
  "knowledge_base_id": 1001,
  "query": "员工报销需要哪些材料？",
  "mode": "vector",
  "top_k": 5
}
```

### 5.3 知识库问答

```text
POST /api/v1/open/chat
权限：knowledge_base:chat
用途：基于授权知识库内容生成回答并返回引用。
```

### 5.4 会话消息

```text
POST /api/v1/open/conversations/{conversation_id}/messages
GET  /api/v1/open/conversations/{conversation_id}/messages
权限：conversation:read、conversation:write
用途：保存多轮问答上下文并读取历史消息。
```

### 5.5 文档上传与处理状态

```text
POST /api/v1/open/documents
GET  /api/v1/open/documents/{document_id}
GET  /api/v1/open/documents/{document_id}/tasks/{task_id}
权限：document:write、document:read
用途：上传文档并异步查询解析、分块和向量化进度。
```

上述 `/api/v1/open` 为当前轻量开放 API 的路径。前端文档页面按该路径展示，后端通过 Nginx 和 Open API Facade 统一代理与鉴权。

## 6. 当前前端实现范围

当前只实现平台管理下的开发者中心 API 文档 Tab：

- 展示 `v1` 当前版本。
- 支持按接口名称、路径、参数和错误码搜索。
- 支持 API 导航切换和接口详情展示。
- 支持请求参数、响应示例和 cURL、Python、JavaScript 代码示例切换。
- 认证说明统一展示为 Bearer Token，实际身份和知识库范围由后端校验。

## 7. 统一开放 API 约束

- 所有当前开放接口使用 `/api/v1/open` 前缀。
- 使用 `Authorization: Bearer <access_token>`，不接受客户端提交的 `user_id`、`created_by` 作为身份依据。
- 当前用户身份和知识库范围由后端服务端校验。
- 写操作支持 `Idempotency-Key`，避免网络重试造成重复上传或重复授权。
- 统一返回 `request_id`、错误码、错误消息和可重试标记。
- 列表接口统一分页，时间统一使用带时区的 ISO 8601 格式。
- 上传和索引采用异步任务，提供任务状态、失败原因和重试接口。
- 对问答、检索、上传分别设置频率限制、并发限制、文件大小限制和租户配额。
- 普通日志不记录 Secret、Token、完整文件内容和完整问题内容。

## 8. 实施分期建议

### 第一阶段：文档和只读问答能力

- 建立 `/api/v1/open` 路由层和现有用户 Token 认证。
- 开放知识库列表、知识库详情、检索、问答和只读会话。
- 统一错误、分页和请求 ID。

### 第二阶段：文档写入能力

- 开放文档上传、文档列表和异步任务查询。
- 增加文件安全检查、配额和幂等控制。
- 增加回调或任务轮询接口。

### 第三阶段：平台运行配置

- API 版本生命周期、废弃提示和变更日志。
- Nginx 入口限流、请求超时和生产环境发布配置。

## 9. 原型验收标准

- 开发者无需阅读后端源码即可找到认证方式、权限范围、请求示例和响应示例；Base URL 作为文档配置项展示。
- 任何开放接口都能在文档页明确看到当前开放状态和限制条件。
- 原型只展示文档内容和代码示例，不包含请求发送、参数编辑或响应查看区域。
- 普通开发者无法通过修改 `kb_id`、`tenant_id`、`user_id` 访问未授权数据。
- 文档、检索、问答、会话和上传接口的错误响应格式一致。
- 内部平台管理接口与开发者开放接口在导航、认证和权限范围上明确隔离。
