# 系统菜单与角色界面展示设计方案

## 1. 文档目的

本文设计系统菜单、页面资源、操作权限以及不同角色登录后的界面展示内容，为数据库、后端接口和前端动态菜单改造提供评审依据。

当前系统角色分为三层：

- 平台角色：`p_super_admin`
- 租户角色：`tenant_owner`、`tenant_admin`、`tenant_member`、`tenant_guest`
- 组织角色：`org_admin`、`org_member`

## 2. 核心设计结论

菜单、页面和操作权限不是同一种数据，不能全部放进菜单表。

```text
系统菜单
  └─ 关联页面资源（可选）

角色
  ├─ 页面资源授权
  └─ 操作权限授权

页面资源
  └─ 页面展示配置
```

四类数据职责如下：

| 数据 | 职责 |
|---|---|
| 系统菜单 | 保存实际展示在导航中的目录和菜单项 |
| 页面资源 | 保存前端路由、页面组件和页面访问权限 |
| 操作权限 | 保存按钮、接口和业务操作权限 |
| 页面展示配置 | 保存角色进入页面后的组件、布局和操作展示差异 |

菜单负责“有什么导航入口”，页面资源负责“能否访问页面”，操作权限负责“能否执行操作”，页面展示配置负责“进入后展示什么”。

## 3. 菜单与页面资源边界

### 3.1 系统菜单只包含导航节点

系统菜单只保留两种节点：

| 类型 | 说明 |
|---|---|
| `directory` | 菜单目录或导航分组 |
| `item` | 可点击的菜单项，关联一个页面资源 |

以下内容不属于菜单：

| 内容 | 示例 | 是否显示在左侧菜单 |
|---|---|---:|
| 页面资源 | 平台概览、用户管理、开发者中心 | 可能显示 |
| 隐藏页面资源 | 详情页、编辑页、无权限页 | 否 |
| 操作权限 | 新增、修改、删除、上传 | 否 |

### 3.2 当前菜单示例

| 菜单编码 | 菜单名称 | 类型 | 关联页面资源 |
|---|---|---|---|
| `platform` | 平台管理 | `directory` | 无 |
| `platform_overview` | 平台概览 | `item` | `platform_overview_page` |
| `platform_users` | 用户管理 | `item` | `platform_users_page` |
| `platform_tenants` | 租户管理 | `item` | `platform_tenants_page` |
| `platform_organizations` | 组织管理 | `item` | `platform_organizations_page` |
| `developer_api` | 开发者中心 | `item` | `developer_api_page` |
| `knowledge_base` | 知识库管理 | `directory` | 无 |
| `knowledge_base_list` | 知识库列表 | `item` | `knowledge_base_list_page` |

开发者中心继续作为平台管理下的页面，不作为左侧独立一级菜单。

### 3.3 当前系统菜单梳理

当前前端原型和页面实现采用同一个应用壳层，左侧主导航只保留两个一级菜单：平台管理和知识库管理。平台管理内部使用 Tab 子导航，知识库进入具体知识库后使用工作区 Tab。

#### 3.3.1 左侧主导航

| 层级 | 菜单编码 | 菜单名称 | 默认路径 | 展示范围 | 说明 |
|---|---|---|---|---|---|
| 一级 | `platform` | 平台管理 | `/platform/overview` | `p_super_admin` | 平台级管理入口 |
| 一级 | `knowledge_base` | 知识库管理 | `/knowledge-bases` | 租户用户 | 知识库列表和知识库工作区入口 |

当前实现说明：前端 `SidebarNav` 目前静态渲染“平台管理”和“知识库管理”两个入口，路由守卫只对访客路径做了限制，尚未根据平台角色、租户角色和组织角色动态过滤左侧菜单。因此表中的“展示范围”是本方案要求的目标展示范围，后续应通过菜单接口和前端菜单过滤实现。

当前左侧导航不包含以下菜单：

- 应用管理。
- 调用日志。
- 配额与用量。
- 独立的开发者中心一级菜单。

开发者中心属于平台管理下的 Tab，不属于左侧独立菜单。

#### 3.3.2 平台管理子菜单

平台管理是一个目录型菜单，页面项通过平台管理页面中的 Element Plus Tab 展示：

| 层级 | 菜单编码 | 页面资源编码 | 页面名称 | 路径 |
|---|---|---|---|---|
| 二级 | `platform_overview` | `platform_overview_page` | 平台概览 | `/platform/overview` |
| 二级 | `platform_users` | `platform_users_page` | 用户管理 | `/platform/users` |
| 二级 | `platform_tenants` | `platform_tenants_page` | 租户管理 | `/platform/tenants` |
| 二级 | `platform_organizations` | `platform_organizations_page` | 组织管理 | `/platform/organizations` |
| 二级 | `developer_api` | `developer_api_page` | 开发者中心 | `/platform/developer-api` |

上述页面均属于平台管理上下文，不能因为用户拥有租户管理员或组织管理员角色就自动展示。

#### 3.3.3 知识库管理页面资源

知识库管理一级菜单对应知识库列表页面；用户从列表进入某个知识库后，进入独立的知识库工作区。

| 页面层级 | 页面资源编码 | 页面名称 | 路径 | 是否为左侧菜单 |
|---|---|---|---|---:|
| 一级菜单页面 | `knowledge_base_list_page` | 知识库列表 | `/knowledge-bases` | 是 |
| 工作区页面 | `knowledge_base_overview_page` | 知识库概览 | `/knowledge-bases/:kbId/overview` | 否 |
| 工作区页面 | `knowledge_base_documents_page` | 文档 | `/knowledge-bases/:kbId/documents` | 否 |
| 工作区页面 | `knowledge_base_chat_page` | 问答 | `/knowledge-bases/:kbId/chat` | 否 |

知识库工作区的“概览、文档、问答”是当前知识库内部的 Tab，不属于系统左侧菜单，也不应作为一级或二级系统菜单展示。

#### 3.3.4 访客页面资源

访客页面是受限访问入口，不使用系统左侧主导航：

| 页面资源编码 | 页面名称 | 路径 | 说明 |
|---|---|---|---|
| `guest_knowledge_base_list_page` | 访客知识库列表 | `/guest/knowledge-bases` | 仅展示访客可访问的知识库 |
| `guest_chat_page` | 访客问答 | `/guest/knowledge-bases/:kbId/chat` | 仅允许在授权知识库中问答 |

访客页面属于页面资源，不关联左侧菜单。`tenant_guest` 不展示平台管理、租户管理、组织管理、文档管理等管理入口。

#### 3.3.5 认证和系统辅助页面

以下页面属于系统页面资源，但不属于登录后菜单：

| 页面资源编码 | 页面名称 | 路径 | 说明 |
|---|---|---|---|
| `login_page` | 登录页 | `/login` | 未登录用户入口 |
| `root_redirect` | 根路径重定向 | `/` | 重定向到登录页 |
| `forbidden_page` | 无权限页 | 预留 | 后续用于无权限访问处理 |

#### 3.3.6 当前菜单和页面资源的归属关系

```text
平台管理（左侧一级菜单）
 ├─ 平台概览（Tab / 页面资源）
 ├─ 用户管理（Tab / 页面资源）
 ├─ 租户管理（Tab / 页面资源）
 ├─ 组织管理（Tab / 页面资源）
 └─ 开发者中心（Tab / 页面资源）

知识库管理（左侧一级菜单）
 └─ 知识库列表（页面资源）
     └─ 知识库工作区（非左侧菜单）
         ├─ 概览（工作区 Tab / 页面资源）
         ├─ 文档（工作区 Tab / 页面资源）
         └─ 问答（工作区 Tab / 页面资源）
```

#### 3.3.7 当前范围内不作为菜单的数据

以下内容后续应维护在操作权限表或页面展示配置中，不应新增为菜单：

- 新增、修改、删除知识库。
- 上传、删除文档。
- 修改租户、组织和成员。
- 进入详情页、编辑页和任务详情页。
- 页面内的查询、刷新、分页和导出操作。
- API 文档中的接口调试能力。本阶段在线调试已去掉。

API 文档当前固定展示 `v1`，不设置版本下拉框。

## 4. 数据表设计

### 4.1 系统菜单表 `t_system_menu`

该表只保存导航层级，不保存按钮、接口权限和页面组件配置。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 自增主键 |
| `parent_id` | bigint | 父菜单 ID，顶级菜单为空 |
| `code` | varchar(100) | 菜单编码，全局唯一 |
| `name` | varchar(100) | 菜单名称 |
| `menu_type` | varchar(32) | `directory`、`item` |
| `page_resource_id` | bigint | 关联页面资源 ID，目录为空 |
| `icon` | varchar(100) | 菜单图标 |
| `sort_order` | integer | 同级排序 |
| `visible` | boolean | 是否展示在导航中 |
| `status` | varchar(32) | `active`、`disabled` |
| `meta` | jsonb | 菜单扩展配置 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束建议：

- `code` 全局唯一。
- `parent_id` 只能指向 `t_system_menu.id`。
- 禁止形成菜单父子循环。
- `item` 必须关联有效页面资源。
- 已被引用的菜单不物理删除，只允许停用。

### 4.2 页面资源表 `t_page_resource`

该表保存前端路由和页面访问资源。页面资源可以关联菜单，也可以作为隐藏页面独立存在。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 自增主键 |
| `code` | varchar(100) | 页面资源编码，全局唯一 |
| `name` | varchar(100) | 页面名称 |
| `route_path` | varchar(255) | 前端路由地址 |
| `route_name` | varchar(100) | 前端路由名称 |
| `component` | varchar(255) | 前端组件标识 |
| `permission_code` | varchar(150) | 页面访问权限编码 |
| `keep_alive` | boolean | 是否缓存页面 |
| `status` | varchar(32) | `active`、`disabled` |
| `meta` | jsonb | 页面扩展配置 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

例如：

```text
platform_overview_page  -> /platform/overview
platform_users_page     -> /platform/users
developer_api_page      -> /platform/developer-api
tenant_detail_page      -> /platform/tenants/:id
```

### 4.3 操作权限表 `t_permission_resource`

该表保存页面内的按钮、接口和业务操作权限。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 自增主键 |
| `code` | varchar(150) | 权限编码，全局唯一 |
| `name` | varchar(100) | 权限名称 |
| `resource_type` | varchar(32) | `button`、`api`、`business` |
| `page_resource_id` | bigint | 所属页面资源，可为空 |
| `http_method` | varchar(16) | API 请求方法，可为空 |
| `request_path` | varchar(255) | API 请求路径，可为空 |
| `status` | varchar(32) | `active`、`disabled` |
| `meta` | jsonb | 扩展配置 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

典型权限编码：

```text
knowledge_base:create
knowledge_base:update
knowledge_base:delete
document:upload
document:delete
```

### 4.4 角色资源授权表 `t_role_resource_grant`

该表统一保存角色与页面资源、操作权限之间的授权关系。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 自增主键 |
| `role_scope` | varchar(32) | `platform`、`tenant`、`organization` |
| `role_code` | varchar(64) | 角色编码 |
| `resource_type` | varchar(32) | `page`、`action` |
| `resource_id` | bigint | 页面资源或操作权限 ID |
| `effect` | varchar(16) | `allow` 或 `deny` |
| `data_scope` | varchar(32) | 数据范围编码，可为空 |
| `status` | varchar(32) | `active`、`disabled` |
| `created_at` | timestamptz | 创建时间 |
| `created_by` | bigint | 创建人 |

建议约束：

```sql
unique (role_scope, role_code, resource_type, resource_id)
```

`role_scope + role_code` 的合法性由 Service 层根据现有平台、租户和组织角色校验。后续如需要严格数据库外键，可以分别建立三类角色授权表。

### 4.5 页面展示配置表 `t_page_view_config`

该表保存角色进入页面后的展示差异，不承担页面访问和接口安全校验。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 自增主键 |
| `page_resource_id` | bigint | 页面资源 ID |
| `role_scope` | varchar(32) | 角色范围 |
| `role_code` | varchar(64) | 角色编码 |
| `landing_path` | varchar(255) | 该角色的默认进入地址 |
| `layout_code` | varchar(100) | 页面布局编码 |
| `visible_components` | jsonb | 可见组件编码列表 |
| `hidden_components` | jsonb | 隐藏组件编码列表 |
| `action_permissions` | jsonb | 页面操作权限编码列表 |
| `config` | jsonb | 页面扩展配置 |
| `status` | varchar(32) | `active`、`disabled` |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

建议唯一约束：

```sql
unique (page_resource_id, role_scope, role_code)
```

## 6. 登录后的菜单生成流程

```text
用户登录
  ↓
加载当前用户上下文
  ↓
获取平台角色、当前租户角色、组织角色
  ↓
查询角色拥有的页面资源
  ↓
查询页面资源对应的菜单项
  ↓
过滤 disabled、visible=false 和无权限节点
  ↓
合并页面展示配置和操作权限
  ↓
组装菜单树
  ↓
返回前端
```

建议新增接口：

```http
GET /api/v1/auth/menus
```

返回示例：

```json
{
  "default_path": "/knowledge-bases",
  "menus": [
    {
      "code": "knowledge_base",
      "name": "知识库管理",
      "type": "directory",
      "children": [
        {
          "code": "knowledge_base_list",
          "name": "知识库列表",
          "type": "item",
          "page": {
            "code": "knowledge_base_list_page",
            "route_path": "/knowledge-bases"
          },
          "actions": ["knowledge_base:read"]
        }
      ]
    }
  ]
}
```

## 7. 权限边界

必须区分三类权限：

| 权限类型 | 作用 |
|---|---|
| 菜单权限 | 是否显示左侧菜单入口 |
| 页面权限 | 是否允许访问具体路由 |
| 操作权限 | 是否允许新增、编辑、删除、上传等操作 |

前端隐藏菜单不能作为安全控制。后端接口必须独立执行：

```text
请求 API
  → 登录认证
  → 当前角色校验
  → 租户 / 组织范围校验
  → 业务资源权限校验
  → 执行业务操作
```

菜单服务只负责查询和组装导航数据，API 层不得直接查询数据库，Service 层负责角色合并、菜单过滤、树形组装和默认首页计算。

## 8. 角色合并规则

1. 只计算当前登录上下文中的角色。
2. 用户切换租户后，重新计算租户和组织范围菜单。
3. 同一页面被多个角色允许时，只保留一份菜单项。
4. `deny` 优先于 `allow`，用于特殊屏蔽场景。
5. 父目录只有在存在可见子菜单时才展示。
6. 隐藏页面资源不生成左侧菜单，但仍可参与路由访问校验。
7. 操作权限不生成菜单，只用于页面按钮和后端接口授权。
8. 平台超级管理员可以获得平台级菜单，但具体租户页面仍需设置当前租户上下文。

## 9. 前端改造范围

1. 登录完成后调用 `/auth/menus`。
2. 左侧菜单只根据菜单接口生成，不维护完整业务菜单硬编码。
3. 路由绑定页面资源编码和权限编码。
4. 页面操作按钮根据操作权限显示。
5. 页面组件根据 `visible_components` 和 `hidden_components` 控制展示。
6. 用户切换租户后刷新菜单、路由权限和默认首页。
7. 无权限访问页面时跳转到无权限页或知识库首页。

前端动态菜单只负责用户体验，后端接口必须继续执行实际授权校验。

## 10. 后端改造范围

1. `scripts/db/data_table_ddl.sql`：新增菜单、页面资源、操作权限和授权表。
2. `scripts/db/data_table_dml.sql`：初始化菜单、页面资源和默认角色授权。
3. `app/db/system_menu.py`：菜单查询和菜单树节点查询。
4. `app/db/page_resource.py`：页面资源和角色页面授权查询。
5. `app/db/permission_resource.py`：操作权限查询。
6. `app/core/services/system_menu.py`：角色合并、菜单过滤和菜单树组装。
7. `app/api/v1/auth.py`：新增当前用户菜单接口。
8. `app/schemas/`：新增菜单树、页面资源和操作权限响应模型。
9. 审计记录：记录菜单和角色资源授权变更。

所有新增、修改和删除授权的 Service 写操作必须显式使用事务。

## 11. 实施阶段

### 第一阶段：菜单和页面资源基础能力

- 新增系统菜单表和页面资源表。
- 初始化当前菜单和页面路由数据。
- 建立菜单与页面资源的关联。

### 第二阶段：角色页面授权

- 新增操作权限表和角色资源授权表。
- 初始化平台、租户、组织角色授权。
- 实现页面访问权限和操作权限查询。

### 第三阶段：菜单接口和前端接入

- 新增 `/api/v1/auth/menus`。
- 前端接入动态菜单。
- 增加默认首页、无权限跳转和租户切换刷新。

### 第四阶段：页面展示差异

- 新增页面展示配置表。
- 支持页面组件显示和隐藏。
- 支持角色默认布局和操作按钮配置。

### 第五阶段：权限管理后台

- 菜单树维护。
- 页面资源维护。
- 操作权限维护。
- 角色资源授权维护。
- 授权变更审计。

## 12. 评审结论项

1. 是否采用“系统菜单、页面资源、操作权限、页面展示配置”职责分离方案。
2. 是否采用统一的 `t_role_resource_grant`，还是按平台、租户、组织拆分授权表。
3. 是否保留 `deny` 覆盖规则。
4. 页面展示配置是否在第一阶段实现，还是在菜单和权限稳定后实现。
5. 前端是否完全通过后端接口生成左侧菜单。
6. 菜单、页面资源和权限资源是否由平台超级管理员维护。
