# 文档管理测试用例

## 1. 测试范围

验证文档查询、分页、上传、文件校验、索引状态、查看分片、重建索引、删除和知识库边界。

## 2. 前端测试用例

| 编号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| 前端-001 | 列表加载 | 打开文档管理 | 文档名称、类型、大小、状态、上传时间、更新时间、操作和分页正常展示 |
| 前端-001A | 更新时间 | 返回包含 `updated_at` 的文档列表 | 展示“更新时间”列，并按公共 `formatDateTime` 以 `YYYY年MM月DD日 HH:mm:ss` 格式显示 |
| 前端-002 | 条件查询 | 输入文档名称和状态查询 | 结果与条件一致，页码回到第一页 |
| 前端-003 | 上传必填 | 不选择文件提交 | 显示文件必填提示，不上传 |
| 前端-004 | 文件校验 | 上传空文件、超限文件、不支持类型 | 显示明确错误，阻止上传 |
| 前端-005 | 上传成功 | 上传合法文件 | 显示处理中状态并刷新列表 |
| 前端-006 | 状态轮询 | 文档从处理中变为完成或失败 | 状态正确更新，失败显示重试入口 |
| 前端-007 | 查看分片 | 点击查看 | 打开分片详情抽屉，支持内容查询和分页 |
| 前端-007A | 查询索引进度 | 点击文档操作列“索引”文本按钮 | 打开索引构建任务进度滑块，展示当前文档最近一次任务信息，不离开列表 |
| 前端-007B | 进度自动刷新 | 打开处理中任务滑块并等待 | 每 5 秒刷新一次真实任务状态，完成或失败后停止刷新 |
| 前端-007M | 手动刷新进度 | 点击处理阶段下方操作区的“刷新”按钮 | 立即重新查询真实任务状态，不停止后续定时刷新 |
| 前端-007N | 操作按钮布局 | 打开索引构建任务进度滑块 | 操作按钮位于处理阶段下方、历史任务上方，右侧对齐，顺序为“重建索引”“刷新” |
| 前端-007C | 进度状态 | 分别模拟等待、处理中、完成、失败、取消和无任务 | 状态、百分比、当前阶段、失败原因和操作按钮展示符合设计，不伪造进度 |
| 前端-007D | 进度异常 | 模拟任务查询接口失败 | 滑块展示错误状态和重新加载按钮，保留文档名称，不使用本地静态数据兜底 |
| 前端-007I | 历史任务列表 | 打开存在多次索引任务的文档进度 | 展示当前任务和历史任务，按创建时间倒序排列，当前任务高亮 |
| 前端-007J | 历史任务分页 | 历史任务超过 10 条 | 历史任务列表独立分页，不影响文档列表分页和筛选条件 |
| 前端-007K | 历史任务只读 | 点击历史任务记录 | 只展示任务详情，不出现重建、取消或删除历史任务按钮 |
| 前端-007L | 无历史任务 | 查询没有历史任务的文档 | 显示“暂无历史索引任务”，不根据文档状态生成虚假记录 |
| 前端-007E | 重建索引立即提交 | 在已完成或失败文档进度滑块点击“重建索引” | 不弹二次确认，立即创建任务，按钮进入提交中状态 |
| 前端-007F | 重建索引成功 | 点击“重建索引”并返回成功 | 创建任务成功，滑块保持打开，文档状态变为处理中并继续查询任务进度 |
| 前端-007G | 重建索引防重复 | 对待处理或处理中文档打开进度滑块 | 滑块内“重建索引”置灰，不允许重复提交；“刷新”仍可用 |
| 前端-007H | 重建索引失败 | 模拟创建重建任务接口失败 | 保留原文档状态，显示真实错误，不伪造处理中状态 |
| 前端-008 | 重建索引 | 对已完成或失败文档点击重建索引 | 确认后状态回到处理中，创建新任务，按钮状态正确 |
| 前端-009 | 删除确认 | 删除文档并确认或取消 | 确认删除，取消不产生请求 |
| 前端-010 | 长内容和滚动 | 使用长文档名、长分片内容 | 单行省略，详情区域可滚动，不撑开页面 |

## 3. 后端测试用例

| 编号 | 接口场景 | 操作 | 预期结果 |
|---|---|---|---|
| 后端-001 | 文档分页 | 传入 kb_id、名称、状态、分页参数 | 返回当前知识库分页数据 |
| 后端-002 | 文件安全 | 上传非法扩展名、空文件、超大文件 | 拒绝上传并返回统一错误 |
| 后端-003 | 文档创建 | 上传合法文件 | 保存文档元数据并创建索引任务 |

## 索引任务可靠性补充

| 用例 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| 后端-003A | Worker 异步接管 | 上传文档后不依赖 HTTP 请求协程，查询任务状态 | 文档进入 `pending`，由索引 Worker 执行并最终进入 `ready` 或 `failed` |
| 后端-003B | Worker 重启恢复 | 索引执行期间停止服务并重新启动 | 超过失联阈值的 `running` 任务重新进入 `pending`，不会永久停留在 `processing` |
| 后端-003C | Embedding 受控并发 | 上传包含大量分块的文档 | Embedding 按配置批量处理并限制并发，任务更新时间持续刷新 |
| 后端-003D | 索引超时收尾 | 模拟 Embedding 持续超时 | 任务和文档进入 `failed`，记录超时原因，不保留 `running/processing` 僵尸状态 |

## 4. 重点验收

- 文档状态为 ready 后才允许稳定进入问答。
- 文档、分片、索引任务必须绑定当前知识库。
