# 菜单权限与操作权限测试用例

## 1. 测试目的

验证平台角色、租户角色和组织角色在前后端的权限实现是否与以下设计文档一致：

- 《角色菜单操作权限矩阵》
- 《角色权限与前端能力控制设计》
- 《系统菜单与角色界面展示设计方案》

本用例重点验证菜单可见性、路由访问、操作按钮、接口鉴权、租户/组织数据范围和租户切换后的权限刷新，避免仅验证前端隐藏按钮而遗漏后端越权。

## 2. 测试范围与角色

### 2.1 角色范围

| 角色 | 测试账号/数据要求 | 主要验证范围 |
|---|---|---|
| `p_super_admin` | `linburgh` 或独立平台管理员账号 | 全平台菜单、全租户数据和平台级操作 |
| `tenant_admin` | `zhangfei` 或临时租户管理员账号 | 当前租户管理操作和数据范围 |
| `tenant_member` | `zhugeliang` | 授权知识库查看和问答，无管理写操作 |
| `tenant_guest` | `guest` | 独立问答，不进入平台和知识库管理 |
| `org_admin` | 需准备独立组织管理员账号 | 负责组织及授权知识库范围 |
| `org_member` | 需准备独立组织成员账号 | 组织授权知识库查看和问答 |

账号密码只通过运行环境变量注入，不写入测试代码和文档。

### 2.2 测试数据

至少准备以下数据：

1. 租户 A：当前角色所属租户，包含组织 A、知识库 A 和文档 A。
2. 租户 B：其他租户，包含组织 B、知识库 B 和文档 B。
3. 组织 A1：`org_admin` 负责组织，绑定知识库 A1。
4. 组织 A2：同租户但不属于该 `org_admin` 负责范围，绑定知识库 A2。
5. 组织 B1、知识库 B1：用于跨租户访问验证。
6. 每个知识库至少准备一个可查看文档和一个已完成索引文档。

## 3. 权限判定规则

1. 菜单权限控制左侧菜单和页面入口。
2. 路由守卫拦截直接输入的无权限地址。
3. 操作权限控制新增、编辑、删除、成员管理、上传、重新索引和问答等业务按钮。
4. 查询、重置、刷新、分页、普通详情和关闭等通用控件不单独绑定操作权限。
5. 前端使用 `v-permission` 控制展示，后端必须使用相同操作编码再次鉴权。
6. 后端必须校验当前租户、组织和知识库数据范围，不能信任前端传入的角色或租户 ID。
7. 无身份返回 `401`；无菜单、操作或数据范围权限返回 `403`；资源不存在返回 `404`；状态冲突返回 `409`。

## 7. 接口权限与错误处理测试

| 编号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| API-001 | 未登录 | 不带 Token 调用菜单、权限和业务接口 | 返回 `401`，前端跳转登录页 |
| API-002 | 无效 Token | 使用过期或伪造 Token 调用接口 | 返回 `401`，清理本地会话，不展示缓存数据 |
| API-003 | 无菜单权限 | 调用无页面权限的查询接口 | 返回 `403`，不返回列表、统计或详情 |
| API-004 | 无操作权限 | 调用新增、编辑、删除、成员、上传、索引接口 | 返回 `403`，数据库和任务表无变化 |
| API-005 | 数据范围越权 | 使用合法 Token 请求其他租户/组织资源 | 返回 `403`，错误信息不泄露资源是否存在 |
| API-006 | 后端权限与前端不一致 | 前端按钮隐藏但直接构造请求 | 后端拒绝；前端展示明确无权限提示，不伪造成功 |

| API-008 | 租户切换失败 | `/auth/tenant` 返回 403/404 | 保留原租户上下文、菜单和页面数据，不切换到半完成状态 |

## 8. 当前已知冲突与专项验收

| 编号 | 冲突 | 当前现象 | 处理要求 |
|---|---|---|---|
| CONFLICT-001 | 平台管理数据范围不一致 | `tenant_admin` 拥有平台管理菜单和操作，但数据范围必须限制在当前租户 | 同步矩阵、原型、DML、前端菜单和后端接口，并补充跨租户 `403` 验收 |
| CONFLICT-002 | 组织接口权限过窄 | 前端显示组织管理，但后端 `/organizations/*` 仍只允许 `p_super_admin` | 按最终规则补充租户/组织数据范围鉴权，完成 `SCOPE` 用例后才能验收 |
| CONFLICT-003 | 前端初始化调用越权接口 | 普通租户进入组织页曾调用平台级 `/tenants` | 平台管理员才加载全部租户；普通租户使用当前租户上下文，不调用平台接口 |
| CONFLICT-004 | 权限错误文案复用错误 | 非评测接口返回“无权操作自主评测” | 按模块返回通用且准确的无权限提示，并补充接口断言 |

## 9. 执行要求与验收标准

1. 每个角色至少执行一次登录、菜单加载、路由直达、按钮展示和接口调用。
2. 每个写操作至少验证一个成功角色和一个失败角色。
3. 每个租户/组织范围接口至少验证当前范围和跨范围各一次。
4. 前端浏览器测试使用 Playwright，后端使用真实 HTTP 接口和测试数据库；账号、Token、租户 ID 通过环境变量或临时数据注入。
5. 不得用只通过 `v-permission` 隐藏按钮代替后端接口鉴权结果。
6. 任何一项菜单、按钮、路由、接口或数据范围结果不一致，整体权限验收标记为“未通过”。
7. 测试执行记录必须填写：执行日期、账号、租户/组织、接口请求、响应状态、页面截图或日志、缺陷编号和最终状态。

### 10.1 本轮关键失败证据

1. `tenant_admin`：`GET /api/v1/organizations/tree?tenant_id=151` 返回 `200`，改为其他租户返回 `403`。
2. `tenant_guest`：`/auth/menus` 返回 `knowledge_base_list`、`knowledge_base_workspace`、`knowledge_base_overview`、`knowledge_base_chat`，超出仅独立问答范围。

4. 非平台角色调用平台、用户、租户、组织和评测接口时均返回 `403`，但错误文案错误复用自主评测模块文案。
