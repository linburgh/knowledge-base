# 组织树 500K 性能测试用例

## 测试数据

- 使用独立租户编码：`org-tree-perf-500k`。
- 默认生成 1,299,998 条组织数据。
- 组织结构为 11 个层级：第 0、1、4～10 级各 100,000 个节点，第 2、3 级各 199,999 个节点。
- `性能测试树-000000-第0级` 下挂载 100,000 个第 1 级同级节点，其中首个节点名称为 `性能测试树-000000-第1级链路`；这些节点均继续连接到第 10 级，便于验证同级节点分页和深层展开。
- `性能测试树-000000-第1级链路` 下挂载 100,000 个第 2 级同级节点，其中首个节点名称为 `性能测试树-000000-第2级链路`。
- `性能测试树-000000-第2级链路` 下挂载 100,000 个第 3 级同级节点，其中首个节点名称为 `性能测试树-000000-第3级链路`。
- 第 4 级到第 10 级保留 100,000 个节点，并保留目标链路继续展开至第 10 级。
- 不修改现有业务租户数据。

## 查询优化与索引

- 父节点接口先执行根节点游标分页，再仅针对当前页节点批量统计直接子节点，禁止在全量根节点聚合后再 `LIMIT`。
- 根节点分页和子节点统计索引统一维护在 `scripts/db/data_table_ddl.sql`：`idx_t_organization_tree_root_page`、`idx_t_organization_tree_children`。
- 验证父节点接口时同时检查租户范围和平台超级管理员全平台范围，确认返回结构、游标顺序和 `has_children` 不变。

## 造数命令

```bash
.venv/bin/python -m tests.performance.seed_organization_tree_500k --reset
```

脚本输出 `tenant_id`，该租户仅用于性能测试。需要清理时，删除该测试租户及其组织数据；不得对其他租户执行清理。

## 性能测试命令

```bash
.venv/bin/python -m tests.performance.test_organization_tree_performance --tenant-id <输出的tenant_id>
```

## 测试场景

| 编号 | 场景 | 验收内容 |
|---|---|---|
| PERF-001 | 根节点首批加载 | 100,000 棵根树中分页返回 20 条，响应结构正确 |
| PERF-002 | 根节点加载更多 | 游标连续请求不重复、不遗漏 |
| PERF-003 | 根节点子节点首批加载 | `性能测试树-000000-第0级` 的 100,000 个第 1 级同级节点按游标返回，响应范围正确 |
| PERF-004 | 子节点连续加载 | 子节点游标存在时连续请求不重复、不遗漏 |
| PERF-005 | 10 级展开 | 沿链路连续展开至少 10 级，每级请求范围正确 |
| PERF-006 | 并发根节点查询 | 8 个并发请求均成功，记录总耗时和单请求耗时 |
| PERF-007 | 数据完整性 | 总节点数为 1,299,998；各级数量符合 100000、100000、199999、199999、100000、100000、100000、100000、100000、100000、100000；目标第 1、2、3 级同级节点均为 100,000 条 |
| PERF-008 | 浏览器递归展开 | 选择性能测试租户，从第 0 级连续展开到第 10 级，所有链路节点均可见 |
| PERF-009 | 父节点分页性能 | 根节点首批查询不执行全量子节点聚合，仅对当前页根节点统计 `has_children` |

浏览器用例：`tests/e2e/organization-tree-depth.spec.ts`。
