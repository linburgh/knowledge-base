# 多角色有效角色测试用例

## 测试目标

验证同一用户拥有多个层级角色时，系统始终以最高权限角色作为有效角色。

| 编号 | 测试场景 | 前置条件 | 操作 | 预期结果 | 状态 |
|---|---|---|---|---|---|
| ROLE-001 | 平台超级管理员覆盖租户管理员 | `linburgh` 同时拥有 `p_super_admin`、`tenant_admin` | 登录并查看 `/auth/me` | `effective_role=p_super_admin` | 通过 |
| ROLE-002 | 平台概览使用平台范围 | 使用 `linburgh` 登录并请求 `/platform/overview` | 查看统计卡片和趋势数据 | 使用全平台数据，不按当前租户缩小 | 通过 |
| ROLE-003 | 平台菜单和操作权限 | 使用 `linburgh` 请求菜单和权限 | 查看默认入口、菜单和操作编码 | 默认进入平台概览，拥有平台超级管理员权限，不降级为租户管理员菜单 | 通过 |
| ROLE-004 | 前端角色展示 | 使用 `linburgh` 打开平台管理页面 | 查看顶部角色和平台概览卡片 | 显示平台超级管理员、平台用户和活跃租户 | 通过 |
| ROLE-005 | 租户管理员不受影响 | `tenant-admin-acc` 只有 `tenant_admin` | 登录并查看平台概览 | `effective_role=tenant_admin`，数据限制当前租户 | 通过 |
| ROLE-006 | 失效平台角色不生效 | 平台角色状态为 disabled，租户角色为 `tenant_admin` | 请求认证上下文和平台概览 | 有效角色为 `tenant_admin`，不获得平台范围 | 通过 |

## 自动化验证

- `.venv/bin/python -m unittest tests.test_roles tests.test_platform_overview`
- `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`
- 使用 `linburgh/linburgh` 实际调用 `/auth/me`、`/auth/menus`、`/auth/permissions` 和 `/platform/overview`。
