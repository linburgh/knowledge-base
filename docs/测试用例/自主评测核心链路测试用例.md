# 自主评测核心链路测试用例

## 测试目标

验证“新建任务 → 创建运行 → Worker 消费 → 运行状态更新 → 报告和逐题结果输出”的完整闭环。重点验证未执行任务不能被误判为运行中、运行配置快照、单题异常收敛和终态结果可查询。

## 后端核心用例

| 编号 | 场景 | 前置条件 | 操作 | 预期结果 | 状态 |
| --- | --- | --- | --- | --- | --- |
| EVAL-FLOW-001 | 新建任务状态 | 超级管理员、有效知识库 | 创建合法导入任务并查询任务分页 | 返回 `active`；`latest_run_status=not_started`；执行按钮条件为可执行 | 已通过自动化 |
| EVAL-FLOW-002 | 创建运行快照 | EVAL-FLOW-001 已完成 | 创建任务运行 | 生成唯一 `run_no`，状态为 `pending`，快照与任务配置一致 | 已通过自动化 |
| EVAL-FLOW-003 | Worker 正常消费 | 存在合法问题内容，知识 Agent 使用可控替身 | 执行 Worker | 状态依次为 `running`、`completed`；报告、指标、题数和逐题结果均落库 | 已通过自动化 |
| EVAL-FLOW-004 | 运行结果读取 | EVAL-FLOW-003 已完成 | 查询运行详情、报告和逐题分页 | 返回真实持久化数据，题数与逐题总数一致 | 已通过自动化 |
| EVAL-FLOW-005 | 单题异常 | 问题集包含可注入异常题 | 执行 Worker | 异常题记录 `error`，其他题继续；运行仍可完成并输出指标 | 已有 Agent 自动化，需真实 Worker 脚本复跑 |
| EVAL-FLOW-006 | 任务级异常 | 注入问题集解析或 Agent 初始化异常 | 执行 Worker | 运行进入 `failed`，报告保存错误摘要，不生成伪造通过结论 | 需故障注入复跑 |
| EVAL-FLOW-007 | 重复运行保护 | 任务已有 pending/running 运行 | 重复创建运行 | 返回 409，不增加运行记录 | 需真实接口复跑 |
| EVAL-FLOW-008 | 权限隔离 | 普通平台用户或租户用户 | 创建、执行、查询任务和结果 | 全部返回 403，不泄露资源内容 | 需权限矩阵复跑 |
| EVAL-FLOW-009 | 模型自主规划 | 注入可控评测模型，返回关注维度和复核规则 | 执行 Agent | Skill 正文进入模型上下文；运行摘要记录模型调用和 `analysis` Skill 版本 | 已通过自动化 |
| EVAL-FLOW-010 | 动态复核决策 | 首轮包含降级或无引用结果，模型选择 `retry_cases` | 执行 Agent | 只复核模型选择且合法的题号，复核后重新计算指标并再次决策 | 已通过自动化 |
| EVAL-FLOW-011 | 自主结束决策 | 模型根据指标选择 `finalize` | 执行 Agent | 不再调用问答工具；报告保存决策理由、发现、建议和置信度 | 已通过自动化 |
| EVAL-FLOW-012 | 决策安全收敛 | 模型返回越界题号、重复题号或超过最大轮次 | 执行 Agent | 越界行动被拒绝或过滤；达到模型、工具、步骤或复核预算后结构化终止，不形成无限循环 | 已通过自动化 |
| EVAL-FLOW-013 | 官方入口 | 检查生产 Agent 构建代码和调用链 | 执行结构测试 | 生产入口实际调用当前锁定 Deep Agents 版本的 `create_deep_agent`，不是直接调用模型后由手写图模拟工具循环 | 已通过自动化验证 |
| EVAL-FLOW-014 | 可信上下文 | 注入租户、组织、用户、知识库和运行标识 | Agent 调用只读工具 | `context_schema` 与 `ToolRuntime` 传递可信字段；模型工具参数不能覆盖这些字段 | 已通过自动化验证 |
| EVAL-FLOW-015 | 官方中间件 | 配置模型/工具调用上限和重试次数 | 注入连续工具请求及瞬时异常 | 官方调用上限和重试 Middleware 生效，项目代码不重复维护同语义计数循环 | 已通过自动化验证 |
| EVAL-FLOW-016 | 结构输出 | 模型完成工具循环 | 读取 Agent 终态 | `response_format` 返回可校验的评测发现、证据、建议和终止原因，确定性门禁不被模型覆盖 | 已通过自动化验证 |
| EVAL-FLOW-017 | 选型审计 | 查看需求和实施方案 | 核对候选框架 | 记录 `create_agent`、`create_deep_agent`、LangGraph Runtime/Middleware/Persistence 的版本、适用性、采用与不采用理由 | 已同步选型记录 |
| EVAL-FLOW-018 | 受限能力 | 检查评测 Harness Profile、Permissions 和工具集合 | 创建评测 Agent | Todo、文件写入、Shell、Subagents 和长期 Memory 均未启用；只读 Skill 与评测工具可用 | 已通过自动化验证 |

## 前端核心用例

| 编号 | 场景 | 操作 | 预期结果 | 状态 |
| --- | --- | --- | --- | --- |
| EVAL-FLOW-101 | 新建后执行 | 新建任务并返回列表 | 状态显示“未执行”，执行按钮可点击，不显示“执行中” | 已修复并通过类型/构建检查 |
| EVAL-FLOW-102 | 运行轮询 | 点击执行 | 打开结果抽屉，显示待执行/执行中；定时请求真实运行详情 | 不使用静态或伪造结果 |
| EVAL-FLOW-103 | 完成输出 | Worker 返回 completed | 抽屉显示指标、结论、报告和逐题结果 | 需浏览器真实接口复跑 |
| EVAL-FLOW-106 | 列表终态同步 | Worker 返回 completed/failed/cancelled | 运行终态后自动重新查询任务列表，列表状态、结论、题数和最近执行时间立即更新，无需手工点击查询 | 已修复并通过构建检查 |
| EVAL-FLOW-104 | 失败输出 | Worker 返回 failed | 抽屉显示失败原因，停止轮询，不展示成功结果 | 需浏览器故障态复跑 |
| EVAL-FLOW-105 | 刷新恢复 | 刷新列表或重新打开结果 | 根据真实运行记录恢复最新状态和结果 | 需浏览器真实接口复跑 |

## 自动化执行

```bash
OS_CONFIG_DIR=etc .venv/bin/python -m unittest tests.test_evaluation_core_flow tests.test_evaluation_agent -v
```

真实接口闭环使用 `tests/integration/test_evaluation_worker.py`，通过 `TEST_ADMIN_ACCOUNT`、`TEST_ADMIN_PASSWORD` 和 `TEST_EVAL_KB_ID` 注入环境变量；禁止将凭证写入代码或文档。
