# 平台用户、租户与组织数据库设计

## 1. 设计范围

数据库设计原则：每张表必须包含一个名为 `id` 的自增主键，统一使用 `bigint generated by default as identity primary key`；业务编码、邮箱、租户编码等字段不能替代表主键。

本设计支撑以下平台级数据：

- 平台用户。
- 平台角色。
- 租户。
- 租户成员和租户角色。
- 组织及组织层级。
- 组织成员。
- 知识库与租户、组织的归属关系。

平台超级管理员角色固定为 `p_super_admin`，不归属于某个租户。

## 2. 角色分层

系统角色按作用范围分为三类：

| 角色类型 | 作用范围 | 存储位置 |
|---|---|---|
| 平台角色 | 整个平台 | `t_platform_role`、`t_platform_user_role` |
| 租户角色 | 单个租户 | `t_tenant_member.role_code` |
| 组织角色 | 单个组织 | `t_organization_member.role_code` |

当前平台角色只有 `p_super_admin`。租户角色包括 `tenant_owner`、`tenant_admin`、`tenant_member`、`tenant_guest`；组织角色包括 `org_admin`、`org_member`。

平台角色、租户角色和组织角色不能混用。一个用户可以同时拥有平台角色、多个租户角色和多个组织角色，但每个角色都必须在对应作用域内判断。

租户角色职责：

- `tenant_owner`：管理当前租户的基本配置、成员、组织、知识库和租户管理员，一个租户只能有一个有效的租户所有者。
- `tenant_admin`：管理当前租户内的用户、组织和知识库日常业务，不得操作其他租户或平台级配置。
- `tenant_member`：按授权使用当前租户的知识库、文档和问答能力，不负责租户成员与组织管理。
- `tenant_guest`：只访问明确授权的知识库或问答功能，不参与文档管理、成员管理和配置修改。

组织角色职责：

- `org_admin`：管理当前组织成员、组织资料、组织成员角色和组织知识库授权，不得操作其他组织或租户级配置。
- `org_member`：使用当前组织已授权的知识库、文档和问答能力，不负责组织成员、组织层级和授权管理。

## 3. 表关系

```text
t_user
├── t_platform_user_role
├── t_tenant_member
└── t_organization_member

t_platform_role
└── t_platform_user_role

t_tenant
├── t_tenant_member
├── t_organization
└── t_knowledge_base.tenant_id

t_organization
├── t_organization_member
├── t_organization.parent_id
└── t_knowledge_base.organization_id
```

## 4. 用户表：t_user

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `username` | varchar(128) | 登录名，平台唯一 |
| `email` | varchar(255) | 邮箱，可选或唯一 |
| `phone` | varchar(32) | 手机号，可选 |
| `display_name` | varchar(128) | 显示名称 |
| `avatar` | varchar(1024) | 头像地址 |
| `password_hash` | varchar(255) | 密码摘要，不保存明文密码 |
| `external_subject` | varchar(255) | 外部身份源用户标识 |
| `status` | varchar(32) | pending、active、disabled、deleted |
| `last_login_at` | timestamptz | 最后登录时间 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束和索引：

- `username` 唯一。
- `email` 在非空时唯一。
- `external_subject` 与身份源组合唯一。
- `status` 建立索引。

## 5. 平台角色表：t_platform_role

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `code` | varchar(64) | 角色编码 |
| `name` | varchar(128) | 角色名称 |
| `description` | varchar(500) | 角色说明 |
| `status` | varchar(32) | active、disabled |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

初始化角色：

```text
p_super_admin：平台超级管理员
```

## 6. 平台用户角色表：t_platform_user_role

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `user_id` | bigint | 用户 ID |
| `role_id` | bigint | 平台角色 ID |
| `created_at` | timestamptz | 授权时间 |
| `created_by` | bigint | 授权人 |

约束：

- `user_id + role_id` 唯一。
- 只保存平台级角色，不保存租户角色。

## 7. 租户表：t_tenant

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `code` | varchar(64) | 租户编码，唯一 |
| `name` | varchar(255) | 租户名称 |
| `logo` | varchar(1024) | Logo 地址 |
| `contact_name` | varchar(128) | 联系人 |
| `contact_email` | varchar(255) | 联系邮箱 |
| `status` | varchar(32) | trial、active、disabled、deleted |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

## 8. 租户成员表：t_tenant_member

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `tenant_id` | bigint | 租户 ID |
| `user_id` | bigint | 用户 ID |
| `role_code` | varchar(64) | tenant_owner、tenant_admin、tenant_member、tenant_guest |
| `is_primary` | boolean | 是否用户在该租户的主成员关系 |
| `status` | varchar(32) | invited、active、disabled、left |
| `joined_at` | timestamptz | 加入时间 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束：

- `tenant_id + user_id` 唯一。
- `tenant_id + role_code` 建立查询索引。
- 一个租户可以有多个 `tenant_admin`，只能有一个有效 `tenant_owner`。

## 9. 组织表：t_organization

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `tenant_id` | bigint | 所属租户 |
| `parent_id` | bigint | 父组织，可为空 |
| `code` | varchar(64) | 组织编码，在租户内唯一 |
| `name` | varchar(255) | 组织名称 |
| `leader_user_id` | bigint | 负责人，可为空 |
| `status` | varchar(32) | active、disabled、deleted |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束和索引：

- `tenant_id + code` 唯一。
- `tenant_id + parent_id` 建立索引。
- `parent_id` 不允许跨租户引用。

## 10. 组织成员表：t_organization_member

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `organization_id` | bigint | 组织 ID |
| `user_id` | bigint | 用户 ID |
| `role_code` | varchar(64) | org_admin、org_member |
| `is_primary` | boolean | 是否主组织 |
| `status` | varchar(32) | active、disabled、left |
| `joined_at` | timestamptz | 加入时间 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束：

- `organization_id + user_id` 唯一。
- 用户加入组织前必须是该组织所属租户成员。
- 组织成员的租户必须与组织所属租户一致。

## 11. 登录日志表：t_login_log

登录日志用于记录登录成功、失败、退出和登录状态刷新事件。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint generated by default as identity | 自增主键 |
| `user_id` | bigint | 登录用户 ID，账号不存在时为空 |
| `login_account` | varchar(255) | 用户输入的用户名或邮箱 |
| `login_type` | varchar(32) | password、oidc、ldap |
| `result` | varchar(32) | success、failed、logout、refresh |
| `failure_reason` | varchar(64) | 失败原因分类，可为空 |
| `ip_address` | varchar(64) | 客户端 IP 地址 |
| `user_agent` | varchar(1024) | 客户端 User-Agent |
| `request_id` | varchar(128) | 请求 ID |
| `created_at` | timestamptz | 事件发生时间 |

设计约束：

- 不保存密码、密码摘要、Token、Cookie 或第三方密钥。
- 支持按用户、账号、结果、登录方式和时间范围查询。
- 登录日志只允许新增和查询，不提供普通业务用户修改、删除能力。
- `user_id` 采用逻辑关联，不建立数据库物理外键。

## 12. 知识库表调整

现有 `t_knowledge_base` 增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenant_id` | bigint | 所属租户，必填 |
| `organization_id` | bigint | 所属组织，可为空 |
| `created_by` | bigint | 创建用户 |
| `owner_id` | bigint | 知识库负责人 |

其中：

- `tenant_id` 是知识库数据隔离的强制条件。
- `organization_id` 为空表示租户公共知识库。
- `created_by` 表示实际创建人。
- `owner_id` 表示当前知识库负责人。

文档、分片、会话、消息和引用通过 `kb_id` 继承知识库租户边界。

## 13. 平台超级管理员数据规则

- `p_super_admin` 写入 `t_platform_user_role`。
- 平台超级管理员不需要写入 `t_tenant_member` 才能操作平台资源。
- 平台超级管理员进入租户资源时，需要明确目标 `tenant_id`。
- 普通租户管理员不能查询其他租户的数据。
- 平台角色与租户角色分表保存，避免角色语义混淆。

## 14. 后续 DDL 顺序

建议按以下顺序维护 DDL：

1. `t_user`。
2. `t_platform_role`。
3. `t_platform_user_role`。
4. `t_tenant`。
5. `t_tenant_member`。
6. `t_organization`。
7. `t_organization_member`。
8. `t_login_log`。
9. 修改 `t_knowledge_base` 增加租户和组织归属字段。
