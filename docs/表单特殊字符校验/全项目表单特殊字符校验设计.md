# 全项目表单特殊字符校验设计（评审稿）

## 1. 设计目标

本方案覆盖前端所有用户可输入或可粘贴文本的表单、筛选框和问答输入框。校验分为三层：

1. 前端失焦校验：及时提示，保留原始输入，不自动静默改写。
2. 前端提交校验：再次校验，失败时不调用接口，并将焦点定位到首个错误字段。
3. 后端服务校验：所有 API 调用必须重复校验，不能依赖前端安全性。

特殊字符校验不是 SQL 注入或 XSS 的替代方案。数据库查询继续使用参数化查询，页面展示继续进行 HTML/Markdown 转义，Prompt 和问答内容不因包含正常代码符号而被误伤。

## 2. 统一字符分类

### 2.1 一律拒绝

- ASCII 控制字符：`U+0000-U+001F`、`U+007F`。
- C1 控制字符：`U+0080-U+009F`。
- 零宽字符：`U+200B-U+200F`、`U+2060`。
- 双向控制字符：`U+202A-U+202E`、`U+2066-U+2069`。
- BOM：`U+FEFF`。

错误提示统一为“字段名不能包含控制字符或不可见字符”。输入内容保留，避免用户无法定位问题。

### 2.2 标识型字段

用于账号、编码、模型标识、文件名等字段。默认允许：中文、英文字母、数字、下划线、短横线、点；不允许空格、路径分隔符、`..`、`: * ? " < > |`。

具体字段若已有更严格业务格式，以业务格式为准：

- 用户账号：字母、数字、点、下划线、短横线，首字符必须为字母或数字。
- 租户编码、组织编码：小写字母、数字、下划线、短横线，首字符为小写字母或数字。
- 向量模型、重排模型：模型注册标识格式，允许中文模型名及 `.`、`_`、`-`，不允许空格和路径字符。
- 文件名：只允许文件名，不允许携带目录路径；扩展名另行白名单校验。

### 2.3 展示文本字段

知识库名称、租户名称、组织名称、评测名称、显示名称、联系人名等允许中文、英文、数字、空格和正常标点；拒绝不可见字符、控制字符、路径分隔符和目录穿越片段。长度、首尾空白和必填规则独立校验。

### 2.4 长文本字段

描述、系统提示词、回答提示词、业务范围描述、生成补充要求、导入问题内容和聊天问题允许正常标点、换行、Markdown/代码符号；只拒绝不可见字符并校验最大长度。不得因为出现 `{}`、`[]`、`<>`、`/`、反斜杠或引号而拒绝。

### 2.5 格式型字段

- 邮箱：先做不可见字符校验，再做邮箱格式校验。
- 手机号：先做不可见字符校验，再按手机号格式校验。
- URL/Logo 地址/API 地址：先做不可见字符校验，再校验 `http/https`、主机和端口格式；不能套用“禁止斜杠”的标识型规则。
- 密码：允许常见特殊符号，禁止控制字符和不可见字符，校验长度和强度；不得在错误提示中回显密码。
- 数字、开关、单选、多选、下拉框：使用组件类型和枚举白名单校验，不做文本特殊字符替换。

## 3. 统一表单长度标准

以下长度是表单验证标准，前端和后端必须使用相同值；数据库脚本中的字段长度不在本次调整范围内。

| 字段 | 统一上限 | 备注 |
| --- | ---: | --- |
| 用户账号 | 32 | 账号格式另行校验 |
| 登录密码 | 64 | 允许空格和常见特殊字符 |
| 用户/联系人姓名 | 30 | 中文企业场景 |
| 租户/组织/知识库/评测名称 | 50 | 兼顾列表展示 |
| 租户/组织编码 | 32 | 小写字母、数字、下划线、短横线 |
| 邮箱地址 | 128 | 数据库存储长度不调整 |
| 中国大陆手机号 | 11 | 仅允许 `1[3-9][0-9]{9}` |
| Logo/URL | 512 | URL 格式另行校验 |
| 普通描述 | 500 | 简短备注和联系人说明 |
| 租户/知识库描述 | 1000 | 业务范围说明 |
| 会话标题 | 50 | 侧边栏展示 |
| 模型标识 | 128 | 与现有模型字段容量一致 |
| 问答问题 | 1000 | 普通、访客和测试问题统一 |
| Prompt/系统提示词 | 5000 | 回答规则和系统提示 |
| 评测业务范围 | 2000 | 评测目标和业务范围 |
| 评测生成要求 | 1000 | 出题补充要求 |
| 评测文件名 | 100 | 仍需校验扩展名和路径 |
| 查询关键词 | 50 | 列表查询场景 |

评测导入文件使用文件大小、问题数量和单条问题长度三层限制，不使用超大字符数作为用户可见表单长度。

## 5. 交互规则

### 4.1 失焦

- 输入值保留，不自动删除特殊字符。
- 错误字段显示红色边框和字段下方错误提示。
- 错误字段增加可访问性错误状态，错误提示与字段关联。
- 用户修正后立即清除错误状态。

### 4.2 提交

- 校验所有可见和条件显示字段。
- 定位到第一个错误字段，并切换到对应 Tab/折叠区。
- 校验失败不发起保存、发布、创建、执行、测试或上传请求。
- 后端返回同类校验错误时，前端展示后端字段级提示，不统一替换成“保存失败”。

### 4.3 文件导入

- 选择文件时先校验文件名和扩展名。
- 解析后逐条校验问题内容；错误提示包含行号，但不回显可能包含敏感信息的完整内容。
- 任意一条问题失败时阻止提交，并提供错误行定位。

## 6. 不应采用的规则

- 不对所有字段统一禁止 `/`、反斜杠、引号或尖括号；长文本和 URL 合法使用这些字符。
- 不做 SQL 关键字黑名单。
- 不在前端通过 `replace` 静默删除字符后提交。
- 不只在前端校验，不在后端重复校验。
- 不把密码、Token、API Key 的原文写入日志或错误提示。

## 7. 实施顺序

1. 扩展公共前后端校验器，统一错误码、字段路径和中文提示。
2. 按用户、租户、组织、知识库、文档、问答配置、评测、登录和问答输入顺序接入。
3. 为每个表单补齐正常、边界、不可见字符、格式错误、权限和提交阻断测试。
4. 更新所有相关原型，补充错误态、Tab 定位、文件导入行号提示和长文本允许符号示例。
5. 评审通过后按上述范围进行前后端编码；当前已完成公共校验器和主要表单接入，剩余接入必须继续遵循本设计稿并补充对应测试。
