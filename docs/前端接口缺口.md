# 前端接口缺口

本文档记录前端按原型开发时发现的接口需求及后端完成状态。

## 已具备接口

- `POST /api/v1/auth/login`：登录页面可直接接入。
- `/api/v1/auth/tenants`、`/api/v1/auth/tenant`：查询当前用户可用租户并切换登录后的当前租户上下文。
- `/api/v1/users`：用户基本资料、状态、分页和逻辑删除。
- `/api/v1/tenants`：租户基本资料、名称、状态、分页和逻辑删除。
- `/api/v1/organizations`：组织树、组织 CRUD 和组织成员分页/维护。组织树查询已接入认证：平台超级管理员不传 `tenant_id` 时默认查询全平台并返回 `tenant_name`，传入 `tenant_id` 时查询指定租户；普通用户只能查询当前租户。
- `GET /api/v1/organizations/page`：组织远程搜索分页接口，支持 `tenant_id`、`keyword`、`status`、`page`、`page_size`，远程下拉固定按每页 20 条加载。
- `GET /api/v1/tenants/page`：租户远程搜索分页接口，支持 `name`、`status`、`page`、`page_size`，远程下拉固定按每页 20 条加载。

## 接口完成状态

### 1. 平台概览统计（已完成）

平台概览统计接口已完成并已接入前端：`GET /api/v1/platform/overview`。接口不能用分页列表推算，当前返回：

- 用户总数、正常用户数。
- 租户总数、正常租户数。
- 组织总数、知识库总数。
- 用户增长趋势。
- 资源指标排名前 5 的租户用户数、组织数、知识库数分布；可通过 `tenant_limit` 调整返回数量，默认值为 5。
- 文档处理状态分布。
- 最近平台活动。

支持 `range=7d|30d|90d|custom`；使用 `custom` 时传入 `start_at` 和 `end_at`，时间参数必须包含时区。

### 2. 当前用户和 Token 生命周期（已完成）

原型需要：

- `GET /api/v1/auth/me`：返回当前用户、平台角色、当前租户、租户角色和组织列表。
- `POST /api/v1/auth/refresh`：刷新登录凭证。
- `POST /api/v1/auth/logout`：使当前凭证失效。

以上接口后端均已提供，前端已完成登录、当前用户加载、Token 刷新和服务端退出接入。

已补充并完成：

- `GET /api/v1/auth/tenants`：返回当前用户有权访问的有效租户列表。
- `POST /api/v1/auth/tenant`：校验租户成员关系并切换当前认证会话的租户上下文。
- `GET /api/v1/auth/me`：返回 `tenants` 全部可用租户、`current_tenant` 当前租户及当前租户下的角色和组织。

前端已接入：单租户自动进入，多租户登录后选择租户，选择结果通过真实接口建立当前租户上下文；平台超级管理员进入平台管理。

### 3. 平台角色与租户成员关系（已完成）

相关接口已完成：

- `GET /api/v1/platform/roles`：平台角色列表。
- `GET /api/v1/platform/users/{user_id}/roles`：查询用户的平台角色。
- `PUT /api/v1/platform/users/{user_id}/roles`：按角色编码覆盖用户的平台角色授权。
- `GET /api/v1/tenants/{tenant_id}/members/page`：租户成员分页列表。
- `GET /api/v1/tenants/{tenant_id}/member-candidates`：租户可选用户列表。
- `POST /api/v1/tenants/{tenant_id}/members`：新增租户成员。
- `PUT /api/v1/tenants/{tenant_id}/members/{member_id}`：修改租户成员角色、主租户关系或状态。
- `DELETE /api/v1/tenants/{tenant_id}/members/{member_id}`：移除租户成员。
- `GET /api/v1/organizations/{organization_id}/member-candidates`：组织可选成员列表。
- `PUT /api/v1/organizations/{organization_id}/members/batch`：批量新增或修改组织成员。

用户管理抽屉需要展示和编辑：

- 平台角色。
- 所属租户及租户角色。
- 所属组织及组织角色。

当前已有用户、组织和以下关系管理接口：

- 平台角色列表和用户授权接口。
- 租户成员列表、新增、修改角色、移除接口。
- 组织成员可选用户列表及批量成员管理接口。

已补充：用户分页支持独立的 `username`、`email` 查询参数，租户列表和分页支持 `name` 查询参数，前端查询条件可直接使用真实接口。

已补充：租户成员分页支持 `role_code` 查询，并返回成员所属组织名称；前端成员列表可以直接使用真实字段完成筛选和展示。

### 4. 租户管理扩展数据（已完成）

租户列表原型需要展示：

- 成员数。
- 知识库数。
- 租户管理员。
- 组织统计。

租户详情和租户列表接口均已返回成员数、知识库数、租户管理员和组织数统计字段；成员管理接口已在“平台角色与租户成员关系”章节标记为已完成。

### 4.1 租户下钻组织和知识库列表（已完成）

本次核对发现：查询接口已经存在，但组织分页接口缺少上级组织、负责人和成员数量；已补齐后端返回字段并完成前端对接。知识库不再返回或查询直接所属组织字段，组织访问统一通过知识库组织授权接口处理。

- `GET /api/v1/organizations/page?tenant_id={tenant_id}&keyword=&status=&page=&page_size=`：支持按租户查询组织，返回组织名称、上级组织名称、负责人、成员数、状态、创建时间和更新时间等字段。
- `GET /api/v1/knowledge-bases/page?tenant_id={tenant_id}&name=&status=&page=&page_size=`：支持按租户查询知识库，返回知识库名称、描述、状态、创建时间、更新时间和创建用户等字段。
- 两个接口均执行当前用户权限和租户范围校验，平台超级管理员可以查询指定租户，其他用户不能跨租户查询。
- 前端只需增加租户页面内的下钻视图和真实接口调用，不新增静态数据或伪造接口兜底。

### 5. 知识库租户上下文（已完成）

平台管理员进入租户资源时需要：

- 按 `tenant_id` 查询知识库。
- 知识库不按 `organization_id` 查询。
- 创建/修改知识库时只提交租户归属，不提交组织归属。
- 组织授权知识库及授权列表接口。

已补充：

- `GET /api/v1/knowledge-bases` 和 `GET /api/v1/knowledge-bases/page` 支持 `tenant_id` 查询。
- 新增、修改知识库请求只支持 `tenant_id`，组织访问通过授权接口维护。
- `GET /api/v1/knowledge-bases/{kb_id}/organizations`：查询知识库组织授权列表。
- `POST /api/v1/knowledge-bases/{kb_id}/organizations`：为组织授权知识库。
- `DELETE /api/v1/knowledge-bases/{kb_id}/organizations/{organization_id}`：撤销组织授权。

### 6. 知识库概览统计（已完成）

知识库概览统计接口已完成，前端图表统一使用 ECharts，通过公共 `TrendLineChart` 组件封装：

- `GET /api/v1/knowledge-bases/{kb_id}/overview`：返回当前知识库的文档总数、分片总数、向量数量和索引失败数。
- 文档处理趋势、文档状态分布和问答趋势（问答次数、活跃会话数双折线图）。
- 平均相似度、低相似度问题、无引用回答统计。
- 热门问题、文档引用排行和最近活动。

接口应支持 `range=7d|30d|90d|custom`，并严格限制在当前 `kb_id` 的数据范围内。

### 7. 租户访客授权知识库列表（已完成）

访客问答工作区的“授权知识库”抽屉需要远程快速查找和分页，不能使用前端静态列表。

- `GET /api/v1/guest/knowledge-bases/page`：仅返回当前登录用户有权访问的知识库。
- 查询参数：`keyword`（可选，匹配知识库名称和描述）、`page`（默认 1）、`page_size`（默认 10）。
- 返回字段：`rows`、`total`、`page`、`page_size`，每条记录至少包含 `id`、`name`、`description`。
- 接口必须按当前登录用户、当前租户和组织授权范围过滤，不能信任前端传入的租户或用户标识。
- 已新增 `GET /api/v1/guest/knowledge-bases/page`，访客前端已接入授权数据源抽屉、关键词防抖查询和分页；不使用本地静态数据兜底。
- 服务端按当前认证用户、当前租户和组织授权范围过滤，仅返回 `active` 知识库。

### 8. 租户访客问答和会话接口（已完成）

访客工作区已按独立的认证上下文接口接入，后端已补充以下能力：

- `POST /api/v1/guest/chat`：从当前认证用户中获取用户、租户和访客角色，不接收前端传入的 `user_id`；校验知识库授权后执行问答。
- `GET /api/v1/guest/conversations`：按当前用户、当前租户和 `kb_id` 返回会话列表。
- `GET /api/v1/guest/conversations/{conversation_id}/messages`：校验会话归属后返回消息。
- `PUT /api/v1/guest/conversations/{conversation_id}`：仅允许当前用户重命名自己的会话。
- `DELETE /api/v1/guest/conversations/{conversation_id}`：仅允许当前用户删除自己的会话。

访客接口已完成当前用户、当前租户、访客角色、知识库组织授权和会话归属校验；现有通用 `/chat` 和 `/conversations` 接口仍保留原有协议，访客工作区不再直接调用这些通用接口。

### 9. 知识库授权选择与批量提交（已完成）

前端已开始接入知识库“授权”下拉、组织授权和用户授权交互。当前后端已有以下用户直接授权接口，前端可以直接使用：

- `GET /api/v1/knowledge-bases/{kb_id}/users`：查询知识库已授权用户。
- `POST /api/v1/knowledge-bases/{kb_id}/users`：为单个用户授权知识库。
- `DELETE /api/v1/knowledge-bases/{kb_id}/users/{user_id}`：撤销用户授权。
- `GET /api/v1/users/page`：支持租户范围、关键词和分页查询用户。

已补充以下接口，并完成租户范围、未授权过滤、关键词搜索、分页和事务性批量授权：

- `GET /api/v1/knowledge-bases/{kb_id}/users/available?keyword=&page=&page_size=`：返回当前知识库所属租户下尚未授权的有效用户。
- `GET /api/v1/knowledge-bases/{kb_id}/organizations/available?keyword=&page=&page_size=`：返回当前知识库所属租户下尚未授权的有效组织，并返回上级组织信息。
- `POST /api/v1/knowledge-bases/{kb_id}/organizations/batch`：请求体提交 `organization_ids`，在同一事务中完成组织授权。
- `POST /api/v1/knowledge-bases/{kb_id}/users/batch`：请求体提交 `user_ids`，在同一事务中完成用户授权。

批量接口会校验知识库、租户成员/组织归属、用户状态、重复 ID 和已有授权；任一条数据校验失败时整体回滚。虽然当前原型不展示“批量授权”按钮，批量接口作为完整授权能力保留。

### 10. 租户资源添加能力（已完成）

本次前端开发核对发现：

- 租户成员候选接口 `GET /api/v1/tenants/{tenant_id}/member-candidates` 当前不支持分页，无法满足待选列表的统一分页规范。
- 租户成员当前只有单条新增接口，无法一次确认多选结果，需要补充批量新增接口。
- 租户组织和知识库调整为平台资源绑定模型：未绑定租户的组织和知识库进入候选池，租户管理中的“添加组织”和“添加知识库”从候选池多选绑定，不再创建新资源。

已补充并完成：

- `GET /api/v1/tenants/{tenant_id}/member-candidates/page`：支持 `keyword`、`page`、`page_size`，返回当前租户尚未加入的有效用户。
- `POST /api/v1/tenants/{tenant_id}/members/batch`：一次提交多个用户及统一成员属性，并在一个事务中完成新增。
- `GET /api/v1/tenants/{tenant_id}/organization-candidates/page`、`POST /api/v1/tenants/{tenant_id}/organizations/batch`：分页查询未绑定组织并批量绑定。
- `GET /api/v1/tenants/{tenant_id}/knowledge-base-candidates/page`、`POST /api/v1/tenants/{tenant_id}/knowledge-bases/batch`：分页查询未绑定知识库并批量绑定。

平台超级管理员使用租户资源绑定接口时，候选资源包含未绑定资源和已绑定其他租户、但尚未绑定当前租户的资源；当前租户已绑定资源会被排除。跨租户绑定组织时会清空父组织；知识库不维护直接组织归属。

### 11. 通用待选列表控件配套接口（已完成）

组织管理的“添加成员”已接入统一待选列表控件，原有全量候选接口不满足分页要求，已补充：

- `GET /api/v1/organizations/{organization_id}/member-candidates/page`：支持 `keyword`、`page`、`page_size`，仅返回当前租户内、尚未加入当前组织的有效用户，并返回所属组织名称。
- 组织成员批量添加继续使用 `PUT /api/v1/organizations/{organization_id}/members/batch`，确认时一次提交临时多选结果。

候选查询、分页、跨页临时勾选、确认提交、取消关闭丢弃选择均已完成真实前端对接。
