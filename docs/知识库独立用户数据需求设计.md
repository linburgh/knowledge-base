# 知识库独立用户数据需求设计

## 1. 文档目标

知识库系统需要具备独立的用户数据和权限边界，不能继续使用固定的 `dev-user` 作为所有数据的归属用户。

系统需要同时支持：

1. 用户管理。
2. 租户管理。
3. 组织管理。
4. 知识库与租户、组织、用户之间的独立归属关系。
5. 用户在不同租户和组织中的不同权限。
6. 平台概览和知识库概览的数据统计与图表展示。

本文用于确认业务范围、数据关系和权限模型，确认后再进入数据库和接口设计。

相关设计文档：

- [平台用户、租户与组织数据库设计](平台用户租户组织数据库设计.md)
- [平台管理前端原型设计](前端原型设计/平台管理原型设计.md)

## 2. 核心数据关系

```text
平台
└── 租户 Tenant
    ├── 用户 User
    ├── 组织 Organization
    │   └── 组织成员 Organization Member
    ├── 租户成员 Tenant Member
    └── 知识库 Knowledge Base
        ├── 知识库成员 Knowledge Base Member
        ├── 文档
        ├── 会话
        ├── 消息
        └── 引用
```

### 2.1 数据隔离原则

- 用户数据必须绑定租户，不能跨租户查询。
- 组织必须属于一个租户。
- 知识库必须属于一个租户。
- 知识库可以归属于一个组织，也可以归属于租户公共空间。
- 文档、分片、会话、消息、引用和检索结果必须继承知识库的数据隔离边界。
- 所有接口都必须从认证上下文获取当前用户和租户，不能仅依赖前端传入的 `tenant_id` 或 `user_id`。
- 管理员也必须在明确的租户范围内操作数据，平台管理员跨租户操作需要单独权限和审计记录。

## 3. 用户管理

### 3.1 用户信息

用户是平台中的自然人账号，建议包含：

- 用户 ID。
- 登录名或邮箱。
- 手机号，可选。
- 显示名称。
- 头像。
- 密码摘要或外部身份标识。
- 账号状态：正常、禁用、锁定、已删除。
- 最后登录时间。
- 创建时间和更新时间。

### 3.1 平台超级管理员

平台设置独立角色 `p_super_admin`，该角色不属于任何具体租户，可以操作平台范围内的全部资源。

平台超级管理员可以：

- 管理全部租户。
- 管理全部用户。
- 管理全部组织。
- 查看和管理全部知识库。
- 管理平台级配置。
- 处理租户、用户、组织和知识库的异常数据。
- 执行平台范围内的数据维护和资源管理操作。

平台超级管理员与租户角色分开定义，不使用普通租户管理员角色替代。建议认证上下文单独保存平台角色：

```json
{
  "user_id": "platform-admin-001",
  "platform_roles": ["p_super_admin"],
  "tenant_id": null,
  "tenant_roles": []
}
```

平台超级管理员进入具体租户资源时，系统上下文需要明确当前目标租户；未选择目标租户时，只允许执行平台级管理操作。

密码、Token 和第三方密钥不得以明文保存。

### 3.2 用户能力

- 用户注册或由管理员创建。
- 用户登录、退出和刷新登录状态。
- 修改个人资料。
- 修改密码或绑定外部身份源。
- 查看自己所属的租户和组织。
- 切换当前工作租户。
- 查看自己有权访问的知识库。
- 查看个人操作记录。

### 3.3 用户状态

```text
pending → active → disabled
                    └→ deleted
```

禁用用户后：

- 不能登录。
- 不能创建会话和发起问答。
- 不能上传或删除文档。
- 既有数据保留其历史归属。
- 管理员可以恢复禁用用户，但不能恢复已删除账号，除非系统明确提供恢复能力。

## 4. 租户管理

租户是数据隔离和计费的基本边界，通常对应一个企业、团队或独立客户。

### 4.1 租户信息

- 租户 ID。
- 租户名称。
- 租户编码，系统内唯一。
- Logo 和品牌配置。
- 联系人和联系方式。
- 租户状态：试用、正常、停用、已删除。
- 配额配置。
- 创建时间和更新时间。

### 4.2 租户配额

租户可以配置或限制：

- 用户数量。
- 组织数量。
- 知识库数量。
- 文档数量。
- 存储容量。
- 单个文件大小。
- 月度问答次数。
- 模型调用预算。
- 向量存储容量。

### 4.3 租户角色

建议至少包含：

| 角色 | 说明 |
|---|---|
| 租户所有者 | 管理租户全部配置、成员和知识库 |
| 租户管理员 | 管理租户内用户、组织和知识库 |
| 普通成员 | 按授权访问组织和知识库 |
| 访客 | 仅访问被授权的知识库或问答能力 |

租户删除建议采用软删除。删除租户后，禁止新增业务操作，但保留数据和审计记录。

## 5. 组织管理

组织用于表达租户内部的部门、团队或业务单元，并承担批量授权和数据归属能力。

### 5.1 组织信息

- 组织 ID。
- 租户 ID。
- 父组织 ID。
- 组织名称。
- 组织编码。
- 组织负责人。
- 组织状态。
- 创建时间和更新时间。

组织支持树形结构：

```text
企业总部
├── 人力资源部
├── 财务部
└── 技术中心
    ├── 平台组
    └── 算法组
```

### 5.2 组织成员

同一个用户可以加入同一租户下的多个组织，但需要明确主组织：

- 用户 ID。
- 组织 ID。
- 是否主组织。
- 组织内角色。
- 加入时间。
- 离开时间。
- 成员状态。

### 5.3 组织操作

- 创建组织。
- 修改组织名称和负责人。
- 调整父子组织关系。
- 添加、移除和批量导入成员。
- 将知识库授权给组织。
- 查看组织可访问的知识库。
- 禁止删除仍包含有效子组织的组织，或提供明确的迁移流程。

## 6. 知识库归属与授权

知识库不再只依赖 `owner_id` 判断权限，建议增加明确的租户和组织归属。

### 6.1 知识库归属

每个知识库至少包含：

- `tenant_id`：所属租户。
- `organization_id`：所属组织，可为空，表示租户公共知识库。
- `created_by`：创建用户。
- `owner_id`：知识库负责人，可保留作为业务负责人字段。

### 6.2 知识库成员权限

建议增加知识库成员授权关系：

| 权限 | 说明 |
|---|---|
| 查看 | 查看知识库基本信息和授权范围 |
| 文档查看 | 查看文档、索引状态和分片信息 |
| 文档管理 | 上传、重新索引、删除文档 |
| 问答 | 发起问答和查看引用 |
| 配置管理 | 修改知识库配置和系统提示词 |
| 成员管理 | 管理知识库成员和权限 |
| 删除 | 删除知识库 |

知识库权限可以授予：

- 指定用户。
- 指定组织。
- 租户内全部成员。

权限计算优先级建议为：

```text
用户直接授权
    + 所属组织授权
    + 租户默认授权
    → 汇总有效权限
```

撤销权限时需要明确直接授权和组织继承授权的优先级，不能只删除一条关系就误判为无权限。

## 7. 平台概览与知识库概览

### 7.1 平台概览

平台概览面向 `p_super_admin`，展示平台范围内的运营和资源数据：

- 用户总数、正常用户数、租户总数、正常租户数、组织总数、知识库总数。
- 用户增长趋势：按日、月统计新增用户和活跃用户。
- 租户资源分布：展示各租户的用户数、组织数和知识库数。
- 知识库创建趋势：按时间统计新增知识库数量。
- 文档处理状态：统计已完成、处理中、失败和待处理文档数量。
- 最近平台活动：展示用户、租户、组织、知识库和文档的近期操作。

平台图表必须遵守当前平台管理员的数据范围，默认展示全部平台数据；进入具体租户后，顶部需要显示当前租户，上述统计切换为当前租户范围。

### 7.2 知识库概览

知识库概览只展示当前 `kb_id` 的数据：

- 文档总数、分片总数、向量数量、索引失败数。
- 文档处理趋势：统计每日新增文档和索引完成数量。
- 文档状态分布：展示待处理、处理中、已完成和失败数量。
- 问答趋势：统计问答次数和活跃会话数。
- 检索质量：展示平均相似度、低相似度问题数量和无引用回答数量。
- 热门问题：按出现次数展示近期高频问题。
- 文档贡献排行：按被引用次数展示热门文档或分片。
- 最近活动：展示上传文档、索引完成、问答和配置修改记录。

### 7.3 图表通用要求

- 支持近 7 天、近 30 天、近 90 天和自定义时间范围。
- 图表点击后可以跳转到对应列表，并带入对应筛选条件。
- 状态继续使用中文文字和文字颜色区分，不使用大面积状态背景。
- 没有数据时显示明确的空状态、数据范围和更新时间。
- 失败数量、低相似度问题、无向量分片等异常指标需要突出显示。
- 图表数据应由统计接口提供，前端不得根据列表分页数据自行推算全量统计结果。
- 前端图表组件统一使用 ECharts，图表样式与现有 Bootstrap 基础样式、Element Plus 交互组件保持一致。

## 8. 认证与当前上下文

后续认证上下文至少应包含：

```json
{
  "user_id": "user-001",
  "tenant_id": "tenant-001",
  "organization_ids": ["org-001", "org-002"],
  "roles": ["tenant_admin"],
  "permissions": ["knowledge_base:read", "document:write"]
}
```

后端业务 Service 必须使用认证上下文完成：

1. 当前用户身份校验。
2. 当前租户校验。
3. 组织关系校验。
4. 知识库权限校验。
5. 文档、会话和引用的继承权限校验。

前端传入的 `user_id`、`tenant_id` 只能作为展示或调试信息，不能作为最终授权依据。

## 8. 管理功能

### 8.1 用户管理页面

- 用户查询。
- 状态筛选。
- 所属租户和组织筛选。
- 创建用户。
- 编辑用户信息。
- 启用、禁用和删除用户。
- 重置密码或重新发送邀请。
- 查看用户所属组织和知识库权限。

### 8.2 租户管理页面

- 租户查询和状态筛选。
- 创建租户。
- 修改租户信息。
- 管理租户管理员。
- 配置租户配额。
- 查看租户用户、组织和知识库统计。
- 停用和恢复租户。

### 8.3 组织管理页面

- 组织树展示。
- 创建、编辑和删除组织。
- 调整组织层级。
- 管理组织负责人。
- 管理组织成员。
- 查看组织可访问知识库。
- 将知识库授权给组织。

## 9. 审计要求

用户、租户、组织和知识库权限变更都必须记录审计日志：

- 操作用户。
- 租户 ID。
- 组织 ID，可为空。
- 操作类型。
- 目标资源类型和 ID。
- 变更前内容摘要。
- 变更后内容摘要。
- 请求 ID。
- IP 和客户端信息。
- 操作时间。

提示词修改、知识库成员调整、租户管理员变更和用户禁用属于重点审计事件。

## 10. 待确认事项

进入数据库和 API 设计前，需要确认：

- 一个用户是否允许加入多个租户。
- 一个用户在不同租户中是否可以使用不同角色。
- 知识库是否允许同时归属于组织和指定用户。
- 是否支持租户公共知识库。
- 组织授权和用户直接授权冲突时的优先级。
- 是否需要邀请注册和邮箱验证。
- 是否需要接入 LDAP、OIDC 或 SSO。
- 租户配额是否第一期就启用。
- 是否需要保留完整权限变更审计。
