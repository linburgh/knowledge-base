# 监控需求

## 1. 文档说明

### 1.1 文档目的

本文档用于定义知识库系统“自主监控智能体”能力的建设范围、监控对象、指标、事件、告警和管理交互，为后续原型评审、接口设计、数据库设计和前后端开发提供统一依据。

本文档当前只做需求设计，不代表已经开始前后端、数据库或 Worker 编码。

### 1.2 建设背景

当前系统已经存在文档处理、知识库问答和自主评测等异步执行链路。系统出现异常时，管理员通常只能通过应用日志判断：

- Worker 是否正在运行；
- 是否有任务等待处理；
- 任务是否长时间没有进度；
- 问答接口是否持续变慢或错误增加；
- 知识库是否存在文档未处理、索引未生效或引用质量下降；
- 自主评测是否真正执行，还是长期处于空轮询、失败或阻塞状态。

因此需要建设自主监控智能体，由智能体持续观察运行状态、业务指标、资源指标和任务事件，识别异常、分析影响、生成告警和给出可追踪的处理建议；平台页面负责展示监控智能体产出的状态、事件、告警和分析结果。

### 1.3 模块定位

自主监控模块是面向平台运行管理的观测、分析和告警模块，由监控总览、数据采集、指标分析、任务监控、告警中心、事件中心、智能分析和审计管理等能力组成；告警通知作为告警中心内的二级视图，负责回答：

1. 当前系统是否可用？
2. 异步任务是否正常消费？
3. 知识库问答质量和性能是否发生异常？
4. 自主评测是否按预期运行并产出结果？
5. 异常从什么时候开始、影响了什么、是否已经恢复？

自主监控模块不替代日志系统、链路追踪系统、数据库监控系统或云平台基础设施监控。模块通过受控采集器、查询接口、周期探针和监控智能体读取这些系统及业务模块提供的结构化数据，形成业务上下文、异常判断、告警实例和处理建议。

项目中的问答、评测和监控智能体与文档处理链路协同工作：

```text
文档处理与索引链路
  └─ 负责文档解析、知识抽取、入库和知识库内容相关处理

自主评测智能体
  └─ 负责组织评测问题、调用问答能力、计算指标和生成评测结果

知识库问答智能体
  └─ 负责在授权范围内检索知识库、生成回答和返回引用

自主监控智能体
  └─ 观察文档处理与索引链路、知识库问答智能体、自主评测智能体及平台运行数据
     分析异常、关联影响、生成告警和提供处理建议
```

问答、评测和监控智能体之间只能通过公开的结构化协议协同，不得互相导入私有 Prompt、私有运行循环、模型实例或内部状态。自主监控智能体对文档处理与索引链路只进行受控观测，不把该链路视为独立 Agent，也不通过硬编码复制其他 Agent 的执行逻辑。

自主监控智能体的运行入口、Runtime、Policies、工具注册表和技能文件必须独立放在 `app/agents/monitoring/` 下，遵守项目 Agent Harness 规范。平台监控页面和 API 通过 Service 调用监控智能体公开的结构化结果，不直接访问其私有状态。

## 2. 建设目标

### 2.1 目标说明

1. 让自主监控智能体持续观察服务、数据库、异步 Worker、知识库、问答链路和其他智能体的健康状态。
2. 监控文档入库、索引构建、自主评测等异步任务的数量、状态、耗时、积压和失败情况。
3. 监控问答请求量、成功率、错误率、降级率、响应耗时和引用返回情况。
4. 监控自主评测任务从创建、排队、执行到结束的完整过程，能够证明 Agent 确实被执行。
5. 由自主监控智能体对超时、失败、积压、连续错误、质量门禁不通过和 Worker 停止等情况生成告警。
6. 支持告警确认、关闭、抑制和恢复，避免同一故障持续刷屏。
7. 支持从指标、告警、事件跳转到具体任务、运行记录、日志上下文和评测报告。
8. 支持平台超级管理员和租户管理员使用自主监控并执行授权操作；平台超级管理员可管理平台范围，租户管理员只能在当前租户范围内操作。
9. 所有监控数据包含统计时间、数据范围、来源和计算状态，避免把无数据误判为零值或健康。

### 2.2 备注

- 本模块当前复用已有日志、链路追踪、数据库和基础设施监控能力，不重复建设通用日志采集平台、APM 平台或主机级监控平台。
- 监控模块只负责观测、分析、告警和建议，不自动修改知识库文档、Prompt、模型、索引配置或评测门禁。
- 监控告警默认不自动重试、暂停、删除或终止业务任务；自动化处置需要另行设计并确认。
- 没有自主评测任务时显示“空闲且健康”，不能直接判断为异常；需要与 Worker 停止和任务积压明确区分。
- 单次偶发慢请求不能直接判定系统故障，必须结合时间窗口、样本量和连续性规则。

自主监控定义为与“平台管理”同级的一级菜单，不放入“平台管理”子菜单，也不放入“知识库”工作区。进入自主监控后，再展示监控总览、数据采集、指标分析、任务监控、告警中心、事件中心、智能分析和审计管理等子模块；告警通知在告警中心内通过 Tab 进入。

模块边界要求：

- 总览、列表和详情页面不得直接查询数据库、日志或 Agent 私有状态，统一调用监控 API。
- 数据采集模块只记录结构化事实，不负责判断告警和生成自然语言建议。
- 指标模块只负责统计口径和数据状态，不覆盖原始事件。
- 规则模块负责确定性触发和恢复；监控智能体负责关联分析，不替代规则。
- 告警处理只允许确认、关闭、抑制和添加备注，不能默认修改或重试业务任务。
- 系统采集配置和告警规则存储在数据库中；采集配置由系统版本和运维流程管理，不向业务用户开放配置、启停或修改入口。

#### 2.3.1 监控总览

监控总览是自主监控的首页，面向平台超级管理员和租户管理员回答“当前是否异常、异常影响什么、从何时开始、如何追溯”。页面采用浅色管理后台风格，与数据采集、指标分析和配置页面保持一致，不使用独立的深色大屏视觉。

监控总览不属于普通报表、日志查询、基础设施监控替代品或自动处置中心，不提供重试、暂停、终止任务，修改 Prompt、模型、索引或知识库配置等操作。页面只负责展示监控统计、健康状态、告警入口、异常关联和证据追溯。

页面固定由以下区域组成，并按顺序展示：

1. 页面头部：展示当前范围、时间窗口、最后更新时间、整体状态、手动刷新、自动刷新开关和数据说明入口。
2. 未恢复告警：按严重级别聚合展示当前范围内的 `firing` 和 `acknowledged` 告警数量，位于健康摘要和图表之前。
3. 运行状态摘要：以紧凑状态条展示平台服务、外部依赖和监控采集自身健康，不与业务状态重复。
4. 告警状态图：以时间趋势展示 `firing`、`acknowledged`、`resolved` 和 `closed` 四类告警状态的变化。
5. 资源容量卡片：使用四张独立卡片展示数据库连接、任务队列、文件存储和向量存储的当前使用率、已用量、容量上限、状态及预警阈值，并在区域标题右侧展示最近采集时间；数据库连接按 PostgreSQL 实例当前连接总数与 `max_connections` 计算，不以单进程连接池上限代替实例容量；文件与向量存储必须按实际已用量和已配置配额计算，未配置配额时显示无法判定，不得使用宿主机本地暂存目录磁盘占用替代。
6. 异常传播链路：以跨监控域时间线和关联连线展示异常发生、影响传播和恢复过程。
7. 业务状态：只展示问答、异步任务和自主评测的当前状态及一个关键值，并在区域标题右侧展示最近更新时间；每项提供 Tip 解释其主要表达内容，请求趋势、任务明细和评测阶段下沉到对应子模块。

总览所有区域必须使用同一数据范围和时间窗口。点击指标、告警、任务、事件或 Worker 状态时，跳转到对应模块并携带当前范围、时间窗口和资源上下文。只展示统计接口返回的数据，不从分页列表推算全量指标。

总览自动刷新必须统一刷新运行状态热力图、告警状态图、资源容量卡片和异常传播链路，并同步更新时间轴和最后更新时间；用户可以关闭自动刷新，关闭后保留当前数据，手动刷新仍可用。刷新失败时不得用 0 覆盖旧数据，应标记数据过期或获取失败。

#### 2.3.2 数据采集

数据采集负责把 API、问答智能体、自主评测、文档处理与索引链路、数据库、Worker 和外部依赖的运行事实转换为统一监控事件和状态数据。

核心功能：

- 通过 `monitor_gather` 装饰器登记稳定目标方法，并根据数据库中的 `target_code` 动态查询采集配置。
- 通过 FastAPI、数据库访问层和 Worker 公共适配器采集通用运行信息。
- 通过周期状态采集获取服务、依赖、Worker、任务积压和容量状态。
- 执行事件脱敏、租户校验、幂等去重和数据状态标记。
- 记录采集器自身的成功、失败、过期和不可用状态。
- 页面只提供采集目标查询、目标详情和事件追溯，不提供采集配置、启停、立即采集或删除任务操作。目标详情只展示目标运行事实、当前数据状态、最近异常、影响范围和事件入口，不展示配置编辑项或版本管理信息。
- 页面按采集总览设计，先表达整体采集是否正常、采集状态趋势和影响范围，再下钻到目标明细；采集概览使用 5 分钟粒度热力图表达各采集域的状态变化，避免将多个采集目标直接堆成列表。

边界要求：数据采集只记录结构化事实，不负责告警判断、自然语言分析或业务任务处置；采集失败不得阻断业务主流程。

#### 2.3.3 指标分析

指标分析负责将原始事件和状态快照按时间窗口、租户、知识库、任务类型、资源和版本上下文聚合为可查询指标。

核心功能：

- 计算问答请求量、成功率、错误率、超时率、降级率、引用率和 P50/P95/P99。
- 计算异步任务积压、等待时长、成功率、失败率、处理速率和重试情况。
- 计算评测完成率、逐题失败率、运行耗时、执行证据完整率和质量门禁结果。
- 计算数据库、队列、存储、向量服务和模型依赖的容量与可用性指标。
- 返回统计时间、时间窗口、数据范围、样本量、计算状态和更新时间。

边界要求：指标分析不得覆盖或修改原始事件；无样本不能转换为 0，采集失败不能转换为健康。

页面按“指标总览”设计，整体风格与数据采集保持一致：顶部展示指标结论，中部展示状态趋势和监控域状态图，底部提供指标明细查询列表。状态趋势按 5 分钟聚合达标、预警、不达标和无法判定指标数量；监控域状态图参考数据采集的状态分布，按知识库问答、平台运行、异步任务和自主评测分行展示状态条；每个监控域采用两行布局，第一行展示域名称和状态构成，第二行展示指标总数、健康率和最近更新时间，用于比较不同监控域的覆盖规模和健康程度；图例只显示状态名称并独立放在区域右上方一行，具体状态数量通过鼠标悬停状态条查看。指标明细查询条件包括指标名称、监控领域、数据范围、时间窗口和数据状态，列表列名统一使用四字名称，包括指标名称、监控领域、当前数值、统计单位、样本数量、统计窗口、考核状态、数据状态、生成时间和操作入口；列表不展示稳定指标编码，指标编码仅在详情和接口语义中使用。

#### 2.3.4 任务监控

任务监控负责查看文档入库、索引构建、自主评测和后续异步任务的运行状态，重点判断任务是否积压、卡住、失败或超时。

核心功能：

- 查询任务状态、任务类型、所属租户、知识库、创建时间、开始时间和结束时间。
- 展示最老待处理任务、当前积压数量、等待时长和处理速率。
- 展示 Worker 心跳、运行状态、最近领取任务和最近完成任务时间。
- 区分 `idle`、`busy`、`stale`、`stopped`、`error` 和 `unknown`。
- 查看评测运行的阶段进度和 Agent 执行证明。

边界要求：Worker 空闲且没有待处理任务属于健康状态；任务监控不得自动重试、暂停、删除或终止业务任务。

页面按“任务总览”设计，整体风格与数据采集、指标分析保持一致：顶部展示任务结论，中部展示 5 分钟粒度任务状态趋势和 Worker 状态，底部提供任务明细查询列表。任务结论必须突出待处理数量、最老等待时长和当前运行任务；Worker 状态使用紧凑状态列表，按行展示 Worker 名称、消费数量、消费能力、运行状态和最近心跳，并汇总 Worker 数量和消费结果；不把空闲状态误判为异常。任务明细查询条件包括任务名称、任务类型、当前状态、工作节点和创建时间，工作节点仅用于筛选和关联定位；列表展示任务名称、任务类型、当前状态、执行进度、等待时长、开始时间、结束时间和操作入口，不重复展示工作节点列。

#### 2.3.5 告警中心

告警中心负责维护告警规则、发现需要处理的告警实例、判断处理优先级、执行人工处置并追溯恢复证据，是管理员处理异常的主要入口。页面在同一模块内提供“告警实例”和“规则配置”两个二级视图：告警实例按“告警总览”展示告警结论、告警趋势、优先分布和告警明细；规则配置提供规则查询、新增、编辑、启停、版本和审计入口。新增和编辑类抽屉表单统一采用单列纵向布局，标签置于控件上方，底部操作按钮右对齐。

核心功能：

- 告警结论展示未恢复、待确认、严重告警和最长持续时间，并补充触发中、已确认、近窗口已恢复和已关闭数量。
- 告警趋势按 5 分钟展示新触发、未恢复和已恢复数量变化，不把检测状态和人工处理状态混为一条互斥状态线。
- 优先分布按严重、警告、提示展示当前未恢复告警，帮助管理员先处理影响最大的告警。
- 告警明细按告警级别、告警状态、监控领域、资源名称和发生时间查询，支持分页；规则名称、资源类型、租户范围和恢复时间作为完整查询条件保留。
- 详情展示告警规则、触发表达式、当前值、阈值、统计窗口、样本量、影响范围、关联指标、事件、任务、评测运行、Worker、Trace ID、处理记录和审计记录。
- 支持确认、抑制、关闭、添加备注和查看恢复信息；操作按告警状态和用户权限动态显示。
- 规则配置展示规则名称、监控域、严重级别、触发表达式、触发窗口、恢复条件、状态、版本和更新时间；保存规则时生成版本，停用规则不删除历史告警实例。

告警状态拆分为两个维度：检测状态包括 `firing`、`resolved`；人工处理状态包括 `unacknowledged`、`acknowledged`、`suppressed`、`closed`。例如告警可以同时处于 `firing + acknowledged`，表示问题仍在持续但已有人确认处理。告警规则负责确定性触发、恢复和去重；告警中心不允许默认执行业务修改或自动重试。

#### 2.3.6 事件中心

事件中心负责查询监控原始事件、事件详情和跨来源时间线，帮助管理员还原异常发生过程。页面参考数据采集、指标分析和任务监控的总览结构，包含事件结论、事件趋势、来源分布和事件明细四个区块。

核心功能：

- 事件结论展示窗口内事件总数、异常事件数、告警相关事件数和最新事件时间。
- 事件趋势按 5 分钟展示全部事件和异常事件的变化，观察状态变化是否集中发生。
- 来源分布按任务运行、Worker、告警、采集与依赖等来源展示事件构成，不把事件列表简单堆叠在页面首屏。
- 事件明细按事件类型、监控域、资源名称、关联标识和发生时间查询，支持分页。
- 详情展示事件 ID、类型、阶段、状态、发生时间、耗时、来源、Trace ID、关联告警、关联任务和脱敏上下文。
- 相关事件按任务、资源、Trace ID 和时间窗口组织为时间线，并支持跳转到任务、评测、告警详情和允许查看的日志上下文。

边界要求：事件中心不能展示超出权限范围的完整问题、答案、文档内容、用户信息或敏感凭证；普通空轮询不作为独立事件展示。

#### 2.3.7 智能分析

智能分析由自主监控智能体负责，对已经采集的指标、事件和告警进行跨来源关联，生成可验证的异常说明、处理建议和对话回答。页面提供“分析总览”和“分析对话”两个 Tab：分析总览展示分析结论、影响范围、证据链路、异常时间和处理建议；分析对话由同一个自主监控智能体负责，围绕当前异常上下文提供追问和结论验证，不与分析总览纵向堆叠，也不是脱离监控证据的通用聊天入口。自主评测智能体只作为被观测对象，提供评测运行状态、评测结果和执行证据。

核心功能：

- 关联文档索引失败、问答引用率下降和评测门禁不通过等影响链路。
- 分析异常开始时间、影响资源、影响租户和可能原因。
- 整理触发告警的指标、事件、任务、版本和 Trace ID 证据。
- 输出异常摘要、影响范围、置信度和人工处理建议。
- 支持问答监控探针和评测结果作为业务质量证据。
- 影响范围必须区分已确认影响、待验证影响和间接影响；证据必须标记直接证据、关联证据或上下文证据。
- 分析对话必须绑定当前异常范围，采用会话列表与消息主区域双栏布局，不常驻参考资料区域。每条智能体回答以“自主监控智能体 · 引用 N 条证据”文本按钮打开该轮回答的参考证据抽屉；抽屉提供证据内容、证据类型、证据等级查询，桌面端查询条件横向单行排列，每项采用“左侧标签＋右侧字段”结构，不以占位文字代替标签，空间不足时按字段组完整换行，并支持后端分页、每页条数选择和行内详情。页面不使用“上下文已锁定”状态；当前异常范围以普通说明文字呈现。回答引用已授权证据并保留引用来源；支持继续追问和快捷问题，不得凭空扩大影响范围或生成无证据结论。
- 分析对话历史归自主监控域保存，优先复用现有 `t_conversation`、`t_conversation_message` 和消息元数据模型，不为分析对话单独新增会话表或消息表；监控异常上下文、证据引用和自主监控 Agent 执行标识通过会话扩展字段及消息 `metadata` 保存。
- 分析对话必须识别平台健康、异常原因、影响范围、证据查看、检查建议、任务诊断、时段回顾和身份介绍；显式时间优先于会话默认时间，支持昨天、今天、最近时长和明确日期。
- 平台健康结论必须综合健康快照、窗口内全部生命周期告警、指标、事件和任务事实，区分正常、预警、异常和无法判断；没有未恢复告警不得直接推导为运行正常。
- 分析总览没有活动告警但存在有效指标或其他授权运行事实时，必须返回正常分析态和对应证据，不得把整页降为空数据；只有授权窗口内所有分析事实均为空时才返回空态。
- 分析总览采用“运行正常、指标待验、告警影响、证据不足”四态合同。后端必须同时返回展示状态、影响等级和建议等级，前端不得根据列表是否为空自行推断状态。
- 运行正常时影响范围显示“未发现已确认影响”，处理建议显示“当前无需处置”，并保留持续观察说明；指标待验时显示“待验证影响”和“人工核查”；存在活动告警时显示“已确认影响”或“待验证影响”以及“优先处理”；核心事实为空、过期、失败或不足以判断时显示“无法判断”和“补充证据”。
- 影响范围或处理建议没有明细时仍须返回语义化摘要，不能统一使用“暂无影响范围”“暂无处理建议”或“暂无数据”；不得为填满页面生成没有证据支持的影响对象或处置任务。
- 回答必须返回实际查询时间、授权范围、数据状态、结论、证据、限制和工具轨迹摘要；证据不足、过期或查询失败时明确说明无法判断。
- 分析计划以 LLM Structured Output 为主路径，允许理解“抖了一下”“稳不稳”“发布之后”等非固定表达；结构化计划只约束执行合同，不以关键词分支承担完整语义识别。模型规划失败时使用有限规则降级并明确标记，不得静默伪装成完整 Agent 分析。

边界要求：智能分析不能替代规则引擎，不能仅凭自然语言答案产生告警，不能导入其他 Agent 私有 Prompt、Runtime 或模型实例，也不能自动修改业务配置。自主监控 Agent 可以引用自主评测智能体产生的结构化评测数据，但分析对话和对话历史不归自主评测智能体负责。

#### 2.3.8 告警通知

告警通知是告警中心内的通知视图，负责根据告警生命周期和通知策略向具备权限的接收人发送通知。

核心功能：

- 在告警中心内配置站内通知和 Webhook 等通知渠道。
- 按严重级别、租户、监控域和规则配置接收范围。
- 支持告警触发、持续、恢复和通知失败通知。
- 支持重复通知抑制、升级通知和静默时间段。
- 记录通知状态、失败原因和重试结果。
- 渠道配置和通知策略分别提供快速查找与简单分页，保证配置数量增加后仍能快速定位；发送记录继续提供完整查询和分页。

边界要求：普通 Worker 空轮询和无任务空闲状态不得发送业务告警通知；通知失败不能删除系统内的告警实例。告警通知不单独作为自主监控一级子模块。

#### 2.3.9 审计管理

审计管理负责记录监控查询、告警处理、规则变更、采集配置变更和权限操作，保证监控结论和管理动作可追溯。

核心功能：

- 记录操作者、角色、租户范围、操作时间、请求结果和 Trace ID。
- 记录告警确认、关闭、抑制、备注和恢复处理。
- 记录规则变更、系统采集配置发布版本和前后差异；系统采集配置不提供业务用户操作入口。
- 支持按操作者、对象、操作类型、时间和结果查询审计记录。

边界要求：审计日志不得记录密码、Token、API Key、完整问题、完整答案和完整文档内容。

##### 审计管理

| 子模块 | 主要职责 | 核心内容 |
| --- | --- | --- |
| 查询审计 | 记录监控数据查询行为 | 操作者、范围、条件、时间、结果和 Trace ID |
| 告警审计 | 记录告警状态变化 | 确认、关闭、抑制、备注、处理人和操作原因 |
| 规则审计 | 记录告警规则变更 | 新增、修改、启停、版本和前后差异 |
| 配置审计 | 记录系统采集配置发布和规则配置变更 | `target_code`、Collector、字段映射、版本、发布来源和操作者 |

### 2.4 协同关系

| 协同对象 | 核心职责 | 向监控提供的结构化结果 | 不负责的内容 |
| --- | --- | --- | --- |
| 文档处理与索引链路 | 解析文档、抽取内容、切分、入库和建立索引 | 文档处理状态、索引状态、知识内容版本、处理错误和耗时 | 不负责 Agent 编排、评测结论和平台告警 |
| 知识库问答智能体 | 在授权范围内检索知识库、生成回答和返回引用 | 问答阶段事件、耗时、命中数、引用数、降级状态、错误分类和版本信息 | 不负责平台健康判断、告警和自动处置 |
| 自主评测智能体 | 生成或加载问题、调用问答能力、执行评测、计算指标和生成报告 | 评测运行状态、阶段事件、逐题结果、指标、门禁结论和报告 | 不负责持续监控平台和其他任务 |
| 自主监控智能体 | 采集、关联、分析运行数据，识别异常，生成告警、处理建议和分析对话 | 健康状态、异常事件、告警实例、影响范围、证据链、建议和分析会话结果 | 不直接修改文档、评测配置、模型或业务数据 |

多智能体协同链路如下：

```text
文档处理与索引链路 ──文档/索引状态、处理事件──┐
知识库问答智能体 ──问答遥测、运行结果──────┤
自主评测智能体   ──评测事件、指标、报告────┘
                                      ├─> 自主监控智能体 ──健康状态/告警/建议──> 管理员
自主评测智能体   ──按公开协议调用────────> 知识库问答智能体
```

自主监控智能体必须能够把多个来源的事件关联成一个故障上下文。例如：文档索引失败导致问答引用率下降，自主评测门禁不通过；监控智能体应把它们关联为同一影响链路，而不是创建三个互不相关的告警。文档处理与索引链路只提供处理和索引事件，不作为独立 Agent 参与调用。

### 2.4.1 问答协同

备注：本节说明自主监控模块与知识库问答智能体之间的遥测、探针和数据边界。

知识库问答智能体是自主监控的核心业务观测对象，但两者不能形成运行时强依赖。知识库问答智能体负责回答用户问题、执行授权范围内的检索和生成引用；自主监控智能体负责观察问答运行事实、判断问答链路健康状态和生成告警。

知识库问答智能体应通过公开的结构化遥测协议向自主监控提供以下信息：

- 请求开始、检索完成、模型调用、回答完成、降级、失败和超时等阶段事件。
- `trace_id`、`run_id`、租户、知识库、索引版本、模型版本和配置版本。
- 总耗时、检索耗时、模型耗时、命中数量、引用数量、终止原因和错误分类。
- 权限拒绝、知识库无资料、检索失败、模型失败和降级回答等可识别状态。

遥测数据只提供运行事实和脱敏摘要。默认不得向自主监控传递完整用户问题、完整回答、文档片段、Token 或其他敏感上下文；确需查看时必须按照操作者权限从业务数据中单独加载。

自主监控可以在发现问答错误率、响应耗时、引用率或降级率异常时，按需调用知识库问答智能体的公开结构化协议执行受控监控探针。监控探针必须满足：

1. 使用专用监控租户、专用知识库和固定测试问题，不使用真实用户问题。
2. 使用 `purpose=monitor_probe` 等明确标识，不计入普通业务问答、租户用量或自主评测统计。
3. 不创建用户会话，不写入普通聊天历史，只允许只读检索和回答。
4. 具有独立的超时、频率、并发和调用预算，避免监控制造业务压力。
5. 默认只保留成功状态、耗时、命中数、引用数和错误分类，不持久化完整问题、答案和文档片段。
6. 探针失败只说明探针范围内的链路异常，不能直接推断全部租户问答均不可用。

自主监控不得导入知识库问答智能体的私有 Prompt、私有函数、模型实例、Runtime 或内部状态，也不得因为问答异常自动修改 Prompt、模型、Rerank、索引或知识库配置。问答智能体不能反向调用自主监控智能体判断自身是否健康。

### 2.4.2 评测协同

备注：本节说明自主监控模块与自主评测智能体之间的执行证据、环境快照和结果可信度关系。

自主评测智能体既是自主监控的观测对象，也是问答质量的主动业务探针。自主评测智能体负责组织问题、调用知识库问答智能体、计算指标和生成评测报告；自主监控智能体负责观察评测是否按预期执行、判断执行环境是否稳定、关联评测结果与平台异常，不改写评测质量结论。

自主评测智能体应向自主监控提供完整的结构化执行证据：

- 任务创建、排队、领取、启动、暂停、取消和结束。
- 配置校验、问题加载或生成、逐题执行、重试、指标计算、报告生成和持久化。
- 每题开始、完成、失败、超时以及知识库问答智能体调用失败。
- 评测使用的知识库、索引版本、问答智能体版本、配置版本和评测规则版本。
- 总题数、完成数、失败数、处理速率、重试次数、排队时长和执行耗时。
- 评测门禁结论及不通过的指标项。
- Worker、Runtime、LangGraph 和知识库问答智能体是否实际执行的证明事件。

自主监控必须区分“评测质量结论”和“评测运行可信度”：

| 情况 | 评测结论 | 监控判断 |
| --- | --- | --- |
| 问答质量不达标且基础设施正常 | 不通过 | 质量问题 |
| 大量问答调用超时或失败 | 不通过或执行失败 | 基础设施异常，结果可能不可比 |
| 评测期间索引版本变化 | 可能不通过 | 评测环境不稳定 |
| Worker 中途停止或事件链断裂 | 未完成或失败 | 评测执行链路异常 |
| 评测完成且执行证据完整 | 通过或不通过 | 结果具备正常执行证据 |

评测运行结果应能够表达以下不同原因：

- `quality_failed`：评测完成，但质量门禁不通过。
- `execution_failed`：评测执行链路失败。
- `environment_degraded`：模型、向量库、数据库等基础设施异常影响结果。
- `inconclusive`：完成度或有效样本不足，不能据此判断质量。

自主评测结果可以作为问答质量监控信号，用于发现 API 返回正常但引用率下降、答案质量回归、某知识库质量下降或索引版本异常等问题。自主监控可以读取评测结果并生成质量告警，但不得自行创建评测任务、自动调整评测配置或自动重跑评测；是否补跑、切换版本或调整配置必须由管理员或另行确认的调度策略决定。

自主评测在开始时可以读取一次自主监控提供的环境快照，用于记录 API、Worker、模型、向量库和数据库状态以及当时未恢复的基础设施告警。该快照属于弱依赖：监控接口暂时不可用时，评测不能因此被阻断；环境快照也不能替代评测指标，更不能直接决定评测通过。

### 2.4.3 交互边界

备注：本节说明问答智能体、评测智能体和监控模块之间的调用方向、协议边界和禁止循环。

三者之间推荐采用“结构化遥测上行、受控探针下行、结果上下文标注”的关系：

```text
知识库问答智能体 ──问答运行遥测────────────┐
自主评测智能体   ──评测执行证据/质量结果────┼─> 自主监控智能体 ──告警/建议──> 管理员
文档处理与索引链路 ──文档/索引处理事件──────┘

自主监控智能体 ──受控问答探针────────────> 知识库问答智能体
自主监控智能体 ──环境快照/异常标记────────> 自主评测报告上下文
自主评测智能体 ──公开协议调用────────────> 知识库问答智能体
```

必须禁止以下循环和隐式控制：

- 自主评测等待自主监控确认健康，自主监控又等待评测产出结果。
- 自主监控发现评测异常后自动重试评测，重试产生的新异常再次触发监控。
- 自主监控把真实用户问题和完整答案交给另一个模型直接判断系统健康。
- 自主监控用自然语言答案替代结构化指标和事件作为健康依据。
- 监控探针复用普通用户会话，或让探针结果触发业务告警、租户用量和评测统计。

问答智能体、评测智能体和监控智能体必须分别保留独立的入口、Runtime、Policies、工具注册表和运行预算。跨 Agent 调用只能使用公开结构化协议，不得导入私有 Prompt、私有方法、模型实例或内部状态。

### 2.5 工作流程

自主监控智能体通过“观测—分析—判断—记录—告警—跟踪恢复”的闭环工作：

1. 从健康检查、指标、任务状态、Agent 事件和结构化日志中获取观测数据。
2. 对不同时间窗口、资源范围和事件来源进行关联，建立异常上下文。
3. 根据监控规则、历史基线和证据判断健康、异常、数据不足或无法判断。
4. 生成结构化监控结论，记录判断依据、置信度、影响范围和关联资源。
5. 满足告警条件时创建或更新告警实例；不满足时继续观察，不产生告警。
6. 监控异常是否恢复，并更新告警生命周期。
7. 对需要人工处理的异常给出建议，但未经明确授权不得执行删除、修改、重试或发布操作。

智能体的结论必须可追溯到具体指标、事件、任务或日志证据。不能只输出“系统异常”或“建议检查服务”这类无法验证的自然语言结论。

### 2.6 告警机制

自主监控的告警数据由业务运行事实经过采集、标准化、聚合和规则判断形成，不能由监控智能体仅根据自然语言推测。整体链路如下：

```text
问答智能体 / 评测智能体 / 文档处理链路 / API / Worker
                  │
        结构化事件、状态快照、指标、健康探针
                  ↓
            监控采集与标准化
                  ↓
              去重、聚合、校验
                  ↓
              监控规则判断
                  ↓
                告警实例
                  ↓
       监控智能体关联分析和生成建议
                  ↓
             告警展示、通知、审计
```

#### 2.6.1 数据来源

监控数据至少来自四类来源：

1. **业务事件**：由问答智能体、评测智能体、文档处理与索引链路、API 和 Worker 在关键状态变化时主动上报。
2. **状态快照**：由采集器周期性读取 API、数据库、Worker、任务表、模型、向量库、存储和队列的当前状态。
3. **聚合指标**：将事件按租户、知识库、任务类型、资源和时间窗口聚合，形成请求量、错误率、P95、积压量、引用率和评测完成率等指标。
4. **主动探针**：在被动数据不足或需要验证链路时，由监控调度器触发专用健康检查或受控问答探针。

业务事件适合还原异常过程，状态快照适合判断当前状态，聚合指标用于规则判断，主动探针用于验证真实业务链路。采集器不得只依赖单一来源判断健康。

#### 2.6.2 事件协议

事件至少包含以下字段：

| 字段 | 说明 |
| --- | --- | --- |
| `event_id` | 事件唯一 ID，重复上报不得重复计数 |
| `event_type` | 事件类型，例如问答完成、评测阶段切换、索引失败、Worker 心跳 |
| `source_type` | 来源类型，例如 API、Worker、knowledge_agent、evaluation_agent 或 document_index |
| `source_id` | 来源实例或业务资源 ID |
| `tenant_id` | 数据所属租户；平台级事件可为空，但必须标记范围 |
| `kb_id` | 关联知识库 ID，无关联时为空 |
| `run_id` / `task_id` | 关联 Agent 运行或异步任务 |
| `trace_id` | 关联调用链，允许跳转日志上下文 |
| `status` | 事件对应状态 |
| `occurred_at` | 事件发生时间，统一使用 UTC 存储 |
| `duration_ms` | 阶段或任务耗时，无耗时时为空 |
| `error_code` | 脱敏后的错误分类，无错误时为空 |
| `version_context` | 索引、模型、Prompt 或配置版本摘要 |

事件不得记录密码、Token、API Key、完整用户问题、完整答案、文档片段和其他敏感请求体。需要查看敏感业务内容时，必须经过权限校验后从业务数据中单独读取。

#### 2.6.3 指标聚合

备注：本节同时说明状态快照如何进入指标统计，以及无数据、采集失败和数据过期的区别。

状态快照至少覆盖 API、数据库和外部依赖可用状态，Worker 心跳和消费状态，任务状态数量，PostgreSQL 实例连接、进程连接池明细、队列、存储和向量服务容量，以及问答错误率、响应耗时、引用率、降级率和评测执行状态。

指标必须按明确的时间窗口和数据范围聚合。每个统计结果至少包含统计时间、窗口、租户或平台范围、样本量、计算状态和数据更新时间。无样本、采集失败、部分采集、数据过期和样本不足必须分别标记，不得统一显示为 0 或健康。

#### 2.6.4 主动探针

主动探针用于验证 API、模型、向量库和问答链路是否真实可用。问答探针必须使用专用监控租户、专用知识库和固定测试问题，并使用 `purpose=monitor_probe` 标识。

探针不得创建普通用户会话、写入聊天历史、计入业务问答量、租户用量、自主评测统计或质量报表。探针必须具有独立的频率、并发、超时和资源预算；探针失败只能证明探针范围异常，不能直接推断所有租户或所有知识库均不可用。

#### 2.6.5 规则边界

备注：本节说明规则判断与监控智能体分析之间的职责边界。

监控规则负责确定性判断，至少负责触发条件、最小样本数、连续次数、恢复条件、告警去重和告警生命周期。示例：

```text
问答错误率 > 10%
且样本数 >= 30
且连续 3 个统计周期满足
=> 触发严重告警
```

监控智能体负责跨来源关联、影响范围分析、证据链整理、异常摘要和人工处理建议。监控智能体不能替代规则引擎单独决定告警，也不能因为告警自动修改 Prompt、模型、索引、评测配置或业务任务。

#### 2.6.6 证据链路

备注：本节说明告警实例如何关联指标、事件、任务、版本和 Trace ID。

告警实例至少保存：

```text
alert_id
rule_id
severity
scope
resource
first_fired_at
last_fired_at
current_value
threshold
status
evidence_event_ids
resolved_at
acknowledged_by
```

每条告警必须能够关联触发它的指标、事件、任务、评测运行、Worker、索引版本或 Trace ID。相同规则、相同数据范围和相同资源在未恢复前只能保留一个告警实例；重复触发只更新发生次数和最近发生时间。

告警应区分原始事件、统计指标和告警实例：原始事件记录发生了什么，统计指标记录一段时间内发生了多少，告警实例记录规则确认后的异常生命周期。三者不得混为一个自然语言字段。

## 3. 权限角色

### 3.1 超管角色

- 平台超级管理员查看和管理平台整体运行状态、全部租户聚合指标和平台级告警。
- 查看和管理平台级异步任务、Worker、问答链路和自主评测运行状态相关的监控内容。
- 查看告警详情、确认告警、关闭告警、抑制告警、添加备注、维护监控规则和管理告警通知。
- 只有在具备相应数据权限时，才能查看具体租户、知识库、文档或评测问题内容。

### 3.2 租户角色

- 租户管理员只能查看和管理当前租户及其管理范围内的知识库、文档处理、问答和评测监控数据。
- 不能看到其他租户名称、任务数量、用户信息、问题内容或告警详情。
- 可以确认、关闭、抑制和备注当前租户范围内的告警，并按授权维护当前租户的监控规则和告警通知。
- 平台服务、数据库、全局 Worker 等平台级基础设施状态只展示与当前租户有关的摘要，不泄露平台全量数据。

### 3.3 非开放角色

普通角色、组织角色和访客不属于本期自主监控使用范围，默认不能进入自主监控管理页面，也不能通过接口访问监控数据。后续如需开放其他角色，必须单独评审权限范围和页面能力。

### 3.4 操作范围

平台超级管理员和租户管理员都具备自主监控的查看和操作权限，区别在于数据范围和操作范围：

| 操作 | 平台超级管理员 | 租户管理员 |
| --- | --- | --- |
| 查询总览、指标、任务、事件和告警 | 全平台及授权租户 | 当前租户 |
| 查看详情和证据 | 授权范围内 | 当前租户授权范围内 |
| 确认、抑制、关闭和备注告警 | 授权范围内 | 当前租户范围内 |
| 维护告警规则 | 平台规则及授权范围 | 当前租户允许维护的规则 |
| 管理告警通知 | 平台和授权租户 | 当前租户允许管理的渠道与策略 |
| 分析总览和分析对话 | 授权监控范围 | 当前租户监控范围 |
| 数据采集目标配置 | 页面不提供业务配置入口 | 页面不提供业务配置入口 |

所有操作仍须经过 API、Service 和 Repository 的角色、租户、资源和状态校验，并写入审计记录。

## 4. 监控领域

自主监控智能体分为六个观测域。每个观测域都必须区分“健康、告警、故障、无数据、未启用、采集中”状态。

| 监控域 | 关注问题 | 主要数据来源 |
| --- | --- | --- |
| 平台运行 | API、数据库和依赖是否可用 | 健康检查、数据库连接、依赖探针 |
| 异步任务 | 文档、索引、评测是否积压或失败 | 任务表、运行表、Worker 心跳 |
| 知识库问答 | 请求是否成功、变慢、降级或缺少引用 | 问答请求事件、调用结果 |
| 自主评测 | Agent 是否运行、评测是否完成、门禁是否通过 | 评测任务、评测运行、Agent 事件 |
| 资源与容量 | 数据库连接、队列、存储和向量服务是否接近上限 | 运行时指标、依赖指标 |
| 告警与事件 | 异常是否已通知、确认、恢复和关闭 | 监控智能体结论、规则、告警实例、事件记录 |

## 5. 监控首页

### 5.1 页面结构

#### 5.1.1 头部筛选

页面头部必须展示页面名称、当前数据范围、当前时间窗口、数据最后更新时间、整体状态、刷新按钮和数据说明入口。

数据范围包括：

- 平台超级管理员：全平台、指定租户；
- 租户管理员：固定为当前租户，不允许切换到其他租户；
- 普通角色、组织角色和访客：不能进入页面，不能通过前端参数访问监控数据。

时间窗口包括最近 15 分钟、1 小时、6 小时、24 小时和 7 天。切换范围或时间窗口后，状态摘要、告警状态图、资源容量卡片和异常传播链路必须使用同一条件重新查询。

#### 5.1.2 告警区域

未恢复告警位于健康摘要和趋势图表之前。总览只按严重级别聚合展示数量，例如“未恢复告警 5 条：严重 2 条、警告 3 条”，不在首屏平铺告警详情，避免告警数量增长导致页面被撑开。每条告警的标题、监控域、资源、当前值、阈值、首次发生时间、最近发生时间、持续时长和当前状态进入告警中心或详情抽屉展示。

总览重点展示 `firing` 和 `acknowledged` 告警，并按严重、警告、提示等级别统计数量。`resolved` 和 `closed` 告警进入告警中心和异常时间线，不默认占据重点告警区域。无未恢复告警时展示“当前范围暂无未恢复告警”。总览提供查看详情和跳转告警中心入口，告警确认、关闭和备注是否直接开放由告警详情权限决定。

#### 5.1.3 状态摘要

总览健康区域使用紧凑的运行状态摘要，只展示平台与监控自身健康，不展示问答、异步任务和自主评测业务状态，避免与业务状态重复。

运行状态使用服务状态热力图表达。在最近 15 分钟和 1 小时时间窗口内按 5 分钟一个时间格展示服务状态，6 小时按 30 分钟、24 小时按 2 小时、7 天按 12 小时切换粒度；横轴与所选查询窗口的开始、结束时间对齐，纵轴为服务，颜色区分正常、预警、故障和无数据。接口返回带时区的标准时间，前端按用户本地时区格式化；无探针事件的历史时间格必须显示无数据，不得使用当前快照状态回填历史。总览最多展示五项运行状态，后端优先返回故障、预警、数据过期和获取失败等需要关注的服务，同一风险等级再按系统预置服务优先级排序。

| 运行域 | 摘要内容 |
| --- | --- |
| 平台服务 | API、数据库和平台基础服务当前状态及异常摘要 |
| 外部依赖 | 模型、Embedding、Rerank、向量服务等依赖当前状态及异常摘要 |
| 监控采集 | 采集器状态、数据新鲜度和失败来源摘要 |

摘要单元必须使用状态色、更新时间和影响范围标签，支持点击进入对应监控域。每类状态必须区分健康、告警、故障、无数据、未启用、采集中、数据过期和获取失败。运行状态名称由后端按资源编码统一返回，页面名称统一使用四个中文字，前端不得维护资源编码与中文名称的重复映射，也不得直接展示英文资源编码。业务状态由下方业务状态表达，Worker 空闲、心跳过期、停止和任务积压不在运行状态摘要中重复展示。

#### 5.1.4 核心视图

总览只保留三类核心图表，避免不同区域重复展示同一指标：

| 图表 | 展示内容 | 重点判断 |
| --- | --- | --- |
| 告警状态图 | `firing`、`acknowledged`、`resolved`、`closed` 随时间变化 | 当前未恢复告警是否增加、持续或恢复 |
| 资源容量卡片 | 数据库连接、任务队列、文件存储和向量存储当前用量、容量上限、使用率、状态及阈值 | 是否存在资源风险以及风险是否可能影响业务 |
| 异常传播链路 | 任务、问答、评测、Worker 和告警事件的时间关系 | 异常从哪里开始、如何传播、是否恢复 |

问答请求趋势、问答质量、任务状态分布、任务积压趋势、评测阶段和完整 Agent 证据不在总览绘制，统一下沉到指标分析、任务监控和评测运行详情。

#### 5.1.5 业务状态

总览只保留问答、异步任务和自主评测三项当前业务状态：

- 知识库问答：展示当前状态、成功率和 P95 中的一个关键值；Tip 解释问答链路健康、成功率和响应耗时的含义，并提供指标分析入口；
- 异步任务：展示当前状态、待处理数量或最老等待时间中的一个关键值；Tip 解释任务消费能力和积压风险，并提供任务监控入口；
- 自主评测：展示当前状态、运行 ID 或当前阶段中的一个关键值；Tip 解释评测 Agent 是否运行及运行是否可追踪，并提供评测运行入口。

摘要不展示完整趋势、状态分布或阶段明细，避免与下游页面重复。

#### 5.1.6 异常链路

异常区域不得只展示按时间倒序排列的事件文本列表，必须以跨监控域时间线表达异常传播关系。时间轴横向表示发生时间，监控域纵向分泳道，事件使用节点表示，具有关联关系的事件使用连线表示。

至少设置平台运行、异步任务、知识库问答、自主评测和告警五条泳道，展示：

- 服务状态变化、Worker 启停和心跳异常；
- 文档处理、索引构建和评测任务状态变化；
- 问答错误率、P95、引用率等指标异常点；
- 评测阶段变化和评测门禁结论；
- 告警触发、确认、恢复和关闭节点。

异常链路必须能够直观表达“索引失败 → 任务积压 → 问答质量下降 → 响应变慢 → 评测异常 → 告警触发”的影响关系，并标记当前是否恢复。普通空轮询不作为独立事件展示。每个节点至少关联事件 ID、资源、告警、任务、评测运行或 Trace ID 中的一项。

#### 5.1.7 明细下沉

任务状态分布、任务积压趋势、Worker 运行泳道和自主评测阶段明细统一放入任务监控页面。总览只保留异步任务当前状态和一个关键值，并通过入口跳转到任务监控，避免总览同时承担发现异常和完整诊断。

### 5.2 图表规则

- 所有图表数据必须来自统计接口，不得由前端分页任务或事件数据推算全量指标。
- 每个图表必须标注当前范围、统计时间、样本量、数据状态和指标口径。
- 图表标题区可以显示当前值和变化方向，但不得将核心指标拆成孤立数字卡片。
- 图表必须能够同时表达趋势、阈值和告警触发/恢复时间，避免只展示单个时点数值。
- 当前无样本时显示“当前时间窗口内暂无数据”，不得显示为 0 并标记正常。
- 数据部分失败时保留可用数据并标记 `partial`；数据过期时保留最后成功数据并标记 `stale`；统计失败时显示 `error`。
- 租户管理员不显示平台级活跃租户、全平台任务等与其管理范围无关的指标。
- 未恢复告警必须位于健康摘要和业务图表之前，不能被图表或指标摘要推到页面下方。
- 图表标题、图例、坐标含义、统计时间和数据状态必须清晰可读；详情抽屉使用白底深色文字，不得继承左侧菜单的浅色文字样式。

### 5.3 状态与交互

- 全部健康：显示当前范围运行正常；没有自主评测任务时显示“Worker 空闲，暂无待处理评测”。
- Worker 忙碌：显示当前任务、运行阶段、运行时长和最近心跳。
- 任务积压：显示待处理数量、最老等待时间和关联 Worker，不把积压隐藏在普通任务数量中。
- 指标无样本：显示“当前时间窗口内暂无数据”，不得显示为 0 并标记健康。
- 指标采集失败：显示失败来源、最后成功时间和重试入口，不使用本地数据兜底。
- 数据过期：保留最后一次成功数据，同时标记数据已过期和更新时间。
- 租户无权查看平台指标：显示“无权限查看”，不得展示平台级数量或资源名称。
- 刷新失败：保留最后一次成功数据，标记数据状态为过期或失败。
- 点击告警、指标、任务、Worker 或事件时，跳转对应页面并保留当前范围、时间窗口和上下文。
- 总览不提供业务任务重试、暂停、终止、删除或配置修改操作。
- 总览必须保持高内聚，只保留告警状态、资源容量和异常传播三类核心视图；问答、任务和评测趋势不得在总览重复绘制。

摘要字段规则：

| 摘要项 | 当前值展示 | Tip 主要说明 | 详情入口 |
| --- | --- | --- |
| 知识库问答 | 当前状态、成功率和 P95 中的一个关键值 | 说明问答链路是否正常、成功率和 P95 的业务含义 | 指标分析 |
| 异步任务 | 当前状态、待处理数量和最老等待中的一个关键值 | 说明任务是否持续消费、最老等待是否反映长期积压 | 任务监控 |
| 自主评测 | 当前状态、运行 ID 和当前阶段中的一个关键值 | 说明评测 Agent 是否运行以及运行是否可追踪 | 任务监控/评测详情 |
| 资源依赖图 | 当前资源使用率或可用状态 | 说明资源使用率、阈值和数据新鲜度 | 采集详情 |

## 6. 指标体系

指标必须同时定义中文指标名称和稳定的指标编码。中文名称用于页面、报表和告警通知，指标编码用于接口、数据库、规则配置和程序计算。统计接口至少返回：指标编码、指标名称、统计范围、统计窗口、样本数、指标值、单位、数据状态、考核状态和生成时间。

统一考核规则：

| 规则 | 说明 |
| --- | --- |
| 有效样本 | 已通过认证、租户和参数校验，并进入对应业务链路的请求、任务或运行；登录、刷新令牌、租户切换和监控探针不计入问答业务指标 |
| 成功样本 | 业务正常完成且未发生超时、失败或降级的样本 |
| 统计窗口 | 支持 15 分钟、1 小时、6 小时、24 小时和 7 天，趋势数据按固定时间桶聚合 |
| 百分位耗时 | 只使用已完成且有耗时的样本计算 P50、P95、P99；样本不足时不得用平均值替代 |
| 最小样本 | 比例指标必须配置最小样本数，未达到时考核状态为“无法判定”，不得触发高严重级别告警 |
| 数据状态 | `ready` 完整、`partial` 部分来源失败、`empty` 无样本、`stale` 数据过期、`error` 计算失败 |
| 考核状态 | `达标`、`预警`、`不达标`、`无法判定`；无样本、样本不足、采集失败和数据过期不能判定为达标 |

比例类指标统一按“分子 / 分母”计算，并在结果中返回分子、分母和排除项。例如：问答成功率 = 正常完成数 / 有效请求数；任务成功率 = completed /（completed + failed + timeout），取消任务不计入分母；引用返回率 = 引用数大于 0 的完成请求数 / 完成请求数。

### 6.1 平台指标

- API 健康检查成功率。
- API 请求量、4xx 数量、5xx 数量。
- API 平均响应时间、P95、P99 响应时间。
- 数据库连接状态、连接池使用率、连接等待数和慢 SQL 数量。
- 外部模型、Embedding、Rerank、向量库等依赖的可用率和错误率。
- 服务启动时间、最近心跳时间和当前实例状态。

| 指标名称 | 指标编码 | 统计口径 | 考核方式 |
| --- | --- | --- | --- |
| 接口可用率 | `platform_api_availability` | 探测成功次数 / 有效探测次数 | 目标 99.9%；低于 99.5% 预警，低于 99% 严重；连续 3 个周期触发 |
| 服务端错误率 | `platform_http_5xx_rate` | 5xx 数量 / 有效 API 请求量 | 样本不少于 100 时，超过 1% 预警、超过 5% 严重 |
| 接口 P95 耗时 | `platform_api_latency_p95` | 完成请求耗时的 95 分位 | 按接口目标考核；连续 3 个周期超标预警 |
| 接口 P99 耗时 | `platform_api_latency_p99` | 完成请求耗时的 99 分位 | 用于极慢请求考核；连续 3 个周期超过严重阈值告警 |
| 数据库连接池使用率 | `platform_db_pool_usage_rate` | 已用连接数 / 连接池最大连接数 | 超过 80% 预警，超过 95% 严重 |
| 数据库等待数 | `platform_db_waiting_total` | 等待连接或执行的请求数 | 连续 3 个周期大于 0 预警，持续增长升级严重 |
| 慢查询数量 | `platform_db_slow_query_total` | 超过慢查询阈值的 SQL 执行次数 | 按 SQL 指纹统计，数量突增预警 |
| 依赖可用率 | `platform_dependency_availability` | 依赖探测成功次数 / 探测次数 | 低于 99% 预警，连续失败达到规则次数严重 |
| 服务心跳状态 | `platform_service_heartbeat` | 当前时间 - 最近心跳时间 | 超过心跳阈值为 `stale`；无数据为 `unknown`，不得显示健康 |

### 6.2 任务指标

按任务类型分别统计：

- pending、running、completed、failed、cancelled、timeout 数量。
- 当前积压量和积压时长。
- 任务成功率和失败率。
- 任务平均耗时、P95 耗时和最长耗时。
- 最近一次成功完成时间。
- 最近一次失败时间和失败原因分类。
- 重试次数、重试后成功率和达到最大重试次数的数量。
- Worker 最近心跳、消费速率和空闲状态。

任务类型至少包括：文档入库、索引构建、自主评测运行。后续新增异步任务必须复用统一任务监控协议。

| 指标名称 | 指标编码 | 统计口径 | 考核方式 |
| --- | --- | --- | --- |
| 待处理任务数 | `task_backlog_total` | `pending + queued` 任务数量 | 超过任务类型阈值预警，持续增长或超过严重阈值严重 |
| 最老等待时长 | `task_oldest_wait_seconds` | 当前时间 - 最早待处理任务创建时间 | 超过任务 SLA 预警，超过 2 倍 SLA 严重 |
| 任务成功率 | `task_success_rate` | completed /（completed + failed + timeout） | 样本不少于 20；低于 99% 预警，低于 95% 严重 |
| 任务失败率 | `task_failure_rate` | failed / 终态任务数 | 按失败分类统计，连续失败达到次数告警 |
| 任务 P95 耗时 | `task_duration_p95` | 已完成任务执行耗时的 95 分位 | 按任务类型配置目标，连续 3 个周期超标预警 |
| 重试后成功率 | `task_retry_success_rate` | 重试后成功任务数 / 发生重试任务数 | 低于 90% 预警；达到最大重试次数的任务单独告警 |
| Worker 消费速率 | `worker_consume_rate` | 窗口内完成任务数 / 窗口时长 | 与积压量联合考核，速率下降且积压增长时告警 |
| Worker 心跳状态 | `worker_heartbeat_status` | 最近心跳时间与当前时间的差值 | `running`、`busy`、`idle` 正常；`stale`、`stopped`、`error` 异常 |

### 6.3 问答指标

- 请求总量和有效请求量。
- 成功率、错误率、超时率和主动取消率。
- 降级率，包括无引用回答、备用回答和服务降级。
- 引用返回率、引用为空率和引用数量分布。
- 首字节耗时、完整响应耗时、P50/P95/P99。
- 按知识库、租户、接口、模型版本和时间窗口聚合。
- Top 错误码、Top 超时接口和 Top 慢知识库。
- 连续失败请求、连续超时请求和短时间异常增长。

登录、刷新令牌、选择租户等非业务操作不计入问答业务指标，也不应作为问答异常事件。

| 指标名称 | 指标编码 | 统计口径 | 考核方式 |
| --- | --- | --- | --- |
| 问答请求量 | `qa_request_total` | 窗口内有效问答请求数 | 按租户、知识库、接口、模型版本和时间桶统计，不单独判故障 |
| 问答成功率 | `qa_success_rate` | 正常完成请求数 / 有效请求数 | 样本不少于 100；目标 99%，低于 98% 预警、低于 95% 严重 |
| 问答错误率 | `qa_error_rate` | failed 请求数 / 有效请求数 | 超过 1% 预警、超过 5% 严重，按错误分类展示 |
| 问答超时率 | `qa_timeout_rate` | timeout 请求数 / 有效请求数 | 超过 0.5% 预警、超过 2% 严重 |
| 问答降级率 | `qa_degraded_rate` | 降级完成请求数 / 有效请求数 | 超过 2% 预警、超过 5% 严重，记录降级原因 |
| 引用返回率 | `qa_citation_return_rate` | 引用数大于 0 的完成请求数 / 完成请求数 | 按知识库目标考核，低于目标 10 个百分点预警 |
| 引用为空率 | `qa_citation_empty_rate` | 完成但引用数为 0 的请求数 / 完成请求数 | 持续升高时按知识库和索引版本触发检索质量告警 |
| 首字节 P95 耗时 | `qa_ttft_p95` | 首个模型输出到达耗时的 95 分位 | 超过模型或接口目标连续 3 个周期预警 |
| 完整响应 P95 耗时 | `qa_duration_p95` | 请求开始至响应完成耗时的 95 分位 | 按接口目标考核，连续 3 个周期超标预警 |
| 连续异常次数 | `qa_consecutive_abnormal` | 同一租户、知识库、接口连续失败或超时次数 | 达到 3 次预警，达到 5 次严重 |
| 请求突增率 | `qa_request_growth_rate` | 当前窗口请求量 / 历史基线请求量 - 1 | 超过基线 200% 且达到最小样本数时预警 |

### 6.4 评测指标

- 评测任务总数、启用任务数、待运行任务数、运行中任务数。
- 评测运行成功率、失败率、超时率和取消数。
- 评测排队时长、执行时长和端到端耗时。
- 评测问题数、已完成数、失败数和处理速率。
- Agent 执行开始、阶段切换、每题执行、指标计算、报告生成和持久化事件数量。
- 评测门禁通过率和不通过的指标项。
- 自主生成问题失败率、知识库上下文加载失败率和 Agent 调用失败率。
- 当前 Worker 是否运行、最近轮询时间、最近领取任务时间和最近完成时间。
- 空轮询次数只能作为 Worker 活跃度辅助指标，不得单独产生故障告警。

| 指标名称 | 指标编码 | 统计口径 | 考核方式 |
| --- | --- | --- | --- |
| 评测运行成功率 | `evaluation_run_success_rate` | completed /（completed + failed + timeout） | 目标 95%；低于 90% 预警、低于 80% 严重；取消不计入分母 |
| 评测排队 P95 时长 | `evaluation_queue_duration_p95` | 领取时间 - 创建时间的 95 分位 | 超过调度 SLA 预警，持续积压升级严重 |
| 评测执行 P95 时长 | `evaluation_execution_duration_p95` | 运行开始至运行结束的 95 分位 | 按题量分层配置目标，连续 3 个周期超标预警 |
| 问题完成率 | `evaluation_case_completion_rate` | completed 问题数 / 应执行问题数 | 目标 98%；低于 95% 预警，低于 90% 严重 |
| Agent 证据完整率 | `evaluation_agent_evidence_rate` | 含必需生命周期事件的运行数 / 已结束运行数 | 目标 100%；低于 100% 不达标并告警 |
| 评测门禁通过率 | `evaluation_gate_pass_rate` | 通过质量门禁的运行数 / 有效完成运行数 | 按质量阈值判断；不通过属于质量问题，不等同基础设施故障 |
| 问题生成失败率 | `evaluation_question_generation_failure_rate` | 生成失败任务数 / 使用自主生成任务数 | 超过 5% 预警，超过 10% 严重 |
| 上下文加载失败率 | `evaluation_context_failure_rate` | 上下文加载失败题数 / 已开始执行题数 | 超过 2% 预警，按知识库和索引版本定位 |
| Agent 调用失败率 | `evaluation_agent_failure_rate` | Agent 调用失败题数 / Agent 调用题数 | 超过 2% 预警，超过 5% 严重 |
| Worker 领取延迟 | `evaluation_worker_claim_latency` | 领取时间 - 任务可执行时间 | 超过调度 SLA 预警；无领取事件不能推断已执行 |
| 空轮询次数 | `evaluation_worker_empty_poll_total` | 未领取任务的轮询次数 | 仅作活跃度辅助指标，不单独产生故障告警 |

### 6.5 资源指标

- 数据库连接池使用率、等待时间和连接耗尽次数。
- 队列或任务表积压量。
- 单租户任务量、单知识库文档量和索引数据量。
- 文件存储使用量、向量数据量和增长趋势。
- 单次评测问题数量、并发数、上下文大小和模型调用量。
- 超过配置上限的请求、任务和数据量。

资源指标必须明确采集来源和采集失败状态。采集不到不能直接显示为“正常”。

| 指标名称 | 指标编码 | 统计口径 | 考核方式 |
| --- | --- | --- | --- |
| 文件存储使用率 | `resource_file_storage_usage_rate` | 已用空间 / 配额空间 | 超过 80% 预警，超过 90% 严重 |
| 向量存储使用率 | `resource_vector_storage_usage_rate` | 向量已用空间 / 配额空间 | 超过 80% 预警，超过 90% 严重 |
| 文档数量 | `resource_document_total` | 租户或知识库有效文档数 | 超过业务配额时阻止继续入库并告警 |
| 索引数据量 | `resource_index_size_bytes` | 知识库索引占用空间 | 异常突增需关联索引任务和索引版本 |
| 评测并发数 | `resource_evaluation_concurrency` | 同时运行的评测任务或问题数 | 超过租户或平台配额时限制调度并告警 |
| 模型调用量 | `resource_model_call_total` | 问答或评测产生的模型调用次数 | 按租户、任务和模型版本统计，超过配额预警 |
| 上下文 P95 大小 | `resource_context_token_p95` | 单次模型调用上下文 token 数的 95 分位 | 接近模型上限预警，超限必须记录失败分类 |
| 资源超限次数 | `resource_limit_exceeded_total` | 请求、任务、数据量或并发超过限制的次数 | 记录资源类型和限制值，连续发生触发告警 |

## 7. 任务监测

### 7.1 工作状态

Worker 状态至少包括：

- `running`：进程运行且最近心跳正常。
- `idle`：进程运行、没有待处理任务。
- `busy`：正在处理任务。
- `stale`：超过心跳阈值没有更新。
- `stopped`：明确停止或进程不存在。
- `error`：最近一次执行出现未恢复错误。
- `unknown`：监控数据缺失或采集失败。

“idle”是健康状态，不得展示成异常。当前没有自主评测任务时，页面应显示“Worker 空闲，暂无待处理评测”，而不是显示告警。

### 7.2 执行证明

为了证明自主评测确实由 Agent 执行，至少记录以下结构化事件：

1. Worker 领取评测运行。
2. 评测运行进入 `running`。
3. 配置校验完成。
4. 问题加载或自主生成完成。
5. Agent 开始执行。
6. 每个问题开始、重试、完成或失败。
7. 指标计算完成。
8. 报告生成完成。
9. 结果持久化完成。
10. 评测运行进入 `completed`、`failed`、`timeout` 或 `cancelled`。

每个事件至少包含 `event_id`、`run_id`、`task_id`、`event_type`、`stage`、`status`、`occurred_at`、`duration_ms`、`trace_id` 和脱敏上下文。问题内容、答案内容和文档内容不能直接写入普通运行日志；需要查看时按权限从业务数据中加载。

### 7.3 空闲规则

Worker 可以按固定间隔查询是否有待处理任务，但空轮询不属于业务事件：

- 空轮询不得按 `INFO` 级别持续打印。
- 默认只记录轮询次数、最近轮询时间等聚合指标。
- 单次空轮询日志使用 `DEBUG`，或者仅在连续空轮询达到采样条件时记录一条摘要。
- 有任务领取、Worker 状态变化、轮询异常时使用 `INFO` 或 `ERROR`。
- “没有任务”不能触发告警。

## 8. 告警设计

### 8.1 严重级别

| 级别 | 含义 | 默认处理时限 |
| --- | --- | --- |
| 紧急 | 核心服务不可用、数据安全风险或大范围业务中断 | 立即处理 |
| 严重 | 核心链路持续失败、任务大量积压或 Worker 停止 | 30 分钟内 |
| 警告 | 性能下降、失败率升高、容量接近阈值 | 4 小时内 |
| 提示 | 配置变更、短时波动、评测门禁不通过等需要关注的事件 | 工作日处理 |

### 8.2 默认规则

默认规则必须支持启用、停用、阈值调整、时间窗口和连续次数配置。建议规则包括：

| 规则 | 触发条件示例 | 恢复条件 |
| --- | --- | --- |
| API 不可用 | 连续 3 个探测周期失败 | 连续 2 个周期成功 |
| 5xx 异常升高 | 5 分钟错误率超过阈值且样本数达到最小值 | 错误率恢复 |
| 问答响应变慢 | P95 连续 3 个周期超过阈值 | P95 恢复 |
| Worker 心跳过期 | 超过心跳阈值无心跳 | 收到有效心跳 |
| 任务积压 | pending 数量或最老任务等待时间超过阈值 | 积压恢复 |
| 任务连续失败 | 同类任务连续失败达到次数 | 出现成功任务 |
| 评测运行超时 | 单次运行超过配置时限 | 运行结束或人工关闭 |
| 评测门禁不通过 | 评测完成但总体结论为不通过 | 新一轮评测通过或人工关闭 |
| 数据库连接池紧张 | 使用率或等待时间超过阈值 | 连接恢复 |
| 依赖服务异常 | 模型、向量库等依赖连续失败 | 依赖恢复 |

告警规则必须具有最小样本数，避免低流量场景下一个请求失败就产生高严重级别告警。

### 8.3 告警周期

```text
正常 -> 触发中(firing) -> 已确认(acknowledged) -> 已恢复(resolved)
                         \-> 已关闭(closed)
```

- `firing`：满足触发条件，尚未处理。
- `acknowledged`：管理员确认已知晓，但问题尚未恢复。
- `resolved`：指标恢复到恢复条件，系统自动结束告警。
- `closed`：管理员确认无需继续处理或已完成处置。
- 同一规则、同一数据范围和同一资源在未恢复前只能保留一个告警实例。
- 告警重复触发时更新次数和最后发生时间，不重复创建无限记录。

### 8.4 告警触发

告警由指标规则引擎触发，不由自主监控 Agent 直接决定。规则引擎读取指标结果、状态快照和事件聚合结果，按规则版本、统计窗口、最小样本数、连续周期和恢复条件进行确定性判断。

```text
事件 / 状态快照
      ↓
指标聚合
      ↓
规则引擎判断
      ├─ 满足触发条件 → 创建或更新 firing 告警
      ├─ 未满足恢复条件 → 保持当前告警状态
      └─ 满足恢复条件 → 更新为 resolved 并记录恢复证据
```

触发类型包括阈值告警、连续周期告警、无数据或数据过期告警、任务超时告警和多条件组合告警。单次低流量失败、没有任务和 Worker 空闲不得直接触发业务告警。

自主监控 Agent 只读取已经触发的告警及其证据，负责跨来源关联、影响分析、异常解释、分析总览和分析对话；Agent 分析失败不能改变规则引擎已经生成的告警结果。

## 9. 告警页面

### 9.1 告警列表

查询条件至少包括：告警级别、告警状态、监控领域、规则名称、资源类型、资源名称、租户范围、发生时间和恢复时间。

表格字段至少包括：告警级别、告警标题、监控领域、资源名称、当前数值、告警阈值、首次发生、最近发生、持续时长、告警状态、确认人员和操作入口。

列表必须提供分页，时间字段统一使用公共时间格式，超长内容单行省略并提供 Tooltip。

### 9.2 告警详情

详情包括：

- 告警规则和触发表达式。
- 当前值、阈值、统计窗口和样本量。
- 影响范围和数据权限说明。
- 指标趋势图和触发前后的对比。
- 关联任务、评测运行、Worker、知识库和 Trace ID。
- 事件时间线。
- 确认、关闭、添加处理备注和跳转日志操作。

告警详情抽屉及其他监控详情抽屉必须使用高对比度文字，标题、字段名、字段值、结构化摘要和操作按钮均应清晰可读；抽屉不能继承左侧导航的浅色文字样式。

### 9.3 事件列表

事件用于记录状态变化，不等同于告警。事件至少包括服务启动、Worker 启停、任务状态变化、评测阶段变化、配置变更、告警触发和告警恢复。

事件支持按时间、事件类型、资源、租户和操作者查询。普通的空轮询不作为独立事件展示。

## 10. 统计口径

### 10.1 时间窗口

- 实时状态：展示最近一次有效采集结果。
- 趋势指标：按 1 分钟、5 分钟或 1 小时桶聚合，具体粒度根据时间范围自动选择。
- 告警判断：使用规则配置的滚动窗口。
- 所有时间统一使用 UTC 存储，页面按用户时区展示。

### 10.2 数据状态

每个指标返回以下状态之一：

- `ready`：数据完整，可正常展示。
- `partial`：部分采集失败，展示数据并标注不完整。
- `empty`：时间窗口内没有样本，显示暂无数据。
- `stale`：数据超过有效期，显示数据已过期。
- `error`：采集或统计失败，显示获取失败。

### 10.3 数据幂等

- 指标事件必须有唯一事件 ID，重复上报不得重复计数。
- 任务状态变化按任务 ID、版本和状态时间排序。
- 告警实例按规则、范围和资源维度去重。
- Worker 重启不能制造虚假的任务完成或评测完成事件。

所有列表接口必须有查询条件和分页。自主监控各列表的表格列名和查询条件字段统一使用四字名称；语义不足四字时补充“名称、状态、结果、入口、范围”等限定词，不使用单字或两字字段。页面查询栏统一采用管理后台列表风格：字段使用左侧标签和标准输入控件，查询、重置和刷新操作保持统一间距与按钮样式；接口层只负责认证、参数解析和响应转换，统计、权限范围和告警状态编排放在 Service 层。

## 12. 安全权限

- 自主监控只允许平台超级管理员和租户管理员访问和操作；平台级监控只允许平台超级管理员访问和操作。
- 租户监控必须在 Service 和 DB 查询层同时校验租户范围，不能只依赖前端传参。
- 告警详情中的问题文本、答案、文档片段、用户信息和 Token 必须脱敏或按权限隐藏。
- 日志和监控事件不得记录密码、Token、API Key 和完整敏感请求体。
- 监控查询必须记录审计日志，至少记录操作者、范围、查询时间和操作结果。
- 告警确认、关闭、规则变更必须记录前后状态和操作原因。

## 13. 异常边界

1. 没有自主评测任务：显示 Worker 空闲，不产生告警。
2. Worker 进程运行但心跳过期：显示 stale，并按规则产生告警。
3. 指标采集失败：显示数据不可用，不显示为 0 或健康。
4. 统计样本不足：展示样本数和“样本不足”，不直接判定异常。
5. 数据库暂时不可用：健康状态进入 unknown/error，并避免告警任务自身反复刷日志。
6. 多个实例上报同一事件：按事件 ID 去重。
7. 服务重启：恢复已有告警和任务状态，不重复创建告警。
8. 告警通知渠道不可用：告警仍需保存在系统内，并展示通知失败状态。
9. 监控系统自身异常：提供监控数据更新时间和采集器健康状态，避免管理员误以为业务全部正常。

## 14. 通知策略

通知渠道作为可配置能力，至少预留站内通知和 Webhook；邮件、短信、企业 IM 等渠道由后续接入适配器实现。

通知必须支持：

- 按严重级别选择渠道。
- 按租户、监控域和规则过滤接收范围。
- 告警触发、持续、恢复和通知失败事件。
- 重复通知抑制、升级通知和静默时间段。
- 通知模板中的告警标题、资源、当前值、阈值、发生时间、详情链接和 Trace ID。

默认情况下，普通空轮询不发送通知。

## 15. 交互原型

原型阶段需要体现以下状态：

- 全部健康。
- Worker 空闲且无评测任务。
- Worker 忙碌并显示当前评测阶段。
- 任务积压。
- 告警触发、已确认、已恢复和已关闭。
- 指标暂无数据。
- 指标采集失败或数据过期。
- 当前租户无权限查看平台级指标。
- 查询列表加载、空数据、分页和刷新。

页面上的“当前范围”“统计时间”“样本量”和“指标口径”必须提供明确文字或 Tooltip，避免管理员误解数据范围。

## 17. 验收标准

1. 没有自主评测任务时，页面明确显示 Worker 空闲，不产生错误告警，不持续刷业务级 INFO 日志。
2. Worker 停止、心跳过期和任务积压可以被区分并产生对应告警。
3. 自主评测从领取到完成的关键 Agent 阶段均可追踪。
4. 问答错误率、P95、降级率和引用率能够按时间范围、租户和知识库正确统计。
5. 告警支持触发、去重、确认、恢复、关闭和处理记录。
6. 指标无数据、采集失败、数据过期和样本不足均有独立状态。
7. 平台超级管理员与租户管理员的数据范围符合权限规则。
8. 监控列表具备查询和分页，详情可以关联到任务、评测运行、事件和日志上下文。
9. 所有监控写入、告警状态变更和规则变更具备审计记录。
10. 测试覆盖正常、空闲、积压、失败、超时、权限、数据隔离、重复事件和监控自身故障场景。

## 18. 评审事项

- 默认监控时间范围和指标刷新频率。
- 告警默认阈值、最小样本数和持续周期。
- 是否接入站内通知、Webhook 或企业 IM。
- 监控数据和告警的保留周期。
- 是否允许租户管理员确认或关闭告警。
- 是否需要支持监控规则按租户覆盖平台默认值。
- 是否需要展示单用户、单知识库或单模型维度的明细。
