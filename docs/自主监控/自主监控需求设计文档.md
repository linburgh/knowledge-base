# 自主监控需求设计文档

## 1. 文档说明

### 1.1 文档目的

本文档用于定义知识库系统“自主监控智能体”能力的建设范围、监控对象、指标、事件、告警和管理交互，为后续原型评审、接口设计、数据库设计和前后端开发提供统一依据。

本文档当前只做需求设计，不代表已经开始前后端、数据库或 Worker 编码。

### 1.2 建设背景

当前系统已经存在文档处理、知识库问答和自主评测等异步执行链路。系统出现异常时，管理员通常只能通过应用日志判断：

- Worker 是否正在运行；
- 是否有任务等待处理；
- 任务是否长时间没有进度；
- 问答接口是否持续变慢或错误增加；
- 知识库是否存在文档未处理、索引未生效或引用质量下降；
- 自主评测是否真正执行，还是长期处于空轮询、失败或阻塞状态。

因此需要建设自主监控智能体，由智能体持续观察运行状态、业务指标、资源指标和任务事件，识别异常、分析影响、生成告警和给出可追踪的处理建议；平台页面负责展示监控智能体产出的状态、事件、告警和分析结果。

### 1.3 智能体定位

自主监控智能体是面向平台运行管理的观测、分析和告警智能体，负责回答：

1. 当前系统是否可用？
2. 异步任务是否正常消费？
3. 知识库问答质量和性能是否发生异常？
4. 自主评测是否按预期运行并产出结果？
5. 异常从什么时候开始、影响了什么、是否已经恢复？

自主监控智能体不替代日志系统、链路追踪系统、数据库监控系统或云平台基础设施监控。它通过受控工具读取这些系统和业务模块提供的结构化数据，形成业务上下文和异常判断。

项目中的多个智能体协同工作：

```text
文档智能体
  └─ 负责文档解析、知识抽取、入库和知识库内容相关处理

自主评测智能体
  └─ 负责组织评测问题、调用问答能力、计算指标和生成评测结果

知识库问答智能体
  └─ 负责在授权范围内检索知识库、生成回答和返回引用

自主监控智能体
  └─ 观察文档智能体、知识库问答智能体、自主评测智能体及平台运行数据
     分析异常、关联影响、生成告警和提供处理建议
```

多个智能体之间只能通过公开的结构化协议协同，不得互相导入私有 Prompt、私有运行循环、模型实例或内部状态。自主监控智能体不直接代替文档处理、知识库问答和自主评测，也不通过硬编码复制另一智能体的执行逻辑。

自主监控智能体的运行入口、Runtime、Policies、工具注册表和技能文件必须独立放在 `app/agents/monitoring/` 下，遵守项目 Agent Harness 规范。平台监控页面和 API 通过 Service 调用监控智能体公开的结构化结果，不直接访问其私有状态。

## 2. 目标与非目标

### 2.1 建设目标

1. 让自主监控智能体持续观察服务、数据库、异步 Worker、知识库、问答链路和其他智能体的健康状态。
2. 监控文档入库、索引构建、自主评测等异步任务的数量、状态、耗时、积压和失败情况。
3. 监控问答请求量、成功率、错误率、降级率、响应耗时和引用返回情况。
4. 监控自主评测任务从创建、排队、执行到结束的完整过程，能够证明 Agent 确实被执行。
5. 由自主监控智能体对超时、失败、积压、连续错误、质量门禁不通过和 Worker 停止等情况生成告警。
6. 支持告警确认、关闭、抑制和恢复，避免同一故障持续刷屏。
7. 支持从指标、告警、事件跳转到具体任务、运行记录、日志上下文和评测报告。
8. 支持平台超级管理员查看平台范围数据；涉及租户业务数据时必须遵守租户数据范围。
9. 所有监控数据包含统计时间、数据范围、来源和计算状态，避免把无数据误判为零值或健康。

### 2.2 非目标

- 不在本模块中实现通用日志采集平台、APM 平台或主机级监控平台。
- 不自动修改知识库文档、Prompt、模型、索引配置或评测门禁。
- 不因为监控告警自动重试、暂停、删除或终止业务任务；自动化处置需要另行设计并确认。
- 不将“没有自主评测任务”判断为异常。无任务时应显示“空闲且健康”，与 Worker 停止、任务积压明确区分。
- 不把一次偶发慢请求直接判定为系统故障，必须结合时间窗口、样本量和连续性规则。

### 2.3 多个智能体协同职责

| 智能体 | 核心职责 | 向其他智能体提供的结构化结果 | 不负责的内容 |
| --- | --- | --- | --- |
| 文档智能体 | 解析文档、抽取内容、切分、入库、建立索引和返回知识内容 | 文档处理状态、索引状态、知识内容版本、处理错误和耗时 | 不负责评测结论和平台告警 |
| 知识库问答智能体 | 在授权范围内检索知识库、生成回答和返回引用 | 问答阶段事件、耗时、命中数、引用数、降级状态、错误分类和版本信息 | 不负责平台健康判断、告警和自动处置 |
| 自主评测智能体 | 生成或加载问题、调用问答能力、执行评测、计算指标和生成报告 | 评测运行状态、阶段事件、逐题结果、指标、门禁结论和报告 | 不负责持续监控平台和其他任务 |
| 自主监控智能体 | 采集、关联、分析运行数据，识别异常，生成告警和处理建议 | 健康状态、异常事件、告警实例、影响范围、证据链和建议 | 不直接修改文档、评测配置、模型或业务数据 |

多智能体协同链路如下：

```text
文档智能体       ──文档/索引状态、处理事件──┐
知识库问答智能体 ──问答遥测、运行结果──────┤
自主评测智能体   ──评测事件、指标、报告────┘
                                      ├─> 自主监控智能体 ──健康状态/告警/建议──> 管理员
自主评测智能体   ──按公开协议调用────────> 知识库问答智能体
```

自主监控智能体必须能够把多个来源的事件关联成一个故障上下文。例如：文档索引失败导致问答引用率下降，自主评测门禁不通过；监控智能体应把它们关联为同一影响链路，而不是创建三个互不相关的告警。

### 2.3.1 与知识库问答智能体的协同

知识库问答智能体是自主监控的核心业务观测对象，但两者不能形成运行时强依赖。知识库问答智能体负责回答用户问题、执行授权范围内的检索和生成引用；自主监控智能体负责观察问答运行事实、判断问答链路健康状态和生成告警。

知识库问答智能体应通过公开的结构化遥测协议向自主监控提供以下信息：

- 请求开始、检索完成、模型调用、回答完成、降级、失败和超时等阶段事件。
- `trace_id`、`run_id`、租户、知识库、索引版本、模型版本和配置版本。
- 总耗时、检索耗时、模型耗时、命中数量、引用数量、终止原因和错误分类。
- 权限拒绝、知识库无资料、检索失败、模型失败和降级回答等可识别状态。

遥测数据只提供运行事实和脱敏摘要。默认不得向自主监控传递完整用户问题、完整回答、文档片段、Token 或其他敏感上下文；确需查看时必须按照操作者权限从业务数据中单独加载。

自主监控可以在发现问答错误率、响应耗时、引用率或降级率异常时，按需调用知识库问答智能体的公开结构化协议执行受控监控探针。监控探针必须满足：

1. 使用专用监控租户、专用知识库和固定测试问题，不使用真实用户问题。
2. 使用 `purpose=monitor_probe` 等明确标识，不计入普通业务问答、租户用量或自主评测统计。
3. 不创建用户会话，不写入普通聊天历史，只允许只读检索和回答。
4. 具有独立的超时、频率、并发和调用预算，避免监控制造业务压力。
5. 默认只保留成功状态、耗时、命中数、引用数和错误分类，不持久化完整问题、答案和文档片段。
6. 探针失败只说明探针范围内的链路异常，不能直接推断全部租户问答均不可用。

自主监控不得导入知识库问答智能体的私有 Prompt、私有函数、模型实例、Runtime 或内部状态，也不得因为问答异常自动修改 Prompt、模型、Rerank、索引或知识库配置。问答智能体不能反向调用自主监控智能体判断自身是否健康。

### 2.3.2 与自主评测智能体的协同

自主评测智能体既是自主监控的观测对象，也是问答质量的主动业务探针。自主评测智能体负责组织问题、调用知识库问答智能体、计算指标和生成评测报告；自主监控智能体负责观察评测是否按预期执行、判断执行环境是否稳定、关联评测结果与平台异常，不改写评测质量结论。

自主评测智能体应向自主监控提供完整的结构化执行证据：

- 任务创建、排队、领取、启动、暂停、取消和结束。
- 配置校验、问题加载或生成、逐题执行、重试、指标计算、报告生成和持久化。
- 每题开始、完成、失败、超时以及知识库问答智能体调用失败。
- 评测使用的知识库、索引版本、问答智能体版本、配置版本和评测规则版本。
- 总题数、完成数、失败数、处理速率、重试次数、排队时长和执行耗时。
- 评测门禁结论及不通过的指标项。
- Worker、Runtime、LangGraph 和知识库问答智能体是否实际执行的证明事件。

自主监控必须区分“评测质量结论”和“评测运行可信度”：

| 情况 | 评测结论 | 监控判断 |
| --- | --- | --- |
| 问答质量不达标且基础设施正常 | 不通过 | 质量问题 |
| 大量问答调用超时或失败 | 不通过或执行失败 | 基础设施异常，结果可能不可比 |
| 评测期间索引版本变化 | 可能不通过 | 评测环境不稳定 |
| Worker 中途停止或事件链断裂 | 未完成或失败 | 评测执行链路异常 |
| 评测完成且执行证据完整 | 通过或不通过 | 结果具备正常执行证据 |

评测运行结果应能够表达以下不同原因：

- `quality_failed`：评测完成，但质量门禁不通过。
- `execution_failed`：评测执行链路失败。
- `environment_degraded`：模型、向量库、数据库等基础设施异常影响结果。
- `inconclusive`：完成度或有效样本不足，不能据此判断质量。

自主评测结果可以作为问答质量监控信号，用于发现 API 返回正常但引用率下降、答案质量回归、某知识库质量下降或索引版本异常等问题。自主监控可以读取评测结果并生成质量告警，但不得自行创建评测任务、自动调整评测配置或自动重跑评测；是否补跑、切换版本或调整配置必须由管理员或另行确认的调度策略决定。

自主评测在开始时可以读取一次自主监控提供的环境快照，用于记录 API、Worker、模型、向量库和数据库状态以及当时未恢复的基础设施告警。该快照属于弱依赖：监控接口暂时不可用时，评测不能因此被阻断；环境快照也不能替代评测指标，更不能直接决定评测通过。

### 2.3.3 问答、评测与监控智能体的交互边界

三者之间推荐采用“结构化遥测上行、受控探针下行、结果上下文标注”的关系：

```text
知识库问答智能体 ──问答运行遥测────────────┐
自主评测智能体   ──评测执行证据/质量结果────┼─> 自主监控智能体 ──告警/建议──> 管理员
文档智能体       ──文档/索引处理事件────────┘

自主监控智能体 ──受控问答探针────────────> 知识库问答智能体
自主监控智能体 ──环境快照/异常标记────────> 自主评测报告上下文
自主评测智能体 ──公开协议调用────────────> 知识库问答智能体
```

必须禁止以下循环和隐式控制：

- 自主评测等待自主监控确认健康，自主监控又等待评测产出结果。
- 自主监控发现评测异常后自动重试评测，重试产生的新异常再次触发监控。
- 自主监控把真实用户问题和完整答案交给另一个模型直接判断系统健康。
- 自主监控用自然语言答案替代结构化指标和事件作为健康依据。
- 监控探针复用普通用户会话，或让探针结果触发业务告警、租户用量和评测统计。

问答智能体、评测智能体和监控智能体必须分别保留独立的入口、Runtime、Policies、工具注册表和运行预算。跨 Agent 调用只能使用公开结构化协议，不得导入私有 Prompt、私有方法、模型实例或内部状态。

### 2.4 自主监控智能体的工作方式

自主监控智能体通过“观测—分析—判断—记录—告警—跟踪恢复”的闭环工作：

1. 从健康检查、指标、任务状态、Agent 事件和结构化日志中获取观测数据。
2. 对不同时间窗口、资源范围和事件来源进行关联，建立异常上下文。
3. 根据监控规则、历史基线和证据判断健康、异常、数据不足或无法判断。
4. 生成结构化监控结论，记录判断依据、置信度、影响范围和关联资源。
5. 满足告警条件时创建或更新告警实例；不满足时继续观察，不产生告警。
6. 监控异常是否恢复，并更新告警生命周期。
7. 对需要人工处理的异常给出建议，但未经明确授权不得执行删除、修改、重试或发布操作。

智能体的结论必须可追溯到具体指标、事件、任务或日志证据。不能只输出“系统异常”或“建议检查服务”这类无法验证的自然语言结论。

## 3. 角色与数据范围

### 3.1 平台超级管理员

- 查看平台整体运行状态、全部租户聚合指标和平台级告警。
- 查看平台级异步任务、Worker、问答链路和自主评测运行状态。
- 查看告警详情、确认告警、关闭告警和维护监控规则。
- 只有在具备相应数据权限时，才能查看具体租户、知识库、文档或评测问题内容。

### 3.2 租户管理员

- 只能查看当前租户及其管理范围内的知识库、文档处理、问答和评测监控数据。
- 不能看到其他租户名称、任务数量、用户信息、问题内容或告警详情。
- 可以确认和关闭当前租户范围内、且允许租户管理员处理的告警。
- 平台服务、数据库、全局 Worker 等平台级基础设施状态只展示与当前租户有关的摘要，不泄露平台全量数据。

### 3.3 普通用户

默认不能进入自主监控管理页面。后续如需开放个人任务状态，只能展示本人有权限查看的任务，不纳入本期管理监控范围。

## 4. 监控域设计

自主监控智能体分为六个观测域。每个观测域都必须区分“健康、告警、故障、无数据、未启用、采集中”状态。

| 监控域 | 关注问题 | 主要数据来源 |
| --- | --- | --- |
| 平台运行 | API、数据库和依赖是否可用 | 健康检查、数据库连接、依赖探针 |
| 异步任务 | 文档、索引、评测是否积压或失败 | 任务表、运行表、Worker 心跳 |
| 知识库问答 | 请求是否成功、变慢、降级或缺少引用 | 问答请求事件、调用结果 |
| 自主评测 | Agent 是否运行、评测是否完成、门禁是否通过 | 评测任务、评测运行、Agent 事件 |
| 资源与容量 | 数据库连接、队列、存储和向量服务是否接近上限 | 运行时指标、依赖指标 |
| 告警与事件 | 异常是否已通知、确认、恢复和关闭 | 监控智能体结论、规则、告警实例、事件记录 |

## 5. 首页监控总览

### 5.1 页面结构

自主监控页面分为：

1. 顶部范围和时间选择：平台范围或当前租户范围、最近 15 分钟/1 小时/6 小时/24 小时/7 天。
2. 系统健康摘要：服务、数据库、异步 Worker、问答链路、依赖服务。
3. 核心指标卡片：请求量、成功率、错误数、任务积压、评测运行数、未恢复告警数。
4. 趋势图：问答请求、错误率、P95 响应时间、任务完成量和告警数量。
5. 当前告警：按严重级别展示未恢复告警。
6. 最近事件：按时间倒序展示任务、Worker、评测和系统状态变化。
7. 异步任务概览：文档处理、索引构建、自主评测的状态分布和最慢任务。

### 5.2 指标卡片规则

- 卡片数字必须来自统计接口，不得由前端分页数据推算。
- 每个数字必须有统计时间、数据范围和口径说明。
- 当前无样本时显示“暂无数据”，不得显示为 0 并标记正常。
- 指标卡片支持点击进入对应监控域，并携带当前范围和时间条件。
- 租户管理员不显示平台级“活跃租户”等与其管理范围无关的指标。

建议卡片：

| 卡片 | 口径 |
| --- | --- |
| 服务健康 | 当前范围内纳入监控的服务状态汇总 |
| 问答请求 | 时间窗口内收到的问答请求数 |
| 问答成功率 | 正常完成请求数 / 有效请求总数 |
| 问答 P95 | 时间窗口内问答请求耗时 P95 |
| 待处理任务 | 当前处于 pending 或 queued 的异步任务数 |
| 未恢复告警 | 当前范围内状态为 firing 或 acknowledged 的告警数 |
| 评测运行中 | 当前状态为 running 的自主评测运行数 |

## 6. 指标体系

### 6.1 平台与服务指标

- API 健康检查成功率。
- API 请求量、4xx 数量、5xx 数量。
- API 平均响应时间、P95、P99 响应时间。
- 数据库连接状态、连接池使用率、连接等待数和慢 SQL 数量。
- 外部模型、Embedding、Rerank、向量库等依赖的可用率和错误率。
- 服务启动时间、最近心跳时间和当前实例状态。

### 6.2 异步任务指标

按任务类型分别统计：

- pending、running、completed、failed、cancelled、timeout 数量。
- 当前积压量和积压时长。
- 任务成功率和失败率。
- 任务平均耗时、P95 耗时和最长耗时。
- 最近一次成功完成时间。
- 最近一次失败时间和失败原因分类。
- 重试次数、重试后成功率和达到最大重试次数的数量。
- Worker 最近心跳、消费速率和空闲状态。

任务类型至少包括：文档入库、索引构建、自主评测运行。后续新增异步任务必须复用统一任务监控协议。

### 6.3 知识库问答指标

- 请求总量和有效请求量。
- 成功率、错误率、超时率和主动取消率。
- 降级率，包括无引用回答、备用回答和服务降级。
- 引用返回率、引用为空率和引用数量分布。
- 首字节耗时、完整响应耗时、P50/P95/P99。
- 按知识库、租户、接口、模型版本和时间窗口聚合。
- Top 错误码、Top 超时接口和 Top 慢知识库。
- 连续失败请求、连续超时请求和短时间异常增长。

登录、刷新令牌、选择租户等非业务操作不计入问答业务指标，也不应作为问答异常事件。

### 6.4 自主评测指标

- 评测任务总数、启用任务数、待运行任务数、运行中任务数。
- 评测运行成功率、失败率、超时率和取消数。
- 评测排队时长、执行时长和端到端耗时。
- 评测问题数、已完成数、失败数和处理速率。
- Agent 执行开始、阶段切换、每题执行、指标计算、报告生成和持久化事件数量。
- 评测门禁通过率和不通过的指标项。
- 自主生成问题失败率、知识库上下文加载失败率和 Agent 调用失败率。
- 当前 Worker 是否运行、最近轮询时间、最近领取任务时间和最近完成时间。
- 空轮询次数只能作为 Worker 活跃度辅助指标，不得单独产生故障告警。

### 6.5 资源与容量指标

- 数据库连接池使用率、等待时间和连接耗尽次数。
- 队列或任务表积压量。
- 单租户任务量、单知识库文档量和索引数据量。
- 文件存储使用量、向量数据量和增长趋势。
- 单次评测问题数量、并发数、上下文大小和模型调用量。
- 超过配置上限的请求、任务和数据量。

资源指标必须明确采集来源和采集失败状态。采集不到不能直接显示为“正常”。

## 7. Worker 与自主评测监控

### 7.1 Worker 状态

Worker 状态至少包括：

- `running`：进程运行且最近心跳正常。
- `idle`：进程运行、没有待处理任务。
- `busy`：正在处理任务。
- `stale`：超过心跳阈值没有更新。
- `stopped`：明确停止或进程不存在。
- `error`：最近一次执行出现未恢复错误。
- `unknown`：监控数据缺失或采集失败。

“idle”是健康状态，不得展示成异常。当前没有自主评测任务时，页面应显示“Worker 空闲，暂无待处理评测”，而不是显示告警。

### 7.2 评测执行证明链路

为了证明自主评测确实由 Agent 执行，至少记录以下结构化事件：

1. Worker 领取评测运行。
2. 评测运行进入 `running`。
3. 配置校验完成。
4. 问题加载或自主生成完成。
5. Agent 开始执行。
6. 每个问题开始、重试、完成或失败。
7. 指标计算完成。
8. 报告生成完成。
9. 结果持久化完成。
10. 评测运行进入 `completed`、`failed`、`timeout` 或 `cancelled`。

每个事件至少包含 `event_id`、`run_id`、`task_id`、`event_type`、`stage`、`status`、`occurred_at`、`duration_ms`、`trace_id` 和脱敏上下文。问题内容、答案内容和文档内容不能直接写入普通运行日志；需要查看时按权限从业务数据中加载。

### 7.3 空轮询日志规则

Worker 可以按固定间隔查询是否有待处理任务，但空轮询不属于业务事件：

- 空轮询不得按 `INFO` 级别持续打印。
- 默认只记录轮询次数、最近轮询时间等聚合指标。
- 单次空轮询日志使用 `DEBUG`，或者仅在连续空轮询达到采样条件时记录一条摘要。
- 有任务领取、Worker 状态变化、轮询异常时使用 `INFO` 或 `ERROR`。
- “没有任务”不能触发告警。

## 8. 告警设计

### 8.1 告警严重级别

| 级别 | 含义 | 默认处理时限 |
| --- | --- | --- |
| 紧急 | 核心服务不可用、数据安全风险或大范围业务中断 | 立即处理 |
| 严重 | 核心链路持续失败、任务大量积压或 Worker 停止 | 30 分钟内 |
| 警告 | 性能下降、失败率升高、容量接近阈值 | 4 小时内 |
| 提示 | 配置变更、短时波动、评测门禁不通过等需要关注的事件 | 工作日处理 |

### 8.2 默认告警规则

默认规则必须支持启用、停用、阈值调整、时间窗口和连续次数配置。建议规则包括：

| 规则 | 触发条件示例 | 恢复条件 |
| --- | --- | --- |
| API 不可用 | 连续 3 个探测周期失败 | 连续 2 个周期成功 |
| 5xx 异常升高 | 5 分钟错误率超过阈值且样本数达到最小值 | 错误率恢复 |
| 问答响应变慢 | P95 连续 3 个周期超过阈值 | P95 恢复 |
| Worker 心跳过期 | 超过心跳阈值无心跳 | 收到有效心跳 |
| 任务积压 | pending 数量或最老任务等待时间超过阈值 | 积压恢复 |
| 任务连续失败 | 同类任务连续失败达到次数 | 出现成功任务 |
| 评测运行超时 | 单次运行超过配置时限 | 运行结束或人工关闭 |
| 评测门禁不通过 | 评测完成但总体结论为不通过 | 新一轮评测通过或人工关闭 |
| 数据库连接池紧张 | 使用率或等待时间超过阈值 | 连接恢复 |
| 依赖服务异常 | 模型、向量库等依赖连续失败 | 依赖恢复 |

告警规则必须具有最小样本数，避免低流量场景下一个请求失败就产生高严重级别告警。

### 8.3 告警生命周期

```text
正常 -> 触发中(firing) -> 已确认(acknowledged) -> 已恢复(resolved)
                         \-> 已关闭(closed)
```

- `firing`：满足触发条件，尚未处理。
- `acknowledged`：管理员确认已知晓，但问题尚未恢复。
- `resolved`：指标恢复到恢复条件，系统自动结束告警。
- `closed`：管理员确认无需继续处理或已完成处置。
- 同一规则、同一数据范围和同一资源在未恢复前只能保留一个告警实例。
- 告警重复触发时更新次数和最后发生时间，不重复创建无限记录。

## 9. 告警与事件页面

### 9.1 告警列表

查询条件至少包括：告警级别、告警状态、监控域、规则名称、资源类型、资源名称、租户、发生时间和恢复时间。

表格字段至少包括：告警级别、告警标题、监控域、资源、当前值、阈值、首次发生、最近发生、持续时长、状态、确认人和操作。

列表必须提供分页，时间字段统一使用公共时间格式，超长内容单行省略并提供 Tooltip。

### 9.2 告警详情

详情包括：

- 告警规则和触发表达式。
- 当前值、阈值、统计窗口和样本量。
- 影响范围和数据权限说明。
- 指标趋势图和触发前后的对比。
- 关联任务、评测运行、Worker、知识库和 Trace ID。
- 事件时间线。
- 确认、关闭、添加处理备注和跳转日志操作。

### 9.3 事件列表

事件用于记录状态变化，不等同于告警。事件至少包括服务启动、Worker 启停、任务状态变化、评测阶段变化、配置变更、告警触发和告警恢复。

事件支持按时间、事件类型、资源、租户和操作者查询。普通的空轮询不作为独立事件展示。

## 10. 数据与统计口径

### 10.1 时间窗口

- 实时状态：展示最近一次有效采集结果。
- 趋势指标：按 1 分钟、5 分钟或 1 小时桶聚合，具体粒度根据时间范围自动选择。
- 告警判断：使用规则配置的滚动窗口。
- 所有时间统一使用 UTC 存储，页面按用户时区展示。

### 10.2 数据状态

每个指标返回以下状态之一：

- `ready`：数据完整，可正常展示。
- `partial`：部分采集失败，展示数据并标注不完整。
- `empty`：时间窗口内没有样本，显示暂无数据。
- `stale`：数据超过有效期，显示数据已过期。
- `error`：采集或统计失败，显示获取失败。

### 10.3 去重和幂等

- 指标事件必须有唯一事件 ID，重复上报不得重复计数。
- 任务状态变化按任务 ID、版本和状态时间排序。
- 告警实例按规则、范围和资源维度去重。
- Worker 重启不能制造虚假的任务完成或评测完成事件。

## 11. 接口需求

以下为接口设计方向，具体字段在接口文档评审后确定：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/monitoring/overview` | 获取监控总览和核心卡片 |
| `GET /api/v1/monitoring/health` | 获取服务、数据库、Worker 和依赖健康状态 |
| `GET /api/v1/monitoring/metrics` | 按指标、范围和时间窗口查询趋势数据 |
| `GET /api/v1/monitoring/tasks` | 查询异步任务监控列表 |
| `GET /api/v1/monitoring/evaluations` | 查询自主评测运行和 Agent 执行摘要 |
| `GET /api/v1/monitoring/events` | 查询事件时间线 |
| `GET /api/v1/monitoring/alerts` | 分页查询告警 |
| `GET /api/v1/monitoring/alerts/{id}` | 查看告警详情 |
| `POST /api/v1/monitoring/alerts/{id}/acknowledge` | 确认告警 |
| `POST /api/v1/monitoring/alerts/{id}/close` | 关闭告警 |
| `GET /api/v1/monitoring/rules` | 查询监控规则 |
| `POST /api/v1/monitoring/rules` | 新增监控规则 |
| `PUT /api/v1/monitoring/rules/{id}` | 修改监控规则 |
| `POST /api/v1/monitoring/rules/{id}/toggle` | 启用或停用规则 |

所有列表接口必须有查询条件和分页。接口层只负责认证、参数解析和响应转换，统计、权限范围和告警状态编排放在 Service 层。

## 12. 权限与安全

- 平台级监控只允许平台超级管理员查看。
- 租户监控必须在 Service 和 DB 查询层同时校验租户范围，不能只依赖前端传参。
- 告警详情中的问题文本、答案、文档片段、用户信息和 Token 必须脱敏或按权限隐藏。
- 日志和监控事件不得记录密码、Token、API Key 和完整敏感请求体。
- 监控查询必须记录审计日志，至少记录操作者、范围、查询时间和操作结果。
- 告警确认、关闭、规则变更必须记录前后状态和操作原因。

## 13. 异常与边界处理

1. 没有自主评测任务：显示 Worker 空闲，不产生告警。
2. Worker 进程运行但心跳过期：显示 stale，并按规则产生告警。
3. 指标采集失败：显示数据不可用，不显示为 0 或健康。
4. 统计样本不足：展示样本数和“样本不足”，不直接判定异常。
5. 数据库暂时不可用：健康状态进入 unknown/error，并避免告警任务自身反复刷日志。
6. 多个实例上报同一事件：按事件 ID 去重。
7. 服务重启：恢复已有告警和任务状态，不重复创建告警。
8. 告警通知渠道不可用：告警仍需保存在系统内，并展示通知失败状态。
9. 监控系统自身异常：提供监控数据更新时间和采集器健康状态，避免管理员误以为业务全部正常。

## 14. 通知策略

通知渠道作为可配置能力，至少预留站内通知和 Webhook；邮件、短信、企业 IM 等渠道由后续接入适配器实现。

通知必须支持：

- 按严重级别选择渠道。
- 按租户、监控域和规则过滤接收范围。
- 告警触发、持续、恢复和通知失败事件。
- 重复通知抑制、升级通知和静默时间段。
- 通知模板中的告警标题、资源、当前值、阈值、发生时间、详情链接和 Trace ID。

默认情况下，普通空轮询不发送通知。

## 15. 原型与交互要求

原型阶段需要体现以下状态：

- 全部健康。
- Worker 空闲且无评测任务。
- Worker 忙碌并显示当前评测阶段。
- 任务积压。
- 告警触发、已确认、已恢复和已关闭。
- 指标暂无数据。
- 指标采集失败或数据过期。
- 当前租户无权限查看平台级指标。
- 查询列表加载、空数据、分页和刷新。

页面上的“当前范围”“统计时间”“样本量”和“指标口径”必须提供明确文字或 Tooltip，避免管理员误解数据范围。

## 16. 实施边界与交付顺序

在本需求文档评审通过后，按以下顺序继续：

1. 完成监控原型和交互评审。
2. 完成指标字典、事件字典和告警规则字典。
3. 完成接口、数据表和统计口径设计。
4. 完成前后端测试用例文档，并登记到测试用例索引。
5. 完成监控数据采集、聚合、告警状态机和权限隔离实现。
6. 完成监控总览、告警列表、事件列表和详情页面。
7. 使用真实任务、空任务、失败任务、超时任务和 Worker 停止场景完成联调验收。

在原型、需求、接口和测试用例评审通过前，不开始自主监控的前后端和数据库业务编码。

## 17. 验收标准

1. 没有自主评测任务时，页面明确显示 Worker 空闲，不产生错误告警，不持续刷业务级 INFO 日志。
2. Worker 停止、心跳过期和任务积压可以被区分并产生对应告警。
3. 自主评测从领取到完成的关键 Agent 阶段均可追踪。
4. 问答错误率、P95、降级率和引用率能够按时间范围、租户和知识库正确统计。
5. 告警支持触发、去重、确认、恢复、关闭和处理记录。
6. 指标无数据、采集失败、数据过期和样本不足均有独立状态。
7. 平台超级管理员与租户管理员的数据范围符合权限规则。
8. 监控列表具备查询和分页，详情可以关联到任务、评测运行、事件和日志上下文。
9. 所有监控写入、告警状态变更和规则变更具备审计记录。
10. 测试覆盖正常、空闲、积压、失败、超时、权限、数据隔离、重复事件和监控自身故障场景。

## 18. 待评审事项

以下内容在原型和接口评审时确认：

- 默认监控时间范围和指标刷新频率。
- 告警默认阈值、最小样本数和持续周期。
- 是否接入站内通知、Webhook 或企业 IM。
- 监控数据和告警的保留周期。
- 是否允许租户管理员确认或关闭告警。
- 是否需要支持监控规则按租户覆盖平台默认值。
- 是否需要展示单用户、单知识库或单模型维度的明细。
