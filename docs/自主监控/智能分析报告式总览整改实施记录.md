# 智能分析报告式总览整改实施记录

## 整改范围

本次整改以已评审通过的《智能分析报告式总览交互原型》和 `tmp/运行正常.png`、`tmp/指标待验.png`、`tmp/告警影响.png`、`tmp/证据不足.png` 四张完整截图为基线，将智能分析总览由普通信息卡片调整为正式报告表单。分析对话及参考证据抽屉保留现有交互，不在正式页面加入原型状态切换器或演示数据。

## 后端实现

分析总览接口新增以下正式报告字段：

| 字段名称 | 字段说明 |
| --- | --- |
| `report_no` | 由生成时间和授权范围组成的可追踪报告编号 |
| `generated_at` | 报告生成时间，前端统一按中国标准时间展示 |
| `checks` | 活动告警、核心指标、运行事件、任务运行四项核查结果 |
| `judgment_boundary` | 当前结论的证据覆盖范围和不可推断边界 |

接口从当前授权范围和时间窗口内的真实告警、指标、事件及任务记录形成核查结果。展示状态统一为运行正常、指标待验、告警影响和证据不足四类；分析执行失败时可信度保持无法计算，不使用伪造分值。

## 前端实现

正式页面按报告抬头、报告元数据、分析结论、核查结果、影响分析、处理建议、关键证据、运行或异常过程、判断边界和报告页脚组织。关键证据入口继续打开可查询、可筛选、可分页的证据抽屉。

视觉实现不再重新设计报告样式，直接复用已评审交互稿的 DOM 语义、字体变量和 CSS 数值，只保留 Vue 数据绑定差异。根据视觉复核反馈，报告内抬头、元数据、正文、表格、状态标签、时间线和页脚字号统一增加 1px，以改善低分辨率屏幕上的中文清晰度。

响应式布局规则如下：

- 桌面宽屏使用五列元数据、影响与建议双列布局。
- 中等宽度使用三列元数据、影响与建议单列布局。
- 390 像素窄屏使用两列元数据和纵向时间过程。
- 核查、影响、建议和证据宽表格只在报告内部滚动，页面主体不产生横向溢出。
