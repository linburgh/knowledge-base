# 自主监控调查型 Agent 改造方案

## 目标说明

本方案把自主监控智能分析从“五类事实查询与汇总”升级为只读调查型 Agent。Agent 应围绕用户目标完成异常发现、对象选择、候选假设、证据验证、关联分析和受控收敛，能够回答告警明细、重复关系、触发原因、影响范围和时间线问题，并在模型或部分数据源失败时保留已经取得的真实事实。

本次改造不增加自动处置。修改告警规则、重启资源、重试任务和其他写操作继续由人工在现有业务入口确认。

## 功能模块

| 一级模块 | 子模块 | 职责边界 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 语义规划 | 目标建模 | 保留用户目标、实体、维度、结果形态和不确定项，不用关键词决定生产工具链 | 问题、会话事实 | 调查目标 |
| 范围控制 | 可信范围 | 服务端确定中国标准时间、租户、角色和数据范围，模型不得覆盖 | 用户上下文 | 可信查询范围 |
| 异常发现 | 概览查询 | 获取健康、告警、指标、事件和任务候选事实 | 调查目标 | 候选对象 |
| 深入调查 | 明细查询 | 按事实 ID、指标、资源或 Trace 深入查询 | 候选对象 | 明细事实 |
| 关联分析 | 证据关联 | 确定性计算时间、资源、指标、规则和 Trace 关系 | 多类事实 | 关系与分组 |
| 证据工作 | 工作空间 | 去重保存事实、调用、假设、关系和未决问题 | 工具结果 | 可追溯事实集 |
| 结果校验 | 充分性检查 | 校验结论、引用、权限、时间和因果边界 | Agent 输出、事实集 | 合法结果 |
| 动态展示 | 结构化视图 | 根据事实类型返回告警列表、关联分组、指标趋势或时间线 | 事实集、用户视图 | Markdown 与视图提示 |
| 失败收敛 | 分级降级 | 模型超时、部分工具失败或终态缺失时保留事实并回答 | 调用轨迹、事实 | 受控结果 |

调用方向保持为 `API -> Monitoring Service -> Monitoring Agent -> Monitoring Tools -> DB Repository`。

## 能力选型

生产入口继续使用 Deep Agents 官方 `create_deep_agent`。自主监控需要官方模型—工具循环、Skills Middleware、结构化输出、工具与模型调用上限；基础 `create_agent` 可以完成工具循环，但不能直接满足当前 Skill 文件加载和受限文件系统需求。自定义 LangGraph 不采用，因为调查阶段不存在官方循环无法表达的固定节点语义。

官方 `ToolCallLimitMiddleware`、`ModelCallLimitMiddleware`、重试 Middleware 和 `ToolStrategy` 继续负责通用 Harness 能力。项目 `runtime.py` 只补充可信范围复核、单工具超时、查询签名去重、证据总量和业务查询预算；`policies.py` 只维护只读白名单与可信字段保护。证据工作区和关联计算属于监控领域能力，不替代官方 Agent 循环。

## 调查方法

Agent 根据问题和中间证据自主执行以下行为，不把这些行为固化为自研工作流节点：

1. 识别调查目标、对象、时间表达、结果形态和不确定项。
2. 使用概览工具发现候选异常；明确明细问题可直接调用明细工具。
3. 形成候选假设，例如“多条告警是否来自同一指标与作用域”。
4. 按事实 ID、指标、资源或 Trace 调用细粒度工具验证。
5. 每次观察后判断继续查询是否能提高结论可信度。
6. 达到证据要求、预算耗尽或无法继续时输出结论、证据、边界和建议。

固定 `intent` 仅用于审计和兼容。模型不可用时，关键词识别只作为降级路径，不能成为生产主路由。

## 工具体系

保留 `query_health_snapshots`、`query_alerts`、`query_metrics`、`query_events` 和 `query_tasks` 五类发现工具，并增加：

| 工具 | 用途 | 可控筛选 |
| --- | --- | --- |
| `get_alert_details` | 查询指定告警完整事实 | 告警事实 ID |
| `correlate_alerts` | 判断多条告警的指标、资源、规则、范围和时间关系 | 告警事实 ID |
| `query_metric_series` | 查询指定指标或资源的窗口序列 | 指标编码、资源编码 |
| `query_resource_timeline` | 查询资源或 Trace 的事件与任务时间线 | 资源编码、Trace ID |

时间起止、租户、用户、角色和作用域始终由 Runtime 注入，不进入模型参数。允许同一工具使用不同筛选参数多次调用；完全相同的成功查询签名不得重复执行。所有工具只返回结构化事实，不生成最终自然语言结论。

## 证据工作

Monitoring Harness 内新增私有 `EvidenceWorkspace`，统一保存事实、关系、查询签名和假设。事实使用稳定 `fact_id`，按事实 ID 去重；关系至少支持 `same_metric`、`same_resource`、`same_scope`、`same_rule`、`time_overlap` 和 `same_trace`。跨轮只恢复同一授权会话中服务端持久化的事实集合，客户端不得注入或覆盖。

用户提出“这些、刚才、4条、分别、第N条”等追问时，模型从上一轮事实集合选择真实 `fact_refs`；程序验证引用属于当前会话和授权范围。正则只负责判断是否需要向模型提供上一轮事实，不负责业务意图分类。

## 判定规则

| 问题类型 | 最低证据 |
| --- | --- |
| 是否正常 | 健康状态或核心指标 |
| 告警明细 | 告警事实 |
| 为什么触发 | 告警规则、指标值、阈值和样本 |
| 是否重复 | 指标、资源、作用域、规则和触发时间 |
| 影响范围 | 直接资源或依赖关系 |
| 根因判断 | 直接因果证据；时间重叠只能判为关联 |

结论继续保留 `normal`、`warning`、`abnormal` 和 `unknown` 兼容编码；调查元数据增加 `confirmed`、`likely`、`possible`、`insufficient` 和 `contradicted` 证据置信级别。模型不能覆盖确定性结论。

## 回答展示

Agent 同时返回中文 Markdown 和结构化 `presentation`。单一告警事实复用告警列表；告警关联结果展示分组、共同点、差异和判断边界；资源调查展示时间线。数值统一保留两位小数，时间统一标注“中国标准时间”，内部指标编码、作用域键和异常堆栈不得面向客户展示。

如果模型超时但已取得事实，优先按用户要求展示明细或关联结果；多类综合问题才使用确定性综合报告。部分工具失败保留成功事实并说明数据缺口；全部失败不判断正常或异常。

## 预算策略

- 总体默认预算调整为 30 秒，回答收敛至少预留 5 秒。
- 监控查询工具最多 10 次，模型调用最多 10 次，单工具默认 5 秒。
- 同一工具可以使用不同安全筛选参数调用；成功的完全相同查询不得重复。
- 事实工作区最多保存 100 条，传入最终上下文最多 50 条；列表通过前端分页查看完整数据。
- 预算、取消、超时、工具失败和裁剪状态必须进入结构化轨迹。

## 验收标准

- “4条告警分别是什么”完整返回四条授权告警。
- “这4条是否重复”比较指标、资源、范围、规则与时间并给出证据边界。
- “为什么触发”返回当前值、阈值、样本和规则依据；证据不全时不认定根因。

## 通用调查

调查结果不再为告警明细、原因、影响、趋势等问题分别维护互斥响应类型，而是统一形成开放目标和可组合调查结构：`analysis_goal` 保存用户实际目标，`subject_refs` 保存本轮对象，`observations` 保存直接事实，`findings` 保存已确认或待确认发现，`relations` 保存重复、关联、影响和时序关系，`causal_assessment` 区分直接触发原因与底层根因，`unknowns` 保存证据缺口，`next_checks` 保存只读检查建议，`evidence_refs` 只引用授权事实。

模型终态可用时由模型填写该结构，并继续经过程序结论和引用校验；模型终态缺失、非法、超时或供应商限流时，由程序根据工具事实生成同一结构。确定性收敛必须保留用户分析目标：原因问题至少输出阈值触发、指标关联和根因边界，影响问题至少输出已确认对象和未知范围，趋势问题至少输出时间序列事实和覆盖边界，不得统一退化成事实列表。

展示协议使用有序 `presentation_blocks`，区块类型包括结论、观察事实、原因发现、关系分组、指标趋势、时间线、判断边界、后续检查和告警列表。一次回答可以组合多个区块；告警列表始终是辅助证据，不能覆盖完整分析正文。前端按区块顺序渲染，未知区块安全忽略并保留 `answer` Markdown 作为兼容正文。
- “影响哪些资源”展示客户可读资源名称，不展示内部作用域编码。
- “今天”始终按中国标准时间自然日查询。
- 模型超时和部分工具失败不丢失已取得事实。
- 多轮追问只能引用同一授权会话中的真实事实 ID。
- 工具调用经过注册、权限、范围、预算、重复查询和超时校验。
- Mock、真实 PostgreSQL 和可用条件下的真实外部模型联调均留下独立结果，不互相替代。

## 实施记录

2026年08月09日已完成第一轮完整改造：新增证据工作区和确定性告警关联模块；注册告警详情、告警关联、指标序列和资源时间线四类细粒度只读工具；Runtime 调整为30秒总预算、10次监控查询、10次模型调用并拒绝完全相同的成功查询；Deep Agent Prompt 与两个 Skill 已同步调查假设、关联边界和动态明细要求；消息协议新增调查元数据，前端告警列表按事实 ID 去重。

专项自动化、监控回归、真实 PostgreSQL 和真实外部模型已执行。真实模型能够根据中间事实自主调用新增工具；当前供应商未返回最终结构化终态时，Harness 会按用户要求同时展示告警明细和关联判断。详细结果见 [`自主监控调查型Agent测试用例`](../测试用例/自主监控调查型Agent测试用例.md)。
