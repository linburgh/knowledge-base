# 分析总览与指标详情整改实施记录

## 问题现象

2026年08月01日核查发现，智能分析的分析总览整页显示暂无数据；指标分析列表点击“查看详情”时抛出 `AttributeError: scope_key`。

## 原因分析

### 分析总览

数据库最近 1 小时实际存在 192 条平台指标结果和 9377 条监控事件，但当前没有活动告警。原实现只围绕活动告警组装证据，只有某条指标被活动告警引用时才进入证据链；没有告警时，即使指标已经正常聚合，也会被全部丢弃并返回整页空态。

### 指标详情

指标结果表使用 `scope_key` 表达 `platform` 或 `tenant:<id>` 范围，告警表没有该字段，使用 `resource_code` 保存对应指标范围。详情接口直接把指标查询过滤条件复用于告警查询，导致数据库通用过滤器访问不存在的 `t_monitor_alert.scope_key`。

## 整改内容

- 分析总览按实际授权范围查询对应的 `scope_key`，平台与租户指标不再混用。
- 没有活动告警但存在有效指标时，最新指标直接进入证据链和时间线，分析状态返回“已完成/数据可用”。
- 无活动告警时只表达“当前范围未发现需要处置的告警”，不据此扩大为平台绝对正常；所有授权事实均为空时才返回空态。
- 监控 Agent 的总览合同支持“无告警但有证据”的正常分析态，并返回可信度和事实数量。
- 指标详情查询告警时将指标范围 `scope_key` 映射为告警表 `resource_code`，租户过滤继续使用 `tenant_id`。

## 真实验证

| 验证项目 | 结果 |
| --- | --- |
| 数据库存量 | 最近 1 小时 192 条平台指标、9377 条事件、0 条活动告警 |
| 分析总览 | `completed/ready`，结论为“当前范围未发现需要处置的告警” |
| 分析证据 | 返回 6 条指标证据和 6 条时间线 |

| 自动化回归 | 后端全量 224 项通过，Python 编译和差异检查通过 |
