## 3. 缺口跟踪

### MON-GAP-001：监控页面路由和菜单

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | 前端路由开发 |
| 缺口 | 后端菜单数据尚未包含自主监控菜单，前端无法仅依靠菜单接口进入页面 |
| 前端临时处理 | 仅在前端路由层为两类授权角色提供入口，不能作为最终方案 |
| 后端安排 | 补充菜单、角色菜单关联和监控操作权限数据 |
| 状态 | 已补充 DDL 菜单与角色权限种子，待真实数据库执行验证 |

### MON-GAP-002：采集总览接口

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | 数据采集页面联调 |
| 缺口 | 当前只有事件分页，无法返回采集结论、成功率、状态分布、5 分钟热力图和目标明细 |
| 前端影响 | 不能使用事件分页推算采集全量统计 |
| 后端安排 | 新增 `collection/overview`、`collection/targets/page` 和目标详情接口 |
| 状态 | 待后端补充 |

### MON-GAP-004：通知与规则分页管理

### MON-GAP-005：审计与分析总览接口

| 项目 | 内容 |
| --- | --- |
| 缺口 | 当前监控 API 没有审计分页和分析总览结构化接口 |
| 后端安排 | 复用 `t_audit_log` 增加监控范围查询，新增分析总览 Service/API，返回结论、影响范围、证据链、时间线和建议 |
| 状态 | 待后端补充 |

### MON-GAP-006：总览模块状态

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | 监控总览空数据与异常状态实现 |
| 缺口 | 总览仅返回全局 `data_status`，事件、告警或运行快照任一查询失败都会中断整个接口，前端无法区分模块空数据、加载失败和部分数据过期 |
| 前端影响 | 只能展示整页错误，无法保留成功模块，也无法在刷新失败后提示最后一次成功数据已过期 |
| 后端安排 | 为事件、告警和运行快照增加独立失败收敛，返回 `section_statuses` 和脱敏的 `section_errors` |
| 状态 | 已补充，合同联调通过 |

### MON-GAP-007：总览时间窗口与演示数据

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | 前端真实接口验收 |
| 缺口 | 前端已经调用真实接口，但后端忽略 `time_range`，导致数据库中超过当前窗口的 `demo-review-event-*` 事件、固定容量快照和关联告警仍被总览展示 |
| 前端影响 | 页面看起来仍在展示 Mock 数据，选择“最近 1 小时”等筛选条件不生效 |
| 后端安排 | 接入 `scope_key`、`time_range` 参数，对事件、告警和快照分别按时间字段过滤；精确清理已识别的演示监控数据 |
| 状态 | 已完成 |

### MON-GAP-008：真实采集引擎

| 项目 | 内容 |
| --- | --- |
| 发现阶段 | 清理演示数据后的真实链路复核 |

| 后端安排 | 按需求 2.3.2 实现目标登记、数据库动态配置、公共适配器、周期采集、脱敏校验、幂等写入和采集器自身状态 |
| 状态 | 未完成，待专项实施 |
