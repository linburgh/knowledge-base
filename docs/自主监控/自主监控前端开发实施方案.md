# 自主监控前端开发实施方案

## 1. 文档定位

本文档依据《自主监控需求设计文档》《自主监控界面原型设计稿》《自主监控数据采集方案》和《自主监控后端开发实施方案》编写，用于指导 `knowledge-base-web` 的自主监控页面、组件、状态管理、接口联调、权限控制和验收。

前端只负责查询条件、页面呈现、用户操作和交互状态，不负责指标计算、告警判断、数据聚合、采集任务配置或 Agent 推理。所有图表和列表数据必须来自后端接口，接口失败时展示错误态，不使用演示数据或本地固定统计值兜底。

前端项目目录：`/home/linburgh/workspace/ai-llm/knowledge-base-web`。

固定技术栈：Vue 3、TypeScript、Vite、Element Plus、Bootstrap、Vue Router、Pinia、Axios、ECharts。

## 2. 实施边界

### 2.1 前端负责

- 自主监控一级菜单、路由和页面权限展示。
- 监控总览、数据采集、指标分析、任务监控、告警中心、事件中心、智能分析和审计管理页面。
- 统一范围筛选、时间范围、自动刷新、查询、分页和详情抽屉。
- ECharts 图表初始化、销毁、响应式 resize、Tooltip、图例和空数据展示。
- 告警确认、恢复、规则配置、通知渠道和通知策略等已确认操作。
- 分析对话列表、消息展示、快捷问题、追问和证据引用展示。

### 2.2 前端不负责

- 不在数据采集页面新增、编辑、启停、删除或立即执行采集目标。
- 不根据列表分页数据自行计算总量、成功率、趋势或图表汇总。
- 不直接访问数据库、调用 LLM、调用 Agent 私有工具或实现告警规则。
- 不自动重试、暂停、终止评测任务，不自动修改业务配置。
- 不把自主评测 Agent 当作分析对话 Agent；分析对话统一调用自主监控分析接口。

## 4. 视觉基线

### 4.1 公共样式

优先复用现有公共组件和样式：`QueryBar`、`AppDrawer`、`WorkspaceHeader`、`TrendLineChart`、`StatusPieChart`、`content-card`、`table-card`、`pagination-bar`、`action-links` 和 `drawer-form`。不得为自主监控重新创建一套查询栏、表单、分页或抽屉风格。

- 使用浅色管理后台风格，不使用深色大屏背景。
- 页面基础间距、字体和布局遵循 Bootstrap；交互组件使用 Element Plus。
- 页面区块使用统一标题、说明文字、内容卡片和底部间距。
- 列表字段内容单行省略，完整内容通过 Tooltip 展示。
- 查询条件标签和列表列名统一使用四字名称，并与原型、接口字段保持语义一致。
- 表单标签 13px、控件高度 38px、抽屉表单单列纵向布局、底部按钮右对齐。
- 列表操作使用文本按钮；分页控件使用文本样式，不使用大面积背景按钮。

### 4.2 图表基线

- 图表容器固定最小高度，避免多个图表挤在同一行导致信息堆叠。
- 图例独立布局，状态分布图例位于右上方单独一行，不与主图重叠。
- 主图内不重复放置状态文字，数量通过 Tooltip 展示。
- 无数据、数据不完整、数据过期和接口失败分别展示，不把异常数据画成 0。
- 所有图表使用后端统计接口的完整数据，不使用分页列表反推。
- 图表组件必须在 `onMounted` 初始化、`onBeforeUnmount` 销毁，并监听容器变化执行 `resize`。

## 5. 权限与路由

### 5.1 角色范围

仅允许平台超级管理员和租户管理员进入自主监控。两类角色都具备设计范围内的查看和操作能力：

- 平台超级管理员：平台范围查看和操作，可在授权范围内切换租户范围。
- 租户管理员：当前租户范围查看和操作，不能切换到其他租户。
- 普通用户、组织角色、访客：菜单不可见，直接访问路由进入统一无权限页，接口返回 403 时展示错误提示。

前端权限只控制菜单、按钮和路由表现，后端 Service 的角色、租户和资源范围校验是最终边界。

### 5.2 权限编码

权限编码统一由公共权限模块维护，页面不得散落定义角色判断：

| 权限 | 用途 |
| --- | --- |
| `monitoring:list` | 查看监控页面和列表 |
| `monitoring:detail` | 查看事件、指标、任务、告警和审计详情 |
| `monitoring:alert-action` | 确认、恢复等告警操作 |
| `monitoring:rule-manage` | 新增、编辑、启停告警规则 |
| `monitoring:notification-manage` | 管理渠道和通知策略 |
| `monitoring:analysis` | 查看分析总览和使用分析对话 |

## 7. 公共状态

### 7.1 范围状态

统一维护 `scope_type`、`tenant_id`、`scope_key` 和时间窗口。总览下钻到采集、指标、任务、告警、事件和分析页面时，使用路由 query 传递范围和时间窗口，刷新页面后保持。

### 7.2 刷新状态

监控页面使用统一自动刷新控制：

- 默认刷新间隔由后端或公共配置提供，前端不得在多个页面分别创建定时器。
- 只在页面激活且用户开启自动刷新时轮询。
- 切换路由、页面卸载、浏览器隐藏或接口请求失败时清理或暂停定时器。
- 一次刷新使用同一范围和时间窗口，请求完成后再更新所有图表和列表。
- 失败后展示最近一次成功时间和错误状态，不用旧数据伪装实时数据。

### 7.3 页面状态

每个页面至少维护 `loading`、`error`、`empty`、`partial`、`stale`、`data`、`query`、`page`、`pageSize` 和当前详情对象。抽屉关闭后清理详情数据和错误，防止上一次页面内容残留。

## 8. 页面实施

### 8.1 监控总览

首屏只保留高内聚内容：告警状态、资源容量、异常传播、运行状态和业务状态。

- 告警状态：展示触发中、已确认、已恢复等状态趋势，点击进入告警中心。
- 资源容量：展示关键资源当前容量和趋势，不重复展示业务指标。
- 异常传播：展示异常起点、影响传播、告警触发和恢复状态的关联链路。
- 运行状态：只表达平台服务、外部依赖和监控采集状态。
- 业务状态：只表达问答、异步任务和自主评测状态。
- 顶部提供范围、时间窗口和统一刷新控制。

总览不平铺任务明细、事件明细、评测报告或所有指标趋势；通过文本入口下钻对应模块。

### 8.2 数据采集

页面定位为采集总览，不是采集配置中心：

- 采集结论：整体成功、部分异常、获取失败和最近采集时间。
- 执行成功率：使用统计接口返回的成功率，不从目标列表计算。
- 状态分布：使用带状或环形表达；图例只展示状态名称，鼠标悬停显示数量。
- 采集热力：展示最近 1 小时、5 分钟粒度的采集状态，Tooltip 展示目标名称、时间和状态。
- 目标明细：查询条件使用“目标名称”，支持分页；列表不展示目标编码、版本和 Work 列。
- 目标详情：只展示运行事实、最近状态、错误原因和事件追溯，不显示配置编辑、启停、立即采集或删除按钮。

### 8.3 指标分析

- 指标结论：展示关键指标当前状态和数据完整性。
- 状态趋势：展示 5 分钟粒度状态趋势。
- 域状态图：使用分行布局展示监控域、指标总数、健康率、状态分布和最近更新时间，避免所有内容挤在一行。
- 指标明细：支持指标名称、监控域、状态和时间范围查询分页。
- 无样本、样本不足、过期和采集失败必须使用明确状态，不显示为达标。

### 8.4 任务监控

- 任务结论：展示待处理、运行中、已完成、失败和最老等待等关键结论。
- 状态趋势：展示 5 分钟粒度任务状态变化。
- 工作状态：使用服务状态热力图或状态矩阵表达 Worker 的时间状态，不与任务明细重复。
- 任务明细：查询条件和分页统一，列表不展示 `Work` 列，不提供重试、暂停或终止按钮。

### 8.5 告警中心

使用 `el-tabs` 分为“告警实例”“规则配置”“告警通知”。

- 告警实例：列表查询、分页、严重级别、当前状态、首次发生、最近发生、确认人和详情抽屉。
- 告警操作：按告警状态展示确认、恢复等文本按钮；操作成功后刷新告警详情和总览相关图表。
- 规则配置：支持查询、新增、编辑、启停、版本和审计入口。保存后使用后端返回的新版本，不在前端生成版本号。
- 告警通知：包含渠道配置、通知策略和发送记录；渠道与策略各自提供快速查找和简单分页，卡片行高、底部分页和标题基线保持一致。
- 新增渠道、新增策略：单列纵向表单，标签位于控件上方，底部右对齐，提交期间禁用按钮并防止重复提交。
- 通知失败：仅展示失败原因、状态和重试次数，不改变告警实例状态。

### 8.6 事件中心

- 事件结论：展示事件总量、异常量、最近事件时间和数据完整性。
- 事件趋势：5 分钟粒度折线图。
- 来源分布：展示问答、评测、任务、采集和依赖来源构成。
- 事件明细：支持事件类型、监控域、资源名称、关联标识和时间查询分页。
- 详情抽屉：展示事件 ID、Trace ID、任务 ID、运行 ID、状态和脱敏摘要，不展示完整问题、答案、文档片段、Token 或 API Key。

### 8.7 智能分析

页面包含“分析总览”和“分析对话”两个 Tab。

- 分析总览：展示分析结论、可信度、影响范围、证据链、异常时间线和处理建议。
- 分析对话：复用知识库问答的三栏视觉结构，包含会话列表、消息区和证据引用区。
- 对话历史：通过监控分析会话接口获取，前端不创建本地独立会话存储。
- 发送问题：调用自主监控分析对话接口，展示用户消息、Agent 回复、Agent 标识和证据引用。
- 分析失败：保留原始告警和事件，展示“分析暂不可用”，不伪造回答。
- 不展示“上下文已锁定”等已删除交互，不提供自动修改配置、重试任务或执行处置按钮。

### 8.8 审计管理

- 查询条件只保留已确认字段，不显示关键字查询条件。
- 列表删除“变更摘要”列，使用统一四字列名。
- 审计详情使用统一抽屉表单视觉，展示操作人、操作类型、目标、结果、请求标识、时间和脱敏摘要。
- 审计查询失败、无数据和详情加载失败都提供明确状态。

## 9. API 封装

`src/api/monitoring.ts` 只负责类型化请求，不在页面内拼接 URL 或处理业务判断。接口按以下资源分组：

| 分组 | 前端接口职责 |
| --- | --- |
| 总览 | 查询总览统计和图表数据 |
| 采集 | 采集结论、热力图、目标列表和目标详情 |
| 指标 | 指标状态、趋势、域状态和指标明细 |
| 任务 | 任务结论、趋势、工作状态和任务明细 |
| 告警 | 告警分页、详情、确认/恢复和规则配置 |
| 通知 | 渠道、策略、发送记录和配置保存 |
| 事件 | 事件结论、趋势、来源分布和事件详情 |
| 分析 | 分析总览、会话列表、消息列表和发送消息 |
| 审计 | 审计分页和审计详情 |

统一分页类型：

```ts
interface PageResponse<T> {
  items: T[];
  total: number;
  page: number;
  page_size: number;
}
```

后端接口未提供或字段未冻结时，前端只完成类型和页面骨架，进入联调前必须在联调记录中登记缺口，不能用演示数据替代。

## 10. 图表实现

### 10.1 组件分工

- `MonitoringTrendChart`：折线、面积和多线状态趋势。
- `MonitoringHeatmap`：5 分钟时间桶热力图。
- `MonitoringStatusChart`：状态分布带、环形图和 Tooltip。
- `MonitoringMatrix`：域状态、资源容量和 Worker 状态矩阵。
- `MonitoringPropagation`：异常传播链路，可使用 ECharts Graph 或结构化链路组件。

所有图表组件只接收后端 DTO，颜色、状态和 Tooltip 文案统一调用公共字典与格式化方法。

### 10.2 数据状态

| 后端状态 | 前端表达 |
| --- | --- |
| `ready` | 正常图表 |
| `empty` | 空状态和“暂无数据” |
| `partial` | 图表保留可用数据并展示数据不完整提示 |
| `stale` | 显示过期标识和最近更新时间 |
| `error` | 错误态、重试文本按钮，不绘制健康数据 |

## 11. 联调顺序

1. 路由、菜单、角色和公共字典。
2. 查询栏、分页、抽屉和统一状态组件。
3. 监控总览统计接口和自动刷新。
4. 采集、指标、任务和事件四个查询页面。
5. 告警实例、规则配置和告警操作。
6. 告警通知渠道、策略、发送记录和失败状态。
7. 智能分析总览、会话列表、消息和证据引用。
8. 审计详情、权限边界、异常态和响应式适配。
9. 删除全部演示数据，执行真实接口联调和验收。

每完成一个页面，必须同步更新接口联调记录和测试用例状态；接口失败只展示错误，不静默回退到本地数据。

- 所有图表使用统计接口，不从当前页列表推算。
- 自动刷新统一驱动总览、热力图、告警、资源和异常传播数据。
- 告警确认、恢复、规则保存、通知渠道和策略保存成功后刷新真实数据。
- 通知失败只更新通知状态，不改变告警状态。
- 分析对话由自主监控 Agent 返回，历史会话能够刷新恢复。
- 覆盖加载、空数据、部分数据、过期、接口失败、403、重复提交和抽屉关闭清理。
- 覆盖桌面端、窄屏和图表容器 resize，不出现图例与主图重叠。

### 12.3 交付门禁

- 原型稿、需求文档、接口文档和测试用例字段一致。
- 页面不存在演示数据、固定统计值或接口失败伪造兜底。
- 所有列表列名和查询条件为四字名称。
- 所有时间字段统一调用公共 `formatDateTime`。
- 所有监控图表可通过范围、时间窗口和自动刷新复现。
- 前端验收通过后，记录真实接口、测试数据、权限账号和失败修复项。
