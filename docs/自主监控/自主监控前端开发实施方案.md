# 自主监控前端开发实施方案

## 1. 文档定位

本文档依据《自主监控需求设计文档》《自主监控界面原型设计稿》《自主监控数据采集方案》和《自主监控后端开发实施方案》编写，用于指导 `knowledge-base-web` 的自主监控页面、组件、状态管理、接口联调、权限控制和验收。

前端只负责查询条件、页面呈现、用户操作和交互状态，不负责指标计算、告警判断、数据聚合、采集任务配置或 Agent 推理。所有图表和列表数据必须来自后端接口，接口失败时展示错误态，不使用演示数据或本地固定统计值兜底。

前端项目目录：`/home/linburgh/workspace/ai-llm/knowledge-base-web`。

固定技术栈：Vue 3、TypeScript、Vite、Element Plus、Bootstrap、Vue Router、Pinia、Axios、ECharts。

## 2. 实施边界

### 2.1 前端负责

- 自主监控一级菜单、路由和页面权限展示。
- 监控总览、数据采集、指标分析、任务监控、告警中心、事件中心、智能分析和审计管理页面。
- 统一范围筛选、时间范围、自动刷新、查询、分页和详情抽屉。
- ECharts 图表初始化、销毁、响应式 resize、Tooltip、图例和空数据展示。
- 告警确认、恢复、规则配置、通知渠道和通知策略等已确认操作。
- 分析对话列表、消息展示、快捷问题、追问和证据引用展示。

### 2.2 前端不负责

- 不在数据采集页面新增、编辑、启停、删除或立即执行采集目标。
- 不根据列表分页数据自行计算总量、成功率、趋势或图表汇总。
- 不直接访问数据库、调用 LLM、调用 Agent 私有工具或实现告警规则。
- 不自动重试、暂停、终止评测任务，不自动修改业务配置。
- 不把自主评测 Agent 当作分析对话 Agent；分析对话统一调用自主监控分析接口。

## 4. 视觉基线

### 4.1 公共样式

优先复用现有公共组件和样式：`QueryBar`、`AppDrawer`、`WorkspaceHeader`、`TrendLineChart`、`StatusPieChart`、`content-card`、`table-card`、`pagination-bar`、`action-links` 和 `drawer-form`。不得为自主监控重新创建一套查询栏、表单、分页或抽屉风格。

- 使用浅色管理后台风格，不使用深色大屏背景。
- 页面基础间距、字体和布局遵循 Bootstrap；交互组件使用 Element Plus。
- 页面区块使用统一标题、说明文字、内容卡片和底部间距。
- 列表字段内容单行省略，完整内容通过 Tooltip 展示。
- 查询条件标签和列表列名统一使用四字名称，并与原型、接口字段保持语义一致。
- 表单标签 13px、控件高度 38px、抽屉表单单列纵向布局、底部按钮右对齐。
- 列表操作使用文本按钮；分页控件使用文本样式，不使用大面积背景按钮。
- 左侧导航一级菜单统一展示语义图标；当前一级菜单使用圆角深蓝底色，当前二级菜单使用左侧高亮蓝线和整行深蓝底色，二级菜单保持统一缩进，不以文字颜色替代完整选中态。
- 自主监控查询区必须使用 Element Plus 的 `el-form`/`el-form-item` 承载字段，输入、选择、日期和操作分别使用 `el-input`、`el-select`、`el-date-picker` 和 `el-button`；列表和分页固定使用 `el-table`、`el-table-column`、`el-pagination`，禁止原生表单控件、自绘表格、自绘页码和无实际绑定的占位查询控件。
- 监控总览采用舒展型布局：卡片内容区内边距 24–26px、区块间距 20–22px；运行状态和告警趋势图表高度约 280px，业务状态项不低于 92px，容量卡不低于 124px，异常传播泳道不低于 224px，并保证空态和异常态高度稳定。

### 4.2 图表基线

- 图表容器固定最小高度，避免多个图表挤在同一行导致信息堆叠。
- 图例独立布局，状态分布图例位于右上方单独一行，不与主图重叠。
- 主图内不重复放置状态文字，数量通过 Tooltip 展示。
- 无数据、数据不完整、数据过期和接口失败分别展示，不把异常数据画成 0。
- 所有图表使用后端统计接口的完整数据，不使用分页列表反推。
- 图表组件必须在 `onMounted` 初始化、`onBeforeUnmount` 销毁，并监听容器变化执行 `resize`。

## 5. 权限与路由

### 5.1 角色范围

仅允许平台超级管理员和租户管理员进入自主监控。两类角色都具备设计范围内的查看和操作能力：

- 平台超级管理员：平台范围查看和操作，可在授权范围内切换租户范围。
- 租户管理员：当前租户范围查看和操作，不能切换到其他租户。
- 普通用户、组织角色、访客：菜单不可见，直接访问路由进入统一无权限页，接口返回 403 时展示错误提示。

前端权限只控制菜单、按钮和路由表现，后端 Service 的角色、租户和资源范围校验是最终边界。

### 5.2 权限编码

权限编码统一由公共权限模块维护，页面不得散落定义角色判断：

| 权限 | 用途 |
| --- | --- |
| `monitoring:list` | 查看监控页面和列表 |
| `monitoring:detail` | 查看事件、指标、任务、告警和审计详情 |
| `monitoring:alert-action` | 确认、恢复等告警操作 |
| `monitoring:rule-manage` | 新增、编辑、启停告警规则 |
| `monitoring:notification-manage` | 管理渠道和通知策略 |
| `monitoring:analysis` | 查看分析总览和使用分析对话 |

## 7. 公共状态

### 7.1 范围状态

统一维护 `scope_type`、`tenant_id`、`scope_key` 和时间窗口。总览下钻到采集、指标、任务、告警、事件和分析页面时，使用路由 query 传递范围和时间窗口，刷新页面后保持。

### 7.2 刷新状态

监控页面使用统一自动刷新控制：

- 默认刷新间隔由后端或公共配置提供，前端不得在多个页面分别创建定时器。
- 只在页面激活且用户开启自动刷新时轮询。
- 切换路由、页面卸载、浏览器隐藏或接口请求失败时清理或暂停定时器。
- 一次刷新使用同一范围和时间窗口，请求完成后再更新所有图表和列表。
- 失败后展示最近一次成功时间和错误状态，不用旧数据伪装实时数据。

### 7.3 页面状态

每个页面至少维护 `loading`、`error`、`empty`、`partial`、`stale`、`data`、`query`、`page`、`pageSize` 和当前详情对象。抽屉关闭后清理详情数据和错误，防止上一次页面内容残留。

监控总览现有内容控件统一接入 `module-state/comp.vue`，正式页面只处理三种非正常展示状态：

- `empty`：接口成功但模块数据为空，展示范围和时间窗口说明，不绘制零值图表。
- `error`：首次请求或模块请求失败，展示错误原因和重新加载入口，不使用本地数据兜底。
- `stale`：刷新失败但存在最后成功数据，或接口返回 `partial`、`stale`，展示最后成功时间和重新加载入口，不标记为实时数据。

前端优先读取总览响应可选的 `section_statuses` 和 `section_errors`；后端未返回模块状态时，根据总览 `data_status` 和各模块数组推导。`partial` 在展示层统一映射为 `stale`，正常业务状态中的告警或故障不得误判为接口错误。

## 8. 页面实施

### 8.1 监控总览

首屏只保留高内聚内容：告警状态、资源容量、异常传播、运行状态和业务状态。

- 告警状态：展示触发中、已确认、已恢复等状态趋势，点击进入告警中心。
- 资源容量：使用四张独立卡片展示数据库连接、队列容量、文件存储和向量存储；每张卡片展示使用率、已用/上限、状态、容量进度和 80% 预警位置，不再使用共享坐标轴柱状图。数据库连接卡片表示 PostgreSQL 实例当前连接总数与 `max_connections`，不得解释为单进程连接池容量。
- 异常传播：展示异常起点、影响传播、告警触发和恢复状态的关联链路。
- 运行状态：只表达平台服务、外部依赖和监控采集状态。
- 业务状态：只表达问答、异步任务和自主评测状态。
- 业务状态右上展示“最近更新”并使用 `business_updated_at`，资源容量右上展示“最近采集”并使用 `resource_capacity_updated_at`；统一复用公共 `formatDateTime` 格式，不使用全局时间或前端当前时间替代模块时间。
- 顶部提供范围、时间窗口和统一刷新控制。
- “查看告警详情”“查看采集详情”和“查看事件详情”统一使用蓝色文本链接，悬停颜色加深。

总览不平铺任务明细、事件明细、评测报告或所有指标趋势；通过文本入口下钻对应模块。

### 8.2 数据采集

页面定位为采集总览，不是采集配置中心：

- 采集结论：整体成功、部分异常、获取失败和最近采集时间。
- 执行成功率：使用统计接口返回的成功率，不从目标列表计算。
- 状态分布：使用带状或环形表达；图例只展示状态名称，鼠标悬停显示数量。
- 图例文案：状态趋势、执行结果和采集概览的图例固定使用 `正常、待采、部分、失败、过期、暂无` 六个双字短名称；ECharts Series、Tooltip、查询选项、目标明细和详情仍使用完整状态名称，短名称不得写回公共字典或接口数据。
- 采集热力：展示最近 1 小时、5 分钟粒度的采集状态，Tooltip 展示目标名称、时间和状态。
- 目标明细：查询条件使用“目标名称”，支持分页；列表不展示目标编码、版本和 Work 列。
- 目标详情：只展示运行事实、最近状态、错误原因和事件追溯，不显示配置编辑、启停、立即采集或删除按钮。

### 8.3 指标分析

- 指标结论：展示关键指标当前状态和数据完整性。
- 状态趋势：展示 5 分钟粒度状态趋势。
- 域状态图：使用分行布局展示监控域、指标总数、健康率、状态分布和最近更新时间，避免所有内容挤在一行。
- 指标明细：支持指标名称、监控域、状态和时间范围查询分页。
- 无样本、样本不足、过期和采集失败必须使用明确状态，不显示为达标。

### 8.4 任务监控

- 任务结论：展示待处理、运行中、已完成、失败和最老等待等关键结论。
- 状态趋势：展示 5 分钟粒度任务状态变化；无趋势数据时仍初始化 ECharts，保留坐标系、待处理/运行中/已完成/失败四项图例和固定图表高度，使用图内提示说明暂无任务状态事件，Series 保持空数组且不生成零值点。
- 工作状态：使用紧凑状态列表展示 Worker 名称、消费数量、消费能力、运行状态、最近心跳和汇总，不与任务明细重复；空闲 Worker 保持健康语义。
- 任务明细：支持任务名称、任务类型、当前状态、工作节点和创建时间查询分页；列表展示任务名称、任务类型、当前状态、执行进度、等待时长、开始时间、结束时间和详情入口，不展示 Worker 列，不提供重试、暂停或终止按钮。
- 任务详情：只读展示真实任务字段和脱敏执行证据时间线，自主评测任务可追溯 Agent 执行阶段。

### 8.5 告警中心

使用 `el-tabs` 分为“告警实例”“规则配置”“告警通知”。

- 告警实例：列表查询、分页、严重级别、当前状态、首次发生、最近发生、确认人和详情抽屉。
- 告警操作：按告警状态展示确认、恢复等文本按钮；操作成功后刷新告警详情和总览相关图表。
- 规则配置：支持查询、新增、编辑、启停、版本和审计入口。新增入口命名为“新增”，放在查询条件栏的查询操作组内；区块标题旁不再放置新增按钮。保存后使用后端返回的新版本，不在前端生成版本号。操作列固定在右侧，按钮按“查看 / 编辑”“启用 / 停用”“审计”展示并保持单行，不显示“启用规则”“停用规则”“查看审计”等长标签。
- 告警通知：包含渠道配置、通知策略和发送记录；渠道与策略各自提供快速查找和简单分页，卡片行高、底部分页和标题基线保持一致。
- 新增渠道、新增策略：单列纵向表单，标签位于控件上方，底部右对齐，提交期间禁用按钮并防止重复提交。
- 通知失败：仅展示失败原因、状态和重试次数，不改变告警实例状态。

### 8.6 事件中心

- 页面结构：按照交互稿实现重要事件、事件趋势与来源分布、事件明细三层结构；趋势与来源区域使用 `1.35:0.65` 布局并适配窄屏。
- 重要事件：参照“任务结论”实现紧凑横向结论条，左侧展示状态标签，中间展示事件主结论、类型、领域和详情入口，右侧分为上下两层；上层展示数量、影响对象、当前状态或关联情况，下层单独展示发生时间或最近事件时间，标签和值保持同一行。事件总数、异常事件数、关联数量和来源数量复用公共 `numeric-value` 组件，分别按调用位置配置最大位数，超限时由组件统一显示 `9N+` 和实际值 Tooltip；图表比例继续使用真实数值。直接消费后端返回的 `focus_event`；不存在重要事件时依据 `data_status` 区分“未发现异常”和“暂无事件”，不在前端推导事件优先级、恢复状态或平台运行结论。
- 事件趋势：使用 ECharts 展示 5 分钟粒度的全部事件和异常事件折线。
- 来源分布：使用后端统一返回的任务运行、Worker、告警、采集与依赖四类中文映射及颜色，不在页面维护原始来源名称映射。
- 事件明细：支持事件类型、监控领域、资源名称和发生时间查询分页；查询区不展示关联标识。列表展示发生时间、事件类型、监控领域、资源名称、事件状态和操作入口，不展示事件内容，并继续在详情中展示关联标识用于追溯。
- 详情抽屉：展示事件 ID、事件内容、Trace ID、任务 ID、运行 ID、状态和脱敏摘要；事件内容保持自然换行，不展示完整问题、答案、文档片段、Token 或 API Key。
- 状态处理：总览、分页和详情均调用真实接口；空数据展示空态，加载失败展示错误状态，不使用本地 Mock 或失败兜底数据。

### 8.7 智能分析

页面包含“分析总览”和“分析对话”两个 Tab。

- 分析总览：展示分析结论、可信度、影响范围、证据链、运行或异常时间线和处理建议。页面直接消费后端返回的 `presentation_state`、`impact_overview` 和 `action_overview`，不根据列表长度推断业务状态。
- 多态展示：`normal` 显示“未发现已确认影响、当前无需处置、持续观察”；`warning` 显示“待验证影响、人工核查”；`alert` 显示“已确认影响、优先处理”；`unknown` 显示“无法判断、补充证据”。影响或建议无明细时使用合同中的语义化标题和说明，不使用统一 `el-empty` 文案。
- 时间标题：正常态使用“运行时间”，其他状态使用“异常时间”；可信度仅在后端返回数值时展示，证据不足时不显示伪造百分比。
- 分析对话：与知识库问答共同复用 `src/components/chat-workspace/comp.vue` 通用问答工作区组件，采用会话列表与消息区双栏配置，不常驻证据引用区；助手消息安全渲染中文 Markdown，并对结论引用块、标题、列表、编号步骤和表格提供统一视觉层级。异常范围、快捷问题和每轮证据入口通过组件插槽注入；证据集合必须绑定当前回答，不得使用最后一轮回答或分析总览证据替代。
- 问答视觉：字号、行高、圆角、边框、阴影、消息气泡、输入焦点和会话选中态全部由通用组件统一维护；正文为 14px，普通辅助信息不低于 13px。分析页面仅维护欢迎提示、快捷问题、证据入口等业务插槽样式，不得重新缩小通用组件字体或改变三栏密度。
- 证据抽屉：顶部展示证据总数、直接证据、关联证据和上下文证据；查询条件为证据内容、证据类型和证据等级，桌面端参照 `tmp/image.png` 横向单行排列，每项使用“左侧标签＋右侧字段”，查询与重置按钮紧随字段组，窄屏按字段组换行。明细展示证据编号、证据类型、证据内容、证据等级、发生时间和操作入口，支持每页 5、10、20 条、文本式分页与行内详情。
- 数据接入：当前消息查询接口已经返回各轮真实授权证据，前端先在该真实集合内完成查询与分页，不增加演示数据或失败兜底；待 `/monitoring/analysis/messages/{id}/evidence` 独立分页接口提供后切换为服务端查询和分页。
- 对话历史：通过监控分析会话接口获取，前端不创建本地独立会话存储。
- 会话操作：复用通用问答组件的快速查找和操作菜单；快速查找将名称关键词传入 `GET /monitoring/analysis/conversations?keyword=...`；操作菜单提供重命名和删除，重命名调用 `PUT /monitoring/analysis/conversations/{conversation_id}`，删除经二次确认后调用 `DELETE /monitoring/analysis/conversations/{conversation_id}`，不得只修改前端内存数据。
- 发送问题：调用自主监控分析对话接口，展示用户消息、智能体回复、智能体标识和证据引用；实际查询起止时间统一标注“中国标准时间”。
- 异步反馈：提交后立即清空输入框并插入临时用户消息，显示证据分析中的等待状态；完成后刷新服务端消息，失败时按“不覆盖新草稿”原则恢复原问题，发送期间拦截重复提交。
- 时间范围：会话标题下方优先展示最近一轮回答实际解析出的自然语言时间标签和起止时间，未发送问题时展示会话默认范围。
- 结果状态：从消息元数据读取正常、预警、异常或无法判断结论；证据区只展示本轮授权工具返回的引用，限制说明保留在回答正文中。
- 分析失败：保留原始告警和事件，展示“分析暂不可用”，不伪造回答。
- 不展示“上下文已锁定”等已删除交互，不提供自动修改配置、重试任务或执行处置按钮。

### 8.8 审计管理

- 查询条件只保留已确认字段，不显示关键字查询条件。
- 列表删除“变更摘要”列，使用统一四字列名。
- 审计详情使用统一抽屉表单视觉，展示操作人、操作类型、目标、结果、请求标识、时间和脱敏摘要。
- 审计查询失败、无数据和详情加载失败都提供明确状态。

## 9. API 封装

`src/api/monitoring.ts` 只负责类型化请求，不在页面内拼接 URL 或处理业务判断。接口按以下资源分组：

| 分组 | 前端接口职责 |
| --- | --- |
| 总览 | 查询总览统计和图表数据 |
| 采集 | 采集结论、热力图、目标列表和目标详情 |
| 指标 | 指标状态、趋势、域状态和指标明细 |
| 任务 | 任务结论、趋势、工作状态和任务明细 |
| 告警 | 告警分页、详情、确认/恢复和规则配置 |
| 通知 | 渠道、策略、发送记录和配置保存 |
| 事件 | 重要事件、趋势、来源分布和事件详情 |
| 分析 | 分析总览、会话列表、消息列表和发送消息 |
| 审计 | 审计分页和审计详情 |

统一分页类型：

```ts
interface PageResponse<T> {
  items: T[];
  total: number;
  page: number;
  page_size: number;
}
```

后端接口未提供或字段未冻结时，前端只完成类型和页面骨架，进入联调前必须在联调记录中登记缺口，不能用演示数据替代。

| --- | --- |

## 14. 差异核对

本轮按交互稿逐项核对自主监控页面，统一执行以下修复：

- 指标、任务、告警和事件总览必须调用各自统计接口，禁止从当前分页列表推算总数、异常数、来源分布或状态分布。
- 指标趋势由真实指标时间桶统计；任务趋势由真实任务状态事件统计；空数组显示空状态，不再补 `[0]`、固定时间轴或“暂无数据”假点。
- 任务明细排除 Worker 心跳事件，Worker 状态由总览接口返回最新事实，避免一条运行事实同时出现在两个区域。
- 自主监控所有查询区复用平台管理公共 `QueryBar` 和 Element Plus 表单、输入、选择、按钮；按钮顺序统一为查询、重置、刷新。
- 区块标题和说明使用纵向标题组，行间距统一为 6px，标题组与图表或列表内容保留独立下间距。
- 生产源码不得保留演示数组、Mock 响应、静态统计值或接口失败后的伪造兜底；测试目录中的接口拦截数据只能服务隔离自动化测试，不进入生产构建。
