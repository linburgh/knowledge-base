# 监控数据

## 1. 设计说明

本文档只定义自主监控的数据模型、字段、索引、状态和数据关系，不执行 DDL，不新增数据库表，不进入后端编码。数据库设计评审通过后，再将确认结果统一落入 `scripts/db/data_table_ddl.sql`。

自主监控数据分为五类：

| 数据类别 | 作用 | 保留原则 |
| --- | --- | --- |
| 运行事实 | 保存问答、评测、文档、索引、Worker 和服务的结构化事件 | 不保存完整问题、答案、文档片段、Token 或 API Key |
| 统计指标 | 保存固定时间窗口内的指标聚合结果 | 保留样本数、分子、分母、数据状态和规则版本 |
| 告警证据 | 保存规则触发、恢复和关联证据 | 必须能回溯事件、指标、任务、Trace ID 或版本 |
| 配置规则 | 保存采集目标、指标定义、阈值和通知策略 | 数据库为唯一配置源，变更必须审计 |
| 管理审计 | 保存菜单、配置、告警处理和查询操作 | 记录操作人、范围、结果和脱敏摘要 |

## 2. 命名约定

- 表名统一使用 `t_monitor_` 前缀，业务主键统一为 `id bigint generated by default as identity primary key`。
- 所有表包含 `created_at`；有状态或可修改配置的表增加 `updated_at`。
- 关联字段只保存业务关联 ID，不创建数据库外键；租户边界和数据存在性由 Service / Repository 校验。
- 时间统一使用 `timestamptz`；耗时统一使用毫秒，计数统一使用整数，比例统一使用小数或百分数并明确单位。
- 事件、指标和告警均保存 `tenant_id`；平台级数据使用空租户范围，但查询必须经过权限范围判断。

## 3. 数据关系

```text
采集目标 ──采集事件配置──> 运行事件 ──聚合──> 指标结果
                                  │              │
                                  └────规则判断──> 告警实例
                                                   │
                                          告警证据/通知记录

指标定义 ──指标规则版本──> 指标结果 ──规则版本──> 告警实例
```

## 4. 事件数据

### 4.1 事件主表

建议表名：`t_monitor_event`

| 字段 | 类型建议 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | bigint identity | 是 | 数据库主键 |
| `event_id` | varchar(128) | 是 | 外部幂等事件 ID，全局唯一 |
| `event_type` | varchar(96) | 是 | 如 `qa_completed`、`evaluation_case_completed` |
| `source_type` | varchar(32) | 是 | `api`、`db`、`worker`、`agent`、`probe`、`middleware` |
| `source_code` | varchar(128) | 是 | 采集目标或服务编码 |
| `tenant_id` | bigint | 否 | 租户范围，平台事件为空 |
| `kb_id` | bigint | 否 | 知识库范围 |
| `task_id` | bigint | 否 | 异步任务范围 |
| `run_id` | bigint | 否 | 评测运行范围 |
| `trace_id` | varchar(128) | 否 | 链路追踪 ID |
| `request_id` | varchar(128) | 否 | 请求 ID |
| `status` | varchar(32) | 是 | `started`、`completed`、`failed` 等事件状态 |
| `stage` | varchar(64) | 否 | 业务阶段 |
| `occurred_at` | timestamptz | 是 | 事件实际发生时间 |
| `duration_ms` | bigint | 否 | 阶段耗时 |
| `error_category` | varchar(64) | 否 | 结构化失败分类 |
| `payload` | jsonb | 是 | 脱敏结构化字段，不存自然语言业务正文 |
| `采集状态` | varchar(32) | 是 | `ready`、`partial`、`error` |
| `created_at` | timestamptz | 是 | 入库时间 |

约束和索引：

- `event_id` 必须建立唯一索引，重复事件只保留一次，不重复聚合。
- 按 `(event_type, occurred_at)`、`(tenant_id, occurred_at)`、`(trace_id)`、`(task_id, occurred_at)` 建立查询索引。
- `payload` 只保存字段白名单；服务端拒绝完整问题、完整答案、文档片段、密码、Token 和 API Key。
- 事件数据按时间分区或归档，归档策略由保留周期配置决定。

### 4.2 状态快照

建议表名：`t_monitor_state_snapshot`

用于保存服务、数据库、依赖服务和 Worker 的最新状态，不替代事件主表。

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `resource_type` | varchar(32) | `service`、`database`、`dependency`、`worker` |
| `resource_code` | varchar(128) | 资源编码 |
| `tenant_id` | bigint | 租户范围，可为空 |
| `status` | varchar(32) | `healthy`、`idle`、`busy`、`stale`、`stopped`、`error`、`unknown` |
| `status_value` | jsonb | 探测结果摘要、版本、实例等结构化字段 |
| `checked_at` | timestamptz | 最近采集时间 |
| `expires_at` | timestamptz | 数据新鲜度截止时间 |
| `error_category` | varchar(64) | 采集失败分类 |
| `updated_at` | timestamptz | 更新时间 |

同一资源和租户范围只保留一条当前快照；历史变化通过事件主表记录。

## 5. 指标数据

### 5.1 指标定义

建议表名：`t_monitor_metric_definition`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `metric_code` | varchar(128) | 指标编码，全局唯一 |
| `metric_name` | varchar(128) | 中文指标名称 |
| `metric_domain` | varchar(32) | `platform`、`task`、`qa`、`evaluation`、`resource` |
| `unit` | varchar(32) | `count`、`percent`、`ms`、`bytes`、`status` |
| `formula` | text | 计算口径说明，不存可执行代码 |
| `dimensions` | jsonb | 支持的统计维度 |
| `minimum_sample_count` | integer | 最小样本数 |
| `status` | varchar(32) | `active`、`inactive` |
| `version` | integer | 指标定义版本 |
| `created_at` / `updated_at` | timestamptz | 创建和更新时间 |

### 5.2 指标结果

建议表名：`t_monitor_metric_value`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `metric_code` | varchar(128) | 对应指标编码 |
| `metric_version` | integer | 指标定义版本 |
| `tenant_id` | bigint | 租户范围 |
| `kb_id` | bigint | 知识库范围 |
| `scope_key` | varchar(255) | 统一范围键，防止不同维度拼接不一致 |
| `window_start` / `window_end` | timestamptz | 统计窗口 |
| `bucket_size` | varchar(32) | 时间桶大小 |
| `sample_count` | bigint | 样本数 |
| `numerator` / `denominator` | numeric | 比例指标分子和分母 |
| `metric_value` | numeric | 指标值 |
| `unit` | varchar(32) | 指标单位 |
| `data_status` | varchar(32) | `ready`、`partial`、`empty`、`stale`、`error` |
| `assessment_status` | varchar(32) | `达标`、`预警`、`不达标`、`无法判定` |
| `source_summary` | jsonb | 来源事件数量、失败来源和采集时间 |
| `rule_version` | integer | 使用的考核规则版本 |
| `calculated_at` | timestamptz | 计算时间 |

唯一性建议为 `metric_code + scope_key + window_start + window_end + rule_version`。页面只查询聚合结果，不根据分页明细重新计算指标。

## 6. 规则配置

### 6.1 采集目标

建议表名：`t_monitor_gather_target`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `target_code` | varchar(128) | 目标编码，全局唯一 |
| `target_name` | varchar(128) | 中文目标名称 |
| `target_type` | varchar(32) | `method`、`api`、`db`、`worker`、`probe` |
| `target_locator` | jsonb | 目标模块、类、方法或连接标识，不存密码和 Token |
| `enabled` | boolean | 是否启用 |
| `tenant_id` | bigint | 目标所属范围 |
| `version` | integer | 配置版本 |
| `effective_at` | timestamptz | 生效时间 |
| `created_by` / `updated_by` | varchar(128) | 操作人 |
| `created_at` / `updated_at` | timestamptz | 时间 |

采集目标表中的目标编码、启用状态和配置版本属于系统发布及运维流程使用的后端配置字段，不作为自主监控用户页面的目标明细展示列。用户页面通过目标名称、采集类型、最近采集、采集耗时、数据状态和目标详情查看运行事实。

### 6.2 采集动作

建议表名：`t_monitor_gather_action`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `target_id` | bigint | 采集目标 ID |
| `action_code` | varchar(128) | 如 `api.http`、`db.execute`、`worker.lifecycle` |
| `hook_position` | varchar(32) | `before`、`after`、`error`、`finally` |
| `field_mapping` | jsonb | 目标参数、返回值、异常和耗时到事件字段的映射 |
| `event_type` | varchar(96) | 输出事件类型 |
| `sampling_rate` | numeric | 采样比例 |
| `enabled` | boolean | 是否启用 |
| `version` | integer | 配置版本 |

监控采集装饰器只关联 `target_code`，每次调用根据目标编码从数据库读取当前有效配置；不加载全部配置，不使用配置文件作为长期配置源。

### 6.3 指标规则

| 字段 | 类型建议 | 说明 |

| `recovery_threshold` | numeric | 恢复阈值 |

| `window_seconds` | integer | 时间窗口 |
| `enabled` | boolean | 是否启用 |
| `version` | integer | 规则版本 |
| `effective_at` | timestamptz | 生效时间 |

## 7. 告警数据

### 7.1 告警实例

建议表名：`t_monitor_alert`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `alert_key` | varchar(255) | 规则、范围和资源组成的去重键 |
| `rule_id` | bigint | 指标规则 ID |
| `metric_code` | varchar(128) | 触发指标编码 |
| `alert_title` | varchar(255) | 中文告警标题 |
| `severity` | varchar(32) | `紧急`、`严重`、`警告`、`提示` |
| `status` | varchar(32) | `firing`、`acknowledged`、`resolved`、`closed` |
| `tenant_id` / `kb_id` | bigint | 数据范围 |
| `resource_type` / `resource_code` | varchar(64/128) | 资源范围 |
| `current_value` / `threshold` | numeric | 触发时数值和阈值 |
| `sample_count` | bigint | 触发时样本数 |
| `first_fired_at` / `last_fired_at` | timestamptz | 首次和最近触发时间 |
| `firing_count` | integer | 重复触发次数 |
| `acknowledged_by` / `acknowledged_at` | varchar/timestamptz | 确认信息 |
| `resolved_at` / `closed_at` | timestamptz | 恢复和关闭信息 |
| `analysis_summary` | text | 监控智能体生成的脱敏摘要 |
| `created_at` / `updated_at` | timestamptz | 时间 |

### 7.2 告警证据

建议表名：`t_monitor_alert_evidence`

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `alert_id` | bigint | 告警实例 ID |
| `evidence_type` | varchar(32) | `event`、`metric`、`task`、`trace`、`version` |
| `evidence_id` | varchar(128) | 证据对象 ID |
| `summary` | varchar(500) | 脱敏摘要 |
| `occurred_at` | timestamptz | 证据发生时间 |
| `created_at` | timestamptz | 关联时间 |

告警详情必须通过证据表展示原始事件、指标窗口、任务、评测运行、Worker、索引版本和 Trace ID 的关联关系，不能只保存一段自然语言结论。

## 8. 通知审计

### 8.1 通知记录

建议表名：`t_monitor_notification_record`

保存告警触发、持续、恢复和失败通知的发送事实：告警 ID、通知渠道、接收范围、模板版本、发送状态、失败分类、发送时间和重试次数。通知记录不能保存 Token、Webhook 密钥或完整业务内容。

### 8.2 操作审计

复用现有 `t_audit_log`，`target_type` 增加 `monitor_target`、`monitor_metric_rule`、`monitor_alert`、`monitor_notification` 等类型。记录菜单访问、系统采集配置发布、指标规则变更、告警确认、关闭、静默和权限变更；采集配置不作为业务用户页面操作对象。

## 9. 数据保留

| 数据 | 在线保留 | 归档建议 | 删除要求 |
| --- | --- | --- | --- |
| 原始事件 | 30 天 | 归档 180 天 | 到期按事件类型和租户范围清理 |
| 指标结果 | 180 天 | 汇总到日粒度长期保留 | 删除前保留规则版本和统计口径 |
| 告警实例 | 1 年 | 可选长期归档 | 不删除未关闭告警 |
| 告警证据 | 与告警实例一致 | 与告警一起归档 | 告警删除前不得孤立删除 |
| 配置和审计 | 长期 | 不归档或独立归档 | 保留版本、操作人和生效时间 |

以上周期只是设计默认值，具体保留期限需结合租户合规要求、存储成本和运维策略审核确认。

## 10. 审核事项

1. 是否确认自主监控使用独立一级菜单 `monitoring`，与平台管理同级。
2. 是否确认事件原始数据、指标结果、告警实例和告警证据分表保存。
3. 是否确认指标规则、采集目标和采集动作全部数据库配置化。
4. 是否确认事件不保存完整问题、答案和文档片段。
5. 是否确认原始事件、指标和告警的默认保留周期。
