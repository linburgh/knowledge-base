# 自主评测前端开发实施方案

## 1. 文档定位

本文档依据《知识库问答评测Agent需求与实施方案.md》《自主评测模块原型设计.md》和自主评测交互原型编写，用于指导 `knowledge-base-web` 的页面、组件、权限、接口联调和验收。

自主评测前端是知识库问答评测 Agent 的平台管理入口，不实现评测编排、指标计算、问题生成或本地 RAG。前端只提交任务配置、触发运行、查询后端结果并展示状态。

前端项目目录：`/home/linburgh/workspace/ai-llm/knowledge-base-web`。

固定技术栈：Vue 3、TypeScript、Vite、Element Plus、Bootstrap、Vue Router、Pinia、Axios。

页面视觉必须严格遵循《自主评测模块原型设计.md》第 8 章的尺寸、颜色、间距、字体、抽屉和响应式基线。实现时优先复用平台公共样式（`QueryBar`、`AppDrawer`、`drawer-form`、`content-card`、`table-card`、`pagination-bar`、`action-links`），不得在自主评测页面重新定义一套等价但不一致的表单、列表或分页样式。

## 2. 页面范围和产品流程

### 2.1 页面范围

新增平台管理路由 `/platform/evaluations`，包含：

- 评测任务查询、分页和列表操作。
- 新增评测任务抽屉。
- 外部问题文件导入和 Agent 自主生成配置。
- 执行、运行状态、删除和结果查看。
- 评测报告、指标详情、失败样品和逐题结果。
- 单题结果详情抽屉。
- 优化建议、“帮我优化”、候选配置、同批问题复测和保存草稿。
- 加载、空数据、错误、无权限、执行中和无法判定状态。

### 2.2 完整用户流程

```text
新增评测任务
  -> 选择导入问题或 Agent 生成
  -> 保存任务
  -> 执行评测
  -> 查询运行进度
  -> 查看评测报告和逐题结果
  -> 查看优化建议
  -> 帮我优化
  -> 生成候选方案并使用同一批问题复测
  -> 对比优化前后指标
  -> 用户确认后保存为草稿
```

前端不得提供自动发布正式问答配置、自动修改文档或自动重建索引的按钮。

## 3. 前置门禁和联调原则

前端编码前必须完成原型和接口评审，冻结字段、状态、权限编码、分页结构和错误码。后端接口未提供时可以先完成结构稿，但进入联调后必须移除演示数据、固定统计值和 `setTimeout` 模拟逻辑。

必须遵守：

- 报告指标直接使用后端统计接口，不根据当前页逐题结果推算全量指标。
- 问题生成、指标计算、门禁判定和优化建议由后端 Agent 完成。
- 文件预览可以是前端临时解析结果，但最终校验和问题数量以后端为准。
- 接口失败展示错误状态，不使用本地任务、固定报告或伪造进度兜底。
- 前端权限只控制交互表现，后端 `p_super_admin`、`tenant_admin` 角色及租户范围校验是最终边界。

## 4. 页面、组件和状态结构

```text
src/
├── views/platform/evaluations/index.vue
├── components/evaluations/
│   ├── EvaluationFilters.vue
│   ├── EvaluationTable.vue
│   ├── EvaluationCreateDrawer.vue
│   ├── EvaluationResultDrawer.vue
│   ├── EvaluationCaseDrawer.vue
│   └── OptimizationDrawer.vue
├── api/evaluation.ts
├── types/evaluation.ts
├── stores/evaluation.ts
└── constants/dictionary.ts
```

### 4.1 组件职责

- `index.vue`：路由页面、查询条件、分页、抽屉开关和页面级错误状态。
- `EvaluationFilters`：评测名称、知识库名、执行状态、评测结论四个查询条件。
- `EvaluationTable`：任务列表、状态、结论、文本操作按钮和分页。
- `EvaluationCreateDrawer`：创建任务、来源切换、文件校验和门禁配置。
- `EvaluationResultDrawer`：运行信息、评测报告、指标、优化建议和逐题分页。
- `EvaluationCaseDrawer`：单题完整答案、引用、终止原因、耗时和错误。
- `OptimizationDrawer`：问题证据、候选方案、复测状态、前后指标和草稿保存。

### 4.2 页面状态

Pinia 或页面组合式状态至少维护：查询参数、分页、列表数据、列表加载/错误状态、当前任务、当前运行、运行轮询句柄、逐题查询参数、当前单题、当前优化方案和复测状态。

抽屉关闭时清理对应详情和请求错误；离开页面时停止运行和复测轮询，重新进入或打开详情时根据后端状态恢复查询。

## 5. 路由、菜单和权限

### 5.1 路由

路由固定为 `/platform/evaluations`，仅在后端菜单接口返回 `platform_evaluations` 且路由守卫通过时显示。无权限直接访问时展示统一无权限页面，不渲染任务和报告内容。

### 5.2 权限编码

| 操作                     | 权限                  |
| ------------------------ | --------------------- |
| 查看列表                 | `evaluation:list`     |
| 新增                     | `evaluation:create`   |
| 修改未执行任务           | `evaluation:update`   |
| 执行                     | `evaluation:execute`  |
| 查看结果                 | `evaluation:detail`   |
| 删除                     | `evaluation:delete`   |
| 生成优化、复测、保存草稿 | `evaluation:optimize` |

使用公共 `v-permission` 或等效权限指令隐藏操作按钮；收到后端 403 时清理 loading 状态并展示无权限提示，不能只依赖前端按钮隐藏。

### 5.3 公共字典和格式化

角色、问题来源、任务状态、运行状态、运行结论、逐题状态、指标结果、优化优先级、置信度和方案状态统一维护在公共字典模块。页面不重复定义编码与中文映射。

创建时间、更新时间、执行时间等统一调用 `formatDateTime`，格式固定为 `YYYY年MM月DD日 HH:mm:ss`。长文本单行省略，使用 Element Plus Tooltip 展示完整内容。

## 6. API 封装和数据类型

`src/api/evaluation.ts` 只负责 Axios 请求和类型化响应：

```ts
getEvaluationPage(params);
createEvaluation(data);
getEvaluation(id);
createEvaluationRun(id);
getEvaluationRuns(id, params);
getEvaluationRun(id, runId);
getEvaluationCases(id, runId, params);
getEvaluationCase(id, runId, caseId);
deleteEvaluation(id);
createOptimization(id, runId);
retestOptimization(id, runId, optimizationId);
saveOptimizationDraft(id, runId, optimizationId);
```

`src/types/evaluation.ts` 至少定义：`EvaluationTask`、`EvaluationRun`、`EvaluationMetric`、`EvaluationCaseResult`、`EvaluationReport`、`OptimizationSuggestion`、`OptimizationComparison`、分页响应和统一业务错误。状态使用联合类型或公共字典类型，不使用任意字符串。

统一分页响应：

```ts
interface PageResponse<T> {
  items: T[];
  total: number;
  page: number;
  page_size: number;
}
```

## 7. 任务列表

### 7.1 查询条件

查询标签必须和原型、接口保持一致，并使用四字名称：

| 页面标签 | 请求字段     | 后端含义                                       |
| -------- | ------------ | ---------------------------------------------- |
| 评测名称 | `name`       | 模糊查询任务名称                               |
| 知识库名 | `kb_id`      | 指定知识库                                     |
| 执行状态 | `status`     | 全部、未执行、待执行、执行中、已完成、执行失败、已取消 |
| 评测结论 | `conclusion` | 通过、不通过、无法判定                         |

点击查询将页码重置为 1；点击重置清空查询条件并重新请求；回车查询可作为辅助行为。筛选项来自真实接口或公共字典，不能在页面散落重复定义。

### 7.2 列表字段和分页

展示评测名称、知识库名称、问题来源、问题数量、执行状态、最新结论、最近执行时间、创建人和操作。列表必须同时具备查询条件和分页，上一页、下一页、页码和每页条数使用文本样式按钮。

分页切换和每页条数变化都请求 `/page`，不得从当前页数据推算 `total`。查询失败显示错误和重新加载；无数据显示空状态和新增入口。

操作列在任务没有运行记录时增加“修改”文本按钮；编辑抽屉复用新增任务表单和校验规则，标题显示“编辑评测任务”，保存调用更新接口。编辑加载失败、保存失败和状态冲突均保留抽屉内容并展示后端错误。

操作规则：

- `not_started` 且没有任何运行记录：允许修改、执行、查看配置和删除；修改成功后任务仍为未执行。
- `pending` 且已经存在运行记录：允许查看执行过程和结果，执行、删除禁用。
- `running`：展示执行中和进度，执行、删除禁用。
- `completed`：允许再次执行、查看结果和删除。
- `failed` / `cancelled`：展示失败或取消原因，允许再次执行、查看结果和删除。
- 修改接口和 Service 必须再次校验没有运行记录；历史运行任务不能通过修改接口改变配置。

## 8. 新增任务抽屉

### 8.1 表单

字段按评测配置对象组织：

- 评测名称、知识库。
- 知识库使用 Element Plus 远程搜索选择框：复用 `GET /api/v1/knowledge-bases/page`，传入 `name`、`status=active`、`page=1` 和 `page_size`；不得在页面初始化时一次性加载固定数量作为完整候选集。
- 问题来源：`imported` 外部导入或 `generated` Agent 生成。
- 导入模式：TXT/JSON/JSONL 文件、问题预览和识别数量。
- 生成模式：问题数量、业务范围来源、业务范围描述和生成补充要求。
- 执行参数：并发数、单题超时、重试次数和是否保留会话。执行参数必须放在独立参数面板中，每项按“参数名称 + Element Plus 控件”排列；数字输入框统一宽度和高度，保持会话开关与数字控件同高对齐，窄屏切换为单列。执行用户不作为页面字段展示，后端未收到 `execution.user_id` 时默认使用当前登录用户 ID；租户角色只能使用当前租户用户。
- 指标门禁：指标名、比较符、阈值以及默认配置提示。

配置字段必须对应后端 `EvaluationConfig`，不能把问题类型、产品分类等业务枚举写死在页面。

知识库远程选择必须覆盖打开下拉、输入关键词防抖、加载中、无匹配、请求失败、清空关键词和编辑任务回填场景。选项只展示当前用户权限范围内的有效知识库，提交仍只使用知识库数字 ID。

### 8.2 导入和生成规则

前端校验文件扩展名、大小、空文件、编码和可读性，并展示临时预览。后端最终校验问题文本、`case_id`、重复问题、可选标准答案、期望文档和 `must_contain` 字段。

生成模式要明确提示：问题可依据外部描述、知识库或两者生成；生成问题会标记 `question_source=generated` 和 `question_basis`。超出知识库范围的问题不能由前端过滤，因为它们用于测试覆盖率和拒答能力。

### 8.3 提交

保存期间禁用按钮，防止重复提交。成功后关闭抽屉、清理表单、刷新列表并提示成功；失败展示后端错误，不把本地表单对象插入任务列表。取消关闭时根据项目公共表单规范处理未保存提示。

## 9. 执行和运行状态

点击“执行”先二次确认，再调用 `POST /{id}/runs`。后端返回 `run_id` 和 `pending` 后，前端立即结束提交 loading，不等待模型执行。

创建运行成功后，前端打开“评测执行过程”居中面板，同时刷新任务列表；面板展示运行编号、当前阶段、总题数、已完成题数、异常题数、进度、已用时间和最近更新时间。关闭面板只退出查看，不中断后端任务；完成、失败或取消后启用“查看评测结果”。点击“查看评测结果”时先自动关闭执行过程面板，再打开结果详情抽屉，并重新加载任务列表、运行详情和逐题结果。

运行状态按 3 至 5 秒轮询运行详情，展示：

- `pending`：等待执行。
- `running`：已完成数量、总问题数和最近更新时间。
- `completed`：总体结论、报告和优化建议。
- `failed`：错误摘要、已完成逐题数和重试执行入口。
- `cancelled`：取消原因和重新执行入口。

达到终态后停止轮询；连续请求失败展示错误和重试。页面离开、抽屉关闭或组件卸载时清理轮询，不能产生重复请求。

## 10. 结果详情和逐题结果

### 10.1 结果抽屉层级

结果右侧抽屉按以下顺序展示：

1. 运行基本信息：任务、运行编号、知识库、配置版本、问题数量、执行人、开始和结束时间。
2. 评测报告：数据集摘要、总体结论、核心发现、风险和失败样品摘要。
3. 指标摘要和指标详情：统一展示中文指标名称（包括总问题数、召回率@K、成功率、错误率、降级率、引用率和响应时间等）、实际值、门禁值、比较符、样本数、是否合格或无法评估；不展示英文标识列。
4. 优化建议：问题证据、建议措施、影响指标、优先级、置信度和人工确认要求。
5. 逐题结果：问题、答案摘要、来源、状态、检索命中、引用数、是否降级、耗时和错误原因。

报告中的知识库、Embedding、Rerank、Chat Model 只显示后端脱敏后的配置摘要，不展示 Token、API Key 或本机路径。

### 10.2 指标展示

基础问题模式展示成功率、错误率、降级率、引用率、有引用回答率、P50/P95/P99、超时率和 Agent 完成率。需要标准答案、标准文档或人工标注的 Recall@K、MRR、NDCG、Answer Correctness 等展示“无法评估”和原因，不显示伪造数值。

### 10.3 逐题查询和单题详情

逐题结果使用独立接口分页，可按状态筛选失败、超时、降级、引用异常和门禁不通过样品。点击“查看”调用单题详情接口，打开右侧抽屉展示问题、来源、生成依据、回答、引用资料、执行状态、终止原因、检索命中、耗时、错误编码、错误摘要和单题指标。

答案和引用资料限制高度并内部滚动；加载失败展示重试；列表长文本不换行，使用 Tooltip 或详情抽屉查看完整内容。

## 11. 优化建议和“帮我优化”

### 11.1 优化建议卡片

后端返回的建议卡片必须展示：问题现象、指标实际值、门禁值、失败数量、关联问题编号、建议调整的参数/Prompt/检索链路/文档处理、预期影响指标、优先级、置信度和是否需要人工确认。

涉及配置发布、索引重建、文档修改、知识库范围或业务规则时显示人工确认提示。前端不能把建议直接写入正式配置。

### 11.2 候选方案抽屉

点击“帮我优化”调用生成候选方案接口，展示：

- 产生建议的指标证据和失败题号。
- 当前配置与候选配置差异。
- 预计影响指标。
- 是否重建索引、是否需要人工确认。
- “开始复测”和“结束”按钮。

接口加载或失败时显示对应状态，不展示静态候选方案。

### 11.3 同批问题复测

点击“开始复测”后调用复测接口，明确提示使用原运行同一批问题。复测过程中禁用重复按钮并轮询复测运行状态。完成后展示：

- 优化前后指标对比。
- 方案状态：建议采用、效果不明显或效果退化。
- 响应时间、引用率等可能变差的指标。
- 是否需要人工确认和是否需要重建索引。

只有后端判定可采用时展示“保存为草稿”。复测未提升、关键指标无法计算或出现退化时不得显示“建议采用”。

复测启动后优化抽屉保留候选方案和复测状态；复测运行进入终态后，前端必须重新查询原优化记录，回填 `after_metrics` 和方案状态，再根据后端判定显示“保存为草稿”。不得因关闭抽屉或仅更新运行对象而丢失候选方案状态。

### 11.4 保存草稿

点击“保存为草稿”调用接口，成功后显示已保存并禁用重复保存；失败保留候选方案并允许重试。保存草稿不修改正式问答配置，不显示发布成功。

## 12. 页面状态和错误处理

每个数据区域必须覆盖：加载中、空数据、请求失败、无权限、执行中、复测中、无法判定和成功终态。

| 场景         | 前端表现                           |
| ------------ | ---------------------------------- |
| 列表加载     | Skeleton 或加载状态，禁用重复查询  |
| 列表为空     | 空状态和新增评测入口               |
| 接口失败     | 错误说明和重新加载，不显示演示数据 |
| 403          | 无权限提示，清理操作状态           |
| 运行失败     | 错误摘要、部分结果和重新执行入口   |
| 指标不可用   | 显示无法评估及后端原因             |
| 优化复测中   | 候选方案保留，按钮禁用并展示进度   |
| 保存草稿失败 | 保留表单和候选方案，支持重试       |

Axios 错误使用公共错误处理器；字段校验错误定位到字段，业务错误展示后端摘要，未知错误使用统一提示。不能使用本地统计值或接口失败后的伪造兜底。

## 13. 实施顺序和联调记录

1. 冻结原型、公共字典、类型、接口路径和权限编码。
2. 实现路由、菜单、权限和任务列表真实分页。
3. 接入新增任务、文件上传/预览和删除。
4. 接入创建运行、状态轮询和运行历史。
5. 接入评测报告、中文指标详情和逐题分页；指标表不展示英文标识列。
6. 接入单题详情、失败样品和引用展示。
7. 接入优化建议、候选方案、同批复测和保存草稿。
8. 联调加载、空、错误、无权限、取消和恢复进入页面状态。
9. 移除所有演示数据和原型模拟逻辑，完成真实环境验收。

接口缺失必须记录在自主评测联调记录中：接口路径、请求参数、响应范围、错误码、影响页面、建议责任方和当前状态。不得静默跳过或使用前端演示数据替代。

## 14. 测试和验收

### 14.1 单元和组件测试

- 查询条件、分页、重置和后端参数映射。
- 状态、结论、指标结果和时间格式化。
- 文件校验、问题来源切换和门禁表单。
- 运行轮询启动、终止、失败和卸载清理。
- 报告指标无法评估、失败样品和单题详情。
- 优化候选方案、复测前后指标、退化判断和草稿按钮。

### 14.2 业务验收

- 平台超级管理员和当前租户的 `tenant_admin` 能够完成“新增 → 执行 → 查看报告 → 查看逐题 → 帮我优化 → 复测 → 保存草稿 → 删除”。
- 两种问题来源都能创建任务，且来源和生成依据正确展示。
- 运行中不能重复执行或删除，离开页面后任务仍可继续并可恢复查询。
- 没有标准标注的高级指标显示无法评估，不伪造数值。
- 接口失败、无权限和空数据均有明确页面状态。
- 无自主评测权限的角色无法查看页面数据和操作接口；租户角色仅能查看当前租户数据。

### 14.3 构建检查

修改前端源码后执行：

```bash
npm run format:check
npm run type-check
npm run build
```

Vue、TypeScript 和 CSS 保持多行可读格式；格式化不得改变接口参数、权限判断和业务逻辑。
