# 角色菜单操作权限矩阵

## 1. 文档目的

本文用于评审当前系统中不同角色的菜单、页面和操作权限关系。

权限分为两层：

- 菜单 / 页面权限：角色是否可以看到菜单并进入页面。
- 页面操作权限：角色进入页面后可以执行哪些操作。

页面操作权限以操作编码为准，初始化数据维护在 `scripts/db/data_table_dml.sql`。

### 3.4 绑定规则

1. 同一业务操作存在多个入口时，所有入口都必须绑定同一个操作编码，包括表格操作按钮、下拉菜单项、抽屉按钮、弹窗确认按钮和快捷入口。
2. “查询”“重置”“刷新”、分页、排序、展开/收起、关闭和普通详情查看等通用控件不绑定 `v-permission`；页面能否进入由菜单权限和路由守卫控制。
3. 页面访问权限不等同于操作权限。页面可访问但没有新增、编辑或删除权限时，只隐藏对应操作入口。
4. `v-permission` 只控制前端展示，不替代后端接口权限校验；后端仍必须使用对应的 `@require_action()` 或 Service 权限校验。
5. 创建和编辑表单的“保存”按钮必须分别绑定创建或编辑权限，不能只绑定打开表单的入口。
6. 删除、移除、撤销和重新索引等破坏性或状态变更操作，必须绑定按钮本身，并在点击后继续处理确认和后端错误响应。
7. `v-permission` 默认使用 `effect = 'remove'`；需要保留但禁止操作时使用 `effect = 'disabled'`，并确保控件同步提供禁用态样式和无障碍属性。

## 6. 授权约束

1. 操作授权必须绑定到页面菜单下的操作记录。
2. 角色没有页面菜单权限时，即使存在操作授权，也不能进入页面或执行操作。
3. 页面操作权限不能突破当前租户、组织和知识库的数据范围。
4. 前端按钮展示权限和后端接口操作权限使用同一操作编码。
5. 初始化数据可以重复执行，已存在的操作和授权恢复为 `active`。
6. 本矩阵是当前初始授权方案，后续业务评审可以细化角色权限，但必须同步修改 DML、接口权限说明和前端权限字典。
