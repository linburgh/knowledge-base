# 知识库问答配置后端配合改造方案

## 1. 方案目标

为知识库“问答”模块右侧配置滑块提供后端能力，支持知识库级问答配置的查询、草稿保存、发布、恢复默认、变更摘要、检索测试、Rerank 连接测试和 Prompt 预览。

本方案只描述后端配合改造，不改变问答模块的单一入口。前端从问答页面打开配置滑块，所有配置接口均以 `kb_id` 作为资源边界。

## 2. 改造边界

### 2.1 涉及范围

- 知识库问答配置查询和版本管理。
- 配置参数校验、全局边界校验和生效方式判断。
- 草稿与已发布版本的保存。
- 发布时创建文档重新入库、重新索引任务。
- 检索测试、Rerank 连接测试和 Prompt 预览。
- 配置读取适配现有问答 Agent、Retriever、Rerank 和回答链路。
- 权限、审计、并发发布和异常处理。

### 2.2 不涉及范围

- 不在后端新增第二套问答入口。
- 不把服务地址、Token、API Key、模型密钥下放到知识库界面。
- 不由前端直接访问向量库、Embedding 或 Rerank 服务。
- 不在本次改造中重写现有 LangGraph 问答 Agent。
- 不在配置发布接口中同步执行耗时的全量索引。

## 3. 后端分层改造

遵循项目调用方向：

```text
API → Service → DB / RAG / 外部模型服务
```

### 3.1 API 层

使用 `app/api/v1/knowledge_base/qa_config.py`，只负责：

- 解析路径参数、查询参数和请求体。
- 获取当前用户和租户上下文。
- 调用 Service。
- 转换响应模型和分页结果。
- 不直接访问数据库、向量库或模型服务。

### 3.2 Service 层

建议新增 `app/core/services/knowledge_base/qa_config.py`，负责：

- 校验 `kb_id` 是否属于当前租户。
- 校验当前用户是否拥有查看、编辑、发布权限。
- 合并系统默认配置、已发布配置和当前草稿。
- 校验参数之间的关系，例如分块重叠小于分块大小、最终返回数量不大于候选数量。
- 计算配置变更摘要和索引影响范围。
- 在事务中保存草稿、发布版本和索引任务记录。
- 编排检索测试、Rerank 测试和 Prompt 预览。

### 3.3 DB 层

建议新增按表拆分的 DB 模块：

- `app/db/knowledge_base/qa_config.py`：配置版本、配置内容，以及发布、恢复默认和失败审计。
- 复用现有文档、索引任务和知识库模块查询影响范围。

DB 层只负责持久化和查询，不生成自然语言，不拼接 Prompt，不判断 HTTP 权限。

### 3.4 RAG 和外部服务适配

- Retriever 根据已解析的知识库配置执行 Top-K、阈值、检索方式和混合权重。
- Rerank 适配器读取平台级服务配置和知识库级模型选择，服务地址仍来自 `app.yaml` / 环境变量。
- Prompt 预览复用正式回答链路的 Prompt 组装方式，但使用草稿配置和测试问题，不写入正式会话。
- Embedding 模型连接、维度和服务凭据继续由平台配置管理，知识库界面通过文本框输入模型标识；服务端校验该标识属于平台已发布且可用模型，配置保存到 `document.embedding_model`，发布时同步更新知识库当前模型并触发新索引代次。

## 4. 数据模型建议

### 4.1 知识库问答配置版本表

建议表名：`t_knowledge_base_qa_config_version`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint identity primary key | 主键 |
| `kb_id` | bigint | 知识库标识 |
| `version_no` | integer | 知识库内递增版本号 |
| `status` | varchar(20) | `draft`、`published`、`archived` |
| `config_json` | jsonb | 配置快照，不保存密钥 |
| `change_summary_json` | jsonb | 变更摘要和生效影响 |
| `requires_reindex` | boolean | 是否需要重新索引 |
| `affected_document_count` | integer | 受影响文档数量 |
| `created_by` | bigint | 创建人 |
| `published_by` | bigint | 发布人，可为空 |
| `published_at` | timestamptz | 发布时间，可为空 |
| `created_at` | timestamptz | 创建时间 |
| `updated_at` | timestamptz | 更新时间 |

约束建议：

- 同一 `kb_id` 同时只能存在一个有效草稿。
- 同一 `kb_id` 同时只能存在一个已发布版本。
- 不创建实际数据库外键，关联完整性由 Service / DB 层保证。
- `config_json` 只保存允许的知识库级参数，禁止保存密码、Token、API Key 和绝对路径。

### 4.2 配置审计表

建议表名：`t_knowledge_base_qa_config_audit`，记录动作类型、版本号、操作人、前后摘要、结果和失败原因，用于追溯配置发布行为。

### 4.3 索引任务衔接

配置发布不直接执行全量索引，发布事务提交后创建现有索引任务。任务至少包含：`kb_id`、配置版本号、任务类型、文档数量、状态、错误信息和执行时间。

### 4.4 索引代次和旧会话定位

`generation-001` 不直接作为临时变量使用，建议新增表 `t_knowledge_base_index_version` 保存索引代次和生命周期：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint identity primary key | 索引版本主键 |
| `kb_id` | bigint | 知识库标识 |
| `generation` | varchar(64) | 业务索引号，例如 `generation-001` |
| `config_version_id` | bigint | 创建该索引时使用的问答配置版本 |
| `status` | varchar(20) | `building`、`active`、`retired`、`failed` |
| `vector_collection` | varchar(255) | 向量库集合或命名空间 |
| `created_at` | timestamptz | 创建时间 |
| `activated_at` | timestamptz | 切换为当前索引的时间 |
| `retired_at` | timestamptz | 允许清理的时间 |

还需要在现有表增加索引版本字段：

| 表 | 字段 | 用途 |
|---|---|---|
| `t_knowledge_base` | `active_index_version_id` | 当前新会话默认使用的索引版本 |
| `t_conversation` | `index_version_id` | 会话创建时冻结的索引版本，旧会话据此查询旧索引 |
| `t_conversation` | `qa_config_version_id` | 会话创建时冻结的问答配置版本 |
| `t_document_chunk` | `index_version_id` | 标记 Chunk 属于哪个索引版本，避免重建时覆盖旧 Chunk |
| `t_indexing_task` | `index_version_id` | 标记索引任务正在构建哪个索引版本 |
| `t_conversation_message` | `index_version_id` | 保存该条问答实际使用的索引版本，便于审计和重新生成 |

处理方式如下：

```text
发布 v4
  → 创建 generation-002，状态 building
  → 生成 Chunk 并写入 generation-002
  → 生成向量并写入独立集合
  → 构建完成后将 generation-002 改为 active
  → 更新 t_knowledge_base.active_index_version_id
  → 新会话读取 generation-002
  → 旧会话仍读取 t_conversation.index_version_id = generation-001
```

`t_document_chunk` 如果继续使用关系表保存 Chunk，查询时必须带上 `index_version_id` 条件；向量库则使用 `vector_collection` 或等价命名空间隔离。旧索引在旧会话有效期或保留期内不能清理。

## 5. 接口建议

接口路径仅作为设计建议，最终以现有 API 版本规范为准。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/knowledge-bases/{kb_id}/qa-config` | 获取已发布配置、草稿和权限信息 |
| `PUT` | `/api/v1/knowledge-bases/{kb_id}/qa-config/draft` | 保存或覆盖当前草稿 |
| `GET` | `/api/v1/knowledge-bases/{kb_id}/qa-config/changes` | 获取前后版本变更摘要 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/publish` | 校验并发布草稿 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/save-and-publish` | 在同一事务中保存配置并发布 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/reset` | 恢复为系统默认配置草稿 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/retrieval-test` | 执行临时检索测试 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/rerank-test` | 测试 Rerank 服务连接 |
| `POST` | `/api/v1/knowledge-bases/{kb_id}/qa-config/prompt-preview` | 使用草稿配置生成预览 |

所有接口必须返回统一错误结构。测试接口必须标记为临时操作，不写入正式问答记录和自主评测结果。

## 6. 配置结构和校验

配置按以下顶层分组保存：

```json
{
  "document": {},
  "retrieval": {},
  "rerank": {},
  "answer": {},
  "agent": {}
}
```

核心校验包括：

- 分块大小大于 0，分块重叠大于等于 0 且小于分块大小。
- 检索 Top-K、候选数量、最终返回数量必须在平台全局上下限内。
- 最终返回数量不能大于 Rerank 候选数量。
- 关键词权重必须在 0%～100% 之间。
- Agent 步骤数、工具调用次数、超时、重试次数和 Graph recursion limit 不得超过全局上限。
- 输入的 Embedding / 选择的 Rerank 模型必须是平台已发布模型。
- `document.embedding_model` 必须是非空模型标识，发布前校验模型与当前 Embedding 服务配置兼容；模型切换必须标记 `requires_reindex=true`。
- Prompt 长度、变量和禁止内容必须通过服务端校验。
- 所有配置文本统一拒绝控制字符、零宽字符、双向控制字符和 BOM；模型标识等标识型字段只允许字母、数字及 `.`、`-`、`_`，Prompt、回答规则和测试问题保留正常标点与换行。
- 发布时重新校验，不能只依赖前端校验结果。

## 7. 发布和生效策略

```text
读取配置 → 编辑草稿 → 服务端校验 → 生成变更摘要
    → 保存草稿 → 发布事务
        → 写入已发布版本
        → 写入审计记录
        → 创建索引任务（如需要）
        → 新会话读取新配置
```

“保存并发布”必须调用 `save-and-publish` 原子接口，不能由前端先调用草稿接口、再调用发布接口。该接口在同一个数据库事务中完成配置合并与校验、草稿写入、已发布版本切换、审计记录和索引任务创建；任一步失败都整体回滚。单独的草稿保存和单独的草稿发布接口继续保留，用于分别执行两个操作。

- 文档处理、分块参数和 `document.embedding_model` 发布后标记 `待重建索引`，新索引完成前保留旧索引可用；只有索引切换为 `active` 后才更新知识库当前向量模型。
- 检索、重排、回答和 Agent 参数在发布成功后供新问答会话读取。
- 已开始的问答会话使用启动时解析出的配置快照，不中途切换配置。
- 发布失败时保留草稿，不覆盖当前已发布版本。
- 使用版本号或乐观锁避免两个管理员互相覆盖草稿。

## 8. 权限和安全

- 查看、编辑、发布、测试和 Prompt 预览分别进行权限判断。
- 所有查询和写入都必须校验 `kb_id` 的租户边界。
- Rerank、Embedding、LLM 的服务凭据只能从后端安全配置读取。
- Prompt 预览不得绕过正式内容安全策略和工具调用权限。
- 发布、恢复默认、测试失败和索引任务创建必须记录日志和审计信息。

## 9. 异常处理

| 场景 | 后端处理 |
|---|---|
| 配置不存在 | 返回系统默认配置并标记为未发布 |
| 参数校验失败 | 返回字段级错误，不保存发布结果 |
| 无知识库权限 | 返回统一无权限错误，不泄漏配置内容 |
| Rerank 不可用 | 返回连接失败详情，是否降级由正式配置决定 |
| Prompt 预览超时 | 终止临时请求，不写入会话，返回可识别错误 |
| 发布并发冲突 | 返回版本冲突，要求重新加载最新草稿 |
| 索引任务创建失败 | 发布版本保留，状态标记为待重试并记录原因 |

## 10. 验收重点

- 从问答页面打开右侧滑块后，能够读取当前知识库配置。
- 草稿、已发布版本和恢复默认行为可追溯。
- 配置发布不影响其他知识库。
- 分块配置发布能够正确触发索引任务，而不是同步阻塞请求。
- Rerank 服务地址仍使用 Ollama 平台配置，不允许前端提交密钥。
- LangGraph Agent 能读取已发布的 Agent 参数并执行递归限制、超时和降级策略。
