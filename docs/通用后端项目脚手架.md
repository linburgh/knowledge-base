# 通用后端项目脚手架

## 1. 文档目标

本文定义一个不依赖具体业务领域的 Python 后端工程骨架，用于快速搭建具备以下能力的项目：

- FastAPI HTTP 服务。
- YAML 分组配置和类型校验。
- 异步数据库访问。
- 清晰的 API、Service、DB 分层。
- 统一认证、异常和日志。
- 单元测试与生产部署。

本文不包含具体业务实体、接口、数据库表或业务规则。

## 2. 技术基线

| 类别 | 推荐技术 |
|---|---|
| Python | 3.10 或更高版本 |
| Web 框架 | FastAPI |
| 本地服务 | Uvicorn |
| 生产服务 | Gunicorn + UvicornWorker |
| 配置 | YAML + Pydantic 类型校验 |
| 数据库 | SQLAlchemy Core + databases |
| HTTP Client | httpx |
| 测试 | unittest / IsolatedAsyncioTestCase |
| 日志 | 标准 logging 或 Loguru |
| 项目管理 | uv |

新项目应固定 Python 和依赖版本，避免开发、测试、生产环境使用不同运行时。

## 4. 分层职责

### 4.1 API 层

`app/api/v1` 负责：

- 解析 HTTP 请求。
- 获取认证上下文。
- 调用 Service。
- 将业务异常转换为 HTTP 响应。
- 返回稳定的接口协议。

API 层不得直接访问数据库或承载复杂业务逻辑。

### 4.2 Service 层

`app/core/services` 负责：

- 业务参数校验。
- 业务流程编排。
- 事务边界。
- 调用 DB 层或外部服务。
- 将底层异常转换为业务异常。

Service 不应依赖 FastAPI 的 Request、Response 或 HTTPException。

### 4.3 DB 层

`app/db` 负责：

- SQLAlchemy Table 定义。
- 查询和持久化函数。
- 单一、原子的数据库操作。

DB 层不得处理 HTTP、展示文案或跨资源业务流程。

### 4.4 Schema 层

`app/schemas` 存放：

- 请求模型。
- 响应模型。
- 分页协议。
- 稳定的内部数据协议。

字段名、层级、类型、枚举和必填规则应由代码及设计文档确定。

### 4.5 Common 层

`app/core/common` 只存放跨模块基础能力：

- 认证信息解析。
- 统一异常。
- 日志初始化。
- 时间、JSON、脱敏等纯工具函数。

不要把领域逻辑堆积到 Common。

### 6.1 uv 项目管理

项目统一使用 `uv` 管理 Python 版本、虚拟环境、依赖和锁文件。

依赖声明源为：

```text
pyproject.toml
```

锁定文件为：

```text
uv.lock
```

`requirements.txt` 只作为兼容导出文件，用于不支持 `uv` 的部署环境，不作为日常开发的依赖编辑入口。

推荐初始化和安装方式：

```bash
uv python install
uv sync
```

新增运行依赖：

```bash
uv add fastapi
```

新增开发依赖：

```bash
uv add --dev ruff
```

导出兼容 `requirements.txt`：

```bash
uv export --no-hashes --format requirements-txt > requirements.txt
```

本地启动：

```bash
ENVIRONMENT=development \
OS_CONFIG_DIR="$(pwd)/etc" \
uv run uvicorn app.main:app \
  --host 127.0.0.1 \
  --port 28003
```

约束：

- 不直接手工编辑 `uv.lock`。
- 新增依赖优先使用 `uv add`，不要同时手改 `pyproject.toml` 和 `requirements.txt`。
- CI、开发和生产应使用同一份 `uv.lock`，避免依赖漂移。
- `.python-version` 固定项目 Python 版本。

### 6.2 VS Code 调试配置

本地开发建议在项目根目录创建：

```text
.vscode/launch.json
```

用于通过 VS Code Python 调试器启动 FastAPI / Uvicorn。新版 Python 调试器应使用 `debugpy`，不要继续使用即将弃用的 `python` 类型。

示例：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "FastAPI: uvicorn",
      "type": "debugpy",
      "request": "launch",
      "module": "uvicorn",
      "args": [
        "app.main:app",
        "--host",
        "127.0.0.1",
        "--port",
        "28003",
        "--reload"
      ],
      "console": "integratedTerminal",
      "justMyCode": true,
      "env": {
        "ENVIRONMENT": "development",
        "OS_CONFIG_DIR": "${workspaceFolder}/etc",
        "PYTHONPATH": "${workspaceFolder}"
      }
    }
  ]
}
```

说明：

- `module` 使用 `uvicorn`，避免写死虚拟环境中的可执行文件路径。
- `OS_CONFIG_DIR` 指向工作区下的 `etc`，服务读取 `${OS_CONFIG_DIR}/app.yaml`。
- `PYTHONPATH` 指向工作区根目录，保证 `app` 包可被正确导入。
- `--reload` 仅用于开发调试，生产环境不启用。
- 调试前应先执行 `uv sync` 创建 `.venv` 并安装依赖。

## 7. 应用入口

`app/main.py`：

```python
import os
from pathlib import Path

from fastapi import FastAPI

from app.api.v1 import api_router
from app.config import CONF, configure
from app.core.common.log import setup as log_setup
from app.db import setup as db_setup
from app.db import shutdown as db_shutdown
from app.types import constants


async def on_startup() -> None:
    configure("app")
    Path(CONF.default.log_dir).mkdir(parents=True, exist_ok=True)
    log_setup(
        Path(CONF.default.log_dir).joinpath(CONF.default.log_file),
        debug=CONF.default.debug,
        level=CONF.default.log_level,
    )
    await db_setup()


async def on_shutdown() -> None:
    await db_shutdown()


environment = os.getenv("ENVIRONMENT", "development")

app = FastAPI(
    title=constants.PROJECT_NAME,
    on_startup=[on_startup],
    on_shutdown=[on_shutdown],
    docs_url=None if environment == "production" else "/docs",
    redoc_url=None if environment == "production" else "/redoc",
    openapi_url=None if environment == "production" else "/openapi.json",
)

app.include_router(api_router, prefix=constants.API_PREFIX)
```

### 9.2 配置示例

`etc/app.yaml.example`：

```yaml
default:
  environment: development
  debug: false
  log_dir: ./log
  log_file: app.log
  log_level: INFO
  database_url: sqlite:///./data/app.db
  dev_user_id: dev-user
  http_trust_env: false

```

真实密码、Token 和密钥不得提交到仓库，应由环境变量或密钥管理系统注入。

### 9.3 配置分组

配置系统参考 `security-agent-demo` 的写法，使用 `Opt / Group / Configuration` 组织配置项。每个配置模块声明：

- `GROUP_NAME`
- `ALL_OPTS`

每个配置项使用 `Opt` 单独声明名称、描述、类型和默认值：

```python
from pydantic import StrictBool, StrictStr

from app.config.base import Opt


debug = Opt(
    name="debug",
    description="Enable debug mode",
    schema=StrictBool,
    default=False,
)

log_dir = Opt(
    name="log_dir",
    description="Log directory",
    schema=StrictStr,
    default="./log",
)

GROUP_NAME = __name__.split(".")[-1]
ALL_OPTS = (
    debug,
    log_dir,
)
```

新增配置组后在 `app/config/__init__.py` 注册。

关键配置应在启动阶段校验，缺失时立即失败。

### 9.4 配置入口

`app/config/__init__.py` 负责集中注册配置组：

```python
import os

from app.config.base import Configuration, Group

from . import default


CONF = Configuration()


def configure(project: str = "app", setup: bool = True) -> Configuration:
    conf_modules = (
        (default.GROUP_NAME, default.ALL_OPTS),
    )
    groups = [Group(*item) for item in conf_modules]
    CONF(groups)
    if setup:
        CONF.setup(project, os.environ.copy())
    else:
        for group in CONF.values():
            for opt in group.values():
                opt.load(None)
    return CONF


configure(setup=False)
```

约定：

- 应用启动时调用 `configure("app")`。
- 普通模块读取 `CONF.default.xxx`。
- `app.yaml` 不存在时启动失败；本地开发需要从 `etc/app.yaml.example` 复制出 `etc/app.yaml` 后再启动。
- 不要在业务代码中直接解析 YAML。

## 10. 数据库骨架

### 10.1 连接管理

`app/db/base.py` 参考 `security-agent-demo` 使用模块级 `DATABASE` 和 `ContextVar DB` 维护异步连接。

```python
from contextvars import ContextVar

from databases import Database, DatabaseURL

from app.config import CONF


DATABASE: Database | None = None
DB: ContextVar[Database | None] = ContextVar("app_db", default=None)


async def setup() -> None:
    db_url = DatabaseURL(CONF.default.database_url)

    global DATABASE
    DATABASE = Database(db_url)
    await DATABASE.connect()


async def inject_db() -> None:
    if DATABASE is None:
        await setup()
    DB.set(DATABASE)
```

DB 函数通过 `check_db_connected` 注入连接上下文：

```python
@check_db_connected
async def get_resource(resource_id: str):
    db = DB.get()
    return await resource_db.get(db, resource_id)
```

### 10.2 调用边界

```text
API -> Service -> DB Function -> Database
```

事务边界放在 Service：

```python
async with db.transaction():
    await resource_db.create(db, values)
    await audit_db.append(db, event)
```

### 10.3 DDL 管理

所有新增或修改 DDL 集中维护在：

```text
scripts/db/data_table_ddl.sql
```

不要在业务目录、测试目录和多个文档目录维护重复 DDL。

若数据库要求继承默认配置，DDL 不应显式声明存储引擎、字符集或排序规则。

## 11. API、Service、DB 模板

### 11.1 API

```python
from fastapi import APIRouter, HTTPException

from app.core.common.exception import BusiException
from app.core.services import resource as resource_service


router = APIRouter()


@router.get("/{resource_id}")
async def get_resource(resource_id: str):
    try:
        return await resource_service.get_resource(resource_id)
    except BusiException as exc:
        raise HTTPException(status_code=exc.status_code, detail=str(exc))
```

### 11.2 Service

```python
from app.core.common.exception import BusiException
from app.db import resource as resource_db
from app.db.api import check_db_connected
from app.db.base import DB


@check_db_connected
async def get_resource(resource_id: str):
    if not resource_id:
        raise BusiException("resource_id 不能为空")

    row = await resource_db.get(DB.get(), resource_id)
    if row is None:
        raise BusiException("资源不存在", status_code=404)
    return dict(row)
```

### 11.3 DB

```python
from sqlalchemy import select

from app.db.models import Resource


async def get(db, resource_id: str):
    query = select([Resource]).where(Resource.c.resource_id == resource_id)
    return await db.fetch_one(query)
```

## 12. 外部 HTTP 服务

外部服务调用应封装在独立 Client 或 Service 中，不要散落在 API 层。

统一处理：

- Base URL。
- Path、Query、Body 参数。
- 认证 Header。
- 连接和读取超时。
- 状态码检查。
- JSON 格式检查。
- 敏感字段脱敏。
- 业务异常转换。

示例：

```python
import httpx

from app.core.common.exception import BusiException


async def get_remote_resource(resource_id: str):
    try:
        async with httpx.AsyncClient(timeout=8, trust_env=False) as client:
            response = await client.get(
                f"https://service.example/api/v1/resources/{resource_id}"
            )
        response.raise_for_status()
        return response.json()
    except Exception as exc:
        raise BusiException(f"外部服务调用失败: {type(exc).__name__}")
```

是否读取系统代理必须明确配置，不要依赖运行机器的 `HTTP_PROXY` 和 `NO_PROXY` 碰巧正确。

## 13. 认证

认证信息必须来自请求上下文或可信 Token。

禁止：

- 接受 Body 中的当前操作者 ID。
- 信任前端传入的权限结论。
- 在生产环境回退到开发身份。

开发身份回退必须同时满足：

- `ENVIRONMENT=development`
- 请求没有正式 Authorization。
- 本地配置明确提供开发身份。

## 14. 异常处理

统一业务异常：

```python
class BusiException(Exception):
    def __init__(self, message: str, status_code: int = 400, payload: dict | None = None):
        super().__init__(message)
        self.message = message
        self.status_code = status_code
        self.payload = payload

    def __str__(self) -> str:
        return self.message

    def to_dict(self) -> dict:
        result = dict(self.payload or ())
        result["message"] = self.message
        return result
```

要求：

- DB 和外部服务异常在 Service 转成业务异常。
- API 层只负责业务异常到 HTTP 状态码的映射。
- 底层堆栈、SQL、密码和内部地址不得直接返回客户端。

## 15. 日志

至少记录：

- Request ID 或 Trace ID。
- 接口路径和处理耗时。
- 外部服务名称、耗时和状态码。
- SQL 执行摘要。
- 事务失败原因。
- 关键状态变化。

不得记录：

- 密码。
- Token。
- 完整证件号。
- 未脱敏联系方式。
- 数据库连接密码。

## 16. 会话和审计

需要会话历史时，建议持久化：

- `session_id`
- `user_id`
- `role`
- `content`
- 结构化 metadata
- 创建时间

需要审计时，审计表至少记录：

- 操作者。
- 操作类型。
- 目标类型和目标 ID。
- 请求摘要。
- 执行结果。
- Request ID。
- 创建时间。

## 20. Gunicorn 示例

```python
import os


bind = f"0.0.0.0:{os.environ.get('APP_PORT', '28003')}"
workers = int(os.environ.get("WORKERS_NUM", "2"))
```

## 21. 新模块开发顺序

新增一个普通业务模块：

1. 在 `app/db/models.py` 定义 Table。
2. 在 `app/db/<module>.py` 实现数据库函数。
3. 在 `app/core/services/<module>.py` 实现业务校验和编排。
4. 在 `app/schemas/<module>.py` 定义接口协议。
5. 在 `app/api/v1/<module>.py` 注册接口。
6. 在 `app/api/v1/__init__.py` 注册 Router。
7. 在 `scripts/db/data_table_ddl.sql` 更新 DDL。
8. 增加 API、Service 和 DB 测试。
9. 更新接口文档。

新增一个外部服务适配：

1. 定义稳定的 Client 接口。
2. 配置 Base URL 和超时。
3. 明确是否使用系统代理。
4. 校验请求和响应协议。
5. 转换底层异常。
6. 增加成功、超时、非 2xx 和格式错误测试。

## 23. 参考实现总结

后续新建项目时，基础脚手架参考 `security-agent-demo` 的组织方式，但只复制通用骨架，不复制具体业务模块。

固定采用以下模式：

- 应用入口：`app/main.py` 只负责 `configure -> log_setup -> db_setup -> include_router`，不写业务逻辑。
- 配置系统：`app/config/base.py` 提供 `Opt`、`Group`、`Configuration`；每个配置模块逐项声明 `Opt` 并暴露 `GROUP_NAME`、`ALL_OPTS`。
- 配置读取：服务启动读取 `${OS_CONFIG_DIR}/app.yaml`；本地开发需要显式准备 `etc/app.yaml`。
- DB 连接：`app/db/base.py` 使用模块级 `DATABASE` 和 `ContextVar DB`；DB 函数通过 `check_db_connected` 注入连接。
- 路由注册：`app/api/v1/__init__.py` 统一注册 Router；单个 API 文件只负责一个资源或场景。
- 异常：`BusiException` 保留 `message`、`status_code`、`payload` 和 `to_dict()`，业务异常由 API 层转换成 HTTP 响应。
- 日志：启动阶段初始化日志，日志实现放在 `app/core/common`，业务模块不自行配置 logging。
- 常量和类型：`app/types/constants.py` 存放项目名、API 前缀等常量；`app/types/__init__.py` 存放通用类型别名。
- 测试：脚手架阶段至少验证配置加载、健康检查和基础工具函数。

不默认加入请求日志中间件、全局异常处理器、认证中间件、数据库建表逻辑或具体业务 API。只有当项目明确需要时，再按模块增量加入。

## 24. 不应直接复制的内容

从已有工程生成新项目时，不应直接复制：

- 具体业务表和字段。
- 业务接口地址。
- 开发环境 Token。
- 数据库密码和外部服务密钥。
- 测试用户。
- 本机绝对路径。
- 历史兼容模块。
- 未使用的重型依赖。
- 拼写错误或过时命名。

建议先搭建最小可运行骨架，再根据实际业务增加模块。
