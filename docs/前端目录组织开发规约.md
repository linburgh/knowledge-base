# 前端目录组织开发规约

## 文档目标

本规约统一 `knowledge-base-web` 的页面、组件、公共状态页、路由和相关私有代码的目录组织及命名方式。后续新增页面、组件、路由和目录重构必须遵守本规约，不再使用页面或组件平铺、文件名重复模块语义的组织方式。

## 适用范围

本规约适用于前端项目 `/home/linburgh/workspace/ai-llm/knowledge-base-web` 中的以下代码：

- `src/pages/` 下的业务页面、登录页面和通用状态页。
- `src/components/` 下的全局复用组件和业务模块共享组件。
- 页面和组件关联的路由、类型、组合式函数、样式及测试。
- 原型稿、设计文档、实施文档和测试用例中的前端路径。

## 核心原则

- 目录表达模块归属和业务语义，入口文件只表达入口类型。
- 页面入口统一使用 `index.vue`，复用组件入口统一使用 `comp.vue`。
- 业务目录统一使用小写 kebab-case，不使用 PascalCase 目录。
- 文件路径不重复模块名、页面名或组件名，不再使用 `*Page.vue` 和 PascalCase 组件入口文件。
- 页面私有代码就近维护，共享代码按复用范围逐级提升。
- 目录或文件调整必须同步源码、路由、测试和文档引用。

## 页面规约

### 业务页面

业务页面必须先按一级业务模块归档，再为每个可路由页面建立独立语义目录：

```text
src/pages/<module>/<page-name>/index.vue
```

示例：

```text
src/pages/monitoring/overview/index.vue
src/pages/platform/evaluations/index.vue
src/pages/knowledge-base/chat/index.vue
```

一级模块和页面目录均使用小写 kebab-case。页面入口固定为 `index.vue`，不得改为以下形式：

```text
src/pages/MonitoringOverviewPage.vue
src/pages/monitoring/MonitoringOverviewPage.vue
src/pages/monitoring/overview/OverviewPage.vue
```

### 登录页面

登录等全局路由页面同样建立独立语义目录：

```text
src/pages/login/index.vue
```

不得将 `LoginPage.vue` 等全局路由页面重新放回 `src/pages/` 根目录。

### 状态页面

无权限、未找到、系统错误等轻量通用状态页统一放在 `src/pages/common/` 下，直接使用小写 kebab-case 语义文件名：

```text
src/pages/common/forbidden.vue
src/pages/common/not-found.vue
src/pages/common/server-error.vue
```

通用状态页是页面 `index.vue` 规则的明确例外，不要求每个状态页再建立独立目录。除 `pages/common/` 外，不得在 `src/pages/` 根目录或其他模块目录中平铺页面文件。

## 组件规约

### 全局组件

全站复用组件必须建立独立语义目录，入口固定为 `comp.vue`：

```text
src/components/<component-name>/comp.vue
```

示例：

```text
src/components/app-drawer/comp.vue
src/components/query-bar/comp.vue
src/components/trend-line-chart/comp.vue
src/components/workspace-header/comp.vue
```

### 模块组件

只在某个业务模块内复用的组件，必须先按模块归档，再建立组件语义目录：

```text
src/components/<module>/<component-name>/comp.vue
```

示例：

```text
src/components/monitoring/alert-trend/comp.vue
src/components/monitoring/business-status/comp.vue
src/components/monitoring/propagation/comp.vue
```

组件目录已经表达模块和组件语义，入口文件不得使用以下形式：

```text
src/components/AppDrawer.vue
src/components/monitoring/MonitoringAlertTrend.vue
src/components/monitoring/alert-trend/MonitoringAlertTrend.vue
```

### 变量命名

目录名和入口文件名使用小写命名，不改变 Vue 组件在 TypeScript 和模板中的 PascalCase 命名：

```ts
import MonitoringAlertTrend from "../../../components/monitoring/alert-trend/comp.vue";
```

```vue
<MonitoringAlertTrend />
```

### 数值展示

- 总览卡片、统计摘要、分布列表等紧凑区域需要限制数值位数时，统一复用 `src/components/numeric-value/comp.vue`。
- 调用方通过 `maxDigits` 指定最大显示位数；超限文案和实际值 Tooltip 由组件统一处理，页面不得重复拼接 `99+`、`999+` 等文案。
- 组件只负责展示，不得用缩写后的文案参与图表比例、分页总数、阈值判断或接口参数计算。
- 数量型整数默认使用组件的三位上限；只有版面明确更紧凑时才设置其他 `maxDigits`。百分比、耗时、容量、指标值、阈值、ID、页码、版本号和日期时间不得套用数量缩写。

## 代码归属

| 代码类型 | 存放位置 |
|---|---|
| 页面入口 | `src/pages/<module>/<page-name>/index.vue` |
| 通用状态页 | `src/pages/common/<status-name>.vue` |
| 页面私有组件 | 对应页面目录内 |
| 页面私有类型、组合式函数和样式 | 对应页面目录内 |
| 模块共享组件 | `src/components/<module>/<component-name>/comp.vue` |
| 全局共享组件 | `src/components/<component-name>/comp.vue` |
| 组件私有子组件、类型和测试 | 对应组件目录内 |
| 全局类型和组合式函数 | `src/types/`、`src/composables/` 等公共目录 |

代码只有在两个及以上页面或组件中确实复用时才提升到模块或全站公共目录，不得为了形式统一提前创建无实际复用关系的公共层。

## 路由规约

路由必须直接导入页面的规范入口：

```ts
component: () => import("../pages/monitoring/overview/index.vue");
component: () => import("../pages/platform/evaluations/index.vue");
component: () => import("../pages/common/forbidden.vue");
```

禁止路由继续引用迁移前的 `*Page.vue` 文件。页面移动或重命名时，必须同时检查重定向、嵌套路由、访客路由和测试中的访问路径。

## 导入规约

- 页面导入组件时必须引用对应的 `comp.vue`。
- 组件导入其他组件时必须引用目标组件的 `comp.vue`。
- 页面或组件下沉目录后，必须同步修正 API、Store、类型、工具和样式的相对路径。
- 导入变量名保持清晰的 PascalCase，不因入口统一为 `index.vue` 或 `comp.vue` 而使用 `Index`、`Comp` 等无业务语义名称。
- 禁止保留旧文件作为兼容转发入口，避免形成两套可用路径。

## 字体规约

- 正式前端与交互原型统一使用全局 `--app-font-family` 字体变量，字体栈固定为 `"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", "Source Han Sans SC", "Segoe UI", Arial, sans-serif`。
- 页面基础字号统一为 13px、基础行高统一为 1.5；标题、正文、辅助信息和图表文字可以按视觉层级调整字号、字重与行高，但不得自行更换字体族。
- 所有业务模块的列表表头字号统一为 13px，Element Plus 表格、原生表格和原型自绘列表均必须继承公共样式，业务页面不得使用局部字号覆盖。
- 原生页面、Bootstrap、Element Plus 和 ECharts 必须绑定同一个全局字体变量或字体常量，保证 DOM 文字、浮层文字和 Canvas 图表文字一致。
- 业务页面和业务组件禁止新增局部 `font-family`，也不得复制一份字体栈覆盖公共主题。字体栈只能在全局主题中维护。
- 代码、SQL、JSON、Trace ID 和规则表达式等具有明确代码语义的内容可以使用项目统一的等宽字体栈；除此之外不得将等宽字体作为视觉装饰使用。
- 调整项目字体栈时必须同步交互原型、全局主题、Element Plus/Bootstrap 变量、ECharts 主题、开发规约和测试用例，不得只修改单个页面。

## 新增流程

新增前端页面或组件时按以下顺序执行：

1. 先修改原型稿，确认页面、模块和交互归属。
2. 再修改设计、接口、实施方案和测试用例中的目录及路径。
3. 按本规约创建页面目录、组件目录和入口文件。
4. 更新路由、菜单、权限、页面或组件导入。
5. 完成业务编码和必要测试。
6. 执行格式、类型、构建和旧路径检查。

## 调整流程

迁移现有页面或组件时必须一次完成以下事项：

1. 确认全部源码、路由、测试和文档引用。
2. 先同步原型稿、设计文档和实施文档。
3. 移动文件并修正内部相对导入。
4. 更新所有调用方的导入路径。
5. 删除旧入口，不保留重复文件。
6. 搜索旧文件名和旧路径，确认无残留。
7. 执行项目校验命令。

## 检查规则

每次修改 `.vue`、`.ts`、`.css` 文件后至少执行：

```bash
npm run format:check
npm run type-check
npm run build
```

格式检查失败时执行：

```bash
npm run format
npm run format:check
```

目录调整还必须检查：

- `src/pages/` 根目录没有新增业务页面文件。
- 业务页面入口均为 `<module>/<page-name>/index.vue`。
- `src/components/` 下没有平铺的 PascalCase `.vue` 文件。
- 复用组件入口均为 `<component-name>/comp.vue`。
- 路由和源码中不存在旧 `*Page.vue` 或旧组件路径。
- `git diff --check` 不存在空白和补丁格式问题。
