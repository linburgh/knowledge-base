# 前端页面原型与实现方案

## 1. 文档目标

本文档用于指导企业知识库问答系统前端的页面原型设计和后续实现。

当前后端已经具备以下基础能力：

- 知识库 CRUD
- 文档上传和索引状态查询
- 文档分片查询
- 向量检索接口
- 会话、消息和引用 CRUD
- `POST /api/v1/chat` 问答接口

前端完整范围包括知识库管理、文档管理、问答、认证授权、运营评测和多租户扩展能力，本文同时给出实现顺序。

## 2. 推荐技术方案

推荐使用：

| 分类 | 方案 |
|---|---|
| 框架 | Vue 3 + TypeScript + Vite |
| UI | Element Plus（Vue 3 对应的 Element UI 组件库）+ Bootstrap 基础样式 |
| 路由 | Vue Router |
| 请求 | Axios |
| 服务端状态 | TanStack Query for Vue 或组合式请求封装 |
| 页面状态 | Pinia |
| Markdown | markdown-it + DOMPurify |
| 代码规范 | ESLint + Prettier + TypeScript strict |

说明：传统 `element-ui` 主要面向 Vue 2；Vue 3 项目使用其 Vue 3 兼容版本 `element-plus`。交互组件使用 Element Plus，页面基础字体、排版、间距和布局遵循 Bootstrap，并通过项目主题覆盖层还原原型视觉。

## 3. 页面信息架构

```text
应用
├── 登录页                     后续接入真实认证
├── 知识库管理                 列表、查询、分页、CRUD
└── 知识库工作区
    ├── 概览                   知识库基本信息和索引统计
    ├── 文档                   有文档菜单权限时显示，提供上传、查询、分页、分片、索引状态
    └── 问答                   会话列表、消息区、引用区
```

推荐路由：

```text
/login
/knowledge-bases
/knowledge-bases/:kbId/overview
/knowledge-bases/:kbId/documents
/knowledge-bases/:kbId/chat
```

## 4. 全局布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo / 系统名称                         用户名 ▾              │
├──────────────┬───────────────────────────────────────────────┤
│ 知识库管理    │ 面包屑 / 页面标题                             │
│               │                                               │
│               │              页面内容                         │
│               │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

布局要求：

- 左侧主导航只保留“知识库管理”。
- 文档和问答不作为全局菜单，必须从知识库列表或当前工作区进入；平台管理 Tab 和知识库工作区 Tab 统一由权限菜单 Tab 控件按菜单接口返回的角色权限动态显示。
- 当前知识库 ID 放在路由中，不依赖全局隐式状态。
- 所有文档、分片、会话和问答请求必须绑定当前 `kb_id`。
- 所有异步操作显示 loading、成功提示和失败原因。
- 删除、重新索引等不可逆或耗时操作必须二次确认。
- 所有列表必须提供查询条件和分页。
- 所有列表中的创建时间、更新时间、加入时间等时间字段统一使用公共时间格式化方法，展示为 `YYYY年MM月DD日 HH:mm:ss`，例如 `2026年08月09日 12:00:00`。
- 列表字段内容过长时保持单行展示，不自动换行；超出列宽统一使用省略号，必要时通过 tooltip 查看完整内容。
- 列表操作列和分页控件统一使用文本按钮，不使用带背景色的按钮。

## 5. 知识库列表页

### 5.1 页面原型

```text
┌──────────────────────────────────────────────────────────────┐
│ 知识库                                  [新建知识库]           │
│ [搜索知识库名称................] [状态 ▾]                     │
├──────────────────────────────────────────────────────────────┤
│ 名称 / 描述          状态       创建时间              创建人    │
│ 企业制度库           正常       2026年07月18日...     linburgh  │
│ 产品资料库           正常       2026年07月18日...     linburgh  │
│ 操作：查看  修改  删除                                         │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 查询、分页和交互

- 查询条件包括名称关键词、状态和创建人。
- 状态条件默认选中第一个选项“全部状态”。
- 点击“查询”从第一页开始展示结果；点击“重置”清空条件并回到第一页。
- 默认按创建时间倒序排列。
- 分页提供总数、上一页、下一页、页码和每页条数。
- 点击“新建知识库”打开右侧抽屉，不使用居中弹窗。
- 创建成功后刷新列表，并跳转到知识库工作区概览。
- 点击“查看”跳转到 `/knowledge-bases/:kbId/overview`。
- 进入工作区后，仅在菜单接口返回 `knowledge_base_documents` 时显示“文档”标签，并进入 `/knowledge-bases/:kbId/documents`。
- 点击“修改”打开回填数据的右侧抽屉。
- 删除前显示知识库名称和影响范围。
- 空列表显示引导文案和“创建第一个知识库”按钮。

### 5.3 表单字段

- `name`：必填。
- `description`：可选。
- `system_prompt`：可选，多行文本，最多 5000 个字符；只对当前知识库问答生效。
- `visibility`：当前可先固定为 `private`。
- 不在列表中展示 `embedding_model`。
- `chunk_size`、`chunk_overlap`、`retrieval_top_k`：高级设置中展示。

### 5.4 特殊字符校验与交互

所有表单在失焦和提交时执行前后端双重校验。统一拒绝控制字符、零宽字符、双向控制字符、BOM 等不可见字符；名称、编码和文件名额外拒绝路径分隔符 `/`、`\\`、`..` 及 `: * ? " < > |`。描述、备注、系统提示词和 Prompt 允许中文、英文、常见标点及换行，不因包含 `{}`、`[]`、`< >` 等正常内容而拒绝。

校验失败时保留用户输入，输入框显示错误边框和字段级提示，提交按钮不发起请求，并定位到第一个错误字段。后端返回校验错误时，前端展示后端真实错误信息，不使用统一的“保存失败”兜底文案。SQL 关键字不作为字符黑名单，数据库操作继续使用参数化查询；页面展示内容必须转义。

系统提示词在知识库新建/修改右侧抽屉中编辑。保存后由后端递增 `system_prompt_version`，问答时与全局基础约束和当前检索上下文一起传给 Chat Model。

## 6. 知识库工作区

### 6.1 概览页

```text
┌──────────────────────────────────────────────────────────────┐
│ 企业制度知识库                                             │
├──────────────┬──────────────┬──────────────┬─────────────────┤
│                                             [统计范围 ▾] [刷新]│
├──────────────────────────────────────────────────────────────┤
│ 文档数量 12   │ 已完成 10     │ 处理中 1      │ 失败 1           │
├──────────────────────────────────────────────────────────────┤
│ 知识库配置                                                    │
│ Embedding：qwen3.7-text-embedding                             │
│ 分块大小：600       重叠：100       Top-K：5                   │
└──────────────────────────────────────────────────────────────┘
```

工作区顶部固定显示当前知识库名称和 `kb_id`。平台管理 Tab 与知识库工作区 Tab 统一使用权限菜单 Tab 控件。控件内部读取菜单状态，在菜单未加载时独立调用 `/api/v1/auth/menus`，再按当前路由上下文过滤对应 Tab；“文档”标签仅对拥有 `knowledge_base_documents` 菜单关系的角色展示。没有文档权限的租户成员和组织成员不能看到该标签，也不能从工作区进入文档页。概览页不重复设置“开始问答”或“进入问答”按钮，进入问答统一使用顶部“问答”Tab。

知识库新建/修改抽屉补充字段级特殊字符校验说明：名称禁止路径字符和不可见字符；描述、系统提示词允许正常标点和换行，仅拒绝不可见字符。文件上传只使用浏览器提供的文件名，后端通过安全文件名和允许扩展名校验，不接受用户传入的存储路径。

概览页在工作区 Tab 下方提供统计时间范围控件，默认选择“近 7 天”，可切换“近 30 天”和“近 90 天”，并提供刷新操作。切换时间范围或点击刷新后重新加载当前知识库概览数据。

权限菜单 Tab 控件不接收页面传入的 Tab 数组，平台管理页面和知识库工作区页面只提供页面容器及路由上下文，Tab 编码、名称和路由映射由控件统一维护。

### 6.2 文档页

```text
┌──────────────────────────────────────────────────────────────┐
│ 当前知识库文档                         [上传文档]            │
│ [文件名查询................] [状态 ▾] [查询] [重置]            │
├──────────────────────────────────────────────────────────────┤
│ 文件名                 类型/大小       状态       操作            │
│ 员工手册.pdf            PDF             已完成     查看  删除      │
│ 报销制度.md             Markdown        处理中     查看  删除      │
│ 旧制度.pdf              PDF             失败       查看 重索引 删除│
│ 共 18 条       上一页  1  2  下一页       10 条/页               │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 上传交互

1. 用户点击“上传文档”，打开右侧抽屉。
2. 用户选择文件。
3. 前端校验扩展名和大小。
4. 使用 `multipart/form-data` 调用上传接口。
5. 上传成功后立即插入 `pending` 或 `processing` 行。
6. 每 2～5 秒轮询文档详情。
7. `ready` 显示成功状态；`failed` 展示 `error_message` 和重新索引按钮。

前端不应假设上传完成就代表索引完成，只有文档状态为 `ready` 后才允许稳定进入问答流程。

### 6.3 文档分片详情

文档列表的“查看”动作定义为“查看分片”，打开右侧详情抽屉，而不是打开原始文件预览。

抽屉显示：

- 文档名称、状态、上传时间、更新时间。
- 分片总数、已生成向量数量、向量维度。
- 分片正文模糊查询。
- 分片列表和分页。

分片列表显示分片序号、内容摘要、Token 数和向量状态。Embedding 模型信息不在该抽屉展示。分片内容查询和分页控件使用文本按钮样式。

### 6.4 索引构建进度

文档操作列统一提供“索引”文本按钮。点击后打开右侧“索引构建任务进度”滑块，按“任务摘要六宫格 → 总体进度 → 处理阶段 → 操作按钮 → 历史任务”的顺序展示。操作按钮位于处理阶段下方、历史任务上方，右侧对齐。`pending/running` 任务显示“中断”和“刷新”；`interrupted/canceled` 任务显示“重试”和“刷新”；普通可重建状态显示“重建索引”和“刷新”。处理中任务每 5 秒刷新，也支持手动刷新；任务完成、失败、中断或取消后停止自动刷新。中断、重试和重建索引均立即提交，不弹出二次确认，提交后滑块保持打开并继续查询任务状态。历史任务按创建时间倒序，独立分页，每页 10 条；没有历史任务时展示空状态，不生成本地占位记录。

## 7. 问答页

### 7.1 页面原型

```text
┌───────────────┬──────────────────────────────────┬──────────────┐
│ 会话           │ 当前知识库问答          [问答配置] │ 参考资料 0 条  │
│ [+ 新建会话]   │                                  │               │
│ [快速查找会话，按 Enter 查询]                       │               │
│ [新会话]       │       ✦ 输入一个问题，开始探索知识库│               │
│ 你是谁... [···]│                                  │               │
│               ├──────────────────────────────────┤               │
│               │ 输入问题........................ │               │
│               │ Enter 发送 · Shift+Enter 换行 [发送问题]│            │
│               │                                  │ 回答后显示参考资料│
└───────────────┴──────────────────────────────────┴──────────────┘
```

快速查找会话属于会话列表交互，控件位于“新建会话”入口下方，不改变中间聊天区和右侧参考资料区的布局。

### 7.2 核心交互

- 首次进入页面时不自动创建会话，点击“新建会话”或首次发送问题时创建。
- 发送期间禁用发送按钮，显示回答生成状态。
- 用户消息和助手消息按时间顺序展示。
- 助手回答中的引用标记可以与右侧引用卡片联动。
- 助手回答支持 Markdown 渲染，包括标题、段落、加粗、列表、引用、代码块和表格。
- Markdown 渲染前使用 DOMPurify 过滤 HTML，禁止模型输出的原始 HTML 直接注入页面。
- 点击引用卡片时高亮对应消息中的引用位置。
- 右侧引用为空时展示“本次回答没有可用引用”。
- 网络错误时保留用户输入，允许重试，不自动重复保存用户消息。
- 切换会话时清空当前引用面板，重新加载目标会话消息和引用。
- 会话列表已有的新建、切换、重命名、删除和独立滚动交互保持不变。
- 快速查找会话：增加关键词输入框，按会话标题远程查询，查询条件绑定当前 `kb_id` 和当前用户。
- 用户输入关键词后按 Enter 触发请求，不设置独立的“查询”按钮，也不使用输入防抖自动查询。
- 清空关键词后按 Enter 查询当前知识库下的全部会话。
- 查询期间显示列表加载状态，查询完成后刷新会话列表，不改变聊天消息区和参考资料区。
- 当前文档页原型、前端页面和索引任务查询/重建接口已完成接入；上线前按测试用例执行真实环境联调。

### 7.3 首次问答流程

```text
用户输入问题
    ↓
前端校验非空
    ↓
POST /api/v1/chat
    ↓
显示用户消息和 loading 占位
    ↓
返回 answer、citations、conversation_id、message_id
    ↓
更新当前 URL 和会话列表
```

## 8. 前端接口映射

### 8.1 知识库

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 查询列表 | `GET` | `/api/v1/knowledge-bases?owner_id=...` |
| 创建 | `POST` | `/api/v1/knowledge-bases` |
| 查询详情 | `GET` | `/api/v1/knowledge-bases/{id}` |
| 修改 | `PUT` | `/api/v1/knowledge-bases/{id}` |
| 删除 | `DELETE` | `/api/v1/knowledge-bases/{id}` |

### 8.2 文档

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 上传 | `POST` | `/api/v1/documents/upload` |
| 查询列表 | `GET` | `/api/v1/documents?kb_id=...` |
| 查询详情 | `GET` | `/api/v1/documents/{id}` |
| 查看分片 | `GET` | `/api/v1/documents/{id}/chunks` |
| 手动索引 | `POST` | `/api/v1/documents/{id}/index` |
| 中断索引任务 | `POST` | `/api/v1/documents/{id}/index-tasks/{task_id}/interrupt` |
| 重试索引任务 | `POST` | `/api/v1/documents/{id}/index-tasks/{task_id}/retry` |

中断和重试请求体统一为 `{ "expected_version": <当前任务版本号> }`。如果返回 409，前端立即刷新任务详情，并按服务端返回的最新状态提示用户，不伪造状态变化。
| 删除 | `DELETE` | `/api/v1/documents/{id}` |
| 查询索引进度和历史 | `GET` | `/api/v1/documents/{id}/index-progress?page=1&page_size=10` |

### 8.3 会话和问答

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 会话列表 | `GET` | `/api/v1/conversations?kb_id=...&user_id=...&keyword=...` |
| 会话详情 | `GET` | `/api/v1/conversations/{id}` |
| 会话消息 | `GET` | `/api/v1/conversations/{id}/messages` |
| 新增问答 | `POST` | `/api/v1/chat` |
| 删除会话 | `DELETE` | `/api/v1/conversations/{id}` |

问答请求：

```json
{
  "kb_id": 1,
  "question": "报销流程需要哪些材料？",
  "conversation_id": null,
  "user_id": "user-1",
  "top_k": 5
}
```

问答响应：

```json
{
  "conversation_id": 1,
  "message_id": 2,
  "answer": "需要准备发票、费用明细和审批单。",
  "citations": [],
  "retrieval": {
    "top_k": 5,
    "hit_count": 1,
    "mode": "vector"
  }
}
```

## 9. 前端状态设计

### 9.1 服务端状态

使用 TanStack Query 管理：

- 知识库列表：`knowledgeBases(ownerId)`。
- 知识库详情：`knowledgeBase(kbId)`。
- 文档列表：`documents(kbId)`。
- 文档详情：`document(documentId)`。
- 会话列表：`conversations(kbId, userId, keyword)`，关键词由后端按会话标题远程过滤，不在前端对已加载数据二次筛选。
- 会话消息：`conversationMessages(conversationId)`。

上传、创建、删除、发送问答成功后，按资源粒度失效对应 Query，不建议整页强制刷新。

### 9.2 页面状态

- `selectedConversationId`
- `draftQuestion`
- `isSending`
- `selectedCitationRank`
- `uploadProgress`
- `documentPollingEnabled`
- `collapsedSidebar`

### 9.3 问答消息模型

前端可以统一转换为：

```ts
type ChatMessage = {
  id: number | string;
  role: "user" | "assistant";
  content: string;
  createdAt?: string;
  citations?: Citation[];
  pending?: boolean;
  error?: string;
};
```

## 10. 错误和空状态

| 场景 | 页面处理 |
|---|---|
| 知识库不存在 | 跳回知识库列表并提示 |
| 知识库已删除 | 禁止进入问答页 |
| 文档索引失败 | 展示失败原因和重试操作 |
| 没有 ready 文档 | 问答页显示“请先上传并完成索引” |
| 检索无命中 | 展示无相关资料提示，不伪造引用 |
| Chat 模型未配置 | 展示管理员配置提示 |
| 请求超时 | 保留输入，提供重试按钮 |
| 401/403 | 跳转登录或展示无权限页面 |
| 500 | 展示 request id 和通用错误提示 |

## 13. 当前后端需要继续补充的能力

- 当前接口仍使用显式 `user_id`，前端接入真实认证后应改为从认证上下文获取。
- Chat 当前固定使用 vector 检索，前端不需要暴露检索模式切换。
- 文档列表暂未返回分块数量和索引进度，可后续增加统计字段。
- Chat 流式输出尚未实现，第一版使用普通 JSON 响应即可。
- 错误响应建议统一增加 `request_id`，便于前端错误提示和日志关联。
- 后续可以增加 SSE 或 WebSocket，实现模型回答流式展示。

## 14. 完整功能验收标准

- 用户可以创建知识库并进入详情页。
- 用户可以上传 Markdown、TXT 等文档。
- 文档索引完成前，页面能显示处理中状态。
- 文档变为 `ready` 后，用户可以进入问答页。
- 用户发送问题后能看到用户消息、助手答案和参考资料。
- 刷新页面后，当前会话和历史消息仍可恢复。
- 模型或检索失败时，页面不会显示伪造答案，并能提供明确重试入口。
