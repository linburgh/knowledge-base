# 前端页面原型与实现方案

## 1. 文档目标

本文档用于指导企业知识库问答系统前端的页面原型设计和后续实现。

当前后端已经具备以下基础能力：

- 知识库 CRUD
- 文档上传和索引状态查询
- 向量检索接口
- 会话、消息和引用 CRUD
- `POST /api/v1/chat` 问答接口

前端完整范围包括知识库管理、文档管理、问答、认证授权、运营评测和多租户扩展能力，本文同时给出实现顺序。

## 2. 推荐技术方案

推荐使用：

| 分类 | 方案 |
|---|---|
| 框架 | Vue 3 + TypeScript + Vite |
| UI | Element Plus（Vue 3 对应的 Element UI 组件库） |
| 路由 | Vue Router |
| 请求 | Axios |
| 服务端状态 | TanStack Query for Vue 或组合式请求封装 |
| 页面状态 | Pinia |
| Markdown | Vue Markdown 渲染组件 |
| 代码规范 | ESLint + Prettier + TypeScript strict |

说明：传统 `element-ui` 主要面向 Vue 2；Vue 3 项目应使用其 Vue 3 兼容版本 `element-plus`。本文统一称为“Vue 3 + Element UI 体系”，实际依赖使用 Element Plus。

## 3. 页面信息架构

```text
应用
├── 登录页                     后续接入真实认证
├── 知识库列表页               创建、搜索、删除知识库
├── 知识库详情页
│   ├── 概览                   知识库基本信息和索引统计
│   └── 文档管理               上传、索引状态、删除文档
└── 知识库问答页               会话列表、消息区、引用区
```

推荐路由：

```text
/login
/knowledge-bases
/knowledge-bases/:kbId/overview
/knowledge-bases/:kbId/documents
/knowledge-bases/:kbId/chat
```

## 4. 全局布局

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo / 系统名称                         用户名 ▾              │
├──────────────┬───────────────────────────────────────────────┤
│ 知识库        │ 面包屑 / 页面标题                             │
│ 文档          │                                               │
│ 问答          │              页面内容                         │
│               │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

布局要求：

- 左侧导航固定，移动端折叠为抽屉。
- 当前知识库 ID 放在路由中，不依赖全局隐式状态。
- 所有异步操作显示 loading、成功提示和失败原因。
- 删除、重新索引等不可逆或耗时操作必须二次确认。

## 5. 知识库列表页

### 5.1 页面原型

```text
┌──────────────────────────────────────────────────────────────┐
│ 知识库                                  [新建知识库]           │
│ [搜索知识库名称................] [状态 ▾]                     │
├──────────────────────────────────────────────────────────────┤
│ 名称          描述          文档数       状态       操作        │
│ 企业制度      ...           12           active     进入 / 删除 │
│ 产品资料      ...           5            active     进入 / 删除 │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 交互

- 点击“新建知识库”打开抽屉或弹窗。
- 创建成功后刷新列表，并跳转到知识库详情页。
- 点击“进入”跳转到 `/knowledge-bases/:kbId/overview`。
- 删除前显示知识库名称和影响范围。
- 空列表显示引导文案和“创建第一个知识库”按钮。

### 5.3 表单字段

- `name`：必填。
- `description`：可选。
- `visibility`：当前可先固定为 `private`。
- `embedding_model`：在高级设置中展示，并说明修改后需要重新生成文档向量。
- `chunk_size`、`chunk_overlap`、`retrieval_top_k`：高级设置中展示。

## 6. 知识库详情与文档管理页

### 6.1 概览页

```text
┌──────────────────────────────────────────────────────────────┐
│ 企业制度知识库                         [文档管理] [开始问答]  │
├──────────────┬──────────────┬──────────────┬─────────────────┤
│ 文档数量 12   │ 已完成 10     │ 处理中 1      │ 失败 1           │
├──────────────────────────────────────────────────────────────┤
│ 知识库配置                                                    │
│ Embedding 模型：text-embedding-3-small                        │
│ 分块大小：600       重叠：100       Top-K：5                   │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 文档管理页

```text
┌──────────────────────────────────────────────────────────────┐
│ 文档管理                         [上传文档] [刷新]              │
├──────────────────────────────────────────────────────────────┤
│ 文件名                 状态          更新时间       操作        │
│ 员工手册.pdf            ready         ...            查看 / 删除  │
│ 报销制度.md             processing    ...            查看        │
│ 旧制度.pdf              failed        ...            重试 / 删除  │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 上传交互

1. 用户选择文件。
2. 前端校验扩展名和大小。
3. 使用 `multipart/form-data` 调用上传接口。
4. 上传成功后立即插入 `pending` 或 `processing` 行。
5. 每 2～5 秒轮询文档详情。
6. `ready` 显示成功状态；`failed` 展示 `error_message` 和重试按钮。

前端不应假设上传完成就代表索引完成，只有文档状态为 `ready` 后才允许稳定进入问答流程。

## 7. 问答页

### 7.1 页面原型

```text
┌───────────────┬──────────────────────────────────┬──────────────┐
│ 会话           │ 企业制度知识库                   │ 引用来源      │
│ [+ 新建会话]   │                                  │               │
│               │ 用户：报销流程需要哪些材料？       │ [1] 员工手册  │
│ 今天           │                                  │ 第 3 页       │
│  报销流程      │ 助手：需要准备发票、明细和审批单。 │               │
│               │                                  │ [2] 报销制度  │
│ 昨天           │                                  │ 第 2 页       │
│  入职流程      │                                  │               │
│               ├──────────────────────────────────┤               │
│               │ 输入问题........................ │               │
│               │                         [发送]   │               │
└───────────────┴──────────────────────────────────┴──────────────┘
```

### 7.2 核心交互

- 首次进入页面时不自动创建会话，点击“新建会话”或首次发送问题时创建。
- 发送期间禁用发送按钮，显示回答生成状态。
- 用户消息和助手消息按时间顺序展示。
- 助手回答中的引用标记可以与右侧引用卡片联动。
- 点击引用卡片时高亮对应消息中的引用位置。
- 右侧引用为空时展示“本次回答没有可用引用”。
- 网络错误时保留用户输入，允许重试，不自动重复保存用户消息。
- 切换会话时清空当前引用面板，重新加载目标会话消息和引用。

### 7.3 首次问答流程

```text
用户输入问题
    ↓
前端校验非空
    ↓
POST /api/v1/chat
    ↓
显示用户消息和 loading 占位
    ↓
返回 answer、citations、conversation_id、message_id
    ↓
更新当前 URL 和会话列表
```

## 8. 前端接口映射

### 8.1 知识库

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 查询列表 | `GET` | `/api/v1/knowledge-bases?owner_id=...` |
| 创建 | `POST` | `/api/v1/knowledge-bases` |
| 查询详情 | `GET` | `/api/v1/knowledge-bases/{id}` |
| 修改 | `PUT` | `/api/v1/knowledge-bases/{id}` |
| 删除 | `DELETE` | `/api/v1/knowledge-bases/{id}` |

### 8.2 文档

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 上传 | `POST` | `/api/v1/documents/upload` |
| 查询列表 | `GET` | `/api/v1/documents?kb_id=...` |
| 查询详情 | `GET` | `/api/v1/documents/{id}` |
| 手动索引 | `POST` | `/api/v1/documents/{id}/index` |
| 删除 | `DELETE` | `/api/v1/documents/{id}` |

### 8.3 会话和问答

| 页面动作 | 方法 | 接口 |
|---|---|---|
| 会话列表 | `GET` | `/api/v1/conversations?kb_id=...&user_id=...` |
| 会话详情 | `GET` | `/api/v1/conversations/{id}` |
| 会话消息 | `GET` | `/api/v1/conversations/{id}/messages` |
| 新增问答 | `POST` | `/api/v1/chat` |
| 删除会话 | `DELETE` | `/api/v1/conversations/{id}` |

问答请求：

```json
{
  "kb_id": 1,
  "question": "报销流程需要哪些材料？",
  "conversation_id": null,
  "user_id": "user-1",
  "top_k": 5
}
```

问答响应：

```json
{
  "conversation_id": 1,
  "message_id": 2,
  "answer": "需要准备发票、费用明细和审批单。",
  "citations": [],
  "retrieval": {
    "top_k": 5,
    "hit_count": 1,
    "mode": "vector"
  }
}
```

## 9. 前端状态设计

### 9.1 服务端状态

使用 TanStack Query 管理：

- 知识库列表：`knowledgeBases(ownerId)`。
- 知识库详情：`knowledgeBase(kbId)`。
- 文档列表：`documents(kbId)`。
- 文档详情：`document(documentId)`。
- 会话列表：`conversations(kbId, userId)`。
- 会话消息：`conversationMessages(conversationId)`。

上传、创建、删除、发送问答成功后，按资源粒度失效对应 Query，不建议整页强制刷新。

### 9.2 页面状态

- `selectedConversationId`
- `draftQuestion`
- `isSending`
- `selectedCitationRank`
- `uploadProgress`
- `documentPollingEnabled`
- `collapsedSidebar`

### 9.3 问答消息模型

前端可以统一转换为：

```ts
type ChatMessage = {
  id: number | string;
  role: "user" | "assistant";
  content: string;
  createdAt?: string;
  citations?: Citation[];
  pending?: boolean;
  error?: string;
};
```

## 10. 错误和空状态

| 场景 | 页面处理 |
|---|---|
| 知识库不存在 | 跳回知识库列表并提示 |
| 知识库已删除 | 禁止进入问答页 |
| 文档索引失败 | 展示失败原因和重试操作 |
| 没有 ready 文档 | 问答页显示“请先上传并完成索引” |
| 检索无命中 | 展示无相关资料提示，不伪造引用 |
| Chat 模型未配置 | 展示管理员配置提示 |
| 请求超时 | 保留输入，提供重试按钮 |
| 401/403 | 跳转登录或展示无权限页面 |
| 500 | 展示 request id 和通用错误提示 |

## 12. 分阶段实现计划

### 阶段一：工程与页面基础

- 初始化前端工程。
- 完成全局布局、路由和导航。
- 完成知识库列表和新建表单。
- 使用 Mock 数据验证页面交互。

### 阶段二：知识库与文档管理

- 接入知识库 CRUD。
- 接入文档上传。
- 接入文档状态轮询。
- 增加失败重试、删除确认和空状态。

### 阶段三：完整问答能力

- 完成会话列表。
- 完成消息历史加载。
- 接入 `POST /api/v1/chat`。
- 展示 answer 和 citations。
- 完成发送中、失败、重试和无命中状态。

### 阶段四：体验优化

- Markdown 渲染和代码块样式。
- 引用高亮和滚动联动。
- 会话标题自动刷新。
- 文档上传进度和批量上传。
- 移动端布局。

### 阶段五：权限和运营能力

- 接入真实登录和 Token。
- 前端根据权限隐藏操作。
- 增加知识库成员管理。
- 增加问答反馈和评测入口。

## 13. 当前后端需要继续补充的能力

- 当前接口仍使用显式 `user_id`，前端接入真实认证后应改为从认证上下文获取。
- Chat 当前固定使用 vector 检索，前端不需要暴露检索模式切换。
- 文档列表暂未返回分块数量和索引进度，可后续增加统计字段。
- Chat 流式输出尚未实现，第一版使用普通 JSON 响应即可。
- 错误响应建议统一增加 `request_id`，便于前端错误提示和日志关联。
- 后续可以增加 SSE 或 WebSocket，实现模型回答流式展示。

## 14. 完整功能验收标准

- 用户可以创建知识库并进入详情页。
- 用户可以上传 Markdown、TXT 等文档。
- 文档索引完成前，页面能显示处理中状态。
- 文档变为 `ready` 后，用户可以进入问答页。
- 用户发送问题后能看到用户消息、助手答案和引用来源。
- 刷新页面后，当前会话和历史消息仍可恢复。
- 模型或检索失败时，页面不会显示伪造答案，并能提供明确重试入口。
