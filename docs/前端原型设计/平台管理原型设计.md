# 平台管理前端原型设计

> 本文档内容已纳入[知识库系统完整前端原型设计](知识库系统完整原型设计.md)。统一可交互原型请打开 `知识库工作区原型.html`，本文件保留作为平台管理专题说明。

## 1. 页面范围

平台管理对 `p_super_admin` 和 `tenant_admin` 展示，包含：

- 平台概览。
- 用户管理。
- 租户管理。
- 组织管理。
- 自主评测。
- 开发者中心。

平台管理完整菜单仍包含租户管理和开发者中心，但 `tenant_admin` 不展示这两个菜单；展示平台管理、平台概览、用户管理、组织管理和自主评测，页面数据和操作范围限制为当前租户。租户管理和租户管理员分配仅面向 `p_super_admin`，其他普通租户角色不展示平台管理菜单。

## 2.1 平台超级管理员权限原则

- 全平台只能存在一个具备 `p_super_admin` 角色的用户。
- 平台超级管理员可以查看平台下所有租户、用户、组织、知识库、文档及平台统计资源。
- 平台超级管理员不受当前租户、组织或知识库授权范围限制；进入具体租户资源时，页面仍显示当前目标租户，作为上下文和操作审计信息。
- 前端根据当前用户的平台角色展示平台管理菜单，但数据范围和唯一性必须由后端权限校验与数据库约束保证。

## 2. 页面结构

```text
平台管理
├── 平台概览
├── 用户管理
├── 租户管理
├── 组织管理
├── 自主评测
└── 开发者中心
```

左侧菜单新增“平台管理”，位于知识库管理之前或之后，具体顺序由最终导航方案确认。

## 3. 平台概览

页面展示平台级统计卡片：

- 用户总数。
- 正常用户数。
- 租户总数。
- 正常租户数。
- 组织总数。
- 知识库总数。

以上六张卡片仅适用于 `p_super_admin`。`tenant_admin` 使用同一页面入口和布局，但前端不展示“租户总数”和“正常租户”卡片；租户状态只在页面顶部的当前租户上下文中展示，统计卡片改为用户、组织和知识库的当前租户范围数据。接口仍保持统一统计字段，避免破坏平台概览响应契约。

下方展示最近创建的租户和最近加入的用户。

概览补充以下图表：

- 用户增长趋势：使用 ECharts 折线图按日、月展示新增用户和活跃用户。
- 统计卡片只展示卡片标题和数字，不展示数字下方的备注文字；鼠标移到每个统计数字时均通过 Tooltip 展示简短统计口径，例如“用户总数”“组织总数”“知识库总数”。租户管理员的“活跃用户”数字按所选时间范围内有登录记录的去重用户数统计，Tooltip 提示“登录人数”。
- 租户资源分布：使用 ECharts 分组柱状图展示资源指标排名前 5 的租户，包含用户数、组织数和知识库数；概览页不提供“查看全部”操作。
- 文档处理状态：展示已完成、处理中、失败和待处理数量。
- 最近平台活动：展示用户、租户、组织、知识库和文档的近期操作。

最近动态只展示业务活动，不展示登录、退出登录、刷新令牌、选择租户等认证或上下文操作。平台超级管理员查看全平台各租户的业务动态；租户管理员只查看当前租户管理范围内的业务动态，范围依据目标资源所属租户判断，不能只依据操作人是否属于当前租户判断。

租户管理员动态的目标资源范围包括当前租户、用户、租户成员、组织、组织成员、知识库、文档和自主评测任务/运行记录。平台超级管理员动态需要保留租户上下文，至少展示目标租户、目标资源和操作结果，避免跨租户同名资源混淆。

图表支持近 7 天、近 30 天、近 90 天和自定义时间范围；点击图表数据可以跳转到对应管理列表。

## 4. 用户管理

### 4.1 列表

页面结构：

```text
用户管理                                      [新建用户]
[用户名称] [邮箱地址] [用户状态] [所属租户] [所属组织] [查询] [重置]
┌──────────────────────────────────────────────────────────┐
│ 用户名称   邮箱地址   所属租户       用户状态   操作       │
│ 张三       ...        企业租户       正常       查看 修改 删除│
│ 李四       ...        产品租户       禁用       查看 修改 删除│
└──────────────────────────────────────────────────────────┘
                         共 28 条  上一页 1 2 下一页
```

查询条件：

- 用户名称查询。
- 邮箱地址查询。
- 用户状态查询。
- 所属租户。
- 所属组织。

操作：

- 查看用户详情。
- 用户详情字段顺序与用户表单一致：用户账号、显示名称、邮箱地址、手机号码；随后展示租户/组织关系、状态和角色信息。
- 修改用户资料。
- 管理用户所属租户和组织。
- 启用或禁用用户。

用户列表用于维护用户基础资料、登录状态和凭证；租户、组织及三类角色关系通过对应的成员管理模块维护，不放在用户新增/修改表单中。

### 4.2 用户抽屉

点击“新建用户”或“修改”打开右侧抽屉，字段包括：

- 用户账号。
- 显示名称。
- 登录密码。
- 邮箱地址。
- 手机号码。
- 用户状态由系统按默认值初始化，新增/修改用户表单不展示该字段；状态查询、状态变更和状态展示在用户列表及独立管理操作中完成。

## 5. 租户管理

### 5.1 列表

```text
租户管理                                      [新建租户]
[租户名称] [租户状态] [查询] [重置]
┌──────────────────────────────────────────────────────────┐
│ 租户名称   租户状态   操作 │
│ 企业租户   36         12         正常   查看 修改 删除    │
└──────────────────────────────────────────────────────────┘
```

操作：

- 查看租户详情。
- 租户详情不展示租户编码。
- 租户详情字段顺序与租户表单一致：租户名称、联系人名、联系邮箱、标识地址、租户描述；随后展示所有者、管理员和统计信息。
- 修改租户信息；“修改”下拉菜单包含“修改信息”“成员列表”“组织列表”“知识库列表”。
- 管理租户成员。
- 租户成员列表支持成员名称、成员角色和成员状态查询，提供“添加成员”“刷新”和分页；列表展示成员名称、邮箱地址、成员角色、所属组织、成员状态、加入时间，操作提供“查看”“修改”“移除”；“添加成员”和“刷新”放在查询条件栏的按钮组中，“返回租户列表”放在标题工具栏右侧。
- 租户成员新增和修改表单统一使用 Element Plus 表单控件，字段包括租户角色、成员状态和“默认租户”。“默认租户”表示用户拥有多个租户成员关系时登录后优先进入的租户，不代表租户所有者，也不改变租户角色。
- 点击“组织列表”进入当前租户的组织列表，使用真实租户范围查询，支持组织名称、组织状态查询和分页；列表展示组织名称、上级组织、负责人、组织状态、创建时间和更新时间，不展示成员数量；成员数量仅在组织详情查看中展示。操作列固定；查询条件栏按钮组包含“查询”“重置”“刷新”“添加组织”。
- 点击“知识库列表”进入当前租户的知识库列表，使用真实租户范围查询，支持知识库名称、知识库状态查询和分页；列表展示知识库名称、描述、知识库状态、创建时间、更新时间和创建用户，不展示所属组织，操作列固定；查询条件栏按钮组包含“查询”“重置”“刷新”“添加知识库”。
- 组织列表和知识库列表页面均提供“返回租户列表”，按钮放在标题工具栏右侧，返回后保留租户列表的查询条件和分页状态。
- 点击“添加成员”“添加组织”或“添加知识库”后，从侧边滑出对应的选择面板；成员展示当前租户下尚未加入的用户，组织和知识库展示尚未绑定当前租户的全部平台资源，包括未绑定资源和已绑定其他租户的资源。三类面板均支持后端搜索、分页和多选，点击“确认”后批量绑定并刷新当前列表，点击“取消”、关闭或遮罩关闭时放弃本次选择。
- 三类待选面板均复用同一套待选列表样式：第一列为多选框，成员面板展示“成员名称、所属组织”，组织面板展示“组织名称、上级组织”，知识库面板展示“知识库名称、知识库描述”；不重新设计独立的表格、分页或按钮样式。
- 管理租户管理员。
- 租户列表不展示租户管理员、成员数量、知识库数和组织数量；这些信息仅在租户详情查看中展示。详情中展示有效 `tenant_admin` 以及成员、知识库和组织统计。
- 查看租户组织和知识库统计。

### 5.2 租户抽屉

- 租户名称。
- 新建租户时前端自动生成租户编码并随表单提交；修改租户信息时不展示租户编码字段。
- 联系人名。
- 联系邮箱。
- 标识地址（Logo）。
- 租户描述。
- 租户状态由系统按默认值初始化，新增/修改租户表单不展示该字段；状态查询、状态变更和状态展示在租户列表及独立管理操作中完成。
- 租户管理员。

## 6. 组织管理

组织管理采用组织树表结构，主页面只展示组织信息，不直接展示用户列表；平台超级管理员默认查看全平台组织，支持按所属租户筛选；普通租户上下文只展示当前租户组织。组织树表一次性展示查询范围内的组织，不分页：

```text
组织管理
┌────────────────┬──────────────────────────────────────────┐
│ 组织树表                                                     │
│ 组织名称｜上级组织｜组织状态｜所属租户｜操作          │
│ 企业总部｜...  ｜—      ｜54    ｜正常｜成员 / 修改 / 删除      │
│ 企业总部       │ [成员名称] [成员状态] [查询] [重置]        │
│ 财务部         │ ┌──────────────────────────────────────┐ │
│ 技术中心       │ │ 成员名称   成员角色   成员状态   操作   │ │
│   平台组       │ └──────────────────────────────────────┘ │
│   算法组       │                                          │
└────────────────┴──────────────────────────────────────────┘
```

组织操作：

- 新建组织。
- 新建组织时由前端自动生成组织编码并随表单提交；新建和修改组织表单均不展示组织编码字段。
- 平台超级管理员默认加载全部租户组织，并可通过“所属租户”筛选单个租户。
- 全平台查询结果必须展示所属租户，避免不同租户下的同名组织混淆。
- 修改组织。
- 组织详情不展示组织编码。
- 组织详情字段顺序与组织表单一致：组织名称、上级组织、负责用户；随后展示所属租户、成员数和状态。
- 组织状态由系统按默认值初始化，新增/修改组织表单不展示该字段；状态查询、状态变更和状态展示在组织列表及独立管理操作中完成。
- 调整父子关系。
- 设置负责人。
- 操作列提供“查看”、修改下拉按钮和“删除”；下拉菜单包含“修改信息”“成员列表”。
- 点击“成员列表”深钻进入当前组织的用户列表。
- 用户列表支持成员名称、成员状态查询、“添加成员”和“刷新”按钮，并提供分页；“添加成员”和“刷新”放在查询条件栏，“返回组织树”放在标题工具栏右侧。
- 将知识库授权给组织。

成员表格提供条件查询和分页，组织树表提供所属租户、组织名称和组织状态条件查询但不分页，操作按钮使用文本按钮。

## 7. 知识库页面变化

知识库列表仍然保留当前页面结构，但数据来源增加租户和组织上下文：

- 平台超级管理员可以选择目标租户查看知识库。
- 租户管理员默认只查看当前租户知识库。
- 普通用户只查看自己有权限访问的知识库。
- 知识库创建/修改抽屉不设置所属组织字段，知识库只归属租户。
- 租户公共知识库通过组织授权控制组织成员访问范围。
- 知识库列表操作列增加“组织授权”，用于维护知识库可访问的组织范围。

## 8. 交互约束

- 所有列表必须提供查询条件和分页。
- 所有列表中的创建时间、更新时间、加入时间等时间字段统一展示为 `YYYY年MM月DD日 HH:mm:ss`，例如 `2026年08月09日 12:00:00`，前端统一复用公共时间格式化方法。
- 列表字段内容过长时保持单行展示，不自动换行；超出列宽统一使用省略号，必要时通过 tooltip 查看完整内容。
- 所有查询条件标签统一使用四字名称，并且列表必须提供对应字段列：用户名称、邮箱地址、用户状态；租户名称、租户状态；组织名称、组织状态；成员名称、成员角色、成员状态。
- 用户管理查询条件拆分为“用户名称”和“邮箱地址”；租户管理查询条件只保留“租户名称”，去掉“租户编码”。
- 所有列表查询条件按字段组自然平铺，宽度不足时按整组自动换行，字段标签不得与对应控件错位。
- 查询条件栏使用流式布局，不按 2K、4K 等固定分辨率预设每行控件数量；字段组按照可用宽度自动排列，空间不足时由完整字段组整体换行。
- 查询条件中的字段组统一使用固定宽度 325px，避免不同显示器下标签和控件宽度变化导致排版跳动；移动端可切换为容器全宽。
- 查询条件栏中的查询、重置、刷新、添加成员、添加组织和添加知识库统一放入独立按钮组；按钮组作为一个完整布局单元参与流式换行，不得与字段标签或字段控件混排错位。
- 查询字段采用“标签在左、控件在右”的同行布局，标签统一左对齐并在控件高度内上下居中；标签与控件属于同一字段组，禁止上下拆分或错位。
- 查询条件交互控件统一使用 Element Plus 的 `el-form`、`el-form-item`、`el-input`、`el-select`、`el-option` 和 `el-button`。
- 用户、租户、组织树和组织成员列表的“刷新”按钮统一放在查询条件栏中，使用文字按钮；“新建组织”仍与组织工具栏同行。
- 查询和重置按钮使用原型统一样式。
- 所有表单使用右侧抽屉，不使用居中弹窗。
- 用户信息、租户信息和组织信息表单统一使用 Element Plus 表单控件，并使用 Bootstrap 的基础布局体系组织表单结构。
- 表单标签统一使用 13px 字号、400 字重和 20px 行高；输入框、选择框和文本域中的输入文字、选择文字和占位文字统一使用 13px 字号，并保持清晰的 20px 行高。
- 表单颜色按信息层级统一：标签使用沉稳的次级文字色，已填写内容使用高对比度主文字色，占位文字使用弱化文字色，禁用内容进一步弱化，校验错误使用明确但不过度刺眼的错误色。
- 表单控件统一使用约 38px 高度；标签与字段控件之间保留明确间距，字段之间保持一致的垂直间距。
- 必填星号不得破坏标签对齐，标签、控件和校验提示必须保持同一字段组内的稳定排版。
- 表单优先复用统一公共样式，不得在单个页面增加随意的字体、颜色或间距覆盖。
- 查询条件标签字体使用 `#151517`，输入内容、占位文字和禁用态继续按既有层级区分；列表仅表头字体使用 `#151517`，表格正文、辅助信息、操作文字和状态文字继续按既有层级区分。
- 列表操作按钮使用文本按钮或统一的更多操作按钮。
- 状态使用文字和颜色区分，不使用状态背景色。
- 平台管理员进入租户资源时，顶部显示当前目标租户名称。

## 9. 待确认页面问题

- 平台管理是否独立使用一套顶部导航。
- 平台超级管理员是否允许直接进入任意租户工作区。
- 租户成员管理和用户管理是否复用同一套成员抽屉。
- 组织授权知识库时是否支持批量选择。
- 用户是否可以同时切换多个租户上下文。
