# 分页树表交互原型设计

## 1. 原型目标

本设计定义一种“父节点追加分页 + 子节点独立追加分页”的树表交互，不使用传统的页码、上一页和下一页。

该设计已落地到组织管理页面，后端接口使用游标续取，前端替换原有一次性组织树。

## 2. 核心概念

```text
树表
├── 父节点分页：首屏加载一批父节点，底部点击“加载更多”追加下一批父节点
└── 子节点分页：每个已展开节点独立加载一批直接子节点，节点内部点击“加载更多”追加下一批子节点
```

父节点和子节点使用两套独立的分页状态：

| 状态 | 父节点 | 子节点 |
|---|---|---|
| 当前已加载数据 | 当前已加载的父节点集合 | 当前父节点下已加载的子节点集合 |
| 加载更多位置 | 整张树表底部 | 当前父节点最后一个子节点下方 |
| 加载影响范围 | 只追加父节点 | 只追加当前父节点的子节点 |
| 加载状态 | 表格底部显示加载中 | 当前父节点内部显示加载中 |
| 失败重试 | 表格底部显示“重新加载” | 当前父节点内部显示“重新加载” |
| 没有更多 | 不显示父节点加载按钮 | 不显示该父节点子节点加载按钮 |

## 4. 交互规则

### 4.1 首次加载

1. 页面首次进入时加载第一批父节点。
2. 父节点默认折叠，避免首次请求一次性加载所有子节点。
3. 父节点列表底部根据服务端返回的 `has_more` 决定是否显示“加载更多”。
4. 首次加载期间显示表格骨架；失败时显示表格级错误和“重新加载”。

### 4.2 展开父节点

1. 点击任意有子节点的节点左侧展开图标后展开当前节点。
2. 第一次展开时加载当前节点的第一批直接子节点。
3. 子节点加载期间，当前父节点下显示局部加载状态，其他父节点保持原状。
4. 已加载过的节点再次收起、展开时，不重复请求，除非用户主动刷新。
5. 子节点如果仍有下级节点，继续显示同样的展开图标和独立分页状态，支持递归展开多级树。
6. 节点没有子节点时显示“暂无子节点”，不显示子节点“加载更多”。

### 4.3 加载子节点

1. “加载更多”固定显示在当前父节点最后一条子节点之后。
2. 点击后仅追加当前父节点的下一批子节点。
3. 其他父节点的展开状态、子节点数据和滚动位置不被重置。
4. 加载期间按钮变为“加载中”，禁止重复点击。
5. 加载失败时保留已经展示的子节点，将按钮变为“重新加载”。
6. 服务端返回 `has_more=false` 后隐藏按钮，并保留“已加载 N 条”信息。

### 4.4 加载父节点

1. “加载更多”固定显示在当前已加载父节点的最后一行之后。
2. 点击后只追加下一批父节点，不清空已加载父节点。
3. 已展开父节点及其子节点数据保持不变。
4. 加载期间父节点按钮变为“加载中”，禁止重复点击。
5. 加载失败时保留当前表格数据，底部显示错误提示和“重新加载”。
6. 服务端返回 `has_more=false` 后隐藏父节点按钮，底部显示“已加载全部父节点”。

### 4.5 查询、重置和刷新

- 查询或重置时清空当前树表数据，父节点和所有子节点分页状态重新开始。
- 查询条件分别作用于父节点和当前展开父节点的子节点，父节点与子节点使用各自的游标状态。
- 刷新时回到第一批父节点，已展开状态清空，避免旧数据与新查询结果混合。
- 查询、重置、刷新期间禁止点击父节点和子节点的“加载更多”。

## 5. 表格字段与操作

- 表格支持固定表头；树节点名称列展示层级缩进和展开/收起图标。
- 树节点展开图标参考 Element UI，使用 `>`；展开后旋转 90 度表示收起入口，不使用 `▶`、`▼` 等三角形字符。
- 父节点和子节点使用同一套列结构，避免展开后列错位。
- 操作列使用文本按钮；父节点和子节点的操作权限分别由权限控制。
- 长文本单行展示，超出列宽显示省略号，Tooltip 展示完整内容。
- 加载更多按钮使用文本按钮，不使用带背景色的按钮。
- “加载更多”不作为普通数据行，不参与排序和操作列统计。

## 6. 状态示意

交互原型提供以下可切换演示状态：

- 正常：父节点和子节点均可追加。
- 父节点加载中：底部显示加载状态，已有内容保持不变。
- 子节点加载中：只在当前父节点内部显示加载状态。
- 父节点加载失败：底部显示错误和重新加载。
- 子节点加载失败：当前父节点内部显示错误和重新加载。
- 父节点无更多：隐藏父节点加载按钮。
- 子节点无更多：隐藏当前父节点子节点加载按钮。
- 父节点无子节点：显示“暂无子节点”。
- 空数据：显示“暂无数据”，不显示加载更多按钮。
- 查询无结果：显示“未找到匹配节点”。

## 7. 已实现接口

### 7.1 父节点批次

```text
GET /api/v1/organizations/tree/parents
  tenant_id
  keyword
  status
  cursor
  page_size

返回：
{
  items: [],
  next_cursor: "...",
  has_more: true
}
```

### 7.2 子节点批次

```text
GET /api/v1/organizations/{parent_id}/children
  status
  keyword
  cursor
  page_size

返回：
{
  items: [],
  next_cursor: "...",
  has_more: true
}
```

父节点和子节点均使用游标续取，排序分别为租户、创建时间、ID以及创建时间、ID；租户管理员只能访问当前租户范围，平台超级管理员可按租户筛选。

## 8. 实现验收重点

1. 父节点是否默认折叠，首次展开时再加载子节点。
2. 父节点和子节点是否都采用游标续取，而不是使用页码。
3. 父节点加载更多后，已展开子节点是否保持展开和原有数据。
4. 查询条件是只过滤父节点，还是需要同时过滤子节点。
5. 父节点和子节点是否使用相同的单批加载数量。
6. 加载失败时是保留已加载数据并局部重试，还是重新加载整个树表。
7. 父节点、子节点和操作列分别需要哪些权限。
