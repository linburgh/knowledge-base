# 组织树快速查找定位原型设计

## 1. 设计目标

在分页树表已经加载部分数据时，用户可以直接使用页面顶部的查询条件进行深度查找，并定位到树表中的真实节点。查询不能只搜索当前已加载的行，必须在当前用户有权限的组织范围内进行服务端查询。

## 2. 页面入口

组织管理页面只保留一个查询条件栏，现有查询条件默认采用深度查找：

```text
组织名称 [请输入组织名称或编码]   组织状态 [全部状态]   [查询] [重置] [刷新]
```

- 组织名称字段同时匹配组织名称和组织编码，点击“查询”后直接执行深度查找。
- 所属租户用于确定查询范围，组织状态作为深度查找过滤条件。
- 默认查询当前页面范围：平台超级管理员为当前选择租户或全平台范围，`tenant_admin` 只能查询当前租户。
- 输入为空时不执行名称定位，展示当前范围的根组织分页。

## 3. 查找结果交互

### 3.1 匹配一条

直接定位，不弹窗。定位时以目标节点的直接父节点为焦点，不加载目标节点之前的全部分页：

1. 一次请求当前范围内的匹配节点、祖先路径、直接父节点和目标节点所在位置摘要。
2. 先展示目标父节点及其第一批子节点，默认每页 5 条。
3. 如果目标节点就在第一批中，直接高亮并滚动定位。
4. 如果目标节点不在第一批中，在第一批之后插入定位结果区域：

   ```text
   节点A父
     节点A兄1
     节点A兄2
     节点A兄3
     节点A兄4
     节点A兄5

     加载更多-父级：节点A父

     节点A

     加载更多-父级：节点A父
   ```

5. 目标节点作为定位结果单独展示，不计入当前普通分页批次。
6. 目标行使用浅蓝色背景和左侧定位标记，并滚动到树表容器中央。
7. 不额外插入“定位结果”文字行，目标节点沿用原组织名称，仅通过高亮和自动滚动标识。

### 3.2 匹配多条

弹出“选择组织”对话框，不直接展开任意结果：

- 标题：选择要定位的组织。
- 展示字段：组织名称、组织编码、所属租户、组织路径、组织状态。
- 组织路径必须从根节点开始，避免同名组织无法区分。
- 默认按组织路径排序，最多展示当前接口返回的 20 条结果。
- 对话框内提供“组织名称/编码”二次过滤，不重新改变主页面树表查询条件。
- 点击某条结果的“定位”后关闭弹窗并执行祖先链加载、滚动和高亮。
- 点击“取消”只关闭弹窗，树表状态保持不变。

### 3.3 定位节点不在首批时的双向续载

- 定位结果区域上方的“加载更多”负责加载目标节点之前的同级节点，并插入到定位节点上方。
- 定位结果区域下方的“加载更多”负责加载目标节点之后的同级节点，并插入到定位节点下方。
- 上下两个加载按钮互相独立，加载一个方向时另一个方向仍可见但不可重复提交。
- 加载到目标节点相邻数据后，定位结果仍保留定位标记，不能被普通分页数据覆盖。
- 前置或后续数据全部加载完成后，对应按钮改为“已加载全部”。
- 定位节点的前后数量、游标和是否还有更多数据由后端返回，前端不根据当前页推算。

### 3.4 深层祖先路径渐进展开

当目标节点层级很深时，不一次性渲染完整祖先链。以第 10 级节点为例，初始定位上下文展示：

```text
第0级
  … 已省略 8 层，点击查看完整路径 …
    第9级链路
      第10级链路
```

用户点击省略行后，只向目标方向补充一层祖先上下文，并展示该层首批子节点：

```text
第0级
  第8级链路
    … 已省略 7 层，点击查看完整路径 …
      第9级链路
      第10级链路
```

以点击“已省略 7 层，点击查看完整路径”为例，必须出现第 8 级及其首批子节点，不能只补出第 8 级名称：

```text
第0级
  … 已省略 7 层，点击查看完整路径 …
    第8级链路
      第8级第一页
        第9级链路
          第10级链路
        第9级同级节点-2
        第9级同级节点-3
        第9级同级节点-4
        第9级同级节点-5

      加载更多-父级：第8级链路
```

其中“已省略 7 层，点击查看完整路径”文本按钮是本次展开的触发入口。

之后按同样规则递推，省略层数依次变为 6、5、4……直到中间层级全部展开。每次点击只加载一层和该层首批数据，不展开该层全部子树；已展开的层级需要缓存，重复点击不重复请求。展开后目标节点必须保持高亮，且通过滚动位置修正继续保持在可视区域内。

省略行是路径上下文操作行，不是组织数据行，不显示查看、编辑、删除等业务操作。请求失败时保留当前已展示内容，仅在该行显示“重新加载”。

### 3.5 已有部分层级展开时的定位

如果查找目标节点时，第 1～6 层已经展开，定位不能重置当前树状态，也不能重复渲染第 1～6 层。应在第 6 层下面接入剩余的压缩路径：

```text
第0级
  第1级
    第2级
      第3级
        第4级
          第5级
            第6级
              … 已省略 2 层，点击查看完整路径 …
                第9级链路
                  第10级链路
                  第10级同级节点-2
                  第10级同级节点-3
                  第10级同级节点-4
                  第10级同级节点-5

                  加载更多-父级：第9级链路
```

- 已展开的第 1～6 层保持展开状态、已加载数据、滚动位置和分页游标。
- 第一次点击“已省略 2 层”时，优先补充靠近目标的第 8 层，并将提示改为“已省略 1 层”。
- 第二次点击后补充第 7 层，完成第 6～9 层之间的路径上下文。
- 每次只增加一个祖先层级及该层首批子节点，不自动展开无关分支。
- 定位结果高亮和自动滚动不因上下文补充而丢失；补充内容导致目标位置变化时，需要修正滚动位置保持目标可见。

### 3.6 没有匹配

不弹窗，输入框下方显示空结果提示：

```text
未找到匹配的组织，请检查组织名称或编码。
```

### 3.7 加载和异常

- 查询中：查找按钮显示“查找中”，输入框保留，禁止重复提交。
- 祖先链加载中：目标结果保持选中状态，树表显示“正在展开组织路径…”。
- 定位上下文加载中：显示“正在加载目标节点附近数据…”，已展示的首批数据不清空。
- 接口失败：显示“快速查找失败，请重试”，不清空当前树表数据。
- 前置或后续分页失败：只在对应方向显示“重新加载”，另一方向和定位结果保持不变。
- 目标节点已删除或无权限：显示“该组织已不存在或无权访问”，不定位到树表。

### 3.8 定位结束

- 定位完成后保留定位上下文，直到用户再次查找、刷新或点击“清除定位”。
- 点击“清除定位”后，移除定位节点上下文和高亮，恢复普通树表分页状态。
- 点击“加载当前层全部”前必须二次提示可能加载大量同级数据。

### 3.9 树节点图标、层级缩进和分页文案

- 有子节点的节点显示 Element Plus `ArrowRight` 展开图标，展开后图标旋转为收起状态；没有子节点的节点保留等宽图标占位，保证子节点文字不会与父节点同级。
- 定位上下文中的祖先路径节点显示为已展开状态，点击展开图标可以收起当前节点以下的定位上下文，再次点击恢复展示；收起不能清除定位目标、祖先路径数据或高亮状态。
- 定位目标和定位上下文中的子节点统一使用树形层级前缀和缩进，目标节点不得因为高亮样式丢失层级标识。
- 所有子节点分页入口都显示父级名称，统一格式为：

  ```text
  加载更多-父级：性能测试树-000000-第9级链路
  ```

- 加载入口必须与对应层级的子节点文字对齐；前置、后置和当前层分页入口使用唯一行键，不能重叠到同一表格行，也不能出现重复文案。
- 根组织分页没有业务父级，显示为“加载更多-父级：根组织”。

## 4. 交互原型状态

原型 HTML 覆盖以下可点击状态：

| 状态 | 演示方式 | 预期结果 |
|---|---|---|
| 单条匹配且在首批 | 输入“平台组”并点击查找 | 直接滚动到节点并高亮 |
| 单条匹配且不在首批 | 输入“节点A”并点击查找 | 展示首批子节点、定位节点和上下双向“加载更多” |
| 多条匹配 | 输入“技术中心”并点击查找 | 弹出选择组织对话框 |
| 无匹配 | 输入“未登记组织”并点击查找 | 显示无匹配提示 |
| 加载中 | 点击查找后短暂等待 | 按钮显示查找中，树表数据不清空 |
| 查找失败 | 点击“模拟接口异常” | 显示错误提示，保留原树表 |
| 取消选择 | 多条结果弹窗点击取消 | 弹窗关闭，树表不变化 |

## 5. 定位规则

- 定位结果必须携带 `id`、`tenant_id`、`name`、`code`、`path`、祖先节点 ID 列表、直接父节点 ID 和目标节点前后数量摘要。
- 初次定位返回祖先路径摘要、目标父节点和目标节点附近首批数据；中间祖先层级由用户点击省略行后按层加载，不自动逐级展开。
- 分层加载必须以当前已展开路径的最深层级为锚点，已存在的树状态不能被定位流程清空或覆盖。
- 分层加载优先补齐靠近目标节点的一层，再向根方向递推，保证每次点击的反馈明确且数据量可控。
- 定位节点不在首批时，接口返回前置/后续分页游标；前端围绕定位节点双向续载。
- 前端按祖先节点 ID 合并树状态，不能仅依赖名称匹配，也不能为了定位逐页扫描全部兄弟节点。
- 同名组织必须通过组织路径、编码和所属租户区分。
- 定位使用主列表的关键词、状态、租户条件，不额外维护第二套查询条件。
- 若目标节点不在当前已加载批次，定位流程只加载目标前后的必要上下文，不加载无关分页；祖先上下文同样遵循按层加载规则。

## 6. 待评审事项

1. 组织名称字段是否同时支持名称和编码，当前原型按同时支持设计。
2. 多结果对话框是否需要展示所属租户，当前按平台超级管理员场景保留该字段。
3. 定位后高亮持续 3 秒，是否需要改为持续高亮直到下一次操作。
4. 当前原型默认最多展示 20 条匹配结果，是否需要在弹窗内继续“加载更多”。
5. 定位节点上下文默认每页展示 5 条，是否需要与树表普通分页统一为 20 条。

## 7. 已落地接口

- `GET /api/v1/organizations/tree/locate`：按当前权限范围搜索组织名称或编码，最多返回 20 条候选。
- `GET /api/v1/organizations/tree/locate/{id}`：一次返回祖先链、直接父组织、首批 5 条同级节点和定位前后游标。
- `GET /api/v1/organizations/tree/locate/{id}/siblings`：根据 `direction=before|after` 围绕目标节点双向加载同级节点。
- `GET /api/v1/organizations/tree/locate/{id}/ancestor-page`：根据目标祖先 ID 返回该层首批子节点及后续游标，支持逐层展开和当前层“加载更多”。
- 所有定位接口复用组织管理权限和租户范围校验；前端不通过逐级请求扫描祖先或同级分页。

## 8. 本次实现总结

- 查询栏的组织名称字段直接执行服务端深度查找，不新增独立“快速查找”入口。
- 单条结果按祖先链、目标父级首批子节点和目标前后同级节点构造定位上下文；多条结果先弹窗选择，再按节点 ID 定位。
- 深层路径采用“已省略 N 层，点击查看完整路径”逐层递推，优先补充靠近目标的一层及该层第一页，不一次性展开全部祖先。
- 已有第 1～6 层展开时保留原有树状态、分页数据和游标，从当前最深展开层继续接入压缩路径。
- 目标父级的子节点按游标分页，支持前置、后置和当前层“加载更多”，定位目标始终保持高亮和自动滚动。
- 已补充定位上下文节点的展开/收起、层级图标占位、分页行唯一键和父级文案，避免节点同级、按钮重叠和重复文案。
- 已通过前端格式检查、类型检查、构建和组织树深度定位 E2E 测试。
