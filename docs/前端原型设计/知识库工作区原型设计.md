# 知识库工作区原型设计

> 本文档内容已纳入[知识库系统完整前端原型设计](知识库系统完整原型设计.md)。统一可交互原型同时包含平台管理与知识库工作区，请打开 `知识库工作区原型.html` 查看。

## 1. 设计目标

本方案先确认前端信息架构和交互，不直接进入代码开发。

系统先展示独立的登录页，仅包含用户名或邮箱、密码、“记住密码”选项、登录按钮和登录失败提示，不要求用户手动选择租户。登录成功后根据用户的租户关系进入对应的租户上下文；退出登录后返回登录页。

“记住密码”勾选后，原型模拟保留本次登录填写的用户名和密码，下次打开登录页时自动回填；未勾选时不回填密码。

登录后的租户处理规则如下：

- 用户只属于一个租户时，自动进入该租户，不额外弹窗。
- 用户属于多个租户时，登录成功后展示租户选择页或弹窗，选择后进入对应租户。
- 平台超级管理员登录后进入平台管理，可在平台管理中选择目标租户。

统一原型提供三类演示路径：单租户用户直接进入知识库主页，多租户用户登录后弹出租户选择层，平台超级管理员登录后弹出目标租户选择层并进入平台管理。

页面路径约定：登录页为 `/login`，登录成功后的知识库管理主页为 `/knowledge-bases`。

系统采用“知识库管理 → 独立知识库工作区”的两级结构，左侧主导航只保留“知识库管理”：

```text
知识库管理
├── 知识库列表
└── 进入某个知识库工作区
    ├── 概览
    ├── 文档
    └── 问答

知识库列表操作
└── 工作区顶部“文档”标签 → 当前知识库工作区的文档页
```

每个工作区都由 URL 中的 `kb_id` 唯一确定：

```text
/knowledge-bases/:kbId/overview
/knowledge-bases/:kbId/documents
/knowledge-bases/:kbId/chat
```

文档管理和问答页面不作为全局功能展示，必须处于某一个知识库工作区内。

## 2. 页面关系

### 2.1 知识库管理

用途：创建、搜索、修改、删除知识库，并进入指定知识库工作区。

页面内容：

- 知识名称、描述、知识状态。
- 条件查询：知识名称、知识状态、创建用户。
- 查询和重置操作。
- 文档数量和索引状态摘要。
- “工作区”操作，进入当前知识库工作区。
- “修改”操作，打开右侧抽屉并回填当前知识库信息。
- 删除操作。
- “新建知识库”右侧抽屉表单。

知识库新建和修改共用同一个右侧抽屉表单，字段顺序如下：

1. 名称：必填，最多 255 个字符。
2. 所属租户：必填，下拉选择有效租户；修改时回填当前所属租户。
3. 描述：可选，最多 500 个字符。
4. 系统提示词：可选，使用多行文本框，最多 10000 个字符。

所属租户未选择时禁止保存，并提示“请选择知识库所属租户”。租户下拉选项展示租户名称，不展示租户 ID；修改知识库时不允许提交空租户。

系统提示词下方展示说明：该提示词只对当前知识库的问答生效，用于补充回答角色、语气、格式和专业规则；不能覆盖系统安全约束，也不能改变知识库隔离规则。

修改系统提示词后，保存时更新提示词版本和更新时间。新建知识库未填写时使用系统默认提示词。

知识库管理是默认首页，负责创建、搜索、修改、删除知识库，并进入指定知识库工作区。

知识库列表不展示 Embedding 模型列，展示知识名称、描述、知识状态、创建时间、创建用户和操作；查询条件与列表字段保持一一对应。

状态使用中文文字展示，例如：`正常`、`处理中`、`已删除`。

创建时间统一格式为：`2026年07月18日 12:00:00`。

列表默认按创建时间倒序排列，底部提供分页：

- 当前页码。
- 每页条数：10、20、50。
- 总记录数。
- 上一页、下一页和页码跳转。

查询条件改变后点击“查询”才发起请求；点击“重置”清空条件并回到第一页。

查询条件栏使用流式布局，不按 2K、4K 等固定分辨率预设每行控件数量；字段组按照可用宽度自动排列，空间不足时按字段组整体换行。

查询条件中的字段组统一使用固定宽度 325px，避免不同显示器下标签和控件宽度变化导致排版跳动；移动端可切换为容器全宽。

查询字段采用“标签在左、控件在右”的同行布局，标签统一左对齐并在控件高度内上下居中；标签与控件属于同一字段组，禁止上下拆分或错位。查询交互控件统一使用 Element Plus 表单控件。


知识库列表展示所属租户名称和所属组织名称，不展示租户 ID 或组织 ID。操作列固定包含“工作区”“修改”“授权”“删除”四个操作，其中“授权”为下拉按钮，包含“用户授权”和“组织授权”两个入口。点击“工作区”进入当前知识库工作区；点击授权入口后打开对应权限管理抽屉；按钮之间保持明确间距，避免操作项挤在一起。

组织授权抽屉标题为“组织访问权限管理”，不复用知识库编辑表单，内容包含当前知识库信息、权限说明和当前已授权组织。点击“添加授权组织”按钮后，从侧边滑出“选择授权组织”面板；面板展示当前租户下尚未授权的组织，使用普通列表展示多选框、组织名称、上级组织三列，并提供搜索和分页。搜索与分页均通过后端接口获取数据，接口原型为 `GET /api/v1/knowledge-bases/{kb_id}/organizations/available`，支持 `keyword`、`page` 和 `page_size` 参数。勾选完成后点击“确认”，所选组织直接追加到当前已授权组织列表，不设置额外的“批量授权”步骤。点击“取消”、关闭按钮或遮罩关闭面板时，放弃本次未确认的选择。已授权组织展示组织名称和访问权限状态，并提供“撤销”操作。授权只控制组织成员对知识库的访问范围，不改变知识库的所属租户或所属组织。

#### 通用待选列表交互规范

待选列表是项目内可复用的通用交互模式，适用于组织、用户、租户成员、数据源等“从候选集合中选择并加入已选结果”的场景。后续新增同类页面必须遵守以下规则：

1. **入口与容器**
   - 在已选结果区域提供明确的“添加”类文本或主按钮。
   - 点击后从右侧滑出“选择[对象]”面板，不跳转页面，不覆盖当前已选结果。
   - 面板关闭、点击遮罩或点击“取消”时，只关闭面板并丢弃本次临时选择。

2. **列表结构**
   - 待选数据使用正常表格列表，不使用下拉框替代，不使用静态卡片堆叠。
   - 第一列固定为多选框列，后续列按对象属性定义；组织和用户场景统一为三列。
   - 组织列表列为：多选、组织名称、上级组织。
   - 用户列表列为：多选、用户名称、所属组织；不展示邮箱地址列。
   - 列表必须同时提供加载中、无结果、接口异常和正常数据状态。

3. **搜索与分页**
   - 查询条件放在列表上方，查询字段使用四字标签或清晰的对象属性提示。
   - 搜索和分页必须通过后端候选接口获取数据，前端不得用全量静态数据模拟分页。
   - 接口至少支持 `keyword`、`page`、`page_size`，返回 `rows`、`total`、`page`、`page_size`。
   - 候选接口必须在服务端按业务上下文过滤，并排除当前已选或已授权对象，避免前端跨页过滤造成总数不准确。
   - 查询条件变化后重置到第一页；切换页码时保留当前关键词。

4. **多选与临时状态**
   - 勾选结果只保存在面板临时状态中，不在勾选时直接写入已选结果或提交后端。
   - 跨页选择时保留已勾选 ID，返回上一页或重新查询时恢复当前页已选状态。
   - 已授权对象不出现在待选列表中；重复选择由前端展示层和后端接口共同防重。

5. **确认与结果回填**
   - 面板底部固定提供“取消”和“确认”两个文本/按钮操作。
   - 点击“确认”后关闭面板，将本次选择结果直接追加到外层的已选结果列表，并刷新数量。
   - 原型不设置额外的“批量授权”按钮；多选后的确认即完成本次选择动作。后端可以使用批量事务接口实现一次提交，但不改变前端交互。
   - 提交或回填失败时保留面板上下文，展示明确错误提示，不使用本地数据伪造成功结果。

6. **复用边界**
   - 只替换对象标题、表格字段、候选接口和结果行展示，不改变待选列表的布局、状态、分页和确认取消逻辑。
   - 需要树形选择、拖拽排序或复杂联动时，应在此规范上扩展，并在对应原型文档中明确说明，不得默默改变通用待选列表行为。

列表页不展示所有知识库的文档，也不提供跨知识库文档列表。

### 2.2 文档管理入口

文档管理不设置独立的左侧菜单入口，也不是跨知识库的文档汇总页。

点击“文档管理”后的行为：

1. 如果尚未选择知识库，展示知识库选择页。
2. 用户选择一个知识库后，进入 `/knowledge-bases/:kbId/documents`。
3. 页面标题、上传动作、查询条件和文档表格全部绑定这个 `kb_id`。
4. 切换知识库后重新加载文档列表，不保留上一个知识库的文档数据。

文档管理首页的知识库选择列表提供：

- 知识名称查询。
- 知识状态筛选。
- 创建用户筛选。
- 查询和重置按钮。
- 刷新按钮与查询条件放在同一工具栏中，使用文字按钮。
- 总记录数、页码、上一页、下一页和每页条数分页。
- 不展示“文档范围”列，选择知识库后再进入对应文档工作区。

文档管理页面提供“进入问答”按钮，进入当前知识库的 `/knowledge-bases/:kbId/chat`。

### 2.3 知识库工作区

进入工作区后，顶部固定显示当前知识库名称、状态和 `kb_id`，并提供工作区内导航：

```text
< 返回知识库列表   企业制度库   [active]
                    概览 | 文档 | 问答
```

工作区内的所有请求都必须使用当前路由的 `kb_id`。

工作区概览补充图表区域：

- 文档处理趋势：使用 ECharts 折线图展示每日新增文档和索引完成数量。
- 文档状态分布：展示待处理、处理中、已完成和失败数量。
- 问答趋势：使用 ECharts 折线图展示问答次数和活跃会话数。
- 检索质量：不在页面展示相似度数值，仅展示无参考资料回答数量等可读性更强的质量指标。
- 热门问题、文档引用排行和最近活动。

图表只统计当前知识库的数据，支持时间范围切换；无数据时显示空状态，异常指标需要突出显示。

### 2.4 文档页

页面职责：管理当前知识库的文档，不显示其他知识库的文档。

页面内容：

- 当前知识库名称和说明。
- 文档统计：全部、已完成、处理中、失败。
- 当前知识库文档表格。
- “上传文档”右侧抽屉。
- 文档详情查看入口。
- 处理中的文档显示处理中状态，不提供重复上传按钮。
- 失败文档的错误信息和重新索引操作。
- 删除文档操作。

用户先从知识库列表进入工作区，再通过工作区顶部的“文档”标签进入对应文档工作区。

进入具体知识库后的文档列表操作列根据状态显示：

- `ready`：查看分片、删除。
- `processing` / `pending`：查看索引状态、删除。
- `failed`：查看错误、重新索引、删除。

文档列表不展示“文档范围”列，因为当前页面已经处于明确的知识库工作区。
列表提供文档名称、文档状态条件查询，以及总记录数、页码、上一页、下一页和每页条数分页；列表必须展示文档名称、文档状态对应字段列。
分页按钮使用纯文本按钮，不使用背景色。

### 2.4.1 文档分片信息

文档列表的“查看”动作定义为“查看分片”，不是打开原始文件预览。

点击后打开右侧详情抽屉，抽屉内容包括：

- 文档名称、文件类型、文件大小、上传时间。
- 文档索引状态和错误信息。
- 分片总数、已生成向量数量和向量维度。
- 分片列表。

分片列表提供内容模糊查询和分页：

- 按分片正文关键词模糊查询。
- 查询和重置按钮。
- 刷新按钮与查询条件放在同一工具栏中，使用文字按钮。
- 总记录数、页码、上一页、下一页和每页条数。
- 查询条件和分页按钮均使用文本样式。

分片列表字段：

| 字段 | 说明 |
|---|---|
| 分片序号 | 当前分片在文档中的顺序 |
| 内容摘要 | 分片正文的前若干字符 |
| Token 数 | 当前分片的 token_count |
| 向量状态 | 已生成或未生成 |
| 操作 | 展开查看完整分片内容 |

分片详情需要能够看到完整文本、来源文档、页码、章节、起始位置和元数据。这样可以直接核对“文档已索引”与“检索实际使用的内容”是否一致。

文档状态：

```text
pending → processing → ready
                       └→ failed
```

上传成功只表示文件已经接收，不代表向量已经生成。只有 `ready` 才表示文档可以参与问答检索。

### 2.5 问答页

页面职责：在当前知识库中创建和继续会话。

页面内容：

- 当前知识库名称和索引可用状态。
- 会话列表，包括唯一的“新建会话”按钮和历史会话。
- 当前会话标题和消息区。
- 点击“新建会话”后清空当前消息并创建新的会话上下文。
- 问题输入区。
- 输入区支持快捷键：按 Enter 发送问题，按 Shift+Enter 换行；发送按钮保留作为鼠标操作入口。
- 当前回答的引用面板。
- 命中数量、会话 ID 等调试信息。
- 助手回答支持 Markdown，包含标题、段落、加粗、列表、引用、代码块和表格。
- Markdown 内容先经过 HTML 安全过滤，再渲染到消息区。

问答请求必须携带：

```json
{
  "kb_id": 1,
  "question": "报销流程需要哪些材料？",
  "user_id": "dev-user",
  "conversation_id": 10
}
```

服务端返回新的 `conversation_id` 后，前端保存它，后续问题继续使用同一会话。

## 3. 导航约束

左侧导航只负责一个一级功能：

- 知识库管理

文档和问答不出现在左侧主导航中。进入具体知识库后，工作区导航显示：

- 概览
- 文档
- 问答

文档管理主导航在没有选定知识库时只展示知识库选择页，不能指向固定知识库 ID。这样既保留文档管理的一级入口，又不会造成所有知识库文档共享的误解。

## 4. 表单交互

所有表单统一使用右侧抽屉，不使用居中对话框：

- 新建知识库：右侧抽屉。
- 编辑知识库：右侧抽屉。
- 上传文档：右侧抽屉。
- 文档元数据编辑：右侧抽屉。

表单视觉规范：

- 知识库信息表单使用 Element Plus 表单控件，并使用 Bootstrap 的基础布局体系组织字段结构。
- 表单标签统一使用 13px 字号、400 字重和 20px 行高；输入框、选择框和文本域中的输入文字、选择文字和占位文字统一使用 13px 字号，并保持清晰的 20px 行高。
- 表单颜色按信息层级统一：标签使用沉稳的次级文字色，已填写内容使用高对比度主文字色，占位文字使用弱化文字色，禁用内容进一步弱化，校验错误使用明确但不过度刺眼的错误色。
- 表单控件统一使用约 38px 高度；标签与控件之间保留明确间距，字段之间保持一致的垂直间距，不能出现标签紧贴字段的情况。
- 必填星号与标签保持稳定的占位和间距，不得导致同一表单中的标签错位；校验提示和帮助文案归属于当前字段组。
- 表单不得使用页面级临时字体或随意覆盖公共间距，新增字段优先复用统一公共表单样式。
- 查询条件标签字体使用 `#151517`，输入内容、占位文字和禁用态继续按既有层级区分；列表仅表头字体使用 `#151517`，表格正文、辅助信息、操作文字和状态文字继续按既有层级区分。

删除确认可以继续使用确认提示，因为它不是表单录入场景。

## 5. 状态展示

列表中的状态只使用文字颜色区分，不使用彩色背景标签：

- `ready` / `active`：绿色文字。
- `processing` / `pending`：橙色文字。
- `failed`：红色文字。
- 其他状态：灰色文字。

这样可以减少视觉噪音，让文件名、知识库名称和操作按钮成为列表的主要信息。

## 6. 关键接口边界

| 页面动作 | 接口 | 必须携带的知识库范围 |
|---|---|---|
| 查询知识库详情 | `GET /knowledge-bases/{id}` | URL 中的 `id` |
| 查询文档 | `GET /documents?kb_id={id}` | 当前工作区 `kb_id` |
| 上传文档 | `POST /documents/upload` | FormData 中的 `kb_id` |
| 删除文档 | `DELETE /documents/{id}` | 由文档记录绑定的 `kb_id` 校验 |
| 发起问答 | `POST /chat` | JSON 中的 `kb_id` |
| 查询引用 | 由问答响应返回 | 只能展示当前回答引用 |

前端不得把文档列表放在全局 Store 中作为跨知识库共享数据。文档列表应以当前工作区的 `kb_id` 为查询键，在路由切换时重新加载。

## 7. 页面原型

可直接打开同目录的 `知识库工作区原型.html` 查看页面切换效果。

原型包含三个状态：

1. 知识库管理列表。
2. 文档管理中的知识库选择状态。
3. `企业制度库` 的文档管理页。
4. `企业制度库` 的问答页。

点击另一个知识库后，原型会切换当前工作区名称和文档集合，说明文档数据属于当前知识库，而不是全局共享。

## 8. 开发前确认项

请确认以下设计后再开始继续开发：

- 是否采用“知识库列表 → 独立工作区”的两级导航。
- 是否同意文档和问答只在当前工作区内出现。
- 是否同意所有表单统一使用右侧抽屉。
- 文档页是否需要增加概览页和文档统计卡片。
- 问答页是否保留会话列表和检索调试信息。
