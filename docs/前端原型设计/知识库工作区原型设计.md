# 知识库工作区原型设计

## 1. 设计目标

本方案先确认前端信息架构和交互，不直接进入代码开发。

系统采用“知识库管理 → 独立知识库工作区”的两级结构，左侧主导航只保留“知识库管理”：

```text
知识库管理
├── 知识库列表
└── 进入某个知识库工作区
    ├── 概览
    ├── 文档
    └── 问答

知识库列表操作
└── 管理文档 → 当前知识库工作区的文档页
```

每个工作区都由 URL 中的 `kb_id` 唯一确定：

```text
/knowledge-bases/:kbId/overview
/knowledge-bases/:kbId/documents
/knowledge-bases/:kbId/chat
```

文档管理和问答页面不作为全局功能展示，必须处于某一个知识库工作区内。

## 2. 页面关系

### 2.1 知识库管理

用途：创建、搜索、修改、删除知识库，并进入指定知识库工作区。

页面内容：

- 知识库名称、描述、状态。
- 条件查询：名称关键词、状态、创建人。
- 查询和重置操作。
- 文档数量和索引状态摘要。
- “进入工作区”操作。
- “修改”操作，打开右侧抽屉并回填当前知识库信息。
- 删除操作。
- “新建知识库”右侧抽屉表单。

知识库管理是默认首页，负责创建、搜索、修改、删除知识库，并进入指定知识库工作区。

知识库列表不展示 Embedding 模型列，展示知识库名称、描述、状态、创建时间、创建人和操作。

状态使用中文文字展示，例如：`正常`、`处理中`、`已删除`。

创建时间统一格式为：`2026年07月18日 12:00:00`。

列表默认按创建时间倒序排列，底部提供分页：

- 当前页码。
- 每页条数：10、20、50。
- 总记录数。
- 上一页、下一页和页码跳转。

查询条件改变后点击“查询”才发起请求；点击“重置”清空条件并回到第一页。

知识库列表操作列固定包含四个文本按钮：进入工作区、管理文档、修改、删除。按钮之间保持明确间距，避免操作项挤在一起。

列表页不展示所有知识库的文档，也不提供跨知识库文档列表。

### 2.2 文档管理入口

文档管理不设置独立的左侧菜单入口，也不是跨知识库的文档汇总页。

点击“文档管理”后的行为：

1. 如果尚未选择知识库，展示知识库选择页。
2. 用户选择一个知识库后，进入 `/knowledge-bases/:kbId/documents`。
3. 页面标题、上传动作、查询条件和文档表格全部绑定这个 `kb_id`。
4. 切换知识库后重新加载文档列表，不保留上一个知识库的文档数据。

文档管理首页的知识库选择列表提供：

- 知识库名称关键词查询。
- 状态筛选。
- 创建人筛选。
- 查询和重置按钮。
- 总记录数、页码、上一页、下一页和每页条数分页。
- 不展示“文档范围”列，选择知识库后再进入对应文档工作区。

文档管理页面提供“进入问答”按钮，进入当前知识库的 `/knowledge-bases/:kbId/chat`。

### 2.3 知识库工作区

进入工作区后，顶部固定显示当前知识库名称、状态和 `kb_id`，并提供工作区内导航：

```text
< 返回知识库列表   企业制度库   [active]
                    概览 | 文档 | 问答
```

工作区内的所有请求都必须使用当前路由的 `kb_id`。

### 2.4 文档页

页面职责：管理当前知识库的文档，不显示其他知识库的文档。

页面内容：

- 当前知识库名称和说明。
- 文档统计：全部、已完成、处理中、失败。
- 当前知识库文档表格。
- “上传文档”右侧抽屉。
- 文档详情查看入口。
- 处理中的文档显示处理中状态，不提供重复上传按钮。
- 失败文档的错误信息和重新索引操作。
- 删除文档操作。

用户从知识库列表操作列点击“管理文档”文本按钮，直接进入对应知识库的文档工作区。

进入具体知识库后的文档列表操作列根据状态显示：

- `ready`：查看分片、删除。
- `processing` / `pending`：查看索引状态、删除。
- `failed`：查看错误、重新索引、删除。

文档列表不展示“文档范围”列，因为当前页面已经处于明确的知识库工作区。
列表提供文件名关键词、文档状态条件查询，以及总记录数、页码、上一页、下一页和每页条数分页。
分页按钮使用纯文本按钮，不使用背景色。

### 2.4.1 文档分片信息

文档列表的“查看”动作定义为“查看分片”，不是打开原始文件预览。

点击后打开右侧详情抽屉，抽屉内容包括：

- 文档名称、文件类型、文件大小、上传时间。
- 文档索引状态和错误信息。
- 分片总数、已生成向量数量和向量维度。
- 分片列表。

分片列表提供内容模糊查询和分页：

- 按分片正文关键词模糊查询。
- 查询和重置按钮。
- 总记录数、页码、上一页、下一页和每页条数。
- 查询条件和分页按钮均使用文本样式。

分片列表字段：

| 字段 | 说明 |
|---|---|
| 分片序号 | 当前分片在文档中的顺序 |
| 内容摘要 | 分片正文的前若干字符 |
| Token 数 | 当前分片的 token_count |
| 向量状态 | 已生成或未生成 |
| 操作 | 展开查看完整分片内容 |

分片详情需要能够看到完整文本、来源文档、页码、章节、起始位置和元数据。这样可以直接核对“文档已索引”与“检索实际使用的内容”是否一致。

文档状态：

```text
pending → processing → ready
                       └→ failed
```

上传成功只表示文件已经接收，不代表向量已经生成。只有 `ready` 才表示文档可以参与问答检索。

### 2.5 问答页

页面职责：在当前知识库中创建和继续会话。

页面内容：

- 当前知识库名称和索引可用状态。
- 当前会话标题和消息区。
- 问题输入区。
- 当前回答的引用面板。
- 检索模式、命中数量、会话 ID 等调试信息。

问答请求必须携带：

```json
{
  "kb_id": 1,
  "question": "报销流程需要哪些材料？",
  "user_id": "dev-user",
  "conversation_id": 10
}
```

服务端返回新的 `conversation_id` 后，前端保存它，后续问题继续使用同一会话。

## 3. 导航约束

左侧导航只负责一个一级功能：

- 知识库管理

文档和问答不出现在左侧主导航中。进入具体知识库后，工作区导航显示：

- 概览
- 文档
- 问答

文档管理主导航在没有选定知识库时只展示知识库选择页，不能指向固定知识库 ID。这样既保留文档管理的一级入口，又不会造成所有知识库文档共享的误解。

## 4. 表单交互

所有表单统一使用右侧抽屉，不使用居中对话框：

- 新建知识库：右侧抽屉。
- 编辑知识库：右侧抽屉。
- 上传文档：右侧抽屉。
- 文档元数据编辑：右侧抽屉。

删除确认可以继续使用确认提示，因为它不是表单录入场景。

## 5. 状态展示

列表中的状态只使用文字颜色区分，不使用彩色背景标签：

- `ready` / `active`：绿色文字。
- `processing` / `pending`：橙色文字。
- `failed`：红色文字。
- 其他状态：灰色文字。

这样可以减少视觉噪音，让文件名、知识库名称和操作按钮成为列表的主要信息。

## 6. 关键接口边界

| 页面动作 | 接口 | 必须携带的知识库范围 |
|---|---|---|
| 查询知识库详情 | `GET /knowledge-bases/{id}` | URL 中的 `id` |
| 查询文档 | `GET /documents?kb_id={id}` | 当前工作区 `kb_id` |
| 上传文档 | `POST /documents/upload` | FormData 中的 `kb_id` |
| 删除文档 | `DELETE /documents/{id}` | 由文档记录绑定的 `kb_id` 校验 |
| 发起问答 | `POST /chat` | JSON 中的 `kb_id` |
| 查询引用 | 由问答响应返回 | 只能展示当前回答引用 |

前端不得把文档列表放在全局 Store 中作为跨知识库共享数据。文档列表应以当前工作区的 `kb_id` 为查询键，在路由切换时重新加载。

## 7. 页面原型

可直接打开同目录的 `知识库工作区原型.html` 查看页面切换效果。

原型包含三个状态：

1. 知识库管理列表。
2. 文档管理中的知识库选择状态。
3. `企业制度库` 的文档管理页。
4. `企业制度库` 的问答页。

点击另一个知识库后，原型会切换当前工作区名称和文档集合，说明文档数据属于当前知识库，而不是全局共享。

## 8. 开发前确认项

请确认以下设计后再开始继续开发：

- 是否采用“知识库列表 → 独立工作区”的两级导航。
- 是否同意文档和问答只在当前工作区内出现。
- 是否同意所有表单统一使用右侧抽屉。
- 文档页是否需要增加概览页和文档统计卡片。
- 问答页是否保留会话列表和检索调试信息。
