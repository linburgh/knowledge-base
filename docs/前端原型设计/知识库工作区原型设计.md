# 知识库工作区原型设计

> 本文档内容已纳入[知识库系统完整前端原型设计](知识库系统完整原型设计.md)。统一可交互原型同时包含平台管理与知识库工作区，请打开 `知识库工作区原型.html` 查看。

## 1. 设计目标

本方案先确认前端信息架构和交互，不直接进入代码开发。

系统先展示独立的登录页，仅包含用户名或邮箱、密码、“记住密码”选项、登录按钮和登录失败提示，不要求用户手动选择租户。登录成功后根据用户的租户关系进入对应的租户上下文；退出登录后返回登录页。

“记住密码”勾选后，原型模拟保留本次登录填写的用户名和密码，下次打开登录页时自动回填；未勾选时不回填密码。

登录后的租户处理规则如下：

- 用户只属于一个租户时，自动进入该租户，不额外弹窗。
- 用户属于多个租户时，登录成功后展示租户选择页或弹窗，选择后进入对应租户。
- 平台超级管理员登录后进入平台管理，可在平台管理中选择目标租户。

统一原型提供三类演示路径：单租户用户直接进入知识库主页，多租户用户登录后弹出租户选择层，平台超级管理员登录后弹出目标租户选择层并进入平台管理。

页面路径约定：登录页为 `/login`，登录成功后的知识库管理主页为 `/knowledge-bases`。

系统采用“知识库管理 → 独立知识库工作区”的两级结构，左侧主导航只保留“知识库管理”：

```text
知识库管理
├── 知识库列表
└── 进入某个知识库工作区
    ├── 概览
    ├── 文档（按角色菜单权限显示）
    └── 问答

知识库列表操作
└── 统一权限菜单 Tab 控件
    ├── 概览
    ├── 文档（拥有文档菜单权限时显示）
    └── 问答
```

每个工作区都由 URL 中的 `kb_id` 唯一确定：

```text
/knowledge-bases/:kbId/overview
/knowledge-bases/:kbId/documents
/knowledge-bases/:kbId/chat
```

文档管理和问答页面不作为全局功能展示，必须处于某一个知识库工作区内。

## 2. 页面关系

### 2.1 知识库管理

用途：创建、搜索、修改、删除知识库，并进入指定知识库工作区。

页面内容：

- 知识名称、描述、知识状态。
- 条件查询：知识名称、知识状态、创建用户。
- 查询和重置操作。
- 文档数量和索引状态摘要。
- “工作区”操作，进入当前知识库工作区。
- “修改”操作，打开右侧抽屉并回填当前知识库信息。
- 删除操作。
- “新建知识库”右侧抽屉表单。

知识库新建和修改共用同一个右侧抽屉表单，字段顺序如下：

1. 知识名称：必填，最多 255 个字符。
2. 所属租户：必填，下拉选择有效租户；修改时回填当前所属租户。
3. 系统提示词：可选，使用多行文本框，最多 10000 个字符。
4. 知识描述：可选，最多 500 个字符。

所属租户未选择时禁止保存，并提示“请选择知识库所属租户”。租户下拉选项展示租户名称，不展示租户 ID；修改知识库时不允许提交空租户。

知识库没有独立详情抽屉，进入知识库工作区后按表单顺序使用知识名称、所属租户、系统提示和知识描述等信息。

系统提示词下方展示说明：该提示词只对当前知识库的问答生效，用于补充回答角色、语气、格式和专业规则；不能覆盖系统安全约束，也不能改变知识库隔离规则。

修改系统提示词后，保存时更新提示词版本和更新时间。新建知识库未填写时使用系统默认提示词。

知识库管理是默认首页，负责创建、搜索、修改、删除知识库，并进入指定知识库工作区。

知识库列表不展示 Embedding 模型列，展示知识名称、描述、知识状态、创建时间、创建用户和操作；查询条件与列表字段保持一一对应。

状态使用中文文字展示，例如：`正常`、`处理中`、`已删除`。

创建时间统一格式为：`2026年07月18日 12:00:00`。

列表字段内容过长时保持单行展示，不自动换行；超出列宽统一使用省略号，必要时通过 tooltip 查看完整内容。

列表默认按创建时间倒序排列，底部提供分页：

- 当前页码。
- 每页条数：10、20、50。
- 总记录数。
- 上一页、下一页和页码跳转。

查询条件改变后点击“查询”才发起请求；点击“重置”清空条件并回到第一页。

查询条件栏使用流式布局，不按 2K、4K 等固定分辨率预设每行控件数量；字段组按照可用宽度自动排列，空间不足时按字段组整体换行。

查询条件中的字段组统一使用固定宽度 325px，避免不同显示器下标签和控件宽度变化导致排版跳动；移动端可切换为容器全宽。

查询字段采用“标签在左、控件在右”的同行布局，标签统一左对齐并在控件高度内上下居中；标签与控件属于同一字段组，禁止上下拆分或错位。查询交互控件统一使用 Element Plus 表单控件。


知识库列表展示所属租户名称，不展示所属组织、租户 ID 或组织 ID。知识库只归属租户，不直接归属组织；组织访问通过组织授权控制。操作列固定包含“工作区”“修改”“授权”“删除”四个操作，其中“授权”为下拉按钮，包含“用户授权”和“组织授权”两个入口。点击“工作区”进入当前知识库工作区；点击授权入口后打开对应权限管理抽屉；按钮之间保持明确间距，避免操作项挤在一起。

组织授权抽屉标题为“组织访问权限管理”，不复用知识库编辑表单，内容包含当前知识库信息、权限说明和当前已授权组织。点击“添加授权组织”按钮后，从侧边滑出“选择授权组织”面板；面板展示当前租户下尚未授权的组织，使用普通列表展示多选框、组织名称、上级组织三列，并提供搜索和分页。搜索与分页均通过后端接口获取数据，接口原型为 `GET /api/v1/knowledge-bases/{kb_id}/organizations/available`，支持 `keyword`、`page` 和 `page_size` 参数。勾选完成后点击“确认”，所选组织直接追加到当前已授权组织列表，不设置额外的“批量授权”步骤。点击“取消”、关闭按钮或遮罩关闭面板时，放弃本次未确认的选择。已授权组织展示组织名称和访问权限状态，并提供“撤销”操作。授权只控制组织成员对知识库的访问范围，不改变知识库的所属租户；知识库不维护直接组织归属。

#### 通用待选列表交互规范

待选列表是项目内可复用的通用交互模式，适用于组织、用户、租户成员、数据源等“从候选集合中选择并加入已选结果”的场景。后续新增同类页面必须遵守以下规则：

1. **入口与容器**
   - 在已选结果区域提供明确的“添加”类文本或主按钮。
   - 点击后从右侧滑出“选择[对象]”面板，不跳转页面，不覆盖当前已选结果。
   - 面板关闭、点击遮罩或点击“取消”时，只关闭面板并丢弃本次临时选择。

2. **列表结构**
   - 待选数据使用正常表格列表，不使用下拉框替代，不使用静态卡片堆叠。
   - 第一列固定为多选框列，后续列按对象属性定义；组织和用户场景统一为三列。
   - 组织列表列为：多选、组织名称、上级组织。
   - 用户列表列为：多选、用户名称、所属组织；不展示邮箱地址列。
   - 列表必须同时提供加载中、无结果、接口异常和正常数据状态。

3. **搜索与分页**
   - 查询条件放在列表上方，查询字段使用四字标签或清晰的对象属性提示。
   - 搜索和分页必须通过后端候选接口获取数据，前端不得用全量静态数据模拟分页。
   - 接口至少支持 `keyword`、`page`、`page_size`，返回 `rows`、`total`、`page`、`page_size`。
   - 候选接口必须在服务端按业务上下文过滤，并排除当前已选或已授权对象，避免前端跨页过滤造成总数不准确。
   - 查询条件变化后重置到第一页；切换页码时保留当前关键词。

4. **多选与临时状态**
   - 勾选结果只保存在面板临时状态中，不在勾选时直接写入已选结果或提交后端。
   - 跨页选择时保留已勾选 ID，返回上一页或重新查询时恢复当前页已选状态。
   - 已授权对象不出现在待选列表中；重复选择由前端展示层和后端接口共同防重。

5. **确认与结果回填**
   - 面板底部固定提供“取消”和“确认”两个文本/按钮操作。
   - 点击“确认”后关闭面板，将本次选择结果直接追加到外层的已选结果列表，并刷新数量。
   - 原型不设置额外的“批量授权”按钮；多选后的确认即完成本次选择动作。后端可以使用批量事务接口实现一次提交，但不改变前端交互。
   - 提交或回填失败时保留面板上下文，展示明确错误提示，不使用本地数据伪造成功结果。

6. **复用边界**
   - 只替换对象标题、表格字段、候选接口和结果行展示，不改变待选列表的布局、状态、分页和确认取消逻辑。
   - 需要树形选择、拖拽排序或复杂联动时，应在此规范上扩展，并在对应原型文档中明确说明，不得默默改变通用待选列表行为。

列表页不展示所有知识库的文档，也不提供跨知识库文档列表。

### 2.2 文档管理入口

文档管理不设置独立的左侧菜单入口，也不是跨知识库的文档汇总页。平台管理 Tab 与知识库工作区 Tab 使用同一个权限菜单 Tab 控件。控件自行读取 `/api/v1/auth/menus` 返回的菜单数据，不依赖页面传入 Tab 数组；工作区中的“文档”标签必须根据 `knowledge_base_documents` 权限动态显示，`tenant_member` 和 `org_member` 不显示该标签。

点击工作区中的“文档”标签后的行为：

1. 如果尚未选择知识库，展示知识库选择页。
2. 用户选择一个知识库后，进入 `/knowledge-bases/:kbId/documents`。
3. 页面标题、上传动作、查询条件和文档表格全部绑定这个 `kb_id`。
4. 切换知识库后重新加载文档列表，不保留上一个知识库的文档数据。

文档管理首页的知识库选择列表提供：

- 知识名称查询。
- 知识状态筛选。
- 创建用户筛选。
- 查询和重置按钮。
- 刷新按钮与查询条件放在同一工具栏中，使用文字按钮。
- 总记录数、页码、上一页、下一页和每页条数分页。
- 不展示“文档范围”列，选择知识库后再进入对应文档工作区。

文档管理页面通过工作区顶部“问答”Tab进入当前知识库的 `/knowledge-bases/:kbId/chat`，不在概览页重复设置问答入口按钮。

概览页在工作区 Tab 下方提供统计时间范围筛选，默认“近 7 天”，支持“近 30 天”和“近 90 天”，并提供刷新操作；控件与 Tab 分区保持独立，不与 Tab 分界线重叠。

### 2.3 知识库工作区

进入工作区后，顶部固定显示当前知识库名称、状态和 `kb_id`，并提供工作区内导航：

```text
< 返回知识库列表   企业制度库   [active]
                    概览 | 文档 | 问答
```

工作区内的所有请求都必须使用当前路由的 `kb_id`。

工作区概览补充图表区域：

- 文档处理趋势：使用 ECharts 折线图展示每日新增文档和索引完成数量。
- 文档状态分布：展示待处理、处理中、已完成和失败数量。
- 问答趋势：使用 ECharts 折线图展示问答次数和活跃会话数。
- 检索质量：不在页面展示相似度数值，仅展示无参考资料回答数量等可读性更强的质量指标。
- 热门问题、文档引用排行和最近活动。

图表只统计当前知识库的数据，支持时间范围切换；无数据时显示空状态，异常指标需要突出显示。

### 2.4 文档页

页面职责：管理当前知识库的文档，不显示其他知识库的文档。

页面内容：

- 当前知识库名称和说明。
- 文档统计：全部、已完成、处理中、失败。
- 当前知识库文档表格。
- “上传文档”右侧抽屉。
- 文档详情查看入口。
- 处理中的文档显示处理中状态，不提供重复上传按钮。
- 失败文档的错误信息和重建索引操作。
- 删除文档操作。

用户先从知识库列表进入工作区，再通过工作区顶部的“文档”标签进入对应文档工作区。

进入具体知识库后的文档列表操作列根据状态显示：

- `ready`：查看分片、索引文本按钮、删除；点击“索引”直接打开构建进度滑块。
- `processing` / `pending`：查看索引状态、索引文本按钮、删除；点击“索引”直接打开构建进度滑块。
- `interrupted`：显示“已中断”，提供索引文本按钮、删除；点击“索引”直接打开构建进度滑块，并在滑块内提供“重试”。
- `failed`：查看错误、索引文本按钮、删除；点击“索引”直接打开构建进度滑块。

文档列表不展示“文档范围”列，因为当前页面已经处于明确的知识库工作区。
列表提供文档名称、文档状态条件查询，以及总记录数、页码、上一页、下一页和每页条数分页；列表必须展示文档名称、文档状态对应字段列。
分页按钮使用纯文本按钮，不使用背景色。

### 2.4.1 文档分片信息

文档列表的“查看”动作定义为“查看分片”，不是打开原始文件预览。

点击后打开右侧详情抽屉，抽屉内容包括：

- 文档名称、文件类型、文件大小、上传时间、更新时间。
- 文档索引状态和错误信息。
- 分片总数、已生成向量数量和向量维度。
- 分片列表。

### 2.4.2 索引构建任务进度

文档列表操作列新增“索引”文本按钮。点击后直接从右侧打开“索引构建任务进度”滑块，不离开当前文档列表，不覆盖列表筛选条件和分页位置。重建索引按钮仅放在进度滑块内，避免列表操作列出现重复入口。

索引进度滑块包含以下区域：

- **文档摘要**：文档名称、文件类型、文档状态、最近更新时间。
- **任务摘要**：任务 ID、任务状态、整体进度、开始时间、最近更新时间、已尝试次数。
- **阶段进度**：解析、分块、向量化、写入索引四个阶段，分别展示未开始、处理中、已完成或失败。
- **历史任务列表**：展示当前文档最近的索引构建任务，按创建时间倒序排列；当前任务高亮显示，历史任务只读查看。
- **失败信息**：任务失败时展示失败原因和失败时间。
- **关闭方式**：保留滑块标题栏右上角唯一的“关闭”按钮，底部不再重复放置关闭入口。
- **操作按钮**：位于处理阶段下方、历史任务上方，右侧对齐。`pending/running` 任务从左到右显示“中断”和“刷新”；`interrupted/canceled` 任务显示“重试”和“刷新”；普通可重建状态显示“重建索引”和“刷新”。三个动作不同时展示，避免用户对同一任务产生多个状态变更入口。

任务状态与展示规则如下：

| 任务状态 | 进度展示 | 交互 |
|---|---|---|
| `pending` | 0%，显示“等待处理” | 支持手动刷新，不能显示预计完成时间 |
| `running` | 显示服务端返回的实际百分比和当前阶段 | 滑块打开期间每 5 秒自动刷新一次，也支持手动刷新 |
| `succeeded` | 100%，所有阶段显示已完成 | 显示完成时间和最终更新时间，停止自动刷新 |
| `failed` | 保留失败前的实际进度，当前阶段标记失败 | 显示失败原因和失败时间，停止自动刷新 |
| `interrupted` | 保留中断前的实际进度，当前阶段标记“已中断” | 显示中断原因和中断时间，停止自动刷新，提供“重试” |
| `canceled` | 显示已取消及取消前进度 | 停止自动刷新，提供“重试”，列表状态以服务端返回为准 |
| 无任务 | 显示“暂无索引构建任务” | 不展示虚假的进度百分比 |

滑块打开时只查询当前文档的数据范围，不能展示其他文档任务。若文档存在多个历史任务，默认展示最近创建的一条任务，并在摘要中标明“最近一次任务”。历史任务列表默认展示最近 10 条，超过 10 条提供列表内分页；列表只支持查看，不提供重新执行、删除或取消历史任务操作。接口异常时保留滑块标题和文档名称，主体显示错误状态及“重新加载”文本按钮，不使用本地静态进度兜底。

历史任务列表字段包括：任务 ID、任务状态、整体进度、开始时间、结束时间、耗时、尝试次数和失败原因。当前运行任务在列表中使用“当前任务”标识；失败原因过长时单行省略，使用 tooltip 查看完整内容。任务列表为空时显示“暂无历史索引任务”，不能用当前文档状态虚构历史记录。

索引进度展示依赖服务端返回任务的 `status`、`progress`、`current_step`、`error_message`、`attempts`、`started_at`、`finished_at` 和 `updated_at`。其中 `progress` 和 `current_step` 必须来自任务执行状态，前端不得根据文档状态或轮询次数自行推算。

### 2.4.3 重建索引

进度滑块中的“重建索引”按钮点击后立即提交重建任务，不再弹出二次确认。系统重新解析、切分并生成当前文档向量，原有可用索引在新任务完成前继续保留。提交成功后滑块保持打开，任务状态回到 pending/running，进度从服务端实际返回值开始展示。

### 2.4.4 中断

“中断”只针对服务端明确返回 `pending` 或 `running` 的任务。用户点击后请求中断当前任务；Worker 采用协作式停止，不强制杀死正在执行的 Embedding 请求。中断成功后，用户主动中断的任务进入 `canceled`；如果是 Worker 失联、进程重启或系统连接异常，则进入 `interrupted`。前端停止自动刷新并展示中断/取消说明。

点击“中断”后按钮进入“中断中…”，滑块保持打开；接口返回成功后任务进入 `canceled` 或由服务端后续标记为 `interrupted`。中断失败时保留原任务状态，不伪造取消结果。

### 2.4.5 重试

“重试”只针对 `interrupted`、`canceled`，以及服务端明确标记为可重试的 `failed` 任务。点击后立即调用重试接口，不弹出二次确认。后端必须在事务中校验当前用户权限、文档 ID 与任务 ID 的归属、任务状态是否仍可重试，并检查同一文档不存在 `pending` 或 `running` 任务。校验通过后创建一条新的 `pending` 任务，保留原任务为只读历史记录，并通过 `retry_of_task_id` 记录重试来源；文档状态回到 `processing`，新任务从服务端实际进度开始更新。

交互规则如下：

- `pending` / `running`：显示“中断”和“刷新”；中断按钮进入“中断中…”，不允许重复操作。
- `interrupted` / `canceled`：显示“重试”和“刷新”；点击后按钮进入“提交中…”，成功后继续轮询新任务。
- `failed`：默认继续使用“重建索引”，只有服务端标记可重试时才显示“重试”。
- 中断或重试接口失败：保留原任务状态、历史信息和错误原因，不把页面强行切换为其他状态。
- 历史任务只读展示原任务的中断原因、尝试次数和重试来源，不允许对历史记录再次操作。

重建索引按钮规则：

- `ready`：按钮可用；点击后立即创建重建任务，文档状态变为 `processing`。
- `failed`：按钮可用；点击后立即创建新的重建任务，保留上一次失败任务的历史信息，列表状态变为 `processing`。
- `pending` / `processing`：按钮置灰，不允许重复创建任务。
- 无权限或文档已删除：不展示可执行按钮。

提交成功后保持进度滑块打开，并立即启动或继续 5 秒一次的任务查询；接口失败时保留原状态并显示失败原因。任务完成或失败后停止定时刷新。

分片列表提供内容模糊查询和分页：

- 按分片正文关键词模糊查询。
- 查询和重置按钮。
- 刷新按钮与查询条件放在同一工具栏中，使用文字按钮。
- 总记录数、页码、上一页、下一页和每页条数。
- 查询条件和分页按钮均使用文本样式。

分片列表字段：

| 字段 | 说明 |
|---|---|
| 分片序号 | 当前分片在文档中的顺序 |
| 内容摘要 | 分片正文的前若干字符 |
| Token 数 | 当前分片的 token_count |
| 向量状态 | 已生成或未生成 |
| 操作 | 展开查看完整分片内容 |

分片详情需要能够看到完整文本、来源文档、页码、章节、起始位置和元数据。这样可以直接核对“文档已索引”与“检索实际使用的内容”是否一致。

文档状态：

```text
pending → processing → ready
                       └→ failed
```

上传成功只表示文件已经接收，不代表向量已经生成。只有 `ready` 才表示文档可以参与问答检索。

### 2.5 问答页

页面职责：在当前知识库中创建和继续会话。

当前实现截图同步基线：

- 页面顶部显示“当前知识库问答”、当前知识库名称和“问答配置”入口。
- 左侧会话面板显示“会话”标题、“＋ 新建会话”文本入口和“新会话”当前项；已有会话行右侧显示“···”操作入口。
- 会话面板和会话列表使用白色背景，普通会话行保持白底，当前“新会话”仅使用浅蓝色高亮，不使用黑色背景。
- 中间问答区域为空时显示星标图标和“输入一个问题，开始探索知识库”，底部固定问题输入框、快捷键提示和“发送问题”按钮。
- 右侧参考资料面板显示“参考资料”和数量“0 条”，无引用时显示“回答后显示参考资料”。
- 问答页使用业务无关的通用问答工作区组件，会话列表、消息流、输入区和发送状态不得在知识库页面重复实现；参考资料作为知识库业务扩展传入。
- 通用问答工作区采用清晰、克制的企业级视觉层级：会话标题、搜索输入、按钮和辅助说明不低于 13px，问答正文统一为 14px；聊天标题为 18px，面板标题为 16px。不得使用 10px、11px 字号承载会话时间、快捷键、引用摘要等需要持续阅读的信息。
- 会话栏、消息区和参考资料区使用一致的圆角、边框、阴影和内边距；当前会话通过浅蓝底、描边和左侧强调线识别，消息区使用浅灰蓝背景承托白色助手消息，用户消息使用品牌色渐变，三栏在不同业务入口中保持相同密度。
- 输入区高度、焦点环、发送按钮和快捷键提示保持统一；助手回答的段落、标题、列表、引用、表格和代码块必须具有清晰层级，长内容不因业务模块不同而缩小字体。
- 参考资料按独立条目卡片展示，来源名称和摘要保持清晰，编号、页码等元信息可弱化颜色但不得牺牲可读性。

页面内容：

- 当前知识库名称和索引可用状态。
- 会话列表，包括“会话”标题、“新建会话”入口和历史会话。
- 会话列表支持独立滚动，滚动范围只覆盖会话列表，不影响聊天消息区和参考资料区。
- 点击会话项加载会话消息，当前会话使用高亮状态；加载过程中保留当前列表并显示加载状态。
- 点击“新建会话”清空当前消息和引用，进入新会话上下文，不提前创建服务端会话。
- 会话操作菜单提供“重命名”和“删除”；重命名在列表项内进入编辑状态，删除需要二次确认。
- 当前会话标题、消息区和参考资料区保持现有布局，查询不会改变聊天区域状态。
- 会话面板顶部提供“快速查找会话”输入框，不设置“查询”按钮；用户输入关键词后按 Enter，按会话标题关键词远程查询。
- 清空关键词后按 Enter 查询当前知识库和当前用户的全部会话。
- 快速查找过程中保留当前会话列表结构并显示加载状态；查询完成后刷新列表并保持当前聊天区域状态。
- 问题输入区。
- 输入区支持快捷键：按 Enter 发送问题，按 Shift+Enter 换行；发送按钮保留作为鼠标操作入口。
- 当前回答的引用面板。
- 命中数量、会话 ID 等调试信息。
- 助手回答支持 Markdown，包含标题、段落、加粗、列表、引用、代码块和表格。
- Markdown 内容先经过 HTML 安全过滤，再渲染到消息区。

问答请求必须携带：

```json
{
  "kb_id": 1,
  "question": "报销流程需要哪些材料？",
  "user_id": "dev-user",
  "conversation_id": 10
}
```

服务端返回新的 `conversation_id` 后，前端保存它，后续问题继续使用同一会话。

## 3. 导航约束

左侧导航只负责一个一级功能：

- 知识库管理

文档和问答不出现在左侧主导航中。进入具体知识库后，工作区导航显示：

- 概览
- 文档
- 问答

文档管理主导航在没有选定知识库时只展示知识库选择页，不能指向固定知识库 ID。这样既保留文档管理的一级入口，又不会造成所有知识库文档共享的误解。

## 4. 表单交互

所有表单统一使用右侧抽屉，不使用居中对话框：

- 新建知识库：右侧抽屉。
- 编辑知识库：右侧抽屉。
- 上传文档：右侧抽屉。
- 文档元数据编辑：右侧抽屉。

表单视觉规范：

- 知识库信息表单使用 Element Plus 表单控件，并使用 Bootstrap 的基础布局体系组织字段结构。
- 表单标签统一使用 13px 字号、400 字重和 20px 行高；输入框、选择框和文本域中的输入文字、选择文字和占位文字统一使用 13px 字号，并保持清晰的 20px 行高。
- 表单颜色按信息层级统一：标签使用沉稳的次级文字色，已填写内容使用高对比度主文字色，占位文字使用弱化文字色，禁用内容进一步弱化，校验错误使用明确但不过度刺眼的错误色。
- 表单控件统一使用约 38px 高度；标签与控件之间保留明确间距，字段之间保持一致的垂直间距，不能出现标签紧贴字段的情况。
- 必填星号与标签保持稳定的占位和间距，不得导致同一表单中的标签错位；校验提示和帮助文案归属于当前字段组。
- 表单不得使用页面级临时字体或随意覆盖公共间距，新增字段优先复用统一公共表单样式。
- 查询条件标签字体使用 `#151517`，输入内容、占位文字和禁用态继续按既有层级区分；列表仅表头字体使用 `#151517`，表格正文、辅助信息、操作文字和状态文字继续按既有层级区分。

删除确认可以继续使用确认提示，因为它不是表单录入场景。

## 5. 状态展示

列表中的状态只使用文字颜色区分，不使用彩色背景标签：

- `ready` / `active`：绿色文字。
- `processing` / `pending`：橙色文字。
- `failed`：红色文字。
- 其他状态：灰色文字。

这样可以减少视觉噪音，让文件名、知识库名称和操作按钮成为列表的主要信息。

## 6. 关键接口边界

| 页面动作 | 接口 | 必须携带的知识库范围 |
|---|---|---|
| 查询知识库详情 | `GET /knowledge-bases/{id}` | URL 中的 `id` |
| 查询文档 | `GET /documents?kb_id={id}` | 当前工作区 `kb_id` |
| 上传文档 | `POST /documents/upload` | FormData 中的 `kb_id` |
| 删除文档 | `DELETE /documents/{id}` | 由文档记录绑定的 `kb_id` 校验 |
| 发起问答 | `POST /chat` | JSON 中的 `kb_id` |
| 查询引用 | 由问答响应返回 | 只能展示当前回答引用 |

前端不得把文档列表放在全局 Store 中作为跨知识库共享数据。文档列表应以当前工作区的 `kb_id` 为查询键，在路由切换时重新加载。

## 7. 页面原型

可直接打开同目录的 `知识库工作区原型.html` 查看页面切换效果。

原型包含三个状态：

1. 知识库管理列表。
2. 文档管理中的知识库选择状态。
3. `企业制度库` 的文档管理页。
4. `企业制度库` 的问答页。

点击另一个知识库后，原型会切换当前工作区名称和文档集合，说明文档数据属于当前知识库，而不是全局共享。
