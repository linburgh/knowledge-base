# 知识库系统完整前端原型设计

## 1. 原型入口

统一 HTML 原型为：

- `知识库工作区原型.html`

该文件已整合平台管理与知识库工作区，左侧导航按权限展示平台管理和知识库管理。

## 2. 页面信息架构

```text
登录页 `/login`
└── 登录成功后跳转知识库管理主页 `/knowledge-bases`

平台管理（仅 p_super_admin）
├── 平台概览
├── 用户管理
├── 租户管理
└── 组织管理

知识库管理
├── 知识库列表
└── 知识库工作区
    ├── 概览
    ├── 文档
    └── 问答
```

平台管理和知识库管理使用同一个应用壳层、左侧菜单和右侧抽屉交互。平台管理员进入租户资源时，顶部应显示当前目标租户。

## 3. 用户登录页

登录页作为独立页面，仅包含：

- 用户名或邮箱输入框。
- 密码输入框。
- “记住密码”复选框。
- 登录按钮。
- 登录失败提示区域。

“记住密码”勾选后，下次打开登录页自动回填用户名和密码；未勾选时不回填密码。登录成功后根据用户租户关系处理租户上下文：用户只属于一个租户时自动进入该租户；用户属于多个租户时登录后展示租户选择页或弹窗；平台超级管理员进入平台管理后再选择目标租户。登录失败时在登录页展示错误提示，不使用居中弹窗。主界面右上角提供退出登录入口，退出后返回登录页。

原型提供单租户、多租户和平台超级管理员三类登录演示路径，用于查看不同租户处理规则下的页面跳转和租户选择交互。

主界面右上角用户区展示当前登录用户的头像首字母、显示名称、用户名和平台角色；退出登录按钮紧邻用户信息展示。

登录后根据当前用户的平台角色、租户角色和组织角色展示对应菜单。普通租户用户不展示平台管理菜单。

角色展示和菜单范围按作用域区分：

- 平台角色：当前原型只展示 `p_super_admin` 可见的平台管理菜单。
- 租户角色：在当前租户上下文中控制用户、组织和知识库的管理入口。
- 组织角色：在当前组织上下文中控制成员和组织授权资源入口。

平台超级管理员拥有全部平台操作权限。平台管理菜单不能因为用户拥有租户管理员或组织管理员角色而直接展示。

## 4. 平台管理

### 3.1 平台概览

展示用户总数、正常用户数、租户总数、正常租户数、组织总数和知识库总数，并展示：

- 用户增长趋势，使用折线图展示时间变化。
- 租户资源分布，默认以柱状图展示资源指标排名前 5 的租户。
- 文档处理状态分布。
- 最近平台活动。

图表支持时间范围切换，点击图表数据可以进入对应管理列表。

### 3.2 用户管理

列表提供用户名称、邮箱地址、用户状态、所属租户查询条件，并提供查询、重置、分页；列表必须同步展示用户名称、邮箱地址、用户状态等对应字段列。操作使用“查看”“修改”“删除”等文本按钮，删除前进行确认。新建和修改通过右侧抽屉完成，字段包含用户名、邮箱、手机号、显示名称、所属租户、所属组织、平台角色、租户角色、组织角色和状态。

### 3.3 租户管理

列表提供租户名称、租户状态查询条件和分页，不再提供租户编码查询条件；展示租户名称、成员数量、知识库数、租户状态等对应字段列。操作列保留“查看”，修改按钮名称仍为“修改”，点击后下拉菜单包含“修改信息”和“成员列表”；删除前进行确认。新建、修改通过右侧抽屉完成。

点击“成员列表”进入当前租户成员列表，提供成员名称、成员角色和成员状态查询条件，并提供查询、重置、“添加成员”和“刷新”按钮以及分页。列表展示成员名称、邮箱地址、成员角色、所属组织、成员状态、加入时间和操作，操作提供“查看”“修改”“移除”；“添加成员”和“刷新”放在查询条件栏，“返回租户列表”保留在页面工具栏。

### 3.4 组织管理

组织管理使用组织树表展示组织层级、上级组织、成员数量和组织状态。组织名称列通过分级缩进、细竖线和圆点体现父子关系，不使用字符树图标。组织树表一次性展示全部组织，不分页；操作列提供“查看”，修改按钮名称仍为“修改”，点击后下拉菜单包含“修改信息”和“成员列表”，另设“删除”列。点击“成员列表”后，深钻进入当前组织的用户列表；用户列表查询条件栏提供成员名称、成员状态查询、“添加成员”和“刷新”按钮，并提供分页；列表同步展示成员名称、成员角色、成员状态对应字段列；“返回组织树”保留在页面工具栏。

## 5. 知识库管理与工作区

知识库列表展示知识名称、描述、知识状态、创建时间、创建用户和操作，不展示模型列。列表提供知识名称、知识状态、创建用户、所属租户、所属组织查询条件与分页，并同步展示对应字段列。所属租户列展示租户名称，所属组织列展示组织名称，不展示租户 ID 或组织 ID。操作列使用“工作区”“修改”“组织授权”“删除”文本按钮；“工作区”进入当前知识库工作区，“组织授权”用于维护当前知识库可访问的组织范围。

组织授权使用独立的“组织访问权限管理”抽屉，展示当前知识库信息和权限说明，提供添加授权组织、已授权组织列表及撤销授权操作。授权只控制组织成员访问范围，不修改知识库归属关系。

点击“工作区”进入独立工作区，工作区包含概览、文档和问答三个标签。文档和会话都必须绑定当前 `kb_id`，不提供跨知识库共享入口。

知识库新建和修改使用右侧抽屉，字段包含名称、所属租户、描述和独立系统提示词。其中所属租户为必填下拉项，展示租户名称并在修改时回填当前租户；未选择所属租户时禁止保存。系统提示词为空时使用默认提示词。

知识库概览增加：

- 文档处理趋势，使用折线图展示每日新增文档和索引完成数量。
- 文档状态分布。
- 问答趋势，使用 ECharts 折线图展示问答次数和活跃会话数。
- 无参考资料回答统计，不在页面展示相似度数值。
- 热门问题、文档引用排行和最近活动。

图表只统计当前知识库 `kb_id` 的数据，不跨知识库混合展示。

问答输入框支持快捷键：按 Enter 发送问题，按 Shift+Enter 换行；发送按钮继续保留，作为鼠标操作入口。

## 6. 统一交互和视觉约束

- 所有列表必须具备查询条件和分页。
- 所有列表的“刷新”按钮统一放在查询条件栏中，使用文字按钮，不使用单独图标按钮；组织树表也遵循此规则。
- 所有列表查询条件按字段组自然平铺，字段标签与对应控件保持同组，宽度不足时按整组自动换行，不允许标签和控件拆开错位。
- 查询条件栏桌面端每行展示四个布局单元，其中最多三个查询字段加一个操作按钮组；字段不足时保持左对齐，宽度不足时按整组换行。
- 每个查询布局单元设置最小宽度 220px、最大宽度 320px；大屏下不继续无限拉伸，查询栏保持左侧紧凑排列并在右侧保留自然留白。
- 查询字段采用“标签在左、控件在右”的同行布局，标签统一左对齐并在控件高度内上下居中；标签与控件属于同一字段组，禁止上下拆分或错位。
- 查询条件交互控件统一使用 Element Plus 表单控件，列表页面保持统一的查询、重置、刷新和分页交互。
- 查询、重置、上一页、下一页和页码按钮遵循统一原型样式。
- 列表操作优先使用文本按钮，按钮之间保留明确间距。
- 所有表单使用右侧抽屉，不使用居中弹窗。
- 状态只使用中文文字和文字颜色区分，不使用背景色标签。
- 平台管理、知识库管理和工作区共享同一套字体、颜色、间距、卡片和表格风格。
- 文本过长时统一限制容器最大宽度，并使用单行或多行省略号，不能撑大页面布局；用户名称、用户名、角色、表格字段和页面标题均遵循此规则。
- 被省略的完整内容通过 Tooltip、详情抽屉或详情页面查看；退出、查询、分页等操作按钮必须保持可见，不因文本过长被挤出布局。
- 顶部用户区和窄屏布局使用 `min-width: 0`、最大宽度和响应式收缩；优先保留用户显示名称，用户名和角色信息作为次要信息收缩或隐藏。
- 页面主体控制在视口高度内，工作区的会话列表、聊天窗口、参考资料分别独立滚动。
- 平台概览和知识库概览使用统计卡片、折线趋势图、环形状态图和最近活动列表组合展示。
- 图表无数据时显示空状态，图表数据应来自独立统计接口，不使用当前分页列表数据推算。
- 图表实现统一采用 ECharts，基础布局和字体沿用 Bootstrap 风格，抽屉、选择器等交互沿用 Element Plus。
