# 会话管理测试说明

## 1. 测试脚本

```text
tests/test_conversation_crud.sh
```

脚本通过 HTTP 接口验证会话、消息和消息引用的基础 CRUD。默认接口地址为：

```text
http://127.0.0.1:28003/api/v1
```

## 2. 前置条件

先启动服务并确认数据库表已经初始化：

```bash
cd /home/linburgh/workspace/ai-llm/knowledge-base
OS_CONFIG_DIR=$PWD/etc .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 28003 --reload
```

需要先准备一个未删除的知识库，并取得其 ID。可以使用知识库脚本创建：

```bash
tests/test_knowledge_base_crud.sh add
```

引用接口需要 `kb_id`、`document_id` 和 `chunk_id`。当前 DDL 没有声明外键，脚本默认使用 `DOCUMENT_ID=1`、`CHUNK_ID=1`；如果数据库启用了外键或希望验证真实引用，请替换为目标知识库下已有文档和分块的 ID。

## 3. 一键测试完整流程

```bash
KB_ID=1 tests/test_conversation_crud.sh all
```

`all` 依次覆盖：

1. 创建会话。
2. 查询会话详情。
3. 修改会话。
4. 查询会话列表。
5. 新增消息。
6. 查询消息列表。
7. 新增引用。
8. 查询引用列表。
9. 删除引用。
10. 删除消息。
11. 删除会话。

脚本会从创建响应中自动提取会话、消息和引用 ID，并校验关键字段。删除会话对应当前服务的软删除，状态应变为 `deleted`；删除消息时服务会先删除其引用，再删除消息本身。

## 4. 单独执行接口测试

```bash
KB_ID=1 tests/test_conversation_crud.sh add
CONVERSATION_ID=1 tests/test_conversation_crud.sh get
CONVERSATION_ID=1 tests/test_conversation_crud.sh modify
KB_ID=1 USER_ID=test-user tests/test_conversation_crud.sh list
CONVERSATION_ID=1 tests/test_conversation_crud.sh add-message
CONVERSATION_ID=1 tests/test_conversation_crud.sh list-messages
MESSAGE_ID=1 KB_ID=1 DOCUMENT_ID=2 CHUNK_ID=3 tests/test_conversation_crud.sh add-citation
MESSAGE_ID=1 tests/test_conversation_crud.sh list-citations
CITATION_ID=1 tests/test_conversation_crud.sh remove-citation
MESSAGE_ID=1 tests/test_conversation_crud.sh remove-message
CONVERSATION_ID=1 tests/test_conversation_crud.sh remove
```

单独测试时，脚本不会自动创建或清理前置资源；请使用实际 ID，并注意删除操作会改变数据库状态。

## 5. 环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `BASE_URL` | API 基础地址 | `http://127.0.0.1:28003/api/v1` |
| `KB_ID` | 知识库 ID；创建会话和新增引用必填 | 空 |
| `USER_ID` | 会话用户 ID及列表过滤条件 | `test-user` |
| `CONVERSATION_ID` | 会话 ID；单独测试会话、消息列表或删除时使用 | 空 |
| `MESSAGE_ID` | 消息 ID；单独测试消息、引用时使用 | 空 |
| `CITATION_ID` | 引用 ID；单独删除引用时使用 | 空 |
| `DOCUMENT_ID` | 引用关联的文档 ID | `1` |
| `CHUNK_ID` | 引用关联的分块 ID | `1` |
| `CURL_CONNECT_TIMEOUT` | curl 连接超时时间（秒） | `5` |
| `CURL_MAX_TIME` | 单个请求最大时间（秒） | `30` |

## 6. 常见问题

- `知识库不存在`：`KB_ID` 不存在或知识库已被删除，请换用有效知识库。
- `引用与消息不匹配`：新增引用时的 `KB_ID` 必须与消息所属知识库一致。
- `消息不存在` 或 `会话不存在`：单独测试使用了已删除或错误的 ID。
- 服务返回 404/422：确认服务已启动、`BASE_URL` 正确，并检查请求路径和参数。
