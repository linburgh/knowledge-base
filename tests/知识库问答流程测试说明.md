# 知识库问答流程测试说明

## 1. 测试脚本

```text
tests/test_chat_flow.sh
```

脚本通过 HTTP 验证从知识库创建、文档上传、索引完成到问答返回的完整流程。

## 2. 前置条件

需要启动：

- PostgreSQL + pgvector
- MinIO
- FastAPI 后端
- Embedding 服务
- Chat 模型服务

后端默认地址：

```text
http://127.0.0.1:28003/api/v1
```

当前检索使用 pgvector，因此文档必须成功索引并生成 embedding；Chat Service 还需要 `etc/app.yaml` 中的 `model.chat_model`、`model.api_key` 和 `model.base_url` 可用。

## 3. 执行完整流程

```bash
cd /home/linburgh/workspace/ai-llm/knowledge-base
tests/test_chat_flow.sh all
```

脚本依次执行：

1. 创建临时知识库。
2. 上传测试 Markdown 文档。
3. 轮询文档状态直到 `ready`。
4. 发起 `POST /api/v1/chat`。
5. 校验 `answer`、`conversation_id`、`message_id`、`citations` 和 `retrieval`。
6. 默认软删除脚本自动创建的知识库。

## 4. Chat 请求

请求接口：

```text
POST /api/v1/chat
```

示例：

```json
{
  "kb_id": 1,
  "user_id": "chat-test-user",
  "question": "报销流程需要哪些材料？",
  "top_k": 5
}
```

如果携带 `conversation_id`，服务会复用该用户在指定知识库下的会话；不携带时自动创建新会话。

## 5. 返回结果

```json
{
  "conversation_id": 1,
  "message_id": 2,
  "answer": "报销需要准备发票、费用明细和审批单。",
  "citations": [

      "source_name": "chat-flow.md",
      "page": null,

    }

```

## 6. 常用环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `BASE_URL` | API 基础地址 | `http://127.0.0.1:28003/api/v1` |
| `KB_ID` | 已有知识库 ID；为空时自动创建临时知识库 | 空 |
| `USER_ID` | 问答用户 ID | `chat-test-user` |
| `CREATED_BY` | 文档创建人 | `chat-test-user` |
| `QUESTION` | 测试问题 | `报销流程需要哪些材料？` |
| `TOP_K` | 检索数量 | `5` |
| `POLL_INTERVAL` | 文档状态轮询间隔秒数 | `2` |
| `POLL_ATTEMPTS` | 最大轮询次数 | `60` |
| `CLEANUP` | 是否软删除自动创建的知识库 | `true` |
| `CURL_MAX_TIME` | 单次 HTTP 请求超时秒数 | `120` |

## 7. 常见失败

- 文档一直是 `processing`：检查 Worker/索引任务、MinIO 和 Embedding 服务。
- 文档变为 `failed`：查看文档的 `error_message`，通常是文件解析、MinIO 或 Embedding 配置问题。
- 返回 `Embedding 生成失败`：检查模型地址、API Key 和 Embedding 模型名称。
- 返回 `Chat 模型未配置`：修改 `etc/app.yaml` 的 `model.chat_model`，不能继续使用 `change-me`。
- 返回 `Chat 模型调用失败`：检查 Chat 模型服务是否兼容 OpenAI Chat Completions 接口。
