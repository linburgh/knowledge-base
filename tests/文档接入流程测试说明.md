# 文档接入流程测试说明

## 1. 脚本位置

```text
tests/test_document_ingestion.sh
```

该脚本用于通过 HTTP 接口测试当前文档接入流程。

默认接口地址：

```text
http://127.0.0.1:28003/api/v1
```

## 2. 前置条件

先启动后端服务：

```bash
cd /home/linburgh/workspace/ai-llm/knowledge-base
OS_CONFIG_DIR=$PWD/etc .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 28003 --reload
```

确认健康检查可用：

```bash
curl http://127.0.0.1:28003/api/v1/health
```

数据库表结构需要已经初始化：

```bash
docker compose exec -T postgres \
  psql -U linburgh -d knowledge_base \
  < scripts/db/data_table_ddl.sql
```

MinIO 是文档接入流程的必需组件，需要先启动：

```bash
docker compose up -d minio
```

当前默认配置：

```text
endpoint: http://127.0.0.1:9000
console: http://127.0.0.1:9001
bucket: knowledge-base
access_key: linburgh
secret_key: linburgh
```

## 3. 一键测试完整流程

执行：

```bash
cd /home/linburgh/workspace/ai-llm/knowledge-base
tests/test_document_ingestion.sh all
```

`all` 会依次执行：

1. 创建测试知识库。
2. 上传测试 Markdown 文件，并由上传接口后台触发索引任务。
3. 查询文档详情。
4. 查询知识库下的文档列表。

脚本会输出每个接口的 JSON 响应。

## 4. 单独测试每个步骤

### 4.1 创建知识库

```bash
tests/test_document_ingestion.sh create-kb
```

输出中会包含：

```text
create-kb passed, KB_ID=1
```

### 4.2 上传文档

使用已有知识库：

```bash
KB_ID=1 tests/test_document_ingestion.sh upload
```

如果不指定 `FILE_PATH`，脚本会自动生成一个临时 Markdown 文件。默认生成：

```text
FILE_SIZE_MB=1
FILE_EXT=.md
```

指定文件上传：

```bash
KB_ID=1 FILE_PATH=tests/tmp/upload_5mb.txt tests/test_document_ingestion.sh upload
```

指定自动生成文件的大小和类型：

```bash
KB_ID=1 FILE_SIZE_MB=10 FILE_EXT=.txt tests/test_document_ingestion.sh upload
```

测试 50MB Markdown 上传：

```bash
KB_ID=1 FILE_SIZE_MB=50 FILE_EXT=.md tests/test_document_ingestion.sh upload
```

测试不支持的文件类型：

```bash
KB_ID=1 FILE_SIZE_MB=1 FILE_EXT=.zip tests/test_document_ingestion.sh upload
```

该请求应返回失败，因为当前允许的扩展名只有 `.pdf`、`.md`、`.markdown`、`.txt`、`.docx`。

上传成功后输出：

```text
upload passed, DOC_ID=1
```

上传接口会在文档记录创建成功后自动提交后台索引任务。后台任务会从 MinIO 下载原始文件，解析文件、切分文本、写入 `t_document_chunk`，并更新文档状态。

### 4.3 查询文档详情

```bash
DOC_ID=1 tests/test_document_ingestion.sh get
```

### 4.4 查询文档列表

```bash
KB_ID=1 tests/test_document_ingestion.sh list
```

请求接口：

```text
GET /api/v1/documents?kb_id=1
```

### 4.5 手动触发文档索引

```bash
DOC_ID=1 tests/test_document_ingestion.sh index
```

请求接口：

```text
POST /api/v1/documents/{DOC_ID}/index
```

该接口主要用于手动重新索引。正常上传文档后，不需要再额外调用它。

## 5. 常用环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `BASE_URL` | API 基础地址 | `http://127.0.0.1:28003/api/v1` |
| `OWNER_ID` | 创建知识库的 owner_id | `test-user` |
| `CREATED_BY` | 上传文档的创建人 | `test-user` |
| `KB_ID` | 知识库 ID | 空 |
| `DOC_ID` | 文档 ID | 空 |
| `FILE_PATH` | 上传文件路径 | 自动生成 Markdown 文件 |
| `FILE_SIZE_MB` | 自动生成文件大小，单位 MiB；仅在 `FILE_PATH` 为空时生效 | `1` |
| `FILE_EXT` | 自动生成文件扩展名；仅在 `FILE_PATH` 为空时生效 | `.md` |
| `CURL_CONNECT_TIMEOUT` | curl 连接超时时间 | `5` |
| `CURL_MAX_TIME` | curl 单请求最大时间 | `120` |

## 6. 示例

完整测试：

```bash
tests/test_document_ingestion.sh all
```

使用已有知识库上传指定文件：

```bash
KB_ID=1 FILE_PATH=tests/tmp/upload_10mb.txt tests/test_document_ingestion.sh upload
```

自动生成指定大小和类型的文件后上传：

```bash
KB_ID=1 FILE_SIZE_MB=10 FILE_EXT=.txt tests/test_document_ingestion.sh upload
```

手动重新触发索引：

```bash
DOC_ID=1 tests/test_document_ingestion.sh index
```

## 7. 注意事项

- `tests/tmp/upload_5mb.txt`、`upload_10mb.txt`、`upload_50mb.txt` 是零字节内容填充的大文件，适合测试上传大小和分块读取。
- 如果要测试索引流程，建议使用脚本自动生成的 `.txt`、`.md`、`.markdown` 文件，或准备有实际文本内容的 `.pdf`、`.docx` 文件。
- 如果用 `FILE_EXT=.pdf` 或 `FILE_EXT=.docx` 自动生成文件，脚本只会生成对应大小的二进制占位文件，适合测试上传，不适合测试解析索引。
- 文档上传会先按分块写入本地临时文件，再上传到 MinIO；数据库中的 `object_path` 保存 MinIO object key，例如 `documents/1/{sha256}_readme.md`。
- 本地临时文件只用于上传缓冲和索引解析，上传 MinIO 后会删除，不作为正式存储。
- 如果脚本提示 `curl: (7) Couldn't connect to server`，说明后端服务没有启动或端口不可达。
